# 02_L1_候选抽取规则

## 一、文件定位

本文是 L0-L7 纵向运行规则组中的 L1 候选抽取规则文件，用于定义罗盘系统如何从 L0 原始输入中抽取候选对象、候选事实、候选资料记录、候选问题、候选签证事项和候选知识，并形成可供后续校验、反问、人工确认和 L2 真源入链判断使用的候选内容。

本文只负责规定候选抽取、候选归口、候选锚点识别、缺口标记、风险提示和向 L2 交接前的边界规则，不负责确认正式对象，不负责确认正式事实，不负责正式入链，不负责正式状态流转，不负责接口 schema、页面布局、数据库表结构、代码实现、测试脚本或部署命令。

L1 候选抽取层是原始输入与正式内容之间的候选缓冲层。L1 输出即使结构完整、来源清楚、风险提示充分，也仍然属于候选内容，不得直接成为正式对象、正式事实、正式状态、正式权限、正式规则或对外展示放行依据。

## 二、适用范围

本文适用于以下 L1 候选抽取场景：

1. 从 L0 原始输入中识别候选对象线索。
2. 从 L0 原始输入中识别候选事实线索。
3. 从 L0 原始输入中识别候选资料记录线索。
4. 从 L0 原始输入中识别候选问题与风险线索。
5. 从 L0 原始输入中识别候选签证事项、变更事项、确认事项和结算关联线索。
6. 从 L0 原始输入中识别候选知识、候选经验、候选模板和候选规则线索。
7. 对多事项混合输入进行候选拆分、归口和缺口标记。
8. 对候选内容形成待补、反问、人工确认、风险提示和追溯准备。

本文不适用于定义字段全集、枚举全集、状态机、权限矩阵、接口协议、页面流程、数据库结构、AI 提示词模板或实施任务。

## 三、L1 总原则

### 3.1 候选唯一原则

L1 只生成候选内容，不生成正式内容。

候选对象不是正式对象资产，候选事实不是正式事实，候选资料记录不是正式资料记录，候选问题不是正式问题与风险记录，候选签证事项不是正式决策与变更记录，候选知识不是正式规则或正式依据。

### 3.2 原始回指原则

L1 抽取的任何候选内容，都必须能够回指 L0 原始输入、来源记录、资料线索、输入元信息或待确认片段。

无法回指原始输入，是指候选内容不能与 L0 已保留的原始输入、来源记录、输入元信息、资料线索或待确认片段建立可追溯关系；或者候选内容只来自 AI 推断、人工补写、页面默认值、历史习惯、口语猜测、上下文猜测而无法说明原始依据来源。

无法回指原始输入的内容，不得形成可交接给 L2 的候选事实，只能形成待补、挂起、阻断或人工说明内容。

### 3.3 归口先行原则

L1 抽取候选内容时，必须先判断其可能归口方向，包括对象资产层、事实记录层、资料记录、问题与风险记录、决策与变更记录、经验规则层或待补内容。

无法判断归口方向的内容，不得默认进入事实记录层，不得默认进入经验规则层，不得默认作为资料资产或正式事实处理。

### 3.4 缺口显性化原则

L1 必须识别候选内容中的项目锚点、主体锚点、资料锚点、物资锚点、时间锚点、证据锚点、金额归属锚点、责任主体锚点和确认主体缺口。

缺口不得由 AI、页面默认值、最近项目、常识推断或历史习惯自动补齐。缺口应进入待补、反问、人工确认、挂起或阻断。

### 3.5 不替代治理原则

L1 可以为标准治理、S2 校验、关键字段反问、风险分级、权限判断、追溯与版本、AI 辅助边界提供候选材料，但不得替代上述治理规则作出正式裁决。

L1 的候选完整、候选匹配、候选分类、候选风险提示和候选置信判断，不等于校验通过，不等于人工确认通过，不等于正式事实成立。

## 四、L1 输入承接规则

L1 只能承接来自 L0 的原始输入、来源记录、输入元信息、锚定线索、风险提示、待补要求、异常说明和阻断状态。

L1 接收 L0 内容时，应先判断以下内容是否具备最低抽取条件：

1. 原始输入是否已保留。
2. 输入来源是否已记录或明确标记缺失。
3. 输入形态是否已记录或明确标记不明。
4. 当前输入是否已经由 L0 标记为阻断自动流转。
5. 项目、主体、资料、物资、事项等锚定线索是否已记录或标记待补。
6. 输入是否存在来源不明、权限不明、读取失败、内容冲突、高风险事项、疑似重复或历史迁移边界。

L1 的阻断判断来源于 L0 阻断状态、L0-L7 纵向运行规则总则、L0 原始输入规则和标准治理中的校验规则口径。L1 不新增独立阻断体系，不自行放宽 L0 已经形成的阻断边界。

满足最低抽取条件但锚定线索不完整的输入，可以带待补标记进入 L1 抽取。已触发阻断条件的输入不得进入候选抽取，除非后续补齐或人工确认解除阻断。

## 五、候选对象抽取规则

### 5.1 候选对象范围

L1 可以从原始输入中识别以下候选对象线索：

1. 候选组织资产线索。
2. 候选项目资产线索。
3. 候选主体资产线索。
4. 候选物资资产线索。
5. 候选资料资产线索。

候选对象线索只表示原始输入中可能存在稳定对象，不表示对象资产已经成立。

### 5.2 候选项目线索

候选项目线索可以来自项目名称、地址、客户名称、合同名称、施工地点、报价资料、结算资料、现场照片、沟通上下文或历史迁移材料。

L1 可以将上述内容识别为项目候选线索，并标记项目锚点缺口、重名风险、归属不清、跨项目风险或待人工确认要求。

L1 不得根据最近项目、默认项目、单一地址、口语简称或聊天上下文直接确认正式项目资产。

### 5.3 候选主体线索

候选主体线索可以来自客户、甲方、甲方员工、供应商、班组、员工、设计师、联系人、项目负责人、外部协同方和转发人等来源。

L1 可以识别主体名称、角色线索、关系线索、提交主体线索和确认主体线索，但不得确认主体身份、主体权限、代表关系或正式责任。

主体重名、称谓混乱、代提交、转发截图、群聊截图、主体关系不明或外部人员权限不明时，应标记为待补、关系冲突或人工确认。

### 5.4 候选资料线索

候选资料线索可以来自合同、报价、预算、图纸、照片、签证、验收资料、结算资料、付款凭证、发票回执、客户确认材料、甲方回执和资料包。

L1 可以识别资料名称、资料类型线索、资料归属线索、资料版本线索、资料缺失线索和资料证据线索，但不得确认资料资产成立、资料记录成立或资料证据效力成立。

### 5.5 候选对象禁止边界

L1 不得执行以下行为：

1. 将候选对象写成正式对象资产。
2. 将相似名称直接合并为同一正式对象。
3. 将资料标题直接确认为资料资产。
4. 将联系人姓名直接确认为主体资产。
5. 将口语项目名称直接确认为正式项目资产。
6. 将对象状态提示写成正式状态投影。
7. 将候选对象提供给 L3 至 L7 作为正式对象消费。

## 六、候选事实抽取规则

### 6.1 候选事实范围

L1 可以从原始输入中识别可能归入事实记录层的候选事实线索，包括沟通与服务、施工、验收与交付、财务、资料、问题与风险、决策与变更、物资流转、出勤、关系、责任与确认、商务维护、履历、复盘与反馈等方向。

上述识别仅表示“可能形成事实记录”，不表示事实已经成立。

### 6.2 多事项拆分

当一条原始输入同时包含多个项目、多个主体、多个时间、多个动作、多个事实方向、多个资料、多个风险、多个金额、多个确认主体或多个处理结果时，L1 应进行候选事项拆分。

候选事项拆分应遵守以下规则：

1. 每个候选事项应尽量保持同一项目、同一核心动作、同一事实方向和同一证据来源。
2. 不得因拆分导致证据链断裂。
3. 不得因拆分导致同一事实的对象、动作、时间、证据分离。
4. 不得把分析、建议、评价和事实混写为同一候选事实。
5. 当同一输入中的项目、主体、时间、动作、金额、责任、证据或确认主体无法对应到同一候选事项，并会影响事实归口、责任归属、金额归属、状态承接或证据链完整性时，应标记为事项冲突、待补或人工确认。
6. 无法拆分且不影响事实判断的内容，可以作为备注线索保留；无法拆分且影响事实判断的内容，不得交接为可入链候选事实。

### 6.3 候选事实归口

L1 应根据原始输入中的动作、对象、资料、金额、责任、确认、时间和证据线索，为候选事实标记可能归口方向。

归口判断应遵守以下边界：

1. 沟通、回访、服务跟进、协同说明等线索，优先作为沟通与服务记录候选。
2. 施工过程、现场进度、质量情况、返工、停工、到场等线索，优先作为施工记录候选。
3. 验收、交付、交付资料、交付确认等线索，优先作为验收与交付记录候选。
4. 收款、付款、成本、结算、扣款、报销、费用等线索，优先作为财务记录候选。
5. 资料上传、提交、补齐、确认、退回、归档、引用、缺失等线索，优先作为资料记录候选。
6. 问题、风险、异常、整改、投诉、阻断、责任争议等线索，优先作为问题与风险记录候选。
7. 承诺、签证、变更、范围调整、价格调整、方案调整、关键确认等线索，优先作为决策与变更记录候选。
8. 采购、到货、领用、退换、调拨、损耗等线索，优先作为物资流转记录候选。
9. 到场、离场、工时、工天、人员参与等线索，优先作为出勤记录候选。
10. 主体关系变化、合作关系、归属关系、介绍关系等线索，优先作为关系记录候选。
11. 责任、确认、复核、授权、确认链路等线索，优先作为责任与确认记录候选。
12. 客户维护、商务跟进、机会推进、回访维护等线索，优先作为商务维护记录候选。
13. 主体经历、合作历史、项目参与经历等线索，优先作为履历记录候选。
14. 项目复盘、阶段反馈、改进线索等线索，优先作为复盘与反馈记录候选。

候选事实归口存在重叠时，应保留冲突提示，不得强行裁定为单一正式事实类型。

## 七、候选资料记录抽取规则

L1 可以从原始输入中识别候选资料记录线索，包括资料上传、资料提交、资料补齐、资料缺失、资料确认、资料退回、资料更新、资料归档、资料引用和资料作废等过程。

候选资料记录与资料资产应保持边界：

1. 资料本体属于资料资产线索。
2. 资料动作属于资料记录候选。
3. 资料作为证据时属于证据链线索。
4. 资料内容被摘要时仍不得替代资料本体。
5. 资料上传成功、读取成功、页面显示成功或外部回执收到，不等于资料记录正式成立。
6. 资料确认、资料缺失、资料退回、资料归档等内容如涉及正式事实，必须经 L2 真源入链规则承接。

L1 不得仅凭资料名称、资料截图、资料摘要或 AI 识别结果确认资料有效性、资料归属或资料证据效力。

## 八、候选问题抽取规则

L1 可以从客户反馈、甲方反馈、现场照片、员工说明、班组回执、供应商回执、施工记录线索、资料缺口、质量异常、工期异常、费用异常和沟通冲突中识别候选问题与风险线索。

候选问题与风险线索应至少标记以下方向：

1. 可能关联的项目线索。
2. 可能关联的主体线索。
3. 可能关联的资料或证据线索。
4. 问题描述或风险现象。
5. 是否涉及质量、工期、成本、收款、资料、客户满意度、责任、对外展示或权限敏感内容。
6. 是否需要待补、反问、人工确认或风险分级。

L1 不得把问题线索写成正式问题与风险记录，不得直接定责，不得直接确认风险等级，不得直接关闭问题，不得将投诉、建议或反馈自动视为事实成立。

## 九、候选签证事项抽取规则

L1 可以从合同、报价、预算、图纸、现场签证、验收资料、结算资料、聊天确认、客户回执、甲方回执、施工变化、工程量变化、材料变化、范围变化和价格变化中识别候选签证事项。

候选签证事项不是新增事实类型。其后续归口应根据内容性质进入资料记录、决策与变更记录、财务记录、验收与交付记录、施工记录或问题与风险记录等既有事实记录方向。

候选签证事项应重点标记以下内容：

1. 项目锚点是否明确。
2. 相关主体和确认主体是否明确。
3. 签证资料、现场证据、聊天确认或外部回执是否存在。
4. 涉及范围、工程量、金额、工期、材料、责任或验收的内容是否清楚。
5. 是否存在口头确认、截图确认、代确认、权限不明、资料缺失或版本冲突。
6. 是否需要人工确认、风险分级、关键字段反问或阻断。

L1 不得把候选签证事项写成正式签证成立，不得把客户或甲方的回执线索直接写成确认成立，不得把金额线索写成结算确认，不得把施工变化直接写成变更正式生效。

## 十、候选知识抽取规则

L1 可以从复盘反馈、问题处理、人工修正、模板使用反馈、资料缺失模式、校验失败原因、重复问题、风险模式和 AI 辅助归纳中识别候选知识线索。

候选知识线索只能作为经验规则层候选来源，不得直接成为待核验参考线索、正式规则、模板候选、正式提示或正式决策依据。

候选知识抽取应遵守以下边界：

1. 必须保留来源事实、来源反馈、来源资料、来源视图或来源人工修正线索。
2. 必须标记适用范围不明、来源不足、风险不明或复检要求。
3. 涉及金额、责任、结算、合同、签证、客户承诺、甲方确认、对外展示、权限和脱敏的候选知识，应按高风险内容提示。
4. AI 辅助归纳只能形成候选知识线索，不得自动形成可被直接采用的经验规则层候选内容。
5. 单次原始输入不得直接沉淀为正式规则或模板候选。

## 十一、锚点、缺口与反问规则

L1 抽取候选内容时，应识别以下锚点和缺口：

1. 项目锚点。
2. 主体锚点。
3. 资料锚点。
4. 物资锚点。
5. 组织归属锚点。
6. 时间锚点。
7. 金额归属锚点。
8. 证据锚点。
9. 责任主体锚点。
10. 确认主体锚点。
11. 权限和可见范围线索。
12. 状态承接线索。

L1 对权限和可见范围线索、状态承接线索只做原始内容中的关键词、语义片段、来源关系和疑似缺口记录，不进行权限判断，不进行状态判断，不生成状态投影，不触发正式状态流转。权限判断和状态承接由标准治理、S2 校验和 L2 真源入链规则承接。

缺少关键锚点时，L1 应形成待补、反问、人工确认、挂起或阻断提示，不得自行补齐。

涉及金额、责任、结算、签证、验收、变更、客户承诺、甲方确认、付款、收款、对外展示或资料证据效力的候选内容，必须标记关键字段反问或人工确认要求。

## 十二、风险提示与 S2 校验准备

L1 不执行 S2 校验，不输出校验通过结论，不形成正式风险等级。

L1 应为 S2 校验准备以下候选材料：

1. 原始输入引用。
2. 候选对象线索。
3. 候选事实线索。
4. 候选资料记录线索。
5. 候选归口方向。
6. 缺失字段和缺失锚点。
7. 证据存在、证据缺失或证据冲突线索。
8. 权限不明、主体不明、项目不明、资料不明和来源不明线索。
9. 高风险事项提示。
10. 待确认片段和人工确认触发原因。
11. 追溯和版本所需的来源关系。

以下情况必须提示 S2 或人工确认重点处理：

1. 涉及客户承诺、甲方确认、结算、付款、收款、签证、变更、验收、责任、赔偿、扣款或合同成立。
2. 来源不明、主体不明、权限不明、资料缺失或证据冲突。
3. 候选事项跨项目、跨主体、跨资料或跨时间。
4. 外部回执可能被误写成正式确认。
5. AI 推断可能被误写成事实。
6. 候选知识可能被误写成正式规则。
7. 候选签证事项可能被误写成正式变更或正式结算依据。

## 十三、AI 辅助抽取边界

AI 可以在 L1 中承担受控辅助作用，包括输入整理、事项拆分建议、候选对象识别、候选事实识别、候选资料线索识别、候选问题识别、候选签证事项识别、候选知识线索识别、缺口提示和待确认片段提示。

AI 在 L1 中不得承担以下职责：

1. 不确认正式对象。
2. 不确认正式事实。
3. 不确认正式资料。
4. 不确认正式状态。
5. 不确认正式风险等级。
6. 不确认对象锚点。
7. 不确认事实锚点。
8. 不确认客户承诺、甲方确认、付款、结算、签证、变更、验收或责任归属。
9. 不替代关键字段反问。
10. 不替代 S2 校验。
11. 不替代权限判断。
12. 不替代人工确认。
13. 不替代 L2 真源入链。
14. 不删除或覆盖 L0 原始输入。
15. 不把推断、建议、分析或经验归纳写成事实结论。

AI 辅助抽取结果必须保留候选属性，并进入 L1 的候选归口、缺口提示、风险提示和后续治理链路。

## 十四、L1 向 L2 交接规则

L1 向 L2 交接时，只能交接候选内容、缺口提示、风险提示、待确认片段、证据线索、候选归口和追溯关系，不得交接正式事实结论。

L1 不自行生成版本号、追溯编号或正式追溯结论。L1 只继承 L0 已保留的原始输入、来源记录和输入元信息，并整理候选内容与来源之间的追溯线索。版本与追溯规则由标准治理中的追溯与版本口径承接。

L1 向 L2 交接前，应满足以下最低要求：

1. 能够回指 L0 原始输入。
2. 已标记候选对象、候选事实、候选资料记录、候选问题、候选签证事项或候选知识中的至少一种候选方向，或明确说明未能抽取原因。
3. 已标记项目、主体、资料、时间、证据、金额、责任、确认主体等关键锚点是否存在缺口。
4. 已标记候选内容可能归口方向。
5. 已标记高风险事项和人工确认触发原因。
6. 已保留来源关系、原始输入关系和追溯线索。
7. 未输出正式对象、正式事实、正式状态、正式风险等级或正式锚点。
8. 未触发应阻断交接的情况。

当候选内容缺少部分锚点但未触发阻断条件时，可以带待补标记交接给 L2 进行正式化前判断。来源无法回指、原始输入缺失、高风险事项未提示、候选事实无来源片段、AI 推断被写成事实、正式结论已混入候选包时，不得交接给 L2。

L2 只能把 L1 输出作为候选材料消费，不得因 L1 抽取完整、AI 置信度高、页面展示清楚或外部回执存在而直接入链。

## 十五、与业务数据体系的承接关系

### 15.1 与对象资产层的关系

L1 可以识别候选组织、候选项目、候选主体、候选物资和候选资料线索，但不得创建或确认正式对象资产。

对象成立、对象归属、对象合并、对象拆分、对象作废、对象状态投影和对象关系确认，由对象资产层及 L2 真源入链规则承接。

### 15.2 与事实记录层的关系

L1 可以识别候选事实方向，但不得创建正式事实记录。

正式事实必须经过标准治理、权限控制、风险判断、关键字段反问、必要人工确认、证据链和追溯要求，并由 L2 真源入链层承接。

### 15.3 与资料资产和资料记录的关系

L1 可以同时识别资料本体线索、资料动作线索和资料证据线索，但必须保持三者边界。

资料本体归资料资产，资料动作归资料记录，资料作为证据时进入证据链和追溯关系。L1 不得把资料存在、资料读取、资料摘要、资料上传或资料回执直接写成正式事实。

### 15.4 与经验规则层的关系

L1 可以识别候选知识、候选经验、候选模板和候选规则线索，但不得形成经验规则层候选内容、正式规则或模板候选。

经验规则层候选内容进入后续受控消费前，必须完成来源核验、适用范围限定、冲突检查、风险判断、必要人工确认和追溯记录。

## 十六、接口、页面与验收承接边界

### 16.1 接口承接

接口可以承接 L1 候选抽取所需的输入和输出边界，但不得通过接口返回、接口成功、外部系统回执或字段映射结果反向确认正式事实。

具体接口边界由 `60_接口边界与集成约束/00_接口边界与集成约束总则.md` 承接。本文只规定 L1 候选抽取的业务边界。

### 16.2 页面承接

页面可以展示候选内容、待补提示、反问提示、风险提示、人工确认提示和阻断原因，但不得通过按钮、状态展示、默认值、交互路径或展示样式反向确认候选内容为正式事实。

具体页面承接由 `70_前后端协同边界与页面承接/00_前后端协同边界与页面承接总则.md` 承接。本文只规定页面不得越过 L1 候选边界。

### 16.3 验收承接

验证与验收应检查 L1 是否只生成候选内容，是否保留原始回指，是否正确识别候选对象、候选事实、候选资料记录、候选问题、候选签证事项和候选知识，是否标记缺口、风险、待补和人工确认要求，是否阻断候选内容直入正式事实。

具体验收规则由 `80_验证与验收规则/00_验证与验收规则总则.md` 承接。本文只规定 L1 成立所需的业务判断口径。

## 十七、禁止项

L1 候选抽取规则中禁止以下行为：

1. 候选对象直接成为正式对象资产。
2. 候选事实直接成为正式事实。
3. 候选资料记录直接成为正式资料记录。
4. 候选问题直接成为正式问题与风险记录。
5. 候选签证事项直接成为正式签证、正式变更或正式结算依据。
6. 候选知识直接成为正式规则、模板候选、正式提示或正式决策依据。
7. AI 输出直接成为正式对象、正式事实、正式状态、正式风险等级或正式确认。
8. 页面展示、接口返回、外部回执、文件读取、资料上传或表格解析结果直接成为正式事实。
9. 缺少来源回指的候选事实进入 L2。
10. 高风险事项未标记人工确认或风险提示。
11. 多事项混合输入未拆分且未标记冲突。
12. 候选内容被 L3 至 L7 作为正式依据消费。
13. L1 替代 S2 校验、权限判断、风险裁决、人工确认或 L2 真源入链。
14. L1 生成正式版本号、正式追溯编号或正式追溯结论。
15. L1 定义接口 schema、页面布局、数据库表结构、代码实现、测试脚本或部署命令。

## 十八、成立条件

L1 候选抽取规则成立，应满足以下判断口径：

1. 能够从 L0 原始输入中抽取候选对象、候选事实、候选资料记录、候选问题、候选签证事项和候选知识。
2. 能够明确 L1 输出全部属于候选内容，不形成正式对象、正式事实、正式状态、正式权限或正式规则。
3. 能够保留所有候选内容对 L0 原始输入的回指关系。
4. 能够明确无法回指原始输入的内容不得交接为可入链候选事实。
5. 能够对多事项混合输入进行候选拆分或冲突标记。
6. 能够区分资料本体、资料动作和资料证据线索。
7. 能够将候选签证事项归口到既有事实记录方向，而不新增事实类型。
8. 能够将候选知识归口到经验规则层候选链路，而不直接将候选内容作为正式依据。
9. 能够识别项目、主体、资料、物资、时间、金额、证据、责任和确认主体等关键锚点缺口。
10. 能够只记录权限、可见范围和状态承接线索，不进行权限判断或状态判断。
11. 能够触发待补、反问、人工确认、风险提示、挂起或阻断。
12. 能够为 S2 校验、权限判断、风险分级、追溯与版本和 L2 真源入链准备候选材料。
13. 能够继承 L0 来源记录和输入元信息，整理追溯线索，但不自行生成正式版本号或正式追溯结论。
14. 能够防止 AI、页面、接口、外部回执、资料上传和表格解析结果反向确认事实成立。
15. 能够将合格候选内容交接给 L2，并阻断不具备来源、追溯、高风险提示或候选边界的内容继续流转。
