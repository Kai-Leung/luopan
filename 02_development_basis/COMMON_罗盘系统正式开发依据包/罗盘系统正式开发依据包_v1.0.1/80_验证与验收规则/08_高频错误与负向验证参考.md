# 08_高频错误与负向验证参考

## 一、文件定位

本文定义罗盘系统开发依据中的高频错误与负向验证参考，用于在验证、联检、回归和准出判断中识别常见越界、误展示、反写真源、权限越界、回执误判、Mock 混入、外部反馈反写、准出误判和基线错误。

本文只汇总已经由上游规则、验收标准、验证场景、回归规则、一致性检测规则、准出规则和前后端协同验收断言明确过的高频错误与负向验证参考，不新增系统能力、字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。

本文不是测试脚本、操作手册、接口调用说明、页面检查清单、代码检查规则或部署验收方案。负向验证参考只能用于识别失败风险和归口问题，不得作为新规则来源反向改写 10-70 目录正文依据。

## 二、使用原则

高频错误与负向验证参考应遵守以下原则：

1. 只用于识别常见失败模式，不替代验收标准、验证方案、验证场景、回归验证、一致性检测和准出规则。
2. 每类错误应能定位到错误对象、触发动作、反向样例、错误表现、应有结果、失败判定、失败归口、影响等级、准出影响和回归要求。
3. 负向验证应优先覆盖真源反写、权限越界、状态反写、回执误判、页面误展示、外部反馈反写、AI 越权、Mock 混入和准出层级误判。
4. 发现高频错误时，应先判断问题是否真实存在、是否归口当前文件、是否影响准出，再决定修补、退回、阻断或记录。
5. 高频错误不能用正向功能通过、页面可显示、接口成功、Mock 通过或联调通过抵消。
6. 负向验证参考不得写成具体测试步骤、自动化测试代码、接口请求样例或页面交互流程。
7. 高频错误如导致新增字段、状态、权限、事实类型、接口能力、页面能力或业务边界，应阻断并请求裁决。
8. 高频错误如只属于表述重复、术语轻微不稳或下游名称后续校准，可记录为非阻断问题。
9. 所有失败问题应归口到对应目录或文件，不得在本文直接补写业务规则、接口规则或页面规则。
10. 负向验证结论应明确是否影响 S1-S6 准出，并明确是否触发 R1-R5 回归。

## 三、高频错误识别模型

每个高频错误应按以下模型识别：

| 识别要素 | 判断要求 |
|---|---|
| 错误编号 | 能唯一标识当前高频错误，便于后续断言总表引用 |
| 错误对象 | 明确错误发生在基准包、YAML、目录职责、输入、候选、事实、接口、页面、AI、外部协同、Mock 或准出判断 |
| 触发点 | 明确错误由录入、上传、补齐、确认、驳回、查询、导出、回执、外部反馈、联调、归集或升版触发 |
| 反向样例 | 明确构造什么错误输入、错误返回、错误展示或错误判断用于暴露问题 |
| 错误表现 | 明确页面、接口、文件、包级结果或准出结论出现了什么不合格表现 |
| 应有结果 | 明确按上游规则应展示、返回、阻断、挂起、撤回、纠偏或归口什么结果 |
| 失败判定 | 明确一旦出现何种结果即判定失败 |
| 失败归口 | 明确归口到 30、40、50、60、70、80 或包级治理 |
| 影响等级 | 明确属于 E1、E2、E3、E4 或 E5 |
| 准出影响 | 明确影响 S1、S2、S3、S4、S5 或 S6 哪一层准出 |
| 回归要求 | 明确需要触发 R1、R2、R3、R4 或 R5 哪一级回归 |

| 当前结论 | 负向验证通过、待补、阻断或需裁决 |
| 验证范围 | 明确覆盖哪些错误类型、负向对象和影响等级 |
| 命中错误 | 列出命中的错误编号或错误类型 |
| 阻断点 | 只列影响当前准出的错误 |
| 非阻断问题 | 只列不影响当前推进但需记录或处理的问题 |
| 失败归口 | 标明归口目录或文件 |
| 准出影响 | 标明影响 S1-S6 哪一层准出 |
| 回归要求 | 标明是否触发 R1-R5 回归 |
| 处理方式 | 修补、退回、阻断、归集前收口、包级回归或请求裁决 |

负向验证结论不得只写“发现问题”“建议优化”“基本可接受”，必须明确是否影响当前准出。
