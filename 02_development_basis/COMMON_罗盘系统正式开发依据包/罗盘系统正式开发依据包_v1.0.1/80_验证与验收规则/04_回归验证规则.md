# 04_回归验证规则

## 一、文件定位

本文定义罗盘系统开发依据在单文件修改、目录完成、归集入包、基准包升版、问题修补、冲突收口和进入下一阶段前的回归验证规则。

本文只定义回归验证的触发条件、回归等级、最低检查集、通过标准、失败标准、阻断条件、非阻断问题、结果记录和准出影响，不定义自动化测试代码、测试脚本、接口调用方式、页面操作流程、数据库结构、部署方案、开发实施计划或具体工具链。

回归验证的核心作用，是确认已经通过的边界、术语、路径、上下游、真源、权限、状态、接口、页面、回执、外部协同和验收断言，在修改、修补、归集或升版后没有被破坏。回归验证不得新增系统能力，不得反向修改上游规则，不得用局部修补覆盖全局口径。

## 二、回归验证总原则

回归验证应遵守以下原则：

1. 凡发生正式稿修改、目录归集、包级升版、问题修补、边界收口或准出判断，均应触发对应范围的回归验证。
2. 回归验证必须覆盖被修改点、直接上游、直接下游、同目录总表、相关禁止项和准出影响。
3. 回归验证不只检查原问题是否解决，还必须检查是否引入新冲突、新越界、新旧称残留、新增能力风险或上下游错误。
4. 已正式化文件被修改后，必须重新检查文件状态、版本、YAML、路径、标题、上下游和正文边界。
5. 目录归集前，应检查同组文件是否齐全、职责闭合、总表收口、路径一致、术语一致和禁止项未被突破。
6. 包级升版后，应检查当前最高基准包是否唯一、tree/manifest 是否同步、包内文件是否完整、旧版本是否未压制新版本。
7. 负向边界回归失败不得用正向功能通过抵消。
8. 回归验证结果必须可归口、可追溯、可判断是否影响继续写作、归集、开发或阶段准出。

## 三、回归等级

回归验证按影响范围分为五个等级。不同等级应使用不同的最低检查集，不得把高等级回归降级为局部检查。

| 回归等级 | 触发条件 | 最低检查范围 | 准出影响 |
|---|---|---|---|
| R1 单文件回归 | 草稿修改、正式化前自检、单文件定向修补、轻微术语收口 | 当前文件正文、YAML、标题、路径、直接上下游、禁止项 | 影响单文件正式化 |
| R2 同组回归 | 同目录文件完成、同组总表生成、同组文件之间承接调整 | 当前目录全部已完成文件、目录总则、总表、组内上下游、术语一致性 | 影响目录继续写作或目录准出 |
| R3 归集前回归 | 准备将目录或文件组写入当前基准包 | 待归集文件、文件状态、路径、版本、YAML、术语、禁止项、与当前基准包同路径关系 | 影响归集准出 |
| R4 归集后 / 包级回归 | 已归集入包、基准包升版、tree/manifest 更新后 | 新基准包、包内路径、文件数量、tree/manifest、压缩包完整性、最高版本唯一性 | 影响包级准出和后续写作基线 |
| R5 开发 / 阶段准出回归 | 准备进入开发拆解、详细设计、联调、部署运行或阶段关闭 | 当前基准包、关键能力边界、正向场景、负向边界、一致性、回归记录、准出规则 | 影响开发准出或阶段准出 |

回归等级可以上调，不得无依据下调。出现真源污染、权限越界、状态反写、接口反写、页面反写、AI 越权、外部反馈反写或新增能力风险时，应至少上调到 R2；若已归集或影响包级基线，应上调到 R4。

## 四、回归触发条件

出现以下情况时，应执行回归验证：

| 触发条件 | 回归等级 | 必检项 |
|---|---:|---|
| 单文件草稿修改后 | R1 | 当前文件职责、术语、YAML、禁止项、上下游 |
| 单文件正式稿生成前 | R1 | file_status、version、title/H1、正文边界、禁止内容 |
| 用户提出审查意见、修改建议或问题清单后 | R1-R2 | 问题真实性、归口、修补范围、修补后边界 |
| 同目录多个文件完成后 | R2 | 文件齐全、职责闭合、总表收口、组内术语一致 |
| 同目录总表生成后 | R2 | 总表是否完整归口前序文件，是否新增规则 |
| 归集前联检后 | R3 | 文件状态、路径、版本、YAML、术语、禁止项、同路径冲突 |
| 归集入包后 | R4 | 新包完整性、tree/manifest、文件数、版本号、压缩包可用性 |
| 基准包升版后 | R4 | 最高版本唯一、旧包不压制新包、新包可读 |
| 术语收口后 | R1-R2 | 旧称残留、术语一致、语义未变形 |
| YAML upstream/downstream 调整后 | R1-R2 | 是否只列直接上下游，是否误列间接链路 |
| 进入下一目录写作前 | R2-R4 | 上一目录是否闭合，新目录是否有可承接上游 |
| 进入开发拆解前 | R5 | 开发依据是否足以支撑详细设计、开发、联调、验收 |
| 发现越界、新增能力或真源反写风险后 | R2-R5 | 受影响目录、包级基线、负向边界和准出影响 |

## 五、单文件回归最低检查集

单文件回归用于确认当前目标文件在修改、正式化或修补后仍然合格。

| 检查项 | 通过标准 | 失败标准 | 准出影响 |
|---|---|---|---|
| 当前目标文件 | 文件职责与当前目标文件一致 | 写入其他目录职责或跨文件扩写 | 阻断单文件正式化 |
| 文件状态 | file_status 与阶段一致 | 草稿、修改稿、正式稿错配 | 阻断正式化或归集 |
| 版本号 | 修改后版本处理合理 | 修改后未升版或无依据空升版 | 阻断归集 |
| YAML 字段 | 只使用允许字段 | 出现 owner、last_checked_by、tags、aliases 等越界字段 | 阻断正式化 |
| title/H1 | YAML title 与 H1 一致 | title 与 H1 不一致 | 阻断正式化 |
| 路径 | canonical_path、source_path 与落位一致 | 路径错误、旧路径残留、目录错位 | 阻断归集 |
| upstream/downstream | 只列直接上游和直接下游 | 展开间接链路、漏掉直接承接或虚构下游 | 阻断或待补 |
| 正文职责 | 只写当前文件职责内容 | 改写上游、提前写下游或跨目录混写 | 阻断 |
| 硬边界 | 未新增字段、枚举、状态、权限、事实类型、接口、页面、业务规则 | 借修补新增能力或改写边界 | 阻断 |
| 禁止内容 | 未写代码、SQL、schema、页面布局、部署、技术选型 | 混入实现内容、测试脚本或页面设计 | 阻断 |
| 术语口径 | 使用当前正式术语 | 出现旧称、混称或自创术语 | 待补或阻断 |
| 正文纯度 | 无过程说明、差异说明、自评说明 | 正文夹带写作过程、质量自评、落位说明 | 阻断正式化 |

## 六、目录级回归最低检查集

目录级回归用于确认一个目录文件组完成后，组内职责完整、边界闭合、总表可归口。

| 检查项 | 通过标准 | 失败标准 | 准出影响 |
|---|---|---|---|
| 文件齐全 | 任务卡规划文件均已完成 | 缺文件、编号断裂或总表缺失 | 阻断目录准出 |
| 总则成立 | 目录总则能约束本目录下游文件 | 总则过窄、过宽或与细则冲突 | 阻断目录准出 |
| 细则归口 | 每个细则只写自身职责 | 多个文件互相覆盖或重复定义 | 阻断或定向修补 |
| 总表收口 | 总表能汇总全组文件职责和承接关系 | 总表不能指导问题归口或新增规则 | 阻断目录准出 |
| 术语一致 | 同组文件使用同一术语口径 | 同组文件混用旧称或不同说法 | 待补 |
| 上下游一致 | 同组上下游直接关系合理 | 细则互相无依据交叉引用 | 待补或阻断 |
| 禁止项一致 | 同组文件未写入禁止内容 | 某文件混入代码、schema、页面布局等 | 阻断 |
| 60/70/80 分工 | 接口、页面、验收分工清楚 | 接口文件写页面设计，页面文件写验收规则，验收文件写实现 | 阻断 |
| 下游承接 | 当前目录能支撑下一目录写作 | 下一目录只能靠猜测补规则 | 阻断继续写作 |

目录级回归通过后，才可进入归集前联检或下一目录写作。

## 七、归集前回归最低检查集

归集前回归用于确认待归集文件可以写入当前基准包。

| 检查项 | 通过标准 | 失败标准 | 准出影响 |
|---|---|---|---|
| 文件状态 | 待归集文件均为正式稿 | 存在草稿或修改稿 | 阻断归集 |
| 文件路径 | 文件落位与 canonical_path 一致 | 文件错位、重复落位、路径旧称残留 | 阻断归集 |
| YAML 合规 | 表头字段、标题、版本、上下游合规 | 表头字段越界、标题不一致、上下游错误 | 阻断归集 |
| 版本处理 | 修改过的文件版本合理 | 修改未升版或无依据升版 | 阻断归集或待裁决 |
| 术语检查 | 无旧称残留和不稳术语 | 旧称残留或同组术语不一致 | 待补或阻断 |
| 禁止内容 | 未写代码、schema、页面布局、部署、技术选型 | 混入实现内容 | 阻断归集 |
| 职责边界 | 文件未越权改写上游或下游 | 当前文件承担其他目录职责 | 阻断归集 |
| 同路径覆盖 | 与当前基准包同路径文件可明确覆盖 | 多个版本无法裁决 | 阻断归集 |
| tree/manifest | 归集前不提前改，归集时再同步 | 归集前擅自修改包级清单 | 阻断或重做归集流程 |

归集前回归通过后，才可执行归集入包和包级升版。

## 八、归集后与包级回归最低检查集

归集后回归用于确认新基准包可作为后续写作依据。

| 检查项 | 通过标准 | 失败标准 | 准出影响 |
|---|---|---|---|
| 包版本 | 新包版本高于旧包，版本号明确 | 新旧包版本冲突或无法确认最高版本 | 阻断包级准出 |
| 文件落位 | 新文件写入正确目录 | 文件缺失、重复或路径错位 | 阻断包级准出 |
| 文件数量 | 包内文件数符合归集结果 | 文件数量异常减少或重复增加 | 阻断包级准出 |
| tree/manifest | 已同步更新 tree 和 manifest | tree/manifest 未更新或内容不一致 | 阻断包级准出 |
| 压缩包完整性 | 压缩包可打开、结构完整 | 压缩包损坏或缺目录 | 阻断包级准出 |
| 旧包关系 | 旧包仅作为历史参考 | 旧包压制新包或被继续当当前依据 | 阻断后续写作 |
| 新包可读 | 后续写作可读取新基准包所需文件 | 新包无法读取或关键文件缺失 | 阻断后续写作 |
| 已归集内容 | 新包内文件与归集文件一致 | 归集后内容被篡改或丢失 | 阻断包级准出 |
| 版本唯一性 | 当前最高基准包可唯一确认 | 多个高版本或同版本不同内容无法裁决 | 阻断后续写作 |

包级回归通过后，才能把新包作为当前最高基准包继续写作。

## 九、问题修补回归规则

问题修补回归用于确认审查意见、冲突检测、联检发现的问题已被正确处理。

| 检查项 | 通过标准 | 失败标准 | 准出影响 |
|---|---|---|---|
| 问题真实性 | 已判断问题是否真实存在 | 照单全收或未核验原文 | 阻断修补 |
| 问题归口 | 已判断是否归口当前文件 | 把上游问题强行修进当前文件 | 阻断修补 |
| 修补范围 | 只修补成立问题和必要范围 | 借修补重写无关章节 | 阻断正式化 |
| 修补后边界 | 修补后未新增能力或越权内容 | 补丁造成职责扩张 | 阻断 |
| 修补后术语 | 修补后术语与当前口径一致 | 修补引入旧称或新术语 | 待补 |
| 修补后上下游 | 修补后上下游仍合理 | 修补导致承接关系错误 | 待补或阻断 |
| 回归结果 | 原问题解决且无新增问题 | 修补解决一个问题，引入多个问题 | 继续修补或阻断 |

修补回归失败时，应继续定向修补或阻断，不能直接正式化或归集。

## 十、接口与页面回归规则

接口与页面回归用于确认 60 和 70 的承接边界没有被破坏。

| 回归对象 | 通过标准 | 失败标准 | 失败归口 |
|---|---|---|---|
| 输入接口 | 输入成功只表达已接收、待补或处理方向 | 输入成功展示为事实成立 | 60_接口边界与集成约束 |
| 外部映射 | 外部字段、状态、编号保留原值并候选映射 | 外部结果覆盖内部结果 | 60_接口边界与集成约束 |
| 回执接入 | 回执成功保持处理方向属性 | 回执成功展示为业务确认 | 60_接口边界与集成约束 |
| 失败回退 | 失败、超时、冲突、熔断可见且阻断扩散 | 失败隐藏为成功 | 60_接口边界与集成约束 |
| 页面动作 | 页面动作只触发接口和后续链路 | 页面按钮直接写正式事实 | 70_前后端协同边界与页面承接 |
| 页面状态 | 页面状态只表达处理方向 | 页面状态新增正式状态 | 70_前后端协同边界与页面承接 |
| 查询展示 | 空结果、无权、脱敏结果正确区分 | 空结果等于事实不存在 | 70_前后端协同边界与页面承接 |
| 外部协同 | 外部反馈、确认线索、外部资料保持线索属性 | 外部反馈直接改写真源 | 60_接口边界与集成约束、70_前后端协同边界与页面承接 |
| Mock 联调 | Mock、联调、演示结果明确标记 | Mock 通过写成真实业务通过 | 60_接口边界与集成约束、70_前后端协同边界与页面承接 |

接口与页面回归失败时，应按 60 或 70 归口处理，不得在 80 中补写接口或页面规则。

## 十一、真源与候选边界回归规则

真源与候选边界回归用于确认系统核心边界没有被修改破坏。

| 回归对象 | 通过标准 | 失败标准 | 准出影响 |
|---|---|---|---|
| 原始输入 | 保留来源、主体、时间、上下文 | 只保留整理后结论 | 阻断相关准出 |
| 候选内容 | 保持候选属性 | 候选展示为正式事实 | 阻断相关准出 |
| 正式事实 | 只由 L2 真源入链层产生 | 页面、接口、AI、外部反馈直接写事实 | 阻断目录或包级准出 |
| 汇总视图 | 只消费事实，不创造事实 | 汇总结果成为新事实 | 阻断相关准出 |
| 经验规则 | 只形成候选经验或可复用资产 | 经验直接发布正式规则 | 阻断相关准出 |
| AI 输出 | 保持辅助、候选、预处理属性 | AI 替代确认、裁决或入链 | 阻断相关准出 |
| 外部反馈 | 保持反馈、问题、线索或回执属性 | 外部反馈直接改写正式数据 | 阻断相关准出 |
| 模板输出 | 保持候选文件或输出结果属性 | 生成成功等于正式文件成立 | 阻断相关准出 |
| 回执结果 | 保持动作结果或处理方向属性 | 回执成功等于业务确认 | 阻断相关准出 |

任何真源边界回归失败，均应视为高优先级问题，影响目录、包级、开发或阶段准出。

## 十二、阻断判定表

出现以下回归失败时，应直接阻断对应准出，不得继续正式化、归集、升版或进入下一阶段。

| 阻断类型 | 具体表现 | 阻断范围 |
|---|---|---|
| 表头越界 | YAML 出现禁用字段或标题路径错误 | 单文件正式化、归集 |
| 文件状态错误 | 待归集文件不是正式稿 | 归集 |
| 路径错位 | canonical_path 与实际落位不一致 | 归集、包级升版 |
| 新增能力 | 新增字段、枚举、状态、权限、事实类型、接口能力、页面能力 | 单文件、目录、包级 |
| 真源反写 | 页面、接口、AI、外部反馈、回执、汇总视图写入正式事实 | 目录、包级、开发准出 |
| 权限越界 | 越权查询、导出、分享、外部展示未被阻断 | 目录、包级、开发准出 |
| 状态反写 | 页面状态、接口状态、外部状态成为正式状态 | 目录、包级 |
| 回执误判 | 回执成功被写成业务确认完成 | 目录、包级 |
| Mock 混入 | Mock 数据或联调结果被当作真实业务结果 | 目录、开发准出 |
| 失败隐藏 | 失败、阻断、撤回、纠偏、熔断被展示为成功 | 目录、开发准出 |
| tree/manifest 不一致 | 归集后包级清单未同步或错误 | 包级准出 |
| 最高版本不唯一 | 多个当前基准包无法唯一裁决 | 后续写作、开发准出 |

## 十三、非阻断问题判定表

以下问题通常不直接阻断，但应记录、定向修补或在归集前处理。

| 非阻断类型 | 具体表现 | 处理方式 |
|---|---|---|
| 轻微重复表达 | 禁止项或边界说明少量重复 | 归集前可轻量收口 |
| 个别术语不稳 | 不影响真源和职责的表述不够精确 | 定向术语收口 |
| downstream 需后续校准 | 下游文件名随任务卡后续明确 | 后续写作或归集时校准 |
| 文件版本不一致 | 同组中修改过文件版本高于未修改文件 | 可接受，包版本统一升版 |
| 总则偏上位 | 总则文件保留较多目录级边界 | 可接受，不要求压成细则 |
| 验收断言待总表收口 | 单篇断言未完全矩阵化 | 在总表中收口 |
| 轻微正文偏长 | 总则或总表篇幅较长但未越界 | 不阻断 |
| 轻微正文偏短 | 已覆盖职责但断言颗粒度可加强 | 后续断言文件补强 |

非阻断问题不得无限积压。若同类非阻断问题反复出现并影响目录职责、术语一致或总表归口，应升级为阻断或待补。

## 十四、回归结论输出口径

回归验证结论应按固定口径输出：

| 输出项 | 内容要求 |
|---|---|
| 当前结论 | 明确通过、待补、阻断、可归集、可升版、可继续写作或不可继续 |
| 阻断点 | 只列影响继续推进的问题 |
| 非阻断问题 | 列出不影响当前推进但需要记录或后续处理的问题 |
| 可继续条件 | 说明可以正式化、归集、升版、继续写作、进入开发或需先修补 |
| 归口说明 | 对失败问题说明归口目录或文件 |
| 版本影响 | 是否需要文件升版、包升版或不升版 |
| 回归范围 | 明确本次是 R1、R2、R3、R4 还是 R5 回归 |

回归结论不得只写“没问题”“通过”“可继续”，必须说明通过范围和准出层级。

## 十五、回归结果记录要求

回归验证结果应至少记录以下信息类别：

| 信息类别 | 记录要求 |
|---|---|
| 回归触发原因 | 修改、修补、归集、升版、冲突检测、准出判断或阶段推进 |
| 回归等级 | R1、R2、R3、R4 或 R5 |
| 回归范围 | 单文件、目录、包级、接口页面、真源边界或开发准出 |
| 回归依据 | 对应验收标准、验证方案、验证场景或上游文件 |
| 回归检查项 | 实际检查的结构、术语、YAML、职责、接口、页面、真源、权限、状态等 |
| 回归结果 | 通过、失败、待补、阻断或需裁决 |
| 失败表现 | 具体冲突、残留、越界、缺失或误展示 |
| 失败归口 | 应回到哪个目录或文件处理 |
| 准出影响 | 是否影响正式化、归集、包级升版、继续写作、开发或阶段准出 |
| 后续处理 | 修改、阻断、退回、归集、升版、继续写作或重新回归 |

回归记录不得只写“已检查”或“无问题”，应能支撑后续追溯和准出判断。

## 十六、回归失败处理规则

回归失败应按以下规则处理：

1. 若失败归口当前文件，应定向修改当前文件并重新回归。
2. 若失败归口上游文件，应阻断当前文件继续推进，并退回对应上游归口。
3. 若失败归口同目录总表，应先修补总表，再回归同组承接关系。
4. 若失败归口接口或页面承接，应分别回到 60 或 70 处理。
5. 若失败涉及新增字段、状态、权限、事实类型、接口能力或页面能力，应阻断并请求裁决。
6. 若失败影响归集，应停止归集，不得强行写入基准包。
7. 若失败影响包级升版，应停止输出新基准包。
8. 若失败影响开发准出，应不得进入开发拆解或执行器任务。
9. 修补完成后，应重新执行同范围回归验证。

回归失败不能用人工承诺、页面临时提示、接口临时返回、Mock 通过、联调通过或正向功能通过抵消。

| 06_准出规则.md | 提供准出前必须完成的回归等级和最低检查集 | 不把局部回归通过放大为阶段准出 |

## 十八、禁止事项

回归验证规则禁止出现以下行为：

1. 禁止把回归验证写成自动化测试代码、测试脚本、接口调用说明或部署步骤。
2. 禁止通过回归验证新增字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。
3. 禁止只检查原问题是否解决，不检查新增冲突和新增越界。
4. 禁止用正向功能通过抵消负向边界回归失败。
5. 禁止归集前跳过文件状态、路径、YAML、术语、职责和禁止项检查。
6. 禁止包级升版后不检查 tree、manifest、文件数、压缩包完整性和最高版本唯一性。
7. 禁止回归失败后强行正式化、归集、升版、继续写作或进入开发。
8. 禁止把 Mock 通过、联调通过、页面可显示、接口 success 写成回归通过。
9. 禁止在本文反向修订 10-70 目录正文依据。
10. 禁止用“已检查、基本没问题、应该可以”等模糊表述替代回归结论。

## 十九、回归验证成立条件

本文成立后，应能支持以下判断：

1. 能明确哪些情况必须触发回归验证。
2. 能区分 R1 单文件回归、R2 同组回归、R3 归集前回归、R4 包级回归和 R5 开发/阶段准出回归。
3. 能明确每个回归等级的最低检查范围、通过标准、失败标准和准出影响。
4. 能判断回归通过、回归失败、阻断、待补和需裁决。
5. 能明确回归失败后应归口到哪个目录或文件。
6. 能区分阻断问题和非阻断问题。
7. 能防止修改、归集、升版和问题修补破坏既有边界。
8. 能支撑一致性检测规则、准出规则和能力边界验收断言总表展开。
