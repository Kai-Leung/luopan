# 05_一致性检测规则

## 一、文件定位

本文定义罗盘系统开发依据的一致性检测规则，用于检查当前基准包、单个文件、同目录文件组、跨目录承接关系、接口页面关系、权限状态口径、真源与候选边界、版本路径和准出条件之间是否保持一致。

本文只定义一致性检测对象、检测维度、通过标准、失败标准、阻断条件、非阻断问题和失败归口，不定义自动化检测代码、测试脚本、数据库结构、接口 schema、页面布局、部署方案或实施计划。

一致性检测的核心作用，是发现文件之间、目录之间、接口与页面之间、上游与下游之间、正式口径与旧口径之间是否存在冲突、错位、重复、缺失或越权。一致性检测不得直接改写被检测文件正文，不得通过检测规则新增系统能力、字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。

## 二、一致性检测总原则

一致性检测应遵守以下原则：

1. 检测对象必须来自当前最高基准包、当前任务卡、当前目录文件组和已生成正式文件。
2. 检测只判断是否一致、是否冲突、是否缺失、是否越界、是否影响准出，不直接替代正文修订。
3. 检测应优先检查硬边界，包括真源、权限、状态、事实入链、候选、回执、AI、外部反馈、页面展示和接口处理方向。
4. 检测应区分阻断问题和非阻断问题，不得把所有问题都扩大为阻断，也不得把硬边界问题降级为非阻断。
5. 检测结果必须能归口到具体目录或文件。
6. 检测发现上游口径冲突时，应按正文依据优先级处理；无法裁决时应阻断。
7. 检测发现下游表述不一致时，应优先判断是否归口当前文件，不得随意反改上游。
8. 检测结果应服务单文件准出、目录准出、归集准出、包级准出和开发准出。

## 三、一致性检测对象总表

| 检测对象 | 检测重点 | 失败风险 | 失败归口 |
|---|---|---|---|
| 基准包版本 | 当前最高版本是否唯一、旧包是否仅作历史参考 | 旧包压制新包 | 包级治理 |
| 文件状态 | 草稿、修改稿、正式稿是否符合阶段 | 非正式文件被归集 | 当前文件或目录 |
| YAML 表头 | 字段、标题、路径、版本、上下游是否合规 | 表头越界或路径错位 | 当前文件 |
| 目录职责 | 10-80 目录职责是否清晰 | 目录之间互相替代 | 对应目录 |
| 术语口径 | 当前正式术语是否一致 | 旧称残留或混称 | 30_标准治理 |
| 架构层级 | L0-L7、横向治理、双回流、一池双区是否一致 | 新增架构层级或独立链路 | 20_系统架构 |
| 数据层级 | 对象资产层、事实记录层、汇总视图层、经验规则层是否一致 | 视图、页面、AI、外部反馈反写真源 | 40_业务数据体系 |
| 业务运行链路 | 输入、候选、确认、入链、输出、回流是否一致 | 绕过业务运行主链路 | 50_系统业务运行规则 |
| 接口边界 | 60 是否只写接口动作边界 | 接口直接写正式事实 | 60_接口边界与集成约束 |
| 页面承接 | 70 是否只写页面承接边界 | 页面定义规则或事实 | 70_前后端协同边界与页面承接 |
| 验收规则 | 80 是否只验证上游规则 | 验收文件新增能力或反改上游 | 80_验证与验收规则 |

## 四、版本与包结构一致性检测

| 检测项 | 通过标准 | 失败标准 | 阻断级别 |
|---|---|---|---|
| 当前基准包 | 当前最高版本唯一可确认 | 多个最高版本或同版本不同内容无法裁决 | 阻断 |
| 旧版本包 | 旧版本仅作为历史参考 | 旧版本压制或覆盖新版本口径 | 阻断 |
| 包内目录 | 目录结构与正式开发依据规划一致 | 目录缺失、重复、错位或旧目录残留 | 阻断或待补 |
| 文件数量 | 包内文件数量与归集结果一致 | 文件异常缺失、重复或未归集 | 阻断 |
| tree/manifest | 归集后 tree 和 manifest 与包内结构一致 | 包级清单未更新或与实际文件不一致 | 阻断 |
| 压缩包完整性 | 压缩包可打开，路径和文件完整 | 压缩包损坏、关键目录缺失 | 阻断 |
| 当前文件版本 | 修改后文件版本合理 | 修改未升版或空升版无依据 | 待补或阻断 |

## 五、YAML 与路径一致性检测

| 检测项 | 通过标准 | 失败标准 | 阻断级别 |
|---|---|---|---|
| 允许字段 | 只使用 document_id、title、file_status、version、canonical_path、source_path、upstream、downstream | 出现 owner、last_checked_by、aliases、tags、review_status 等越界字段 | 阻断 |
| title 与 H1 | YAML title 与正文 H1 一致 | title 与 H1 不一致 | 阻断 |
| file_status | 文件状态符合当前交付阶段 | 草稿被归集、正式稿未生成文件 | 阻断 |
| canonical_path | canonical_path 与文件实际落位一致 | 路径错位或旧路径残留 | 阻断 |
| source_path | source_path 与基准包目录关系一致 | source_path 指向错误包或旧目录 | 待补或阻断 |
| upstream | 只列直接上游 | 展开间接上游、缺直接上游、引用不存在文件 | 待补或阻断 |
| downstream | 只列直接下游，且属于规划内文件 | 虚构下游、展开多级链路、错指非规划文件 | 待补或阻断 |

YAML 检测失败时，应先修正表头和路径，再判断正文是否可继续。

## 六、目录职责一致性检测

| 目录 | 应承担内容 | 一致性失败表现 |
|---|---|---|
| 10_顶层定义 | 系统定位、边界、产品属性、阶段边界、第一用户、第一业务验证场景 | 后续目录重新定义系统是什么 |
| 20_系统架构 | L0-L7、横向治理、双回流、一池双区、组织隔离、系统组成、读写边界 | 业务规则、接口或页面新增架构层级 |
| 30_标准治理 | 术语、字段、枚举、状态、权限、风险、校验、追溯、反问、脱敏、AI 口径 | 60/70/80 重新定义字段、状态或权限 |
| 40_业务数据体系 | 对象资产层、事实记录层、汇总视图层、经验规则层及真源边界 | 页面、接口、视图、AI、外部反馈创造事实 |
| 50_系统业务运行规则 | 身份识别、访问范围、L0-L7 运行、横向治理、沉淀池与资料存储 | 验收文件或页面文件重写业务链路 |
| 60_接口边界与集成约束 | 接口收到什么、记录什么、返回什么、停止什么、交给谁 | 写成标准治理、页面设计或接口 schema |
| 70_前后端协同边界与页面承接 | 页面收到什么、展示什么、允许什么、禁止什么、交给谁 | 写成页面布局、接口规则或业务裁决 |
| 80_验证与验收规则 | 验证标准、方案、场景、回归、一致性、准出和断言 | 新增能力、写测试脚本或反向修改上游 |

目录职责一致性失败时，应按目录职责归口修补，不得在当前文件内扩大修订范围。

## 七、术语一致性检测

| 检测项 | 通过标准 | 失败标准 | 处理方式 |
|---|---|---|---|
| 目录名称 | 使用当前正式目录名称 | 使用运行模块、业务数据模型、知识沉淀层等旧称 | 定向术语收口 |
| 层级名称 | 使用对象资产层、事实记录层、汇总视图层、经验规则层 | 使用旧层级名或混称 | 定向修补 |
| AI 术语 | 使用 AI 辅助预处理、候选归整、辅助输出等受控表达 | 写成 AI 裁决、AI 确认、AI 自动治理 | 阻断或修补 |
| 页面术语 | 使用页面承接、处理方向、状态提示 | 写成页面裁决、页面真源、页面入链 | 阻断 |
| 接口术语 | 使用接口动作、处理方向、回执、失败回退 | 写成接口直接确认、接口写事实 | 阻断 |
| 验收术语 | 使用断言、通过标准、失败标准、归口、准出影响 | 只写功能正常、可用、通过 | 待补 |

术语一致性检测不得为了统一措辞而改变正文事实边界。

## 八、真源与候选一致性检测

| 检测对象 | 通过标准 | 失败标准 | 阻断级别 |
|---|---|---|---|
| 原始输入 | 保留来源、主体、时间、上下文 | 只保留整理后结论 | 阻断相关准出 |
| 候选内容 | 保持候选属性 | 候选展示为正式事实 | 阻断 |
| 正式事实 | 只由 L2 真源入链层产生 | 页面、接口、AI、外部反馈、回执直接写事实 | 阻断 |
| 资料 | 区分资料本体、资料动作、资料证据引用 | 上传、识别、展示即证据成立 | 阻断 |
| 汇总视图 | 只消费对象资产层和事实记录层 | 汇总结果创造新事实 | 阻断 |
| 经验规则 | 只形成候选经验、模板候选或规则候选 | 经验直接发布正式规则 | 阻断 |
| 状态投影 | 只展示状态结果 | 状态投影成为状态真源 | 阻断 |
| 外部反馈 | 保持反馈、问题、线索或回执属性 | 直接改写真源 | 阻断 |

真源一致性失败属于高优先级问题，原则上影响目录、包级、开发或阶段准出。

## 九、权限与可见性一致性检测

| 检测项 | 通过标准 | 失败标准 | 阻断级别 |
|---|---|---|---|
| 查询权限 | 查询只返回权限范围内结果 | 越权返回原始输入、资料、事实或追溯 | 阻断 |
| 导出权限 | 导出受权限、脱敏、版本和输出范围约束 | 越权导出或直接外发 | 阻断 |
| 外部展示 | 只展示授权范围内脱敏内容 | 展示内部成本、内部分析、未授权资料 | 阻断 |
| 页面可见 | 页面展示以后端可见范围为准 | 页面本地判断权限 | 阻断 |
| 无权限提示 | 无权限不展示为数据不存在 | 无权限被写成空结果或数据不存在 | 待补或阻断 |
| 脱敏结果 | 脱敏结果标识清楚 | 脱敏内容被展示为完整结果 | 阻断 |
| Mock 权限 | Mock 不进入正式权限判断 | Mock 权限结果当真实权限 | 阻断 |

权限一致性失败不得由前端隐藏入口或页面文案遮盖。

## 十、接口与页面一致性检测

| 检测项 | 通过标准 | 失败标准 | 失败归口 |
|---|---|---|---|
| 接口处理方向 | 60 返回已接收、待补、挂起、阻断、失败、回执、熔断等方向 | 70 展示为正式事实、正式状态或正式确认 | 60 或 70 |
| 页面动作 | 页面动作交给接口和后续链路 | 页面按钮直接写入正式事实 | 70 |
| 回执展示 | 回执只展示处理方向 | 回执成功展示为业务确认完成 | 60 或 70 |
| 输出展示 | 输出成功只表示输出动作完成 | 输出成功展示为外部认可 | 60 或 70 |
| 失败展示 | 失败原因和处理方向可见 | 失败隐藏为成功 | 60 或 70 |
| Mock 联调 | Mock 与真实结果区分 | Mock 通过展示为真实业务通过 | 60、70 或 80 |
| 状态提示 | 页面状态只表达处理方向 | 页面状态新增正式状态 | 70 |

接口与页面一致性检测失败时，应判断是 60 返回边界不清，还是 70 页面承接误展示，不得直接在 80 中补写接口或页面规则。

## 十一、回执、外部反馈与输出一致性检测

| 检测对象 | 通过标准 | 失败标准 | 阻断级别 |
|---|---|---|---|
| 回执成功 | 保持动作结果或处理方向属性 | 展示为客户确认、甲方确认、付款确认、验收确认 | 阻断 |
| 外部系统 success | 保留外部原值并进入回执或候选映射 | 覆盖系统内部结果 | 阻断 |
| 外部反馈 | 作为反馈、问题、补充或确认线索 | 直接改写责任、金额、验收、结算、状态或事实 | 阻断 |
| 外部资料 | 作为资料输入或补充线索 | 上传成功即证据成立 | 阻断 |
| 授权输出 | 保留输出范围、版本、接收对象 | 输出成功即外部主体认可 | 阻断 |
| 外部展示异常 | 撤回、纠偏、阻断或熔断可见 | 异常隐藏为成功 | 阻断 |

## 十二、AI 与模板输出一致性检测

| 检测对象 | 通过标准 | 失败标准 | 阻断级别 |
|---|---|---|---|
| AI 转译 | 保持辅助转译属性 | 转译结果直接成为事实 | 阻断 |
| AI 候选归整 | 进入候选处理链路 | AI 结果直接进入 L2 | 阻断 |
| AI 缺口提示 | 作为疑似缺口提示 | AI 自行生成正式反问规则 | 阻断 |
| AI 决策建议 | 仅作为受控建议 | 替代权限判断、风险裁决或人工确认 | 阻断 |
| 模板取数 | 保留取数来源和候选属性 | 取数成功即事实成立 | 阻断 |
| 候选文件 | 保持候选文件属性 | 生成成功即正式文件成立 | 阻断 |
| 缺口清单 | 用于补齐提示 | 缺口清单成为业务裁决 | 待补或阻断 |

AI 与模板输出一致性检测重点是防止辅助能力被升格为正式能力。

## 十三、验收文件内部一致性检测

| 检测对象 | 通过标准 | 失败标准 |
|---|---|---|
| 00 总则 | 80 目录职责和下游分工清楚 | 总则新增能力或替代上游 |
| 01 验收标准 | 覆盖能力、边界、失败归口和准出判断 | 只写原则，不能判断通过失败 |
| 02 验证方案 | 定义验证组织、对象、方法和结果归口 | 写成测试脚本或实现方案 |
| 03 验证场景集 | 覆盖正向、负向、边界、回归和准出场景 | 只列正向功能场景 |
| 04 回归验证规则 | 定义回归等级、最低检查集、阻断/非阻断判定 | 回归范围不清或不能支撑准出 |
| 05 一致性检测规则 | 定义跨目录、跨文件、跨接口页面一致性检查 | 直接改写被检文件 |
| 06 准出规则 | 定义单文件、目录、归集、包级、开发、阶段准出 | 把局部通过写成阶段准出 |
| 07 前后端协同验收断言 | 定义接口页面、Mock、联调验收断言 | 写页面布局或接口 schema |
| 08 高频错误与负向验证参考 | 汇总高频错误和负向验证参考 | 把错误参考写成新规则 |
| 09 能力边界验收断言总表 | 汇总能力边界、归口和断言 | 新增能力边界 |

## 十四、阻断问题判定

出现以下一致性问题时，应阻断对应准出：

1. 当前最高基准包无法唯一确认。
2. YAML 表头字段越界或路径错位。
3. 待归集文件不是正式稿。
4. 当前文件新增字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。
5. 页面、接口、AI、外部反馈、回执、汇总视图反写正式事实。
6. 权限越界、脱敏失败、未授权展示或越权导出未被阻断。
7. 页面状态、接口状态或外部状态被写成正式状态。
8. 回执成功、输出成功、外部 success 被写成业务确认完成。
9. Mock、联调、演示结果被写成真实业务结果。
10. 失败、阻断、撤回、纠偏或熔断被隐藏为成功。
11. 目录职责冲突导致无法确定归口。
12. 任务卡规划文件缺失导致目录无法闭合。

## 十五、非阻断问题判定

以下一致性问题通常不直接阻断，但应记录并定向处理：

1. 少量重复边界说明，但未影响职责。
2. 总则文件保留较多上位口径，但未越权。
3. 个别术语表述不够精确，但不影响真源和职责。
4. 文件版本因部分修补而不完全一致，但包版本可统一升版。
5. downstream 指向规划内下游，但下游文件名后续可能调整。
6. 验收断言在单篇中不够矩阵化，但可在总表中收口。
7. 普通细则中禁止事项略多，但未影响正文职责。
8. 个别文件较长或较短，但已覆盖任务卡职责。

非阻断问题若反复出现并影响目录职责、归口判断、术语一致或准出判断，应升级为待补或阻断。

## 十六、一致性检测结论输出口径

一致性检测结论应按以下口径输出：

| 输出项 | 内容要求 |
|---|---|
| 当前结论 | 明确通过、待补、阻断、可归集、可升版、可继续写作或不可继续 |
| 检测范围 | 明确是单文件、目录、包级、跨目录、接口页面还是全包检测 |
| 阻断点 | 只列影响继续推进的问题 |
| 非阻断问题 | 列出不影响当前推进但需要记录或后续处理的问题 |
| 失败归口 | 对每个失败点说明归口目录或文件 |
| 可继续条件 | 明确是否可正式化、归集、升版、进入下一目录或进入开发 |
| 版本影响 | 说明是否需要文件升版、包升版或无需升版 |
| 回归要求 | 说明是否需要触发 R1-R5 回归 |

一致性检测不得只输出“通过”或“无问题”，必须说明检测范围和准出层级。

## 十七、与下游文件的关系

| 下游文件 | 本文提供的支撑 | 下游不得做的事 |
|---|---|---|
| 06_准出规则.md | 提供准出前必须完成的一致性检测对象和阻断判定 | 不把未完成检测的结果写成准出 |
| 09_能力边界验收断言总表.md | 提供能力边界一致性断言、归口和失败标准 | 不新增能力边界 |
| 80 其他验收文件 | 提供跨文件、跨目录、跨页面、跨接口一致性检查口径 | 不反向改写被检文件 |

## 十八、禁止事项

一致性检测规则禁止出现以下行为：

1. 禁止把一致性检测写成自动化检测代码、测试脚本、接口调用说明或部署步骤。
2. 禁止通过一致性检测新增字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。
3. 禁止一致性检测直接改写被检测文件正文。
4. 禁止把非阻断问题无限积压，导致目录职责或准出判断失效。
5. 禁止把阻断问题降级为普通建议。
6. 禁止用页面可显示、接口 success、Mock 通过、联调通过替代一致性通过。
7. 禁止忽略旧称残留、路径错位、YAML 越界和文件状态错误。
8. 禁止在检测中用旧版本基准包压制当前最高基准包。
9. 禁止通过检测结果反向修改 10-70 目录正文依据。
10. 禁止用“基本一致、问题不大、可以先过”等模糊表述替代检测结论。

## 十九、一致性检测规则成立条件

本文成立后，应能支持以下判断：

1. 能明确一致性检测对象和检测维度。
2. 能判断单文件、目录、包级、跨目录、接口页面和验收文件内部是否一致。
3. 能区分阻断问题和非阻断问题。
4. 能明确一致性失败后的归口目录和处理方向。
5. 能支撑准出规则和能力边界验收断言总表展开。
6. 能防止页面、接口、AI、外部系统、Mock、回执、模板输出和汇总视图反写真源。
