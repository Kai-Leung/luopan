# 07_前后端协同验收断言

## 一、文件定位

本文定义罗盘系统前后端协同场景下的验收断言，用于验证页面动作、接口返回、页面展示、处理方向、权限提示、失败回退、回执展示、外部协同、Mock 联调和真实接口承接是否符合 60 接口边界与 70 页面承接规则。

本文只定义前后端协同应满足的验收断言、失败判定、失败归口和准出影响，不定义接口 URL、HTTP 方法、JSON schema、页面布局、组件样式、前端代码、后端代码、数据库结构、自动化测试脚本、部署方案或实施计划。

前后端协同验收的核心作用，是确认前端页面没有误解后端返回结果，后端接口没有用实现便利性绕过上游规则，页面展示没有把接口处理方向、回执结果、Mock 结果、外部反馈或失败结果误展示为正式事实、正式状态、正式权限或业务确认。

## 二、断言总原则

前后端协同验收断言应遵守以下原则：

1. 断言只验证接口与页面是否按既有边界承接，不新增接口能力、页面能力或业务规则。
2. 后端返回成功，不等于业务确认完成。
3. 前端页面显示成功，不等于正式事实成立。
4. 页面动作可点击，不等于该动作具备业务执行权限。
5. Mock、演示、联调结果，不等于真实业务结果。
6. 回执已接收，不等于客户、甲方、供应商、班组或外部主体已确认。
7. 候选已生成，不等于 L2 真源入链完成。
8. 输出成功，不等于外部主体已认可。
9. 空结果不等于事实不存在。
10. 无权限不等于数据不存在。
11. 失败、阻断、撤回、纠偏、熔断不得被页面隐藏为成功。
12. 前后端协同通过只能作为准出材料之一，不得直接替代目录准出、包级准出、开发准出或阶段准出。

## 三、断言表达模型

每条前后端协同验收断言应至少包含以下要素：

| 断言要素 | 内容要求 |
|---|---|
| 断言编号 | 能唯一标识当前断言 |
| 验收对象 | 页面动作、接口返回、页面展示、回执结果、失败处理、权限提示或 Mock 联调 |
| 前端动作 | 页面触发的录入、上传、补齐、候选处理、查询、导出、外部反馈或状态查看动作 |
| 后端返回 | 后端应返回的处理方向、回执结果、失败原因、权限提示、脱敏结果或查询结果 |
| 页面展示 | 页面应如何展示该结果 |
| 不得出现 | 一旦出现即判定失败的误展示、越权、反写或默认成功 |
| 失败归口 | 失败应回到 60、70、80 或上游目录哪个位置 |
| 准出影响 | 是否影响 S1、S2、S3、S4、S5 或 S6 准出 |

断言不得写成“页面正常显示”“接口调用成功”“用户可以操作”等模糊表达。断言必须能判断通过、失败、待补、阻断或归口。

## 十二、准出影响判定

前后端协同验收断言失败应按以下规则判断准出影响：

| 失败类型 | 准出影响 |
|---|---|
| 页面误展示但未反写真源 | 阻断 S2 目录准出或 S5 开发准出，需定向修补 |
| 接口返回边界不清 | 阻断 S2 或 S5，归口 60 |
| 页面反写真源 | 阻断 S2、S4、S5，必要时触发包级回归 |
| 权限越界或脱敏失败 | 阻断 S2、S4、S5 |
| 回执成功误展示为业务确认 | 阻断 S2、S5 |
| Mock 混入真实结果 | 阻断 S5 或 S6 |
| 联调通过被写成阶段准出 | 阻断 S6 |
| 失败隐藏为成功 | 阻断 S2、S5 |
| 空结果/无权限误展示 | 阻断 S2 或待补，视影响范围判断 |
| 断言归口不清 | 阻断 S2 或 S5，需回到 70/09 或 60/08 收口 |

前后端协同验收断言通过，只表示接口与页面承接一致，不自动表示包级准出、开发准出或阶段准出完成。

## 十三、验收结论输出口径

前后端协同验收结论应包含以下内容：

| 输出项 | 内容要求 |
|---|---|
| 当前结论 | 前后端协同验收通过、待补、阻断或需归口修补 |
| 验收范围 | 明确覆盖哪些页面动作、接口返回、状态提示、Mock 或外部协同对象 |
| 断言结果 | 说明通过、失败或未覆盖的断言编号 |
| 阻断点 | 只列影响准出的断言失败 |
| 非阻断问题 | 列出不影响当前准出但需记录的问题 |
| 失败归口 | 标明归口 60、70、80 或上游目录 |
| 准出影响 | 标明影响 S1-S6 哪一层准出 |
| 回归要求 | 标明是否需要触发 R1-R5 回归 |

验收结论不得只写“联调正常、页面正常、接口正常”。

## 十五、禁止事项

前后端协同验收断言禁止出现以下行为：

1. 禁止把本文写成接口 schema、页面布局、组件说明、测试脚本或自动化代码。
2. 禁止通过验收断言新增字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。
3. 禁止把接口 success、页面显示成功、Mock 通过、联调通过直接写成业务验收通过或阶段准出。
4. 禁止把页面动作直接写成正式事实、正式状态、正式权限或正式确认。
5. 禁止把候选、AI 输出、模板输出、外部反馈、回执结果、汇总视图结果写成正式事实。
6. 禁止把空结果写成事实不存在，把无权限写成数据不存在。
7. 禁止隐藏失败、阻断、撤回、纠偏、熔断、权限不足或脱敏失败。
8. 禁止用前端默认值、本地缓存、最近上下文、外部字段或 Mock 数据补造正式内容。
9. 禁止本文反向修订 60 接口边界或 70 页面承接正文。
10. 禁止用“页面正常、接口正常、联调正常”等模糊表述替代断言结果。

## 十六、前后端协同验收断言成立条件
