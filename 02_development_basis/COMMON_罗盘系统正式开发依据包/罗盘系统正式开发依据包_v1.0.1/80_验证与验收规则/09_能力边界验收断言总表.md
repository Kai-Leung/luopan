# 09_能力边界验收断言总表

## 一、文件定位

本文是 `80_验证与验收规则` 目录的能力边界验收断言总表，用于汇总罗盘系统开发依据中已经定义的系统定位、架构边界、标准治理、业务数据体系、业务运行规则、接口边界、页面承接、AI 辅助、模板输出、外部协同、失败回退、回归验证、一致性检测和准出规则的验收断言。

本文只汇总能力边界、通过标准、失败标准、失败归口、准出影响和高频错误参考，不新增系统能力、字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。

本文用于支持后续详细设计、开发拆解、前后端联调、测试执行、归集联检、包级准出和阶段准出时判断：某项能力是否只在已定义边界内成立，是否被页面、接口、AI、外部系统、Mock、回执、模板或汇总视图反向改写。

## 二、断言总表使用原则

能力边界验收断言总表应遵守以下原则：

1. 断言只验证已经在 10-80 目录中定义过的能力和边界。
2. 断言不得成为新增能力、扩展业务范围或补写上游规则的来源。
3. 每条断言必须能判断通过、失败、归口、准出影响和回归要求。
4. 正向能力断言必须配套负向失败判断。
5. 涉及真源、权限、状态、回执、AI、外部反馈、Mock 和失败回退的断言，应优先按硬边界处理。
6. 断言失败时，应按归口目录修补，不得在总表中直接补写业务规则、接口规则或页面规则。
7. 总表通过只表示能力边界断言可支撑后续验收，不直接等同于包级准出、开发准出或阶段准出。
8. 后续详细设计和开发实现不得绕过本表中的禁止项和失败标准。

## 三、断言字段说明

| 字段 | 含义 |
|---|---|
| 断言编号 | 能唯一标识能力边界断言 |
| 能力边界 | 被验证的系统能力、承接边界或禁止边界 |
| 应成立条件 | 正常情况下必须满足的边界 |
| 不得出现 | 一旦出现即判定失败的越界结果 |
| 失败归口 | 失败后应回到的目录或文件组 |
| 准出影响 | 影响 S1-S6 哪类准出 |
| 回归要求 | 失败后最低触发 R1-R5 哪级回归 |
| 高频错误参考 | 对应 `08_高频错误与负向验证参考` 中的错误类型或错误编号 |

断言不得只写“功能正常”“页面可用”“接口成功”“测试通过”。断言必须明确边界是否成立。

## 十五、能力边界失败处理总表

| 失败类型 | 默认处理 | 不得处理为 |
|---|---|---|
| 当前文件职责越界 | 定向修补当前文件并执行 R1 | 继续正式化 |
| 同目录职责冲突 | 回到对应细则或总表修补并执行 R2 | 直接归集 |
| 归集前文件状态或路径失败 | 停止归集并执行 R3 | 强行写入基准包 |
| 包级版本或 tree/manifest 失败 | 停止使用新包并执行 R4 | 把新包作为当前基准 |
| 真源反写 | 阻断对应目录、包级或开发准出，回到归口文件修补 | 用正向功能通过抵消 |
| 权限越界 | 阻断并回到权限、接口或页面归口处理 | 用前端隐藏或提示文案替代 |
| 回执误判 | 阻断并回到 60/03、60/04 或 70/08 处理 | 认为外部 success 即业务确认 |
| AI 越权 | 阻断并回到 30、50 或 70 处理 | 认为 AI 输出可人工默认通过 |
| 外部反馈反写 | 阻断并回到 60/07 或 70/07 处理 | 认为外部主体表达即可确认 |
| Mock 混入 | 阻断开发或阶段准出并执行 R5 | 沿用 Mock 通过结论 |

## 十七、能力边界断言结论输出口径

能力边界验收结论应包含以下内容：

| 输出项 | 内容要求 |
|---|---|
| 当前结论 | 通过、待补、阻断、可归集、可升版、可继续写作、可进入开发或不可继续 |
| 断言范围 | 明确覆盖哪些断言组和断言编号 |
| 命中失败 | 列出失败断言编号和失败表现 |
| 阻断点 | 只列影响当前准出的断言失败 |
| 非阻断问题 | 列出不影响当前推进但需记录或后续处理的问题 |
| 失败归口 | 标明归口目录或文件 |
| 准出影响 | 标明影响 S1-S6 哪一层准出 |
| 回归要求 | 标明是否触发 R1-R5 回归 |
| 处理方式 | 修补、退回、阻断、归集前收口、包级回归或请求裁决 |

能力边界验收结论不得只写“全部通过”“基本合格”“可以继续”，必须说明通过范围、准出层级和未覆盖内容。

## 十八、禁止事项

能力边界验收断言总表禁止出现以下行为：

1. 禁止通过总表新增系统能力、字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。
2. 禁止把总表写成测试脚本、接口调用说明、页面操作手册、代码检查清单或部署步骤。
3. 禁止总表反向修订 10-70 目录正文依据。
4. 禁止把断言通过直接写成包级准出、开发准出或阶段准出。
5. 禁止只列正向成立条件，不列失败标准、归口、准出影响和回归要求。
6. 禁止用页面成功、接口 success、Mock 通过、联调通过、功能可点击替代能力边界通过。
7. 禁止把候选、AI 输出、模板输出、外部反馈、回执结果、汇总视图结果写成正式事实。
8. 禁止把硬边界失败降级为普通建议。
9. 禁止用“问题不大、后续优化、暂时可接受”替代阻断判断。
10. 禁止忽略权限越界、真源反写、状态反写、回执误判、失败隐藏、AI 越权和外部反馈反写。
