# 02_验证方案

## 一、文件定位

本文定义罗盘系统开发依据的验证方案，用于说明验证工作如何组织、验证对象如何选择、验证顺序如何安排、验证结果如何记录、验证失败如何归口，以及验证结论如何支撑回归、一致性检测和准出判断。

本文只定义验证组织方式、验证对象、验证路径、验证结果归口和验证输出边界，不定义自动化测试代码、测试脚本、接口协议、页面布局、数据库结构、部署方案、技术选型或实施计划。

验证方案的核心作用，是把验收标准转化为可执行的验证安排，确保正向能力、负向边界、一致性、回归和准出判断都能被覆盖。验证方案不得新增系统能力，不得通过验证设计反向修改上游规则，不得以验证便利性降低权限、状态、追溯、风险、脱敏和真源边界。

## 二、验证方案总原则

验证方案应遵守以下原则：

1. 验证对象必须来自当前基准包已经定义的目录、文件、能力、边界和承接关系。
2. 验证方案只安排如何验证，不定义被验证对象本身。
3. 正向验证、负向验证、一致性检测、回归验证和准出判断应组合使用，不得只验证功能可用。
4. 页面可展示、接口可返回、Mock 可跑通、联调可通过，均不得单独作为验证通过依据。
5. 验证结果必须能归口到具体目录、文件、接口边界、页面承接或验收断言。
6. 验证失败时不得在验证方案中补写规则，应退回对应归口文件处理。
7. 验证过程应保留验证对象、验证依据、验证动作、验证结果、失败原因和归口方向。
8. 涉及正式事实、权限、状态、回执、外部反馈、AI 输出、模板输出和汇总视图的验证，必须覆盖反写真源风险。

## 三、验证对象分组

验证对象按以下分组组织：

| 验证对象组 | 验证内容 | 主要依据 |
|---|---|---|
| 顶层与架构组 | 系统定位、系统边界、L0-L7、运行主链路、双回流、一池双区、组织隔离 | 10、20 目录 |
| 标准治理组 | 术语、字段、枚举、状态、权限、风险、校验、追溯、反问、脱敏、AI 辅助口径 | 30 目录 |
| 业务数据体系组 | 对象资产层、事实记录层、汇总视图层、经验规则层、资料资产和真源边界 | 40 目录 |
| 业务运行组 | 输入、候选、确认、入链、回流、资料存储、授权输出、失败与人工处理 | 50 目录 |
| 接口边界组 | 输入接口、外部映射、回执接入、失败回退、页面动作接口、X1 外部连接 | 60 目录 |
| 页面承接组 | H5、PC、录入补齐、候选、事实追溯、查询、外部协同、状态提示 | 70 目录 |
| 验收规则组 | 验收标准、验证场景、回归、一致性、准出、前后端断言、负向参考和能力边界总表 | 80 目录 |

各组验证可以按对象归口分组执行，但验证结论必须回到统一验收标准和准出规则，不得形成多套通过口径。

## 四、验证顺序

验证应按以下顺序展开：

1. 先验证当前基准包版本、目录结构、文件状态、路径、YAML 和上下游关系。
2. 再验证顶层定义和系统架构是否被后续目录继承。
3. 再验证标准治理、业务数据体系和系统业务运行规则是否保持真源、权限、状态、追溯和候选边界。
4. 再验证接口边界是否按“收到什么、记录什么、返回什么、停止什么、交给谁”执行。
5. 再验证页面承接是否按“收到什么、展示什么、允许什么、禁止什么、交给谁”执行。
6. 再验证正向业务场景是否能够连贯承接。
7. 再验证负向边界是否能够拦截。
8. 再验证跨目录、跨接口、跨页面、跨状态和跨版本一致性。
9. 最后形成回归判断和准出判断。

验证顺序可以按任务阶段裁剪，但不得跳过负向边界、一致性和回归判断。

## 五、验证方法

验证方案采用以下方法组合：

| 验证方法 | 使用场景 | 输出结果 |
|---|---|---|
| 文件结构检查 | 检查目录、文件、版本、路径、YAML、上下游 | 结构通过、结构失败或需修补 |
| 口径一致性检查 | 检查术语、层级、状态、权限、真源、候选、AI、外部反馈等口径 | 一致、冲突、旧称残留或归口不清 |
| 正向场景验证 | 验证录入、候选、入链、查询、输出、外部协同等可正常承接 | 正向通过或正向失败 |
| 负向边界验证 | 验证越权、误展示、回执误判、AI 越权、外部反馈反写、失败隐藏等是否被拦截 | 负向通过或负向失败 |
| 接口页面一致性验证 | 验证 60 返回处理方向是否被 70 正确展示 | 一致、误展示或归口错误 |
| 追溯验证 | 验证输入、资料、事实、回执、输出、失败处理是否可追溯 | 可追溯、追溯缺失或版本断裂 |
| 回归验证 | 验证修改、归集、升版后旧边界是否未被破坏 | 回归通过或回归失败 |
| 准出判断 | 验证单文件、目录、包级、开发或阶段是否可进入下一步 | 准出、待补、阻断或退回 |

验证方法不得降级为只看页面是否显示、接口是否返回或功能是否可点击。

## 六、正向验证安排

正向验证应覆盖以下主线：

| 正向验证主线 | 验证动作 | 合格判断 |
|---|---|---|
| 输入承接 | 原始输入、语音转写、图片文件上传进入系统 | 保留来源、主体、时间、上下文和处理方向 |
| 候选生成 | 输入、资料、AI 辅助预处理或外部反馈形成候选内容 | 候选属性明确，未展示为正式事实 |
| 反问补齐 | 缺口提示进入页面，用户补齐后重新提交 | 补齐动作返回接口，不直接确认事实 |
| 事实入链展示 | 上游已入链结果在页面展示 | 页面只展示结果，不产生事实 |
| 查询展示 | 按项目、主体、时间、资料、权限范围查询 | 只返回权限范围内结果或脱敏结果 |
| 授权输出 | 候选文件、导出、分享、外部展示动作完成 | 输出范围、版本、接收对象和回执可追溯 |
| 外部协同 | 外部主体查看脱敏内容、提交反馈或补充资料 | 外部动作保持反馈、线索或回执属性 |
| 失败处理 | 上传失败、识别失败、超时、权限失败、撤回纠偏 | 失败原因和处理方向可见且可归口 |

正向验证通过只表示能力按边界承接，不表示阶段准出自动完成。

## 七、负向验证安排

负向验证应覆盖以下风险：

| 负向风险 | 验证动作 | 失败判定 |
|---|---|---|
| 页面反写真源 | 页面确认、弹窗确认、批量勾选、查询结果尝试写事实 | 页面动作直接写成正式事实 |
| 接口成功误判 | 接口返回 success、输出成功、回执成功 | 被展示为业务确认完成 |
| AI 越权 | AI 输出候选归整、缺口提示、建议结论 | 被展示为正式事实、状态、规则或裁决 |
| 外部反馈反写 | 客户、甲方、供应商、班组反馈 | 直接改写责任、金额、验收、结算或状态 |
| 权限失败误展示 | 无权查看、脱敏可见、空结果 | 被展示为数据不存在或完整结果 |
| 资料误判 | 上传成功、识别成功、挂接成功 | 被展示为资料有效或证据成立 |
| 汇总视图误判 | 统计摘要、经营摘要、结算摘要 | 被展示为新事实或真源数据 |
| Mock 混入 | Mock 数据、模拟回执、联调数据 | 被展示为真实业务结果 |
| 失败隐藏 | 上传失败、识别失败、超时、熔断 | 被隐藏为成功或继续推进 |
| 版本断裂 | 撤回、纠偏、资料版本、输出版本 | 原记录被删除或追溯断裂 |

负向验证失败应优先阻断准出，不得用正向场景通过抵消。

## 八、一致性验证安排

一致性验证应覆盖以下关系：

1. 10-80 目录职责是否各自归口，不互相替代。
2. 30 术语、字段、状态、权限、风险、追溯口径是否被 60、70、80 正确继承。
3. 40 对象资产层、事实记录层、汇总视图层、经验规则层是否未被页面、接口、AI 或视图反写。
4. 50 输入、候选、确认、入链、回流、资料存储、授权输出链路是否未被 60/70 绕过。
5. 60 接口返回处理方向是否被 70 页面正确展示。
6. 70 页面状态是否未新增正式状态口径。
7. 60/08 与 70/09 总表之间的动作归口是否一致。
8. 80 验收标准、验证方案、场景、回归、一致性、准出和断言总表是否互相支撑。
9. YAML upstream/downstream 是否只列直接上下游，且不展开间接链路。
10. 文件状态、版本、路径、标题和 H1 是否一致。

一致性验证发现冲突时，应先定位归口，不得直接在当前文件扩大修订范围。

## 九、回归验证安排

以下情况应触发回归验证：

1. 单文件修改后。
2. 当前目录全组完成后。
3. 当前目录归集进基准包前。
4. 基准包升版后。
5. 发现术语、路径、YAML、上下游或职责冲突后。
6. 接口边界、页面承接或验收断言修改后。
7. 负向验证发现问题并修补后。
8. 准备进入下一目录、下一阶段或开发任务前。

回归验证至少应检查：

1. 被修改文件是否解决原问题。
2. 被修改文件是否新增越界内容。
3. 直接上游是否仍被正确继承。
4. 直接下游是否未被破坏。
5. 同目录总表是否仍能归口。
6. 术语、路径、状态、YAML 是否一致。
7. 正向场景是否仍通过。
8. 负向边界是否仍能拦截。
9. 准出判断是否受影响。

## 十、验证结果记录要求

验证结果应记录以下信息类别：

| 信息类别 | 记录要求 |
|---|---|
| 验证对象 | 被验证文件、目录、接口边界、页面承接、能力或场景 |
| 验证依据 | 对应上游文件、验收标准或断言来源 |
| 验证动作 | 执行了结构检查、口径检查、正向验证、负向验证、回归验证还是准出判断 |
| 验证结果 | 通过、失败、待补、挂起、阻断、回归失败或准出失败 |
| 失败表现 | 具体失败点、冲突点、旧称残留、越界行为或误展示表现 |
| 失败归口 | 应回到哪个目录、文件或后续实现环节处理 |
| 准出影响 | 是否影响单文件、目录、归集、包级、开发或阶段准出 |
| 后续处理 | 修改、退回、阻断、归集、升版、回归或继续写作 |

验证记录不得只写“通过/失败”，必须能支持后续归口和回归。

## 十一、验证失败归口流程

验证失败按以下流程处理：

1. 判断问题是否真实存在。
2. 判断问题是否属于当前验证对象。
3. 判断问题归口当前文件、上游文件、下游文件、后续详细设计还是开发实现。
4. 判断是否影响准出。
5. 判断是否需要修改、阻断、退回或裁决。
6. 修改后触发对应回归验证。
7. 回归通过后再进入下一步。

不得照单全收，不得把不属于当前文件的问题强行修进当前文件，也不得把需要上游裁决的问题写成验收补丁。

## 十二、验证与准出的关系

验证结果与准出判断关系如下：

| 验证结果 | 准出影响 |
|---|---|
| 正向验证通过 | 只能作为准出材料之一 |
| 负向验证通过 | 是边界准出的必要条件 |
| 一致性验证通过 | 是目录、归集和包级准出的必要条件 |
| 回归验证通过 | 是修改后继续推进的必要条件 |
| Mock 或联调通过 | 不能单独支撑准出 |
| 页面显示正常 | 不能单独支撑准出 |
| 接口返回成功 | 不能单独支撑准出 |
| 负向验证失败 | 原则上阻断相关准出 |
| 归口不清 | 阻断目录准出或包级准出 |
| 新增能力风险 | 阻断并请求裁决 |

准出判断应由 `06_准出规则.md` 进一步细化。本文只定义验证结果如何服务准出，不替代准出规则本身。

## 十三、与下游文件的关系

| 下游文件 | 本文提供的支撑 | 下游不得做的事 |
|---|---|---|
| 03_验证场景集.md | 提供正向、负向、边界、外部协同和异常场景组织方式 | 不新增业务流程 |
| 04_回归验证规则.md | 提供回归触发条件和回归检查对象 | 不替代文件修订 |
| 05_一致性检测规则.md | 提供一致性检测对象和关系 | 不直接改写被检文件 |
| 06_准出规则.md | 提供验证结果与准出的关系 | 不把局部通过扩大为阶段准出 |
| 07_前后端协同验收断言.md | 提供接口页面一致性验证方法 | 不定义页面布局或接口 schema |
| 08_高频错误与负向验证参考.md | 提供负向风险组织方式 | 不把错误参考写成新规则 |
| 09_能力边界验收断言总表.md | 提供验证对象、断言和归口组织方式 | 不新增能力或替代上游规则 |

## 十四、禁止事项

验证方案禁止出现以下行为：

1. 禁止把验证方案写成自动化测试脚本、测试代码、接口调用说明或部署方案。
2. 禁止通过验证方案新增字段、枚举、状态、权限、事实类型、接口能力、页面能力或业务边界。
3. 禁止把页面可显示、接口可返回、Mock 可跑通、联调可通过直接写成验收通过或阶段准出。
4. 禁止只验证正向功能，不验证负向边界、一致性和回归。
5. 禁止为通过验证而降低权限、状态、追溯、风险、脱敏和真源边界。
6. 禁止把失败问题直接在验证方案中补写成新规则。
7. 禁止验证方案反向修改 10-70 目录的正文依据。
8. 禁止用“正常、可用、通过、成功”等模糊结果替代具体断言。
9. 禁止把 AI 输出、外部反馈、接口回执、页面状态、Mock 数据或汇总视图结果写成正式事实。
10. 禁止忽略失败、阻断、挂起、撤回、纠偏、熔断和权限不足等负向结果。

## 十五、验证方案成立条件

本文成立后，应能支持以下判断：

1. 能说明验证对象如何分组。
2. 能说明验证应按什么顺序展开。
3. 能说明正向验证、负向验证、一致性验证、回归验证和准出判断如何配合。
4. 能说明验证结果如何记录和归口。
5. 能说明验证失败后如何判断修改、退回、阻断或回归。
6. 能支撑后续验证场景集、回归验证规则、一致性检测规则、准出规则和验收断言总表展开。
