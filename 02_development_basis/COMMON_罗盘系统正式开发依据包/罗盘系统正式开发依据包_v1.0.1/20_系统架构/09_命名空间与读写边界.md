# 09_命名空间与读写边界

## 一、文件定位

本文是 `20_系统架构` 下的命名空间与读写边界文件，用于定义罗盘系统不同架构组成、数据归口、治理规则、接口承接、页面展示、回流沉淀和底层基础支撑之间的命名空间划分、读取边界、写入边界、跨空间访问边界和禁止反写规则。

本文回答以下问题：

1. 罗盘系统中哪些内容应划入独立命名空间；
2. 不同命名空间分别承接什么系统内容；
3. 哪些命名空间可以读取其他命名空间内容；
4. 哪些命名空间可以写入自身内容；
5. 哪些命名空间不得写入其他命名空间；
6. 跨命名空间访问应遵守哪些边界；
7. 页面、接口、测试、底层基础支撑和代码实现为什么不能反向定义业务命名空间；
8. 下游标准治理、接口边界和页面承接应如何继承本文确定的读写边界。

本文只定义系统架构层的命名空间和读写边界，不定义字段命名细则、接口 schema、数据库表、代码包结构、API 路径、页面路由、权限矩阵、测试脚本或实施计划。

## 二、命名空间总原则

命名空间是系统架构层对不同内容归属、读写权限、跨空间访问和禁止反写关系的分区定义。

命名空间遵守以下原则：

1. 命名空间用于隔离内容归属，不是数据库 schema 设计；
2. 命名空间用于约束读写边界，不是代码包命名规范；
3. 命名空间用于承接系统组成依赖，不替代字段规范、接口规范或页面规范；
4. 每类内容必须有明确归属命名空间；
5. 读取其他命名空间内容不等于拥有写入权限；
6. 展示其他命名空间内容不等于拥有修改权限；
7. 引用其他命名空间内容不等于可以反向定义该空间规则；
8. 真源类命名空间只能由正式归口写入，不能被视图、页面、接口、反馈、测试或技术支撑反写；
9. 治理类命名空间只能定义规则，不能生成业务事实；
10. 技术支撑类命名空间只提供记录、存储、通知、调度、缓存、溯源等底座能力，不参与业务事实裁定。

本文中的命名空间是开发依据中的架构边界概念，不是数据库表名、代码目录、前端路由或接口路径。

## 三、命名空间总表

罗盘系统至少包含以下命名空间：

| 命名空间 | 架构归属 | 主要承接内容 | 读写属性 | 不得承担 |
|---|---|---|---|---|
| 顶层定义命名空间 | `10_顶层定义` | 系统定位、系统边界、产品属性、阶段边界 | 上位定义，只读约束下游 | 不写字段、接口、页面和实现细节 |
| 系统架构命名空间 | `20_系统架构` | 分类真源、L0 原始输入层至 L7 反馈回流层、横向治理、事实回流与智能回流、权限架构、运行主链路、组成、依赖、读写边界 | 架构定义，只读约束下游 | 不写运行流程和实现设计 |
| 来源输入命名空间 | L0 原始输入层 | 原始输入、上传资料、外部载荷、输入元信息、来源记录 | 写入来源内容，供候选读取 | 不写正式事实 |
| 候选内容命名空间 | L1 候选抽取层 | 候选对象、候选事实、候选字段、缺口线索、风险线索 | 写入候选内容，供真源归口读取 | 不写真源 |
| 真源入链命名空间 | L2 真源入链层 | 正式对象、正式事实、证据链、状态锚点、追溯锚点 | 唯一正式事实写入空间 | 不接受页面、接口、视图、反馈直写 |
| 业务数据体系命名空间 | `40_业务数据体系` | 对象资产层、事实记录层、汇总视图层、经验规则层 | 统一业务数据归口 | 不替代系统架构 |
| 标准治理命名空间 | `30_标准治理` | 术语、字段、枚举、状态、权限、风险、校验、追溯、反问、脱敏 | 规则定义空间 | 不生成业务事实 |
| 结果与视图命名空间 | L3 结果生成层 / 汇总视图层 | 视图、清单、台账、报告草稿、输出草稿 | 读取真源生成结果 | 不创造事实 |
| 分析与建议命名空间 | L4 分析判断层至 L5 建议编排层 | 分析判断、风险提示、复盘线索、候选建议、候选方案 | 读取事实与视图形成非真源材料 | 不形成正式决策或自动执行 |
| 执行响应命名空间 | L6 执行响应层 | 执行响应、接口调用记录、外部回执、任务反馈、动作结果 | 写入响应记录和回执材料 | 不改写真源 |
| 反馈回流命名空间 | L7 反馈回流层 | 用户修正、外部反馈、复盘材料、事实回流线索、规则候选、模板候选 | 写入回流线索和候选沉淀 | 不直接修正事实或发布规则 |
| 权限架构命名空间 | 横向约束 | 组织、项目、主体、用户、角色、外部对象、高风险动作边界 | 约束读写与展示范围 | 不裁定事实成立 |
| 接口边界与集成约束命名空间 | `60_接口边界与集成约束` | 输入接口、输出接口、回执接口、外部系统映射、失败回退 | 承接跨系统访问边界 | 不定义系统真源 |
| 页面承接命名空间 | `70_前后端协同边界与页面承接` | 页面入口、状态展示、按钮、清单、看板、详情、导出入口 | 展示与交互承接 | 不定义事实、状态或权限 |
| 验证与验收命名空间 | `80_验证与验收规则` | 架构验证、治理验证、权限验证、接口页面验证、负向拦截 | 检查规则是否成立 | 不反向定义业务规则 |
| 底层基础支撑命名空间 | 技术支撑类组成 | 日志、消息、调度、缓存、文件存储、全局溯源、系统参数 | 底层基础支撑 | 不参与业务事实生成和业务裁决 |

上述命名空间共同构成系统读写边界基础。下游可以细化命名规则，但不得改变本文确定的归属边界。

## 四、命名空间分组

### 4.1 上位定义类命名空间

上位定义类命名空间包括：

1. 顶层定义命名空间；
2. 系统架构命名空间。

这类命名空间只负责定义系统定位、边界、架构、层级、真源、组成、依赖和读写边界，对下游具有约束作用。

上位定义类命名空间不得被页面、接口、代码、测试、数据库结构、用户习惯或临时需求反向修改。

### 4.2 业务链路类命名空间

业务链路类命名空间包括：

1. 来源输入命名空间；
2. 候选内容命名空间；
3. 真源入链命名空间；
4. 结果与视图命名空间；
5. 分析与建议命名空间；
6. 执行响应命名空间；
7. 反馈回流命名空间。

这类命名空间按照运行主链路顺序承接业务内容。除真源入链命名空间外，其他业务链路类命名空间均不得直接写入正式事实。

### 4.3 业务数据类命名空间

业务数据类命名空间包括业务数据体系命名空间及其下属对象资产层、事实记录层、汇总视图层、经验规则层。

业务数据体系命名空间负责承接业务数据结构归口，不负责修改系统架构，也不负责定义页面和接口实现。

### 4.4 治理规则类命名空间

治理规则类命名空间包括标准治理命名空间和权限架构命名空间。

这类命名空间负责定义规则和约束，不负责生成业务事实。它可以约束业务链路、接口、页面、验证和技术支撑，但不得直接写入正式事实。

### 4.5 承接展示类命名空间

承接展示类命名空间包括接口边界与集成约束命名空间、页面承接命名空间和验证与验收命名空间。

这类命名空间负责承接、展示、连接和检查，不负责定义系统真源、业务事实、正式状态、正式权限或正式规则。

### 4.6 技术支撑类命名空间

技术支撑类命名空间包括底层基础支撑命名空间。

该命名空间负责日志、消息、调度、缓存、文件存储、全局溯源和系统参数等底层基础支撑能力，不参与业务事实生成、业务流程决策、正式状态裁定、正式权限裁定或规则发布。

## 五、读取边界总规则

读取边界用于定义某一命名空间可以消费、引用、展示或检查哪些其他命名空间内容。

读取边界遵守以下规则：

1. 读取不等于写入；
2. 引用不等于确认；
3. 展示不等于修改；
4. 导出不等于对外传播；
5. 查询成功不等于业务事实成立；
6. 页面可见不等于操作可执行；
7. 接口返回不等于真源可改；
8. 测试读取不等于规则定义；
9. 技术日志可读不等于业务结论成立；
10. 跨命名空间读取必须继承来源空间的权限、状态、风险、追溯和脱敏边界。

任何命名空间读取其他命名空间内容时，均不得扩大被读取内容的原有属性、权限、状态、风险等级、适用范围和真源属性。

## 六、写入边界总规则

写入边界用于定义某一命名空间可以生成、更新或沉淀哪些内容。

写入边界遵守以下规则：

1. 每类内容只能写入其归属命名空间；
2. 写入自身命名空间不代表可以写入上游命名空间；
3. 下游命名空间不得直接写入上游真源命名空间；
4. 页面承接命名空间不得写入正式事实；
5. 接口边界与集成约束命名空间不得绕过真源入链命名空间；
6. 验证与验收命名空间不得写入业务规则；
7. 底层基础支撑命名空间不得写入业务事实；
8. 反馈回流命名空间不得直接写入事实沉淀区；
9. 分析与建议命名空间不得直接写入执行结果；
10. 结果与视图命名空间不得直接写入事实记录层。

写入边界应优先保护真源、标准治理和权限架构，不得为了页面展示、接口便利、测试便利或技术实现便利而放宽。

## 七、跨命名空间访问边界

跨命名空间访问是指一个命名空间读取、引用、展示、输出、检查或支撑另一个命名空间内容。

跨命名空间访问遵守以下规则：

1. 跨空间访问必须保留来源空间归属；
2. 跨空间访问必须保留内容原有属性；
3. 跨空间访问必须保留权限与可见性限制；
4. 跨空间访问必须保留状态边界；
5. 跨空间访问必须保留风险等级或风险提示边界；
6. 跨空间访问必须保留追溯与版本关系；
7. 跨空间访问必须接受脱敏与外部展示边界；
8. 跨空间访问不得改变被访问内容的真源属性；
9. 跨空间访问不得新增被访问空间的字段、枚举、状态或规则；
10. 跨空间访问不得通过页面、接口、测试或代码实现反向修改被访问空间。

跨空间访问可以形成消费、展示、检查、引用或回流线索，但不得形成反向定义权。

## 八、来源输入命名空间读写边界

来源输入命名空间负责承接原始输入、上传资料、外部载荷、输入元信息和来源记录。

读取边界如下：

1. 可读取输入主体、输入时间、输入渠道、来源类型和上传资料；
2. 可被候选内容命名空间读取；
3. 可被追溯与版本规则引用；
4. 可被验证与验收命名空间检查；
5. 可被底层基础支撑命名空间记录来源日志和文件存储信息。

写入边界如下：

1. 只能写入原始输入和来源元信息；
2. 只能写入来源记录和输入锚点；
3. 不得写入候选内容；
4. 不得写入正式事实；
5. 不得写入视图、分析、建议、执行或反馈结果。

来源输入命名空间不得因文件保存成功、页面提交成功、接口接收成功或外部反馈存在而生成正式事实。

## 九、候选内容命名空间读写边界

候选内容命名空间负责承接候选对象、候选事实、候选字段、候选资料、缺口线索和风险线索。

读取边界如下：

1. 可读取来源输入命名空间中的原始输入和来源记录；
2. 可读取字段规范、枚举总表、状态口径和校验规则；
3. 可读取必要的权限与可见性边界；
4. 可被真源入链命名空间读取；
5. 可被页面承接命名空间展示候选状态；
6. 可被验证与验收命名空间检查候选边界。

写入边界如下：

1. 只能写入候选对象、候选事实、候选字段、候选资料和候选归口；
2. 只能写入缺口线索、风险线索和待补线索；
3. 不得写入正式对象；
4. 不得写入正式事实；
5. 不得写入正式状态、正式责任、正式金额、正式结算或正式规则。

候选内容命名空间不得因候选字段完整、候选枚举匹配、页面展示完成或提示已处理而生成正式事实。

## 十、真源入链命名空间读写边界

真源入链命名空间负责承接正式对象、正式事实、证据链、状态锚点、追溯锚点和入链记录。

读取边界如下：

1. 可读取候选内容命名空间中的待入链材料；
2. 可读取业务数据体系命名空间中的对象资产和事实归口规则；
3. 可读取标准治理命名空间中的字段、枚举、状态、权限、风险、校验、追溯和脱敏规则；
4. 可读取权限架构命名空间中的组织、项目、主体、用户、角色和高风险动作边界；
5. 可读取来源输入命名空间中的来源与证据引用；
6. 可被结果与视图、分析与建议、执行响应、反馈回流、验证与验收读取和消费。

写入边界如下：

1. 可以写入正式对象；
2. 可以写入正式事实；
3. 可以写入证据链、状态锚点、追溯锚点和入链记录；
4. 不得写入视图结果；
5. 不得写入分析判断；
6. 不得写入候选建议；
7. 不得写入执行响应；
8. 不得写入反馈复盘；
9. 不得写入正式规则发布结果。

真源入链命名空间不得接受页面、接口、外部回执、视图统计、分析判断、候选建议、执行响应、反馈回流、测试样例或技术支撑直写。

## 十一、业务数据体系命名空间读写边界

业务数据体系命名空间负责承接对象资产层、事实记录层、汇总视图层和经验规则层。

读取边界如下：

1. 可读取系统层级与分类真源；
2. 可读取真源入链命名空间中的正式对象和正式事实；
3. 可读取标准治理命名空间中的字段、枚举、状态、权限、风险、校验和追溯规则；
4. 可读取一池双区和回流沉淀边界；
5. 可被结果与视图、分析与建议、执行响应、反馈回流、接口、页面和验证读取。

写入边界如下：

1. 可以写入对象资产层内容；
2. 可以写入事实记录层内容；
3. 可以写入汇总视图层内容；
4. 可以写入经验规则层内容；
5. 不得改变系统架构命名空间；
6. 不得把汇总视图写成事实记录；
7. 不得把经验规则层内容写成正式事实；
8. 不得让接口字段、页面展示、测试样例或数据库表反向定义业务数据结构。

业务数据体系命名空间是全量业务数据归口，不是真源入链动作本身，也不是结果展示层本身。

## 十二、标准治理命名空间读写边界

标准治理命名空间负责承接标准术语、字段、枚举、状态、权限、风险、校验、追溯、反问、脱敏和候选输出边界。

读取边界如下：

1. 可读取顶层定义命名空间；
2. 可读取系统架构命名空间；
3. 可读取业务数据体系命名空间的对象、事实、视图和经验规则层归口；
4. 可读取运行规则、接口、页面、验证反馈中的治理缺口线索；
5. 可被全系统其他命名空间读取和遵守。

写入边界如下：

1. 可以写入术语规则；
2. 可以写入字段规则；
3. 可以写入枚举规则；
4. 可以写入状态规则；
5. 可以写入权限与可见性规则；

## 二十二、禁止跨空间反写规则

以下跨空间反写必须禁止：

| 反写方向 | 禁止内容 |
|---|---|
| 来源输入 → 真源入链 | 原始输入、文件上传、外部载荷不得直写正式事实 |
| 候选内容 → 真源入链 | 候选对象、候选事实、候选字段不得直写正式对象或正式事实 |
| 结果与视图 → 真源入链 | 视图、清单、台账、报告草稿不得反写正式事实 |
| 分析与建议 → 真源入链 | 分析判断、风险提示、候选建议不得写成正式事实或正式决策 |
| 执行响应 → 真源入链 | 执行成功、接口成功、外部回执不得改写真源 |
| 反馈回流 → 真源入链 | 用户反馈、外部反馈、复盘结论不得直接修正事实 |
| 页面承接 → 标准治理 | 页面按钮、标签、状态、提示不得反向定义字段、枚举、状态或权限 |
| 接口边界与集成约束 → 标准治理 | 接口字段、接口枚举、接口 schema 不得反向定义标准治理规则 |
| 验证与验收 → 标准治理 | 测试样例、测试账号、测试通过不得反向定义规则 |
| 底层基础支撑 → 业务链路 | 日志、消息、缓存、文件、调度、参数不得反向定义业务事实或业务状态 |
| 代码实现 → 开发依据 | 代码结构、技术便利性、已有实现不得反向修改正式开发依据 |

禁止跨空间反写是命名空间与读写边界的核心红线。
