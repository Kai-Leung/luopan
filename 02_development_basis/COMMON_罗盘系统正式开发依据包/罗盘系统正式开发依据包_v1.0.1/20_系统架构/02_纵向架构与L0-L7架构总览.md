# 02_纵向架构与L0-L7架构总览

## 一、文件定位

本文是 `20_系统架构` 下的纵向架构与 L0 原始输入层至 L7 反馈回流层 架构总览文件，用于定义罗盘系统从原始输入到候选抽取、真源入链、结果生成、分析判断、建议编排、执行响应、反馈回流的纵向层级、层级职责、读写边界和上下游承接关系。

本文回答以下问题：

1. L0 原始输入层至 L7 反馈回流层分别处于系统纵向架构的哪个位置；
2. 每一层负责承接什么内容；
3. 每一层允许读取什么内容；
4. 每一层允许写入什么内容；
5. 哪一层可以形成系统真源；
6. 哪些层只能形成候选、结果、分析、建议、执行记录或反馈沉淀；
7. 哪些层不得反写正式事实、正式对象、正式状态、正式权限或正式规则；
8. L0 原始输入层至 L7 反馈回流层如何支撑后续系统业务运行规则、接口边界、页面承接和验证与验收。

本文只定义 L0 原始输入层至 L7 反馈回流层的架构层级、层级职责和层间读写边界，不定义各层具体运行步骤、字段全集、接口字段、页面流程、数据库结构、测试实现、人工处理流程或实施计划。

## 二、纵向架构总原则

L0 原始输入层至 L7 反馈回流层是罗盘系统纵向运行主链路的架构分层，用于把真实业务世界中的来源材料，逐级转化为候选内容、正式真源、可消费结果、分析判断、建议编排、执行响应和反馈沉淀。

纵向架构遵守以下原则：

1. L0 原始输入层只接收原始输入，不生成正式事实；
2. L1 候选抽取层只生成候选内容，不直接写入真源；
3. L2 真源入链层负责承接正式对象、正式事实和入链追溯锚点；
4. L3 结果生成层只消费正式真源并生成结果、清单、台账、视图或输出内容，不反写真源；
5. L4 分析判断层只基于正式事实和结果内容形成分析判断，不生成正式事实和正式决策；
6. L5 建议编排层只形成建议编排和候选方案，不自动触发执行；
7. L6 执行响应层只承接受控执行响应、执行记录、外部调用结果或回执，不越权改写真源；
8. L7 反馈回流层只承接反馈、复盘、修正线索、模板候选、规则候选和回流内容，不覆盖正式事实；
9. 标准治理应贯穿 L0 原始输入层至 L7 反馈回流层，但不由本文展开具体治理规则；
10. 页面、接口、模板、外部反馈、辅助输出和测试样例不得反向改变 L0 原始输入层至 L7 反馈回流层层级职责和读写边界。

L0 原始输入层至 L7 反馈回流层不是技术模块列表，也不是数据库分表方案。L0 原始输入层至 L7 反馈回流层是系统架构层面对内容流向、真源位置、消费边界和禁止反写关系的分层定义。

## 三、L0 原始输入层至 L7 反馈回流层层级总表

| 层级 | 层级名称 | 架构职责 | 真源属性 | 主要输出 |
|---|---|---|---|---|
| L0 原始输入层 | 原始输入层 | 接收人工录入、图片、文件、聊天记录、外部载荷、外部反馈和其他来源材料 | 否 | 原始输入、来源记录、输入元信息 |
| L1 候选抽取层 | 候选抽取层 | 从原始输入中识别候选对象、候选事实、候选字段、候选枚举、候选资料和疑似缺口 | 否 | 候选内容、候选归口、缺口线索 |
| L2 真源入链层 | 真源入链层 | 承接符合正式成立条件的对象、事实、证据链和追溯锚点 | 是 | 正式对象、正式事实、入链记录、追溯锚点 |
| L3 结果生成层 | 结果生成层 | 消费正式对象和正式事实，生成清单、台账、视图、草稿、报告或输出结果 | 否 | 结果内容、视图结果、输出草稿、台账清单 |
| L4 分析判断层 | 分析判断层 | 基于正式事实和结果内容形成分析、异常识别、风险提示、趋势判断和复盘线索 | 否 | 分析判断、异常提示、风险线索、复盘线索 |
| L5 建议编排层 | 建议编排层 | 将分析判断、规则口径和业务目标编排为候选建议、候选方案、候选动作或处理优先级 | 否 | 候选建议、候选方案、候选动作、优先级提示 |
| L6 执行响应层 | 执行响应层 | 承接受控执行响应、任务反馈、外部调用、回执接收和执行记录 | 否 | 执行响应记录、外部回执、任务反馈、动作结果 |
| L7 反馈回流层 | 反馈回流层 | 承接执行反馈、用户修正、项目复盘、模板反馈、规则候选和回流线索 | 否 | 反馈内容、修正线索、模板候选、规则候选、复盘沉淀 |

L2 真源入链层是 L0 原始输入层至 L7 反馈回流层中唯一承担正式事实真源入链职责的层级。L3 结果生成层至 L7 反馈回流层可以消费、分析、编排、执行、反馈和沉淀，但不得直接覆盖 L2 真源入链层中的真源。

## 四、L0 原始输入层

### 4.1 层级定义

L0 原始输入层是罗盘系统接收业务世界信息的入口层，用于承接人工录入、图片、文件、聊天记录、表格、外部载荷、外部反馈、上传资料、第三方回执和其他未经治理的来源材料。

L0 原始输入层的架构身份是来源入口层，不具备正式事实真源属性。

### 4.2 层级职责

L0 原始输入层负责在架构层承接以下内容：

1. 原始输入来源；
2. 输入主体；
3. 输入时间；
4. 输入渠道；
5. 输入类型；
6. 来源标识；
7. 载荷摘要；
8. 可追溯输入锚点；
9. 外部来源进入系统的初始边界；
10. 后续候选抽取所需的来源基础。

L0 原始输入层不判断事实是否成立，不判断字段是否完整，不判断责任、金额、结算、客户确认或甲方确认是否成立。

### 4.3 读取边界

L0 原始输入层可以接收系统外部或用户提交的来源材料，但不应读取下游正式事实、汇总视图、分析判断、建议编排、执行结果或反馈沉淀来反向改写原始输入。

L0 原始输入层可以为后续层级提供来源引用，但不得根据后续层级结果修改原始来源属性。

### 4.4 写入边界

L0 原始输入层只能写入原始输入、输入元信息、来源锚点和输入记录。L0 原始输入层不得写入正式对象、正式事实、正式状态、正式权限、正式风险等级、汇总视图、分析判断、建议内容或执行结果。

L0 原始输入层 写入内容的属性是来源材料，不是正式业务结论。

### 4.5 禁止事项

L0 原始输入层不得执行以下行为：

1. 把原始输入写成正式事实；
2. 把外部载荷写成系统正式状态；
3. 把上传资料写成已确认资料；
4. 把外部回执写成正式确认；
5. 把页面提交成功写成业务事实成立；
6. 绕过 L1 候选抽取层、L2 真源入链层直接进入正式真源；
7. 直接改变对象资产、事实记录、汇总视图或经验规则层内容。

### 4.6 下游承接

L0 原始输入层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/01_L0_原始输入规则.md` 承接。本文只定义 L0 原始输入层的架构位置、职责和读写边界。

## 五、L1 候选抽取层

### 5.1 层级定义

L1 候选抽取层是原始输入与正式内容之间的候选生成层，用于把 L0 原始输入层中的输入的来源材料转化为候选对象、候选事实、候选字段、候选枚举、候选资料、候选归口和疑似缺口。

L1 候选抽取层的架构身份是候选缓冲层，不具备正式事实真源属性。

### 5.2 层级职责

L1 候选抽取层负责在架构层承接以下内容：

1. 候选对象识别；
2. 候选事实识别；
3. 候选字段识别；
4. 候选枚举匹配；
5. 候选资料归口；
6. 候选证据线索；
7. 疑似缺口；
8. 疑似风险线索；
9. 外部反馈候选化；
10. 向 L2 真源入链层提供待入链材料。

L1 候选抽取层的作用是让系统能够承接不完整、不确定、未治理的信息，而不是直接生成正式内容。

### 5.3 读取边界

L1 候选抽取层可以读取 L0 原始输入层中的原始输入、来源元信息、已有对象引用线索、标准治理规则和必要的上下文边界。

L1 候选抽取层不得读取汇总视图、分析判断、建议内容、执行反馈或经验规则层内容来反向生成正式事实。若后续内容提供修正线索，应通过 L7 反馈回流层中的回流和运行规则承接，不得由 L1 候选抽取层直接改写真源。

### 5.4 写入边界

L1 候选抽取层只能写入候选内容、候选归口、候选字段、候选枚举匹配、缺口线索和待治理内容。L1 候选抽取层不得写入正式事实、正式对象、正式状态、正式风险等级、正式确认结果、正式规则或汇总视图。

L1 候选抽取层的输出即使格式完整，也仍然属于候选内容。

### 5.5 禁止事项

L1 候选抽取层不得执行以下行为：

1. 把候选对象写成正式对象资产；
2. 把候选事实写成正式事实；
3. 把候选字段写成正式字段值；
4. 把候选枚举匹配写成正式枚举裁定；
5. 把候选状态提示写成正式状态；
6. 把疑似风险线索写成风险等级裁定；
7. 把候选反问建议写成正式反问流程；
8. 绕过 L2 真源入链层直接供 L3 结果生成层至 L7 反馈回流层 作为正式依据使用。

### 5.6 下游承接

L1 候选抽取层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/02_L1_候选抽取规则.md` 承接。本文只定义 L1 候选抽取层的架构位置、职责和读写边界。

## 六、L2 真源入链层

### 6.1 层级定义

L2 真源入链层是 L0 原始输入层至 L7 反馈回流层的纵向架构中的真源核心层，用于承接符合系统正式成立条件的对象资产、正式事实、证据链、状态锚点和追溯锚点。

L2 真源入链层是 L0 原始输入层至 L7 反馈回流层中唯一承担正式对象和正式事实入链职责的层级。

### 6.2 层级职责

L2 真源入链层负责在架构层承接以下内容：

1. 正式对象资产入链；
2. 正式事实入链；
3. 来源与证据绑定；
4. 事实类型归口；
5. 对象锚点绑定；
6. 状态口径接入；
7. 权限、风险、校验和追溯口径接入；
8. 正式事实对后续受控参考边界；
9. 真源与非真源内容隔离；
10. L3 结果生成层至 L7 反馈回流层消费正式事实的基础。

L2 真源入链层的职责不是执行所有治理流程，而是在架构层定义正式真源只能在此处形成。

### 6.3 读取边界

L2 真源入链层可以读取 L1 候选抽取层中的候选内容、对象资产候选、来源输入、证据线索、标准治理规则、业务数据体系规则和必要追溯材料。

L2 真源入链层不得读取页面展示、汇总视图、分析判断、建议编排、执行反馈、经验沉淀或测试样例来反向定义正式事实。

### 6.4 写入边界

L2 真源入链层可以写入正式对象、正式事实、入链记录、事实状态锚点、证据引用和追溯锚点。

L2 真源入链层不写汇总视图，不写分析判断，不写建议方案，不写页面展示，不写执行动作，不写经验规则正式发布结果。

### 6.5 禁止事项

L2 真源入链层不得执行以下行为：

1. 接收未经候选与治理边界约束的原始输入直写；
2. 接收页面状态、接口成功、外部回执、模板输出、视图统计或测试通过结果直写真源；
3. 把分析判断写成正式事实；
4. 把建议编排写成正式决策；
5. 把执行响应写成事实修正；
6. 把反馈复盘直接覆盖正式事实；
7. 允许 L3 结果生成层至 L7 反馈回流层 反向改写正式对象或正式事实。

### 6.6 下游承接

L2 真源入链层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/03_L2_真源入链规则.md` 承接。本文只定义 L2 真源入链层的架构位置、真源属性和读写边界。

## 七、L3 结果生成层

### 7.1 层级定义

L3 结果生成层是正式真源的第一层消费层，用于基于 L2 真源入链层中的正式对象、正式事实和授权范围内可消费内容生成清单、台账、汇总视图结果、草稿、报告和输出结果。

L3 结果生成层的架构身份是结果生成层，不具备正式事实真源属性。

### 7.2 层级职责

L3 结果生成层负责在架构层承接以下内容：

1. 执行清单；
2. 资料缺失清单；
3. 问题风险清单；
4. 项目台账；
5. 视图结果；
6. 输出草稿；
7. 结算草单候选；
8. 报告草稿；
9. 对外展示前的内容组织；
10. 向 L4 分析判断层提供分析判断所需的结果内容。

L3 结果生成层的作用是把正式事实转化为可阅读、可查询、可组织、可输出的结果内容。

### 7.3 读取边界

L3 结果生成层可以读取 L2 真源入链层中的正式对象、正式事实、证据引用、状态口径、权限范围和授权可消费内容。

L3 结果生成层不得以 L0 原始输入层中的原始输入、L1 候选抽取层中的候选内容、外部来源内容、页面展示内容或测试样例作为正式结果的唯一真源依据。

### 7.4 写入边界

L3 结果生成层只能写入结果内容、汇总视图结果、清单、台账、输出草稿、报告草稿和其他非真源结果产物。

L3 结果生成层不得写入正式事实、正式对象、正式状态、正式金额、正式责任、正式结算、正式权限或正式规则。

### 7.5 禁止事项

L3 结果生成层不得执行以下行为：

1. 用结果内容反写 L2 真源入链层中的正式事实；
2. 用视图统计反写事实状态；
3. 用结算草单反写正式结算；
4. 用清单遗漏反向否定底层事实；
5. 用报告草稿形成正式对外结论；
6. 用导出结果扩大底层事实权限；
7. 绕过权限、风险、脱敏和追溯边界输出正式内容。

### 7.6 下游承接

L3 结果生成层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/04_L3_结果生成规则.md` 承接。本文只定义 L3 结果生成层的架构位置、消费范围和禁止反写边界。

## 八、L4 分析判断层

### 8.1 层级定义

L4 分析判断层是基于正式事实和结果内容形成分析、异常识别、风险提示、趋势判断、经营判断材料和复盘线索的层级，不具备正式事实真源属性。

L4 分析判断层的架构身份是分析判断层，不具备正式事实真源属性，也不是决策层。

### 8.2 层级职责

L4 分析判断层负责在架构层承接以下内容：

1. 经营分析；
2. 执行分析；
3. 结算分析；
4. 风险提示；
5. 异常识别；
6. 趋势判断；
7. 差异识别；
8. 复盘线索；
9. 建议编排依据；
10. 规则候选和模板候选的分析材料。

L4 分析判断层的作用是帮助系统从正式事实和结果内容中形成可解释的分析判断材料，但不形成正式事实、正式决策或执行动作。

### 8.3 读取边界

L4 分析判断层可以读取 L2 真源入链层中的正式对象、正式事实、L3 结果生成层中的结果内容、授权汇总视图、标准治理规则和必要追溯信息。

L4 分析判断层不得把候选内容、页面展示、外部反馈、未授权内容或测试样例作为分析判断的正式事实依据。

### 8.4 写入边界

L4 分析判断层只能写入分析判断、风险提示、异常识别、趋势判断、差异提示、复盘线索和建议编排依据。

L4 分析判断层不得写入正式事实、正式状态、正式责任、正式金额、正式结算、正式决策、执行动作或正式规则。

### 8.5 禁止事项

L4 分析判断层不得执行以下行为：

1. 把分析判断写成正式事实；
2. 把风险提示写成责任裁决；
3. 把趋势判断写成经营决策；
4. 把异常识别写成事实修正；
5. 把分析结果写成对外承诺；
6. 把分析材料直接写成正式规则；
7. 反向覆盖 L2 真源入链层中的正式事实或 L3 结果生成层中的结果来源。

### 8.6 下游承接

L4 分析判断层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/05_L4_分析判断规则.md` 承接。本文只定义 L4 分析判断层的架构位置、读取范围和非真源边界。

## 九、L5 建议编排层

### 9.1 层级定义

L5 建议编排层是基于 L4 分析判断层中的分析判断、正式事实、标准规则和业务目标形成候选建议、候选方案、候选动作、处理优先级和编排材料的层级，不具备正式事实真源属性。

L5 建议编排层的架构身份是建议编排层，不具备正式事实真源属性，不是决策层，也不是执行层。

### 9.2 层级职责

L5 建议编排层负责在架构层承接以下内容：

1. 候选建议；
2. 候选方案；
3. 候选动作；
4. 处理优先级；
5. 待确认事项；
6. 方案比较材料；
7. 执行前候选动作材料；
8. 提醒内容；
9. L6 执行响应层中的执行响应前的输入材料；
10. 反馈回流所需的建议来源。

L5 建议编排层的作用是把分析判断和规则依据组织成可供人或系统后续处理的建议材料，但不自动执行。

### 9.3 读取边界

L5 建议编排层可以读取 L2 真源入链层中的正式事实、L3 结果生成层中的结果内容、L4 分析判断层中的分析判断、标准治理规则、授权视图和必要追溯材料。

L5 建议编排层不得以候选内容、页面提示、外部反馈或未授权分析材料作为正式建议依据。

### 9.4 写入边界

L5 建议编排层只能写入候选建议、候选方案、候选动作、处理优先级、提醒内容和建议编排记录。

L5 建议编排层不得写入正式事实、正式决策、正式责任、正式金额、正式结算、正式执行结果或正式规则。

### 9.5 禁止事项

L5 建议编排层不得执行以下行为：

1. 把建议写成决策；
2. 把候选动作写成已执行动作；
3. 把优先级写成强制执行命令；
4. 把方案比较写成最终结论；
5. 自动触发高风险执行；
6. 自动改变事实状态；
7. 自动对外发送、承诺、确认、扣款、付款、结算或归责。

### 9.6 下游承接

L5 建议编排层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/06_L5_建议编排规则.md` 承接。本文只定义 L5 建议编排层的架构位置、建议属性和禁止自动执行边界。

## 十、L6 执行响应层

### 10.1 层级定义

L6 执行响应层是承接受控执行响应、任务反馈、外部调用、动作结果、回执接收和执行记录的层级，不具备正式事实真源属性。

L6 执行响应层的架构身份是执行响应层，不具备正式事实真源属性。L6 执行响应层记录执行响应和回执结果，但不得越权改变正式事实。

### 10.2 层级职责

L6 执行响应层负责在架构层承接以下内容：

1. 执行响应；
2. 任务反馈；
3. 外部调用记录；
4. 外部回执；
5. 动作结果；
6. 执行失败；
7. 执行阻断；
8. 回执来源；
9. 向 L7 反馈回流层提供反馈回流材料；
10. 与接口边界和页面动作的架构衔接。

L6 执行响应层的作用是承接执行动作及其结果在系统中的响应记录，而不是替代事实真源。

### 10.3 读取边界

L6 执行响应层可以读取 L5 建议编排层 候选动作、L2 真源入链层中的正式事实、L3 结果生成层中的结果内容、L4 分析判断层中的分析判断、权限边界、接口边界和必要追溯材料。

L6 执行响应层不得绕过权限、风险、接口边界和事实归口直接读取或改写真源。

### 10.4 写入边界

L6 执行响应层只能写入执行响应记录、外部调用记录、回执内容、任务反馈、动作结果和执行相关非真源记录。

L6 执行响应层不得直接写入正式事实、正式对象、正式状态、正式金额、正式责任、正式结算或正式规则。执行结果如需影响事实真源，必须由后续归口规则承接，不得由 L6 执行响应层 直接覆盖。

### 10.5 禁止事项

L6 执行响应层不得执行以下行为：

1. 把执行成功写成业务事实成立；
2. 把接口成功写成正式确认；
3. 把外部回执写成正式事实；
4. 把页面动作写成正式状态变化；
5. 把任务完成写成责任结论；
6. 把执行结果直接覆盖 L2 真源入链层中的真源；
7. 绕过 L7 反馈回流层中的反馈回流和相关归口规则。

### 10.6 下游承接

L6 执行响应层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/07_L6_执行响应规则.md` 承接。本文只定义 L6 执行响应层的架构位置、执行响应属性和禁止反写边界。

## 十一、L7 反馈回流层

### 11.1 层级定义

L7 反馈回流层是承接执行反馈、用户修正、外部反馈、项目复盘、模板优化、规则候选、事实修正线索和系统迭代线索的沉淀反馈层。

L7 反馈回流层的架构身份是反馈回流层，不具备正式事实真源属性，不是正式规则放行层。

### 11.2 层级职责

L7 反馈回流层负责在架构层承接以下内容：

1. 执行反馈；
2. 用户修正；
3. 外部反馈补充；
4. 项目复盘；
5. 事实修正线索；
6. 模板优化候选；
7. 规则候选；
8. 经验沉淀线索；
9. 问题闭环反馈；
10. 系统迭代线索。

L7 反馈回流层的作用是把系统运行、执行响应和复盘过程中的反馈材料重新纳入候选、修正、沉淀或后续规则承接边界。

### 11.3 读取边界

L7 反馈回流层可以读取 L6 执行响应层中的执行响应、L5 建议编排层中的建议来源、L4 分析判断层中的分析判断、L3 结果生成层中的结果内容、L2 真源入链层中的正式事实、外部反馈、用户修正和必要追溯材料。

L7 反馈回流层不得直接将反馈内容覆盖 L2 真源入链层中的正式事实，也不得把复盘结论直接写成正式规则。

### 11.4 写入边界

L7 反馈回流层只能写入反馈内容、修正线索、回流线索、模板候选、规则候选、复盘沉淀、问题闭环线索和系统迭代线索。

L7 反馈回流层不得直接写入正式事实、正式对象、正式状态、正式金额、正式责任、正式结算、正式确认或正式规则。

### 11.5 禁止事项

L7 反馈回流层不得执行以下行为：

1. 把反馈内容直接覆盖正式事实；
2. 把用户修正直接写成事实修正；
3. 把复盘结论直接写成正式规则；
4. 把模板优化候选直接作为正式事实、正式规则、模板规则、对外承诺或正式输出依据；
5. 把规则候选直接写成正式规则；
6. 把外部反馈直接写成正式确认；
7. 绕过标准治理和业务数据体系改变系统真源。

### 11.6 下游承接

L7 反馈回流层的具体运行规则由 `50_系统业务运行规则/02_L0-L7纵向运行规则/08_L7_反馈回流规则.md` 及相关回流规则文件承接。本文只定义 L7 反馈回流层的架构位置、反馈回流属性和禁止覆盖真源边界。

## 十二、L0 原始输入层至 L7 反馈回流层与分类真源的关系

L0 原始输入层至 L7 反馈回流层与分类真源之间应保持一致：

| 分类真源类别 | 对应 L 层位置 | 架构关系 |
|---|---|---|
| 原始输入 | L0 原始输入层 | L0 原始输入层 承接来源材料 |
| 候选内容 | L1 候选抽取层 | L1 候选抽取层 形成待治理候选 |
| 对象资产 | L2 真源入链层 | L2 真源入链层 承接正式对象入链 |
| 正式事实 | L2 真源入链层 | L2 真源入链层 承接正式事实入链 |
| 汇总视图 | L3 结果生成层 | L3 结果生成层消费正式事实生成结果和视图 |
| 经验规则层内容 | L7 反馈回流层 为主要入口，L4 分析判断层/L5 建议编排层 只形成候选线索，须经回流或归口治理后进入经验规则层 | 反馈、分析、建议和复盘不得直接覆盖事实 |
| 标准治理内容 | 横向贯穿 L0 原始输入层至 L7 反馈回流层 | 标准治理约束各层，不替代业务事实 |
| 外部来源内容 | L0 原始输入层/L6 执行响应层/L7 反馈回流层 均可能接收 | 作为来源、回执或反馈，不直接成为真源 |
| 页面展示内容 | 主要承接 L1 候选抽取层至 L7 反馈回流层的展示与交互 | 展示层不得反写系统真源 |

分类真源定义内容身份，L0 原始输入层至 L7 反馈回流层 定义内容在纵向架构中的位置。二者不得互相冲突。

## 十三、L0 原始输入层至 L7 反馈回流层与横向治理的关系

横向治理应贯穿 L0 原始输入层至 L7 反馈回流层，但本文不展开具体治理规则。

横向治理与 L0 原始输入层至 L7 反馈回流层的关系如下：

1. 字段规范约束 L1 候选抽取层中的候选字段、L2 真源入链层中的正式字段、L3 结果生成层中的结果字段和后续输出字段；
2. 枚举总表约束 L1 候选抽取层中的候选枚举匹配、L2 真源入链层中的正式枚举引用和 L3 结果生成层至 L7 反馈回流层 输出分类；
3. 状态口径约束 L0 原始输入层至 L7 反馈回流层中输入状态、候选状态、事实状态、结果状态、执行状态和反馈状态的边界；
4. 权限与可见性口径约束各层读取、写入、展示、导出和对外协同边界；
5. 风险分级口径约束高风险输入、高风险候选、高风险事实、高风险建议和高风险执行响应；
6. 校验规则口径约束候选内容、正式事实、视图结果、建议编排、执行响应和反馈回流的校验边界；
7. 追溯与版本口径约束来源、入链、生成、分析、建议、执行和反馈的可追溯关系；
8. 关键字段反问口径约束候选内容缺口识别后的补齐归口；
9. 脱敏与外部展示口径约束 L3 结果生成层至 L7 反馈回流层 输出、页面展示、外部协同和导出传播边界。

横向治理由 `30_标准治理` 承接。L0 原始输入层至 L7 反馈回流层只能消费和嵌入横向治理，不得反向定义标准治理规则。

## 十四、L0 原始输入层至 L7 反馈回流层与接口、页面、验证的关系

L0 原始输入层至 L7 反馈回流层 为接口、页面和验证提供架构边界，但不定义具体实现。

接口承接边界如下：

1. 输入接口主要承接 L0 原始输入层中的原始输入进入系统的边界；
2. 候选接口应尊重 L1 候选抽取层中的候选属性；
3. 入链接口不得绕过 L2 真源入链层中的真源边界；
4. 输出接口不得把 L3 结果生成层中的结果写成正式事实；
5. 分析、建议、执行、反馈相关接口不得越过 L4 分析判断层至 L7 反馈回流层的非真源边界；
6. 外部回执接口不得把外部成功状态写成正式事实或正式确认。

页面承接边界如下：

1. 页面可以展示 L0 原始输入层至 L7 反馈回流层 内容状态，但不得反向定义层级职责；
2. 页面可以展示候选内容，但不得把候选内容展示为正式事实；
3. 页面可以展示视图结果、分析、建议、执行反馈和回流内容，但不得把展示结果写成真源；
4. 页面按钮、页面标签、页面提示和 Mock 状态不得定义后端正式状态和正式事实。

验证承接边界如下：

1. 验证应检查 L0 原始输入层至 L7 反馈回流层是否存在越层写入；
2. 验证应检查 L1 候选抽取层中的候选内容是否被误写成正式事实；
3. 验证应检查 L2 真源入链层中的真源是否被页面、接口、模板、外部反馈或下游输出反写；
4. 验证应检查 L3 结果生成层至 L7 反馈回流层 非真源输出是否保持非真源属性；
5. 验证应检查横向治理是否贯穿各层；
6. 验证应检查接口、页面和测试样例是否反向定义架构层级。

具体接口、页面和验证规则分别由 `60_接口边界与集成约束`、`70_前后端协同边界与页面承接` 和 `80_验证与验收规则` 承接。

## 十五、层间禁止倒挂规则

L0 原始输入层至 L7 反馈回流层 必须防止下游输出反向定义上游真源。

以下倒挂必须禁止：

1. L0 原始输入层中的原始输入直接写成 L2 真源入链层中的正式事实；
2. L1 候选抽取层中的候选内容直接写成 L2 真源入链层中的正式事实；
3. L3 结果生成层 视图结果反写 L2 真源入链层中的正式事实；
4. L4 分析判断层中的分析判断反写 L2 真源入链层中的正式事实；
5. L5 建议编排层中的建议编排反写 L2 真源入链层中的正式事实或自动进入 L6 执行响应层中的执行；
6. L6 执行响应层中的执行响应直接覆盖 L2 真源入链层中的正式事实；
7. L7 反馈回流层中的反馈回流直接覆盖 L2 真源入链层中的正式事实；
8. 页面展示内容反写 L0 原始输入层至 L7 反馈回流层 任一层级职责；
9. 接口成功状态反写真源；
10. 测试样例反向定义 L0 原始输入层至 L7 反馈回流层层级职责。

层间倒挂一旦出现，应按 `01_系统层级与分类真源.md`、`03_横向治理架构总览.md`、`30_标准治理` 和 `50_系统业务运行规则` 的归口进行修正。

## 十六、下游承接关系

本文直接下接 `50_系统业务运行规则/02_L0-L7纵向运行规则/00_L0-L7纵向运行规则总则.md`。

本文对下游的承接要求如下：
