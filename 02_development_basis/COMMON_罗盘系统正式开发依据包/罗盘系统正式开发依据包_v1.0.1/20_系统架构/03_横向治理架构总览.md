# 03_横向治理架构总览

## 一、文件定位

本文是 `20_系统架构` 下的横向治理总览文件，用于定义标准治理、校验闸门、权限约束、风险约束、状态约束、追溯审计和脱敏边界如何贯穿罗盘系统各纵向层级。

本文回答以下问题：

1. 横向治理在系统架构中的位置是什么；
2. 横向治理与 L0 原始输入层至 L7 反馈回流层的纵向架构之间是什么关系；
3. 字段、枚举、状态、权限、风险、校验、追溯、反问和脱敏如何横向约束各层；
4. 哪些治理规则属于横向规则源；
5. 哪些治理结果不能反向生成业务事实；
6. 横向治理如何防止越层写入、真源污染、权限绕行、状态倒挂、视图反写和页面倒挂；
7. 横向治理如何支撑 `30_标准治理`、`50_系统业务运行规则`、`60_接口边界与集成约束`、`70_前后端协同边界与页面承接` 和 `80_验证与验收规则`。

本文只定义横向治理在系统架构中的嵌入关系、贯穿方式和跨链路约束，不定义字段全集、枚举全集、状态全集、权限矩阵、校验细则、接口 schema、页面流程、数据库结构、测试实现或实施计划。

## 二、横向治理总原则

横向治理是贯穿系统各纵向层级的规则约束层。它不是独立业务层级，不直接生成业务事实，也不替代业务数据体系、系统业务运行规则、接口边界、页面承接或验证与验收规则。

横向治理遵守以下原则：

1. 横向治理是规则源，不是事实源；
2. 横向治理贯穿 L0 原始输入层至 L7 反馈回流层，但不得改变 L0 原始输入层至 L7 反馈回流层的层级职责；
3. 横向治理约束原始输入、候选内容、正式事实、结果生成、分析判断、建议编排、执行响应和反馈回流；
4. 横向治理不得反向创造正式事实、正式对象、正式状态、正式权限或正式规则；
5. 横向治理只定义系统统一判断口径，具体运行动作由系统业务运行规则承接；
6. 横向治理只定义接口、页面、输出、外部协同和验证应遵守的边界，不直接替代接口、页面和测试文件；
7. 横向治理应防止页面、接口、模板、外部反馈、视图结果、候选输出和测试样例反向定义系统真源；
8. 横向治理必须与系统层级、分类真源和 L0 原始输入层至 L7 反馈回流层的纵向架构保持一致。

横向治理的核心作用是让系统各层在使用字段、枚举、状态、权限、风险、校验、追溯、反问和脱敏时保持统一边界，防止各层各自创造规则。

## 四、横向治理与纵向架构的关系

横向治理与 L0 原始输入层至 L7 反馈回流层的关系，是“纵向层级承接业务内容，横向治理约束各层读写”。

纵向架构定义内容从哪里来、进入哪一层、能否成为真源、如何被消费；横向治理定义每一层使用字段、枚举、状态、权限、风险、校验、追溯、反问和脱敏时应遵守的统一规则。

二者关系如下：

1. L0 原始输入层 接收原始输入，横向治理约束来源标识、输入权限、输入类型、来源追溯和外部来源边界；
2. L1 候选抽取层 生成候选内容，横向治理约束候选字段、候选枚举、候选状态、缺口识别、候选校验和候选追溯；
3. L2 真源入链层 形成正式真源，横向治理约束正式字段、正式枚举、正式状态、权限、风险、校验、证据、来源和追溯；
4. L3 结果生成层 生成结果和视图，横向治理约束结果字段、视图状态、输出权限、脱敏边界、导出边界和追溯来源；
5. L4 分析判断层 形成分析判断，横向治理约束分析依据、风险提示、异常识别和非真源边界；
6. L5 建议编排层 形成建议编排，横向治理约束建议来源、建议状态、建议风险、执行前权限和禁止自动执行边界；
7. L6 执行响应层 承接执行响应，横向治理约束执行权限、外部回执、接口边界、动作结果和执行追溯；
8. L7 反馈回流层 承接反馈回流，横向治理约束反馈来源、修正线索、规则候选、模板候选、复盘沉淀和回流追溯。

横向治理不改变 L0 原始输入层至 L7 反馈回流层的层级身份。任何层级即使通过横向治理校验，也不得因此获得超出其层级职责的真源权限。

## 五、横向治理贯穿总表

| L 层 | 主要内容 | 横向治理嵌入重点 | 禁止越界 |
|---|---|---|---|
| L0 原始输入层 | 原始输入、外部来源、输入元信息 | 来源、权限、输入类型、载荷标识、追溯起点 | 不得直写真源 |
| L1 候选抽取层 | 候选对象、候选事实、候选字段、候选归口 | 字段、枚举、状态、校验、反问、风险线索 | 不得生成正式事实 |
| L2 真源入链层 | 正式对象、正式事实、证据、追溯锚点 | 字段、枚举、状态、权限、风险、校验、追溯 | 不得被下游反写 |
| L3 结果生成层 | 视图、清单、台账、报告、输出草稿 | 权限、状态、脱敏、导出、追溯来源 | 不得创造事实 |
| L4 分析判断层 | 分析、异常、风险提示、趋势判断 | 分析依据、风险边界、追溯来源、非真源标识 | 不得形成决策 |
| L5 建议编排层 | 候选建议、候选方案、优先级、候选动作 | 建议状态、权限、风险、执行边界 | 不得自动执行 |
| L6 执行响应层 | 执行响应、接口调用、外部回执、任务反馈 | 权限、接口边界、回执校验、执行追溯 | 不得覆盖真源 |
| L7 反馈回流层 | 反馈、修正线索、规则候选、复盘沉淀 | 来源、版本、追溯、候选边界、回流归口 | 不得直接发布规则或改写真源 |

该表只说明横向治理嵌入位置，不定义各层具体运行步骤。

## 六、字段治理架构边界

字段治理用于保证系统各层对字段名称、字段含义、字段归口、字段引用和字段适用范围保持一致。

字段治理在架构层的边界如下：

1. L0 原始输入层 可接收原始字段或外部字段，但外部字段不等于系统正式字段；
2. L1 候选抽取层 可形成候选字段，但候选字段不等于正式字段值；
3. L2 真源入链层使用正式字段支撑对象资产和正式事实入链；
4. L3 结果生成层使用字段生成视图、清单、台账和输出内容；
5. L4 分析判断层至 L7 反馈回流层使用字段引用正式事实、结果内容和反馈材料，但不得新造正式字段；
6. 接口、页面、模板和测试样例不得反向新增字段；
7. 字段新增、废弃、合并、重命名和跨域复用，应归口字段规范总表或其后续规则承接；
8. 字段治理不得直接生成业务事实。

开发判断时，只要某字段需要跨对象、跨事实、跨视图、跨接口、跨页面复用，就不得在单一页面、单一接口、单一模板或单一运行规则中私自定义，应回到字段规范归口处理。

## 七、枚举治理架构边界

枚举治理用于保证系统分类、类型、状态组、事实类型、对象类型、风险类型、输出类型等可选值具有统一来源和统一解释。

枚举治理在架构层的边界如下：

1. L0 原始输入层外部输入中的分类词不等于系统正式枚举；
2. L1 候选抽取层 可形成候选枚举匹配，但不等于正式枚举裁定；
3. L2 真源入链层中的正式事实和正式对象引用的枚举必须来自正式枚举口径；
4. L3 结果生成层至 L7 反馈回流层 输出、分析、建议、执行和反馈中的分类表达不得新造枚举；
5. 页面选项、接口枚举、模板选项、测试值和外部系统值不得反向定义系统枚举；
6. 枚举与字段、状态、权限、风险和校验之间应保持引用关系，不得混写；
7. 枚举治理只定义值域和引用边界，不直接定义业务事实是否成立。

开发判断时，只要某一组选项会被多个事实类型、对象类型、状态组、接口、页面或测试共同使用，就应归入枚举治理，而不是写成局部选项。

## 八、状态治理架构边界

状态治理用于统一系统中对象、事实、候选、结果、输出、执行、反馈、归档、作废和恢复等状态的含义与边界。

状态治理在架构层的边界如下：

1. 页面状态不等于系统正式状态；
2. 接口成功状态不等于业务状态成立；
3. 外部系统状态不等于系统正式状态；
4. L1 候选抽取层中的候选状态不等于 L2 真源入链层中的正式状态；
5. L3 结果生成层 视图状态不反写 L2 真源入链层 事实状态；
6. L4 分析判断层 风险提示状态不等于责任或事实裁定；
7. L5 建议编排层中的建议状态不等于执行状态；
8. L6 执行响应层中的执行状态不直接覆盖事实状态；
9. L7 反馈回流层中的反馈状态不直接覆盖正式状态；
10. 状态变化必须具备归口、追溯和边界约束。

状态治理不替代运行流程。状态如何流转、何时挂起、何时驳回、何时恢复、何时关闭，由系统业务运行规则承接；本文只定义状态不得跨层误用和反写。

## 九、权限与可见性治理架构边界

权限与可见性治理用于约束系统中不同主体对不同层级内容的读取、写入、导出、展示、确认、协同和外部访问范围。

权限与可见性治理在架构层的边界如下：

1. L0 原始输入层中的输入主体不等于该主体拥有后续读写权限；
2. L1 候选抽取层中的候选内容可见不等于可确认；
3. L2 真源入链层中的真源内容可见必须受对象、项目、组织、角色和风险边界约束；
4. L3 结果生成层 视图展示不得扩大底层事实权限；
5. L4 分析判断层中的分析判断不得暴露无权限事实；
6. L5 建议编排层中的建议编排不得把无权限内容编入可执行建议；
7. L6 执行响应层中的执行响应不得绕过操作权限；
8. L7 反馈回流层中的反馈回流不得使外部主体越权修改系统真源；
9. 页面展示、导出、接口返回和外部协同必须服从同一权限与可见性边界；
10. 高风险事项应接受更严格的权限收紧原则。

权限与可见性治理不直接裁定业务事实。它约束谁能看、谁能写、谁能触发、谁能导出、谁能协同，不替代事实成立、责任认定或金额确认。

## 十、风险分级治理架构边界

风险分级治理用于区分普通事项、高风险事项和需要受限处理的事项，并决定它们在系统各层中应接受的治理强度。

风险分级治理在架构层的边界如下：

1. L0 原始输入层 高风险来源不等于高风险事实成立；
2. L1 候选抽取层 疑似风险线索不等于风险等级裁定；
3. L2 真源入链层 涉及高风险的正式事实必须接受正式风险口径约束；
4. L3 结果生成层 高风险输出不得扩大展示和导出范围；
5. L4 分析判断层 风险提示不得写成责任裁决；
6. L5 建议编排层 高风险建议不得自动进入执行；
7. L6 执行响应层 高风险执行响应不得直接覆盖事实真源；
8. L7 反馈回流层 高风险反馈不得直接发布为规则或修正事实；
9. 风险分级应与权限、校验、追溯、脱敏和对外展示共同约束；
10. 风险分级不替代业务事实归口、责任归属或金额确认。

风险分级治理只定义风险边界和治理强度，不直接生成业务结论。

## 十一、校验治理架构边界

校验治理用于约束系统中对象、事实、候选、结果、建议、执行和反馈内容是否满足进入下一层或被下游消费的规则条件。

校验治理在架构层的边界如下：

1. L0 原始输入层中的输入接收不等于校验通过；
2. L1 候选抽取层中的候选抽取不等于正式校验通过；
3. L2 真源入链层中的真源入链必须接受正式校验口径约束；
4. L3 结果生成层中的结果生成应验证其来源是否来自正式对象和正式事实；
5. L4 分析判断层中的分析判断应验证其分析依据和事实来源；
6. L5 建议编排层中的建议编排应验证建议来源、权限、风险和执行边界；
7. L6 执行响应层中的执行响应应验证执行来源、动作权限和回执边界；
8. L7 反馈回流层中的反馈回流应验证反馈来源、回流归口和版本关系；
9. 校验结果不得被页面展示、接口成功或测试通过结果替代；
10. 校验治理不等于事实本身，校验通过也不得使非真源内容自动变成真源。

校验治理只定义系统判断边界。具体校验步骤、校验失败处理、待补、挂起、驳回、阻断和熔断，由系统业务运行规则承接。

## 十二、追溯与版本治理架构边界

追溯与版本治理用于保证系统中来源、候选、入链、生成、分析、建议、执行、反馈、修正、作废、回滚和输出均具备可追溯关系。

追溯与版本治理在架构层的边界如下：

1. L0 原始输入层应成为来源追溯起点；
2. L1 候选抽取层中的候选内容应保留与原始输入的来源关系；
3. L2 真源入链层中的正式真源应具备来源、证据、状态、版本和入链追溯；
4. L3 结果生成层 视图、清单、台账和输出应能追溯到底层事实；
5. L4 分析判断层中的分析判断应能追溯到分析依据；
6. L5 建议编排层中的建议编排应能追溯到建议来源；
7. L6 执行响应层中的执行响应应能追溯到触发来源和动作结果；
8. L7 反馈回流层中的反馈回流应能追溯到反馈来源、被反馈对象和后续归口；
9. 作废、回滚、恢复、替代和修正不得脱离版本记录；
10. 追溯缺失时，不得把内容提升为不可追溯的正式结论。

追溯与版本治理不替代事实本身，但它决定系统内容是否具备被审查、被验证、被复盘和被维护的基础条件。

## 十三、关键字段反问治理架构边界

关键字段反问治理用于约束候选内容、事实入链、外部反馈、页面输入和接口输入中关键字段缺失、归属不清、来源不明、时间不明或证据不足时的补齐归口。

关键字段反问在架构层的边界如下：

1. 关键字段反问属于横向治理对象，不属于页面自定义流程；
2. L1 候选抽取层中的候选内容可触发关键字段缺口识别，但不直接定义反问结果；
3. L2 真源入链层中的正式事实入链不得绕过必要关键字段边界；
4. L3 结果生成层至 L7 反馈回流层如果暴露关键字段缺口，应回到对应归口处理，不得自行补造事实；
5. 页面可以承接反问展示，但不得反向定义关键字段规则；
6. 接口可以承接反问数据，但不得绕过反问规则；
7. 外部主体答复不等于正式事实成立；
8. 关键字段反问不得替代权限、风险、校验和追溯；
9. 反问结果是否可进入正式链路，由后续运行规则和标准治理共同承接；
10. 本文只定义关键字段反问在架构中的治理位置，不展开执行流程。

## 十四、脱敏与外部展示治理架构边界

脱敏与外部展示治理用于约束系统内容在页面、导出、外部协同、接口返回、客户展示、甲方展示和输出包中的可见范围。

脱敏与外部展示在架构层的边界如下：

1. 可内部查看不等于可外部展示；
2. 可页面展示不等于可导出；
3. 可导出不等于可对外传播；
4. 可作为内部分析依据不等于可作为外部结论；
5. L3 结果生成层至 L7 反馈回流层的输出、分析、建议、执行和反馈内容对外展示前必须接受脱敏与外部展示边界约束；
6. 页面展示不得暴露内部成本、利润、责任推演、未确认事实和内部治理过程；
7. 接口返回不得扩大底层事实可见范围；
8. 外部主体只能看到其权限范围内的内容；
9. 对外展示不得把候选内容、风险提示、建议内容、执行响应或反馈线索展示成正式结论；
10. 脱敏与外部展示规则不得反向修改底层事实。

脱敏与外部展示治理是横向约束，不是事实生成机制。

## 十五、横向治理防倒挂规则

横向治理必须防止以下倒挂：

1. 页面字段反向定义正式字段；
2. 接口枚举反向定义正式枚举；
3. 页面状态反向定义正式状态；
4. 导出结果反向扩大事实权限；
5. 外部反馈反向定义事实成立；
6. 候选校验结果反向写成正式事实；
7. 风险提示反向写成责任裁决；
8. 分析判断反向写成正式结论；
9. 建议编排反向触发执行；
10. 执行响应反向覆盖真源；
11. 反馈回流反向发布正式规则；
12. 测试样例反向改变字段、枚举、状态、权限、风险、校验、追溯和脱敏口径。

出现倒挂时，应回到 `20_系统架构/01_系统层级与分类真源.md`、`20_系统架构/02_纵向架构与L0-L7架构总览.md`、`30_标准治理` 和 `50_系统业务运行规则` 的归口边界处理。

## 十六、接口、页面与验证承接边界

横向治理为接口、页面和验证提供规则边界，但不替代具体文件。

接口承接边界如下：

1. 接口输入必须区分原始输入、候选内容、正式事实和外部来源内容；
2. 接口返回不得扩大字段、状态、权限和脱敏边界；
3. 外部回执不得绕过校验、权限、风险和追溯；
4. 接口成功不得被写成业务事实成立；
5. 接口 schema 不得反向新增标准字段、枚举、状态和权限。

页面承接边界如下：

1. 页面只能承接横向治理结果，不得自定义正式字段、状态、权限和风险；
2. 页面展示候选内容时必须保持候选属性；
3. 页面展示风险提示时不得写成责任裁决；
4. 页面展示建议内容时不得写成正式决策；
5. 页面展示外部内容时必须遵守权限和脱敏边界。

验证承接边界如下：

1. 验证应检查横向治理是否贯穿 L0 原始输入层至 L7 反馈回流层；
2. 验证应检查非真源内容是否被误写成真源；
3. 验证应检查字段、枚举、状态、权限、风险、校验、追溯和脱敏是否被页面、接口、模板或测试样例反向定义；
4. 验证应检查接口、页面、输出和外部协同是否绕过横向治理；
5. 验证应检查高风险事项是否触发对应治理边界。

具体接口规则、页面规则和验证规则分别由 `60_接口边界与集成约束`、`70_前后端协同边界与页面承接` 和 `80_验证与验收规则` 承接。
