# 08_系统组成依赖

## 一、文件定位

本文是 `20_系统架构` 下的系统组成依赖文件，用于定义罗盘系统各组成之间的依赖关系、依赖强度、依赖边界、禁止依赖和倒挂风险。

本文回答以下问题：

1. 系统各组成之间哪些属于强依赖；
2. 哪些属于弱依赖；
3. 哪些属于规划依赖；
4. 哪些依赖关系被禁止；
5. 运行主链路组成之间应如何依赖；
6. 横向治理组成如何约束其他组成；
7. 业务数据体系、视图、分析、建议、执行、反馈之间如何依赖；
8. 接口、页面、验证、底层基础支撑如何依赖业务架构；
9. 哪些依赖不得反向修改系统层级、分类真源、L0 原始输入层至 L7 反馈回流层、运行主链路和正式事实边界；
10. 下游命名空间与读写边界文件应如何承接本文依赖关系。

本文只定义系统组成之间的架构依赖关系，不定义具体调用流程、接口 schema、数据库外键、代码模块依赖、页面跳转关系、任务执行顺序、测试脚本或实施计划。

## 二、依赖关系总原则

系统组成依赖，是指罗盘系统各组成在架构上“必须依赖什么、可以依赖什么、未来可依赖什么、不得依赖什么”的关系。

系统组成依赖遵守以下原则：

1. 依赖关系必须服从系统定位、系统边界和产品属性；
2. 依赖关系必须服从系统层级与分类真源；
3. 依赖关系必须服从 L0 原始输入层至 L7 反馈回流层的纵向架构；
4. 依赖关系必须服从横向治理；
5. 依赖关系必须服从一池双区与事实回流与智能回流边界；
6. 依赖关系必须服从组织隔离与权限架构；
7. 依赖关系必须服从运行主链路；
8. 依赖关系不得让非真源组成反写真源组成；
9. 依赖关系不得让页面、接口、测试、代码实现或底层基础支撑组成反向定义系统组成；
10. 依赖关系不得被理解为开发排期、接口调用顺序或代码 import 关系。

本文中的依赖关系是架构职责依赖，不是技术实现依赖。

## 三、依赖类型定义

系统组成依赖分为四类：

| 依赖类型 | 定义 | 是否必须成立 | 典型场景 |
|---|---|---|---|
| 强依赖 | 某组成成立必须以前置组成边界为依据，否则会失去架构合法性 | 必须成立 | 真源入链依赖候选承接、业务数据体系依赖真源边界、视图依赖正式事实 |
| 弱依赖 | 某组成可以消费或参考另一组成，但不以其作为成立前提 | 可以成立 | 分析与建议参考视图、页面展示参考提示内容、验证参考运行结果 |
| 规划依赖 | 当前架构预留的后续承接关系，当前不要求完整实现 | 可逐步成立 | 外部协同增强、导出扩展、底层基础支撑增强、跨项目汇总增强 |
| 禁止依赖 | 某组成不得依赖另一组成来反向改变自身职责、真源属性或规则边界 | 必须禁止 | 页面反向定义状态、接口反向定义字段、视图反写真源、测试反向定义规则 |

依赖关系只说明架构上的承接和约束，不说明具体实现方式。

## 四、系统组成依赖总表

| 组成类别 | 强依赖 | 弱依赖 | 规划依赖 | 禁止依赖 |
|---|---|---|---|---|
| 来源入口组成 | 系统层级、权限边界、来源追溯 | 页面入口、接口输入、底层文件存储 | 外部输入增强 | 不得依赖页面或接口成功直写真源 |
| 候选承接组成 | 来源入口、字段规范、枚举总表、校验边界 | 关键字段反问、风险线索、页面提示 | 候选归口增强 | 不得依赖候选完整度直接生成正式事实 |
| 真源入链组成 | 候选承接、业务数据体系、横向治理、追溯与版本 | 权限架构、风险分级、来源证据 | 入链规则增强 | 不得依赖页面、接口、视图、分析、建议、执行或反馈直写 |
| 业务数据体系组成 | 分类真源、真源入链、横向治理 | 视图、经验规则层、沉淀线索 | 数据类型扩展 | 不得依赖视图、页面、接口或测试反向定义业务数据 |
| 横向治理组成 | 系统定位、分类真源、架构总则 | 运行规则、验证反馈、沉淀线索 | 治理规则扩展 | 不得依赖页面、接口或测试反向定义标准 |
| 结果与视图组成 | 正式对象、正式事实、权限边界、脱敏边界 | 分析与建议、页面展示、导出输出 | 视图扩展 | 不得依赖自身结果反写真源 |
| 分析与建议组成 | 正式事实、结果与视图、横向治理 | 经验沉淀、反馈回流 | 分析维度扩展 | 不得依赖分析结果形成正式事实或自动执行 |
| 执行响应组成 | 建议编排、权限边界、接口边界、追溯边界 | 反馈回流、外部回执 | 执行能力扩展 | 不得依赖执行成功改写真源 |
| 反馈回流组成 | 执行响应、事实回流、智能回流、追溯与版本 | 经验规则层、标准治理候选 | 回流规则扩展 | 不得依赖反馈直接修正事实或发布规则 |
| 权限与隔离组成 | 组织、项目、主体、用户、角色边界 | 页面、接口、导出、外部协同 | 权限模型扩展 | 不得依赖页面可见或接口成功定义权限 |
| 接口边界与集成约束组成 | 运行主链路边界、权限边界、数据归口、追溯边界 | 外部系统、页面动作、执行响应 | 外部系统扩展 | 不得依赖接口 schema 反向定义系统架构 |
| 页面承接组成 | 分类真源、权限可见性、状态口径、脱敏边界 | 接口、视图、提示、反馈 | 端侧形态扩展 | 不得依赖页面菜单、按钮、标签反向定义系统规则 |
| 验证与验收组成 | 正式开发依据、架构边界、治理规则 | 运行结果、接口结果、页面表现 | 测试覆盖扩展 | 不得依赖测试样例反向定义业务规则 |
| 底层基础支撑组成 | 系统日志、文件存储、消息、调度、缓存、溯源支撑边界 | 全链路运行、接口、页面、验证 | 底层基础支撑组成增强 | 不得依赖技术成功状态定义业务事实 |

系统组成依赖应优先保障运行主链路不倒挂、真源不污染、治理不被反向定义、页面接口不越权。

## 五、运行主链路强依赖

运行主链路中的组成存在基础强依赖关系。

运行主链路强依赖如下：

1. 候选承接组成强依赖来源入口组成；
2. 真源入链组成强依赖候选承接组成；
3. 业务数据体系组成强依赖真源入链组成和分类真源；
4. 结果与视图组成强依赖业务数据体系中的正式对象和正式事实；
5. 分析与建议组成强依赖正式事实、结果与视图和横向治理边界；
6. 执行响应组成强依赖建议编排、权限边界、接口边界和追溯边界；
7. 反馈回流组成强依赖执行响应、事实回流、智能回流和追溯与版本边界；
8. 事实回流线索强依赖事实归口边界；
9. 智能回流材料强依赖经验规则层、标准治理候选或系统迭代归口；
10. 全部运行主链路组成强依赖横向治理、权限架构和追溯边界。

运行主链路强依赖只允许顺向承接，不允许下游结果反向定义上游真源。

## 六、来源入口依赖

来源入口组成是系统接收来源材料的入口，不依赖后续层级才能成立。

来源入口组成的依赖关系如下：

1. 强依赖系统层级与分类真源，用于保持原始输入属性；
2. 强依赖权限与隔离边界，用于识别输入主体、组织、项目、外部来源和可见范围；
3. 强依赖追溯与版本边界，用于保留来源记录；
4. 弱依赖页面承接组成，用于承接页面提交入口；
5. 弱依赖接口边界与集成约束组成，用于承接外部载荷和接口输入；
6. 弱依赖底层基础支撑组成，用于承接文件存储、日志和来源记录；
7. 规划依赖外部协同能力增强，用于后续扩展外部反馈来源。

来源入口组成不得依赖页面提交成功、接口成功、文件保存成功或外部反馈存在来判定事实成立。

## 七、候选承接依赖

候选承接组成负责承接来源材料形成的候选内容。

候选承接组成的依赖关系如下：

1. 强依赖来源入口组成，用于获取原始输入和来源记录；
2. 强依赖字段规范，用于识别候选字段；
3. 强依赖枚举总表，用于识别候选枚举匹配；
4. 强依赖状态口径，用于保持候选状态与正式状态区分；
5. 强依赖校验规则口径，用于识别候选缺口、来源不足和归属不清；
6. 强依赖权限与可见性口径，用于约束候选内容可见范围；
7. 弱依赖关键字段反问口径，用于归口字段缺口；
8. 弱依赖页面承接组成，用于展示候选状态和缺口提示；
9. 规划依赖候选归口增强能力，用于后续提升归口准确性。

候选承接组成不得依赖候选内容完整、字段匹配成功或页面展示完成来直接生成正式事实。

## 八、真源入链依赖

真源入链组成是正式对象和正式事实写入的唯一入口。

真源入链组成的依赖关系如下：

1. 强依赖候选承接组成，用于获得待入链材料；
2. 强依赖业务数据体系，用于确定对象资产、事实记录和正式归口；
3. 强依赖字段规范、枚举总表、状态口径、权限与可见性、风险分级、校验规则、追溯与版本边界；
4. 强依赖组织隔离、项目隔离、主体隔离和高风险动作隔离；
5. 强依赖来源证据关系，用于维持事实可追溯；
6. 弱依赖底层基础支撑组成，用于保存日志、文件引用和追溯记录；
7. 规划依赖后续事实入链规则细化。

真源入链组成不得依赖页面、接口、外部回执、视图统计、分析判断、候选建议、执行响应、反馈复盘、模板候选或规则候选直写。

## 九、业务数据体系依赖

业务数据体系组成是全量业务数据统一归口体系。

业务数据体系组成的依赖关系如下：

1. 强依赖分类真源，用于区分对象资产、事实记录、汇总视图和经验规则层；
2. 强依赖真源入链组成，用于承接正式对象和正式事实；
3. 强依赖横向治理组成，用于统一字段、枚举、状态、权限、风险、校验、追溯和脱敏边界；
4. 强依赖一池双区架构，用于区分事实沉淀区和智能沉淀区；
5. 弱依赖结果与视图组成，用于提供视图消费对象；
6. 弱依赖反馈回流组成，用于承接事实修正线索和经验规则层候选内容；
7. 规划依赖数据类型扩展，用于后续增加对象、事实、视图或经验规则层细则。

业务数据体系组成不得依赖页面展示、接口字段、测试样例、数据库表或代码模块反向定义业务数据结构。

## 十、横向治理依赖

横向治理组成是贯穿全系统的规则约束组成。

横向治理组成的依赖关系如下：

1. 强依赖顶层定义，用于保持系统定位、系统边界和产品属性一致；
2. 强依赖系统层级与分类真源，用于确定治理对象和治理边界；
3. 强依赖纵向架构与运行主链路，用于确定治理规则嵌入位置；
4. 强依赖组织隔离与权限架构，用于约束权限、可见性和高风险动作；
5. 弱依赖系统业务运行规则，用于承接具体触发、处理和异常规则；
6. 弱依赖验证与验收组成，用于发现治理规则执行缺口；
7. 规划依赖标准治理规则扩展，用于后续完善字段、枚举、状态、权限、风险、校验、追溯、反问和脱敏细则。

横向治理组成不得依赖页面、接口、模板、测试样例或代码现状反向定义正式术语、字段、枚举、状态、权限、风险、校验、追溯和脱敏规则。

## 十一、结果与视图依赖

结果与视图组成是正式事实的消费展示组成。

结果与视图组成的依赖关系如下：

1. 强依赖业务数据体系中的正式对象和正式事实；
2. 强依赖权限与可见性口径，用于约束视图可见范围；
3. 强依赖脱敏与外部展示口径，用于约束导出和对外展示；
4. 强依赖追溯与版本口径，用于保持视图结果可追溯；
5. 弱依赖页面承接组成，用于展示视图、清单、台账和报告草稿；
6. 弱依赖接口边界与集成约束组成，用于输出查询结果；
7. 弱依赖分析与建议组成，用于提供分析输入；
8. 规划依赖视图扩展，用于后续增加视图类别和输出形态。

结果与视图组成不得依赖自身统计结果、页面展示结果、导出结果或报告草稿反写真源。

## 十二、分析与建议依赖

分析与建议组成是非真源分析和候选建议组成。

分析与建议组成的依赖关系如下：

1. 强依赖正式事实和结果与视图；
2. 强依赖横向治理规则，用于控制分析依据、风险提示、权限、追溯和非真源边界；
3. 强依赖权限与隔离组成，用于防止无权限事实被纳入分析和建议；
4. 弱依赖反馈回流组成，用于形成经验沉淀、规则候选和模板候选；
5. 弱依赖页面承接组成，用于展示分析提示和候选建议；
6. 弱依赖执行响应组成，用于向后续执行响应提供候选材料；
7. 规划依赖分析维度扩展和建议类型扩展。

分析与建议组成不得依赖分析结果、风险提示、趋势判断、候选建议或方案比较直接形成正式事实、正式决策或自动执行动作。

## 十三、执行响应依赖

执行响应组成承接受控执行响应、外部回执和动作结果。

执行响应组成的依赖关系如下：

1. 强依赖建议编排组成，用于承接候选动作来源；
2. 强依赖权限与隔离组成，用于约束操作权限和高风险动作；
3. 强依赖接口边界与集成约束组成，用于承接接口调用和外部回执；
4. 强依赖追溯与版本口径，用于记录执行来源、动作结果和回执关系；
5. 弱依赖反馈回流组成，用于形成事实回流线索和智能回流材料；
6. 弱依赖底层基础支撑组成，用于承接日志、消息通知和任务调度支撑；
7. 规划依赖执行能力扩展。

执行响应组成不得依赖执行成功、接口成功、外部回执、任务完成或消息发送成功直接改写真源、正式状态、正式责任或正式结算。

## 十四、反馈回流依赖

反馈回流组成承接事实回流线索和智能回流材料。

反馈回流组成的依赖关系如下：

1. 强依赖执行响应组成，用于承接执行反馈和动作结果；
2. 强依赖一池双区架构，用于区分事实回流与智能回流；
3. 强依赖追溯与版本口径，用于记录反馈来源、版本关系和回流对象；
4. 强依赖业务数据体系，用于回到对象资产、事实记录、汇总视图或经验规则层归口；
5. 强依赖横向治理组成，用于约束反馈、修正、规则候选和模板候选边界；
6. 弱依赖页面承接组成，用于展示反馈状态和回流线索；
7. 弱依赖验证与验收组成，用于暴露回流边界问题；
8. 规划依赖回流规则扩展。

反馈回流组成不得依赖用户反馈、外部反馈、复盘结论、模板候选或规则候选直接修正事实、直接发布正式规则或直接发布模板规则。

## 十五、权限与隔离依赖

权限与隔离组成是全系统可见、写入、导出、外部展示和高风险动作的隔离基础。

权限与隔离组成的依赖关系如下：

1. 强依赖组织、项目、主体、用户、角色和外部对象边界；
2. 强依赖分类真源，用于判断内容属性；
3. 强依赖 L0 原始输入层至 L7 反馈回流层层级，用于判断层级可见与操作范围；
4. 强依赖风险分级口径，用于识别高风险动作；
5. 强依赖追溯与版本口径，用于记录权限变化和高风险动作；
6. 弱依赖页面承接组成，用于执行展示裁剪；
7. 弱依赖接口边界与集成约束组成，用于执行接口鉴权；
8. 规划依赖权限模型扩展。

权限与隔离组成不得依赖页面可见、按钮存在、接口成功、测试账号或临时配置反向定义正式权限。

## 十六、接口边界与集成约束依赖

接口边界与集成约束组成承接系统输入、输出、外部连接、页面动作、外部回执和联调边界。

接口边界与集成约束组成的依赖关系如下：

1. 强依赖运行主链路，用于确认接口承接的是 L0 原始输入层、L1 候选抽取层、L2 真源入链层、L3 结果生成层、L4 分析判断层、L5 建议编排层、L6 执行响应层 还是 L7 反馈回流层 内容；
2. 强依赖分类真源，用于区分原始输入、候选内容、正式事实、视图结果、执行响应和反馈线索；
3. 强依赖权限与隔离组成，用于执行接口鉴权和可见范围控制；
4. 强依赖横向治理组成，用于约束接口字段、枚举、状态、风险、校验、追溯和脱敏；
5. 弱依赖底层基础支撑组成，用于承接日志、文件、缓存、消息和任务支撑；
6. 规划依赖外部系统扩展和回执规则增强。

接口边界与集成约束组成不得依赖接口 schema、外部字段、外部状态、接口成功或联调便利性反向定义系统字段、枚举、状态、事实或架构。

## 十七、页面承接依赖

页面承接组成用于呈现系统内容和承接用户交互。

页面承接组成的依赖关系如下：

1. 强依赖分类真源，用于区分原始、候选、正式、视图、分析、建议、执行和反馈内容；
2. 强依赖权限与可见性口径，用于控制页面展示范围；
3. 强依赖状态口径，用于展示状态但不定义状态；
4. 强依赖脱敏与外部展示口径，用于控制外部展示和导出边界；
5. 强依赖接口边界与集成约束组成，用于承接页面动作和数据返回；
6. 弱依赖结果与视图组成，用于展示视图、清单、台账和详情；
7. 弱依赖反馈回流组成，用于展示反馈和回流状态；
8. 规划依赖端侧形态扩展。

页面承接组成不得依赖页面菜单、按钮、标签、提示、筛选项、Mock 状态或展示便利性反向定义系统组成、字段、状态、权限或事实。

## 十八、验证与验收依赖

验证与验收组成用于检查系统架构、治理规则、接口页面和运行边界是否成立。

验证与验收组成的依赖关系如下：

1. 强依赖正式开发依据文件；
2. 强依赖系统层级、分类真源、L0 原始输入层至 L7 反馈回流层、横向治理、运行主链路、权限架构和一池双区边界；
3. 强依赖接口边界和页面承接规则；
4. 强依赖负向拦截场景；
5. 弱依赖运行结果、接口结果、页面表现和日志记录；
6. 弱依赖底层基础支撑组成，用于获取测试记录、日志和追溯材料；
7. 规划依赖测试覆盖扩展。

验证与验收组成不得依赖测试样例、测试账号、测试通过、验收便利性或代码现状反向定义系统规则、业务事实、权限、字段、枚举或系统组成。

## 十九、底层基础支撑依赖

底层基础支撑组成提供日志、消息、调度、缓存、文件存储、全局溯源和系统参数等底层基础支撑组成能力。

底层基础支撑组成的依赖关系如下：

1. 强依赖系统组成地图，用于明确自身属于技术支撑类组成；
2. 强依赖权限与隔离边界，用于控制日志、文件、消息和追溯材料的访问范围；
3. 强依赖追溯与版本口径，用于承接日志、操作记录和溯源记录；
4. 弱依赖接口、页面、运行规则和验证组成，用于提供技术支撑；
5. 规划依赖底层基础支撑组成增强，包括消息通知、调度、缓存、文件存储和全局溯源能力扩展。

底层基础支撑组成不得依赖日志存在、消息发送成功、任务执行完成、缓存命中、文件保存成功、参数配置存在或溯源记录生成来认定业务事实成立、状态成立、权限成立或规则成立。

## 二十、禁止依赖总表

| 禁止依赖方向 | 禁止原因 |
|---|---|
| 页面 → 系统组成 | 页面菜单、按钮、状态、提示不得反向定义系统组成 |
| 页面 → 正式事实 | 页面展示、提交、点击、导出不得直接生成或修改正式事实 |
| 接口 → 系统架构 | 接口 schema、外部字段、外部状态不得反向定义系统架构 |
| 接口 → 正式事实 | 接口成功、回执成功不得直接写成正式事实或正式确认 |
| 视图 → 真源 | 视图统计、台账、清单、报告不得反写正式事实 |
| 分析与建议 → 执行 | 分析结果、风险提示、候选建议不得自动执行 |
| 执行响应 → 真源 | 执行完成、任务反馈、外部回执不得直接覆盖正式事实 |
| 反馈回流 → 真源 | 用户反馈、外部反馈、复盘结论不得直接修正事实 |
| 经验规则层 → 事实记录层 | 经验、模板、规则候选不得直接写成正式事实 |
| 测试 → 规则 | 测试样例、测试通过、测试账号不得反向定义业务规则 |
| 代码实现 → 开发依据 | 代码便利性、现有模块、技术实现不得反向修改开发依据 |
| 底层基础支撑组成 → 业务事实 | 日志、消息、调度、缓存、文件存储、溯源记录不得认定业务事实成立 |

禁止依赖是架构红线，不得被实现便利性、页面设计、接口设计、测试样例或临时业务需求突破。
