# 00_系统架构总则

## 一、文件定位

本文是 `20_系统架构` 目录的总则文件，用于定义系统架构目录的总体职责、文件分工、结构约束、架构边界和下游承接关系。

本文回答“系统架构组负责什么、不负责什么；各架构文件分别承接哪些边界；系统架构与顶层定义、标准治理、业务数据体系、系统业务运行规则、接口边界、页面承接和验证与验收之间如何分工；后续架构文件不得越界写入哪些内容”。

本文只写系统架构目录的入口性规则和分工约束，不展开 L0 原始输入层至 L7 反馈回流层运行细则、字段全集、接口字段、页面流程、数据库结构、测试实现、人工处理流程或实施计划。

## 二、系统架构目录总职责

`20_系统架构` 的总职责，是把顶层定义确定的系统定位、系统边界、产品属性和阶段边界，转化为后续开发依据可以共同遵守的架构层级、真源边界、治理嵌入、组成关系和读写约束。

系统架构目录承担以下职责：

1. 定义系统内容层级、分类身份、真源属性和跨层读写边界；
2. 定义纵向架构中各层级的职责、读写关系和上下游位置；
3. 定义横向治理如何嵌入系统各层，但不展开具体治理规则；
4. 定义事实沉淀、智能沉淀、回流关系和系统沉淀边界；
5. 定义组织隔离、权限架构、外部协同隔离和高风险边界在架构中的位置；
6. 定义运行主链路在架构层面的上下游关系，但不展开运行流程细节；
7. 定义系统组成地图和组成依赖，防止局部能力被误写为独立系统；
8. 定义命名空间与读写边界，防止字段、事实、视图、接口、页面、模板、外部反馈和测试结果互相污染。

系统架构目录不负责定义字段全集、枚举全集、状态全集、权限矩阵、校验规则明细、反问流程、接口 schema、页面组件、数据库表结构、测试脚本、部署方案或实施任务。

## 三、上位约束

系统架构必须服从 `10_顶层定义` 已确定的系统定位和边界，不得反向修改顶层定义。

系统架构应遵守以下上位约束：

1. 罗盘系统是面向小型装修 / 工程类企业的公司级经营执行系统；
2. 系统以项目为业务执行单元，以公司为经营能力沉淀归属主体；
3. 系统主线是将真实经营执行过程沉淀为可治理、可追溯、可查询、可复盘、可复用的经营执行能力；
4. 原始输入、候选内容、外部反馈、接口回执、页面状态、模板结果、汇总视图、辅助输出和测试样例不得直接成为正式事实；
5. 正式事实、对象资产、汇总视图、经验规则层和标准治理之间必须保持层级边界；
6. 页面、接口、模板、辅助输出、外部反馈、测试结果和代码实现不得反向定义系统定位、事实边界、权限边界或架构层级；
7. 系统架构只承接和结构化顶层边界，不通过新增层级、新增入口、新增组成或新增链路突破顶层定义。

系统架构中的任何文件，如需承接具体业务流程、字段规则、接口实现、页面交互或验收断言，应转入对应下游目录，不得在系统架构组内越界展开。

## 四、系统架构文件分工

系统架构目录内部文件按职责分工承接，不得互相替代。

| 文件 | 主要职责 | 不负责 |
|---|---|---|
| `00_系统架构总则.md` | 定义系统架构目录总职责、文件分工、结构约束、架构边界和下游承接关系 | 不写运行细则、字段全集、接口字段、页面流程、数据库结构、测试实现和实施计划 |
| `01_系统层级与分类真源.md` | 定义内容层级、分类身份、真源属性、读写边界、消费边界和冲突裁定标准 | 不写运行流程、校验流程、人工审核流程、接口实现和页面设计 |
| `02_纵向架构与L0-L7架构总览.md` | 定义 L0 原始输入层至 L7 反馈回流层的纵向层级、层间关系、各层职责和读写边界 | 不写各层具体运行操作步骤 |
| `03_横向治理架构总览.md` | 定义字段、枚举、状态、权限、风险、校验、追溯等横向治理如何贯穿系统各层 | 不替代标准治理细则 |
| `04_双回流与一池双区架构.md` | 定义事实沉淀区、智能沉淀区、事实回流、智能回流、候选归口和禁止反写关系 | 不把智能沉淀写成事实真源 |
| `05_组织隔离与权限架构.md` | 定义组织、项目、主体、外部对象、接口和高风险动作之间的系统级隔离原则 | 不替代具体角色权限表、页面可见性或脱敏细则 |
| `06_运行主链路.md` | 定义系统运行主链路在架构层的上下游关系、闸门位置和归口边界 | 不替代系统业务运行规则中的具体流转规则 |
| `07_系统组成地图.md` | 定义系统组成、业务类组成、技术支撑类组成和各组成对象的架构位置 | 不把组成存在写成独立产品线 |
| `08_系统组成依赖.md` | 定义组成之间的强依赖、弱依赖、规划依赖和禁止依赖 | 不替代 YAML 表头，不展开多级间接上下游 |
| `09_命名空间与读写边界.md` | 定义主要命名空间、读写边界和跨命名空间污染拦截原则 | 不替代字段规范总表、接口规范或数据库表结构 |

上述文件共同构成系统架构组。任何架构文件都不得直接定义字段、枚举、状态、权限明细、接口 schema、页面组件、数据库表、测试脚本或实施计划。

## 五、系统架构组与其他目录的关系

系统架构目录是顶层定义之后、标准治理和业务数据体系之前的架构承接层。

系统架构与其他目录的关系如下：

1. `10_顶层定义` 决定系统定位、系统边界、产品属性和阶段边界，系统架构不得反向修改；
2. `20_系统架构` 定义层级、真源、治理嵌入、组成关系、隔离边界和读写约束；
3. `30_标准治理` 定义术语、字段、枚举、状态、权限、风险、校验、追溯、反问、脱敏等横向规则；
4. `40_业务数据体系` 定义对象资产层、事实记录层、汇总视图层和经验规则层的业务数据归口；
5. `50_系统业务运行规则` 定义输入、候选、校验、反问、确认、入链、输出、异常、回流和治理动作的具体运行规则；
6. `60_接口边界与集成约束` 定义输入输出、外部连接、页面动作、回执、失败回退和联调边界；
7. `70_前后端协同边界与页面承接` 定义页面如何展示状态、触发动作、承接系统返回和降低用户理解成本；
8. `80_验证与验收规则` 定义如何验证系统能力、治理边界、权限边界、追溯边界和负向拦截是否成立。

系统架构组不得替代标准治理、业务数据体系、运行规则、接口边界、页面承接或验证与验收文件。下游文件也不得反向改变系统架构定义的层级、真源、读写边界和组成关系。

## 六、架构分层总约束

系统架构组应保证后续文件在统一层级下展开。

架构分层应至少保持以下边界：

1. 来源类内容与正式事实必须分离；
2. 候选内容与正式内容必须分离；
3. 对象资产与过程事实必须分离；
4. 汇总视图与事实真源必须分离；
5. 经验规则层与正式事实、标准治理必须分离；
6. 标准治理与业务事实必须分离；
7. 外部来源内容与系统真源必须分离；
8. 页面展示内容与后端正式状态、正式事实、正式权限必须分离；
9. 接口成功、页面成功、导出成功和测试通过不得被解释为业务事实成立；
10. 下游输出不得反写上游真源。

具体分类、真源属性、读写边界和冲突裁定，由 `01_系统层级与分类真源.md` 承接。本文只定义架构组对分层边界的总要求。

## 七、纵向架构承接规则

纵向架构用于说明系统从输入到候选、从候选到正式、从正式到视图、从视图到沉淀和回流的层级关系。

`02_纵向架构与L0-L7架构总览.md` 应承接以下内容：

1. L0 原始输入层至 L7 反馈回流层的架构层级；
2. 各层主要职责；
3. 各层读写边界；
4. 各层之间的输入、消费、输出和禁止反写关系；
5. 不具备正式事实真源属性的层级与 L2 真源入链层的边界；
6. 运行主链路在纵向架构中的位置；
7. 与业务数据体系、标准治理、系统业务运行规则的衔接关系。

`00_系统架构总则.md` 不展开 L0 原始输入层至 L7 反馈回流层具体层级定义，不写每一层的操作步骤，不写流程状态，也不写运行细则。

## 八、横向治理承接规则

横向治理用于说明字段、枚举、状态、权限、风险、校验、追溯、反问、脱敏等规则如何约束系统各层。

`03_横向治理架构总览.md` 应承接以下内容：

1. 横向治理在各架构层中的嵌入位置；
2. 标准治理与纵向架构的关系；
3. 标准治理与业务数据体系的关系；
4. 标准治理与运行规则、接口、页面、验证的关系；
5. 横向治理如何防止越层写入、真源污染、权限绕行和状态倒挂；
6. 横向治理如何支撑后续标准治理文件的消费。

具体字段定义、枚举定义、状态定义、权限规则、风险规则、校验规则、追溯规则、反问规则和脱敏规则，由 `30_标准治理` 下各文件承接。系统架构组只定义治理嵌入关系和跨层边界。

## 九、沉淀与回流承接规则

系统长期运行会形成事实沉淀、经验沉淀、模板沉淀、规则候选和反馈回流。系统架构需要规定这些内容的架构位置，但不直接定义具体运行流程。

`04_双回流与一池双区架构.md` 应承接以下内容：

1. 系统沉淀池的总体边界；
2. 事实沉淀区与智能沉淀区的分类关系；
3. 事实回流与智能回流的架构区别；
4. 正式事实、视图输出、复盘结论、模板候选、规则候选和候选知识之间的真源边界；
5. 沉淀内容不得反写正式事实的原则；
6. 回流内容进入后续运行规则和标准治理的承接边界。

具体回流步骤、回流状态、回流处理、规则候选处理和模板发布流程，由 `50_系统业务运行规则`、`30_标准治理`、`40_业务数据体系` 和后续相关文件承接。

## 十、隔离与权限承接规则

系统架构应在目录层明确组织隔离、项目隔离、主体隔离、外部协同隔离、接口隔离、页面展示隔离和高风险动作隔离的位置。

`05_组织隔离与权限架构.md` 应承接以下内容：

1. 组织、项目、主体、用户、角色和外部对象之间的架构隔离关系；
2. 内部用户、外部主体、外部系统和系统能力之间的访问边界；
3. 权限与可见性在系统架构中的嵌入位置；
4. 高风险动作与普通动作的系统级隔离原则；
5. 外部来源内容、页面展示内容和接口调用不得越权进入正式链路的边界；
6. 权限架构如何与标准治理、接口边界、页面承接和验证规则衔接。

具体角色、权限项、可见性范围、脱敏规则、操作授权和页面展示权限，由 `30_标准治理`、`60_接口边界与集成约束`、`70_前后端协同边界与页面承接` 和 `80_验证与验收规则` 承接。

## 十一、运行主链路承接规则

运行主链路用于说明系统经营执行主线在架构层如何连接输入、候选、治理、事实、视图、输出、回流和沉淀。

`06_运行主链路.md` 应承接以下内容：

1. 运行主链路的架构顺序；
2. 运行主链路中各层的归口边界；
3. 标准治理、业务数据体系、接口边界、页面承接和验证规则在运行主链路中的位置；
4. 运行主链路与候选、正式事实、汇总视图、经验规则层之间的关系；
5. 运行主链路不得被页面、接口、模板、外部反馈、辅助输出或测试结果反向定义的原则。

具体运行状态、校验步骤、待补、挂起、驳回、确认、入链、输出、回流、异常处理和人工介入规则，由 `50_系统业务运行规则` 承接。系统架构组只定义运行主链路的架构位置和承接关系。

## 十二、系统组成承接规则

系统组成文件用于说明罗盘系统由哪些组成部分构成、这些组成部分处于什么架构位置、彼此之间存在什么依赖。

`07_系统组成地图.md` 应承接：

1. 系统组成分类；
2. 各组成对象的架构位置；
3. 各组成对象与顶层定义、系统架构、标准治理、业务数据体系、运行规则、接口、页面和验收的关系；
4. 局部组成不得被误写成独立产品线的边界；
5. 业务类组成与技术支撑类组成的区分，以及底层基础支撑组成的架构位置。

`07_系统组成地图.md` 应明确底层基础支撑组成只提供日志、消息、调度、缓存、文件存储、全局溯源和系统参数支撑，不参与业务事实生成、业务流程决策或正式规则发布。

`08_系统组成依赖.md` 应承接：

1. 组成之间的强依赖；
2. 组成之间的弱依赖；
3. 组成之间的规划依赖；
4. 禁止依赖；
5. 依赖关系与文件上下游的区别。

系统组成文件不得新增系统定位，不得新增独立产品线，不得把单个能力、页面、接口、模板、辅助输出或外部协同写成与罗盘系统并列的独立系统。

## 十三、命名空间与读写边界承接规则

命名空间与读写边界用于防止不同层级、不同目录、不同对象、不同接口、不同页面之间互相污染。

`09_命名空间与读写边界.md` 应承接以下内容：

1. 主要命名空间分类；
2. 不同命名空间的读写边界；
3. 对象、事实、视图、标准、接口、页面、模板、外部来源和测试之间的边界；
4. 下游输出不得反写上游真源的规则；
5. 命名空间冲突、字段误用、状态误用、接口误写和页面状态倒挂的拦截原则。

该文件不得替代字段规范总表、枚举总表、状态口径总表、接口 schema 或数据库结构设计。它只定义系统架构层的命名空间边界和读写约束。

## 十四、禁止倒挂规则

系统架构目录必须防止下游能力反向定义上游边界。

以下倒挂必须禁止：

1. 原始输入、候选内容、外部反馈、接口回执、页面状态、模板结果、导出结果或测试结果直接成为正式事实；
2. 业务数据体系反向改变系统定位、系统边界和产品属性；
3. 字段、枚举、状态、权限或接口 schema 反向新增系统能力；
4. 页面动作、按钮、提示语或 Mock 状态反向定义正式事实、正式状态或正式权限；
5. 接口成功、回执成功、外部写入成功反向定义事实成立；
6. 汇总视图、查询结果、导出结果或外部展示结果反向创造事实；
7. 辅助输出、分析与建议或复盘结论反向覆盖正式事实；
