# 07_风险分级口径

## 一、文件定位

本文是 `30_标准治理` 下的风险分级口径文件，用于统一罗盘系统中对象、事实、候选内容、视图输出、经验规则、标准治理、接口、页面、外部协同、导出分享和对外展示相关事项的风险识别、风险分级、风险处理边界和阻断条件。

本文回答“哪些事项属于风险事项、风险等级如何划分、哪些事项必须收紧权限、哪些事项必须进入 S2 校验、哪些事项必须人工确认、哪些事项必须 S3 追溯、哪些事项不得自动放行”。

本文只定义风险判断口径，不替代权限与可见性口径、校验规则口径、追溯与版本口径、脱敏与外部展示口径、接口规则、页面规则、数据库结构、代码实现、法务判断、财税判断、安全管理制度或完整风控系统。

## 二、风险分级口径职责

风险分级口径承担以下职责：

1. 定义风险等级；
2. 定义风险触发来源；
3. 定义金额、责任、结算、合同、签证、付款、扣款、赔付、客户确认、甲方确认、对外展示、权限变更、真源修订、规则发布、AI 输出采纳和外部反馈采纳等高风险事项；
4. 定义不同风险等级对应的权限收紧、S2 校验、人工确认、S3 追溯和阻断要求；
5. 定义对象资产层、事实记录层、汇总视图层、经验规则层和标准治理中的风险边界；
6. 定义页面、接口、模板、导出包、分享包、外部反馈和 AI 输出不得绕过风险判断；
7. 为校验规则口径、追溯与版本口径、脱敏与外部展示口径、接口边界与集成约束、前后端协同边界与页面承接和验证与验收规则提供风险依据。

本文不负责定义完整风险控制系统、专业法务结论、专业财税结论、安全制度全集、赔偿裁决、责任终局裁决或诉讼判断。

## 三、上位约束

风险分级必须服从以下上位约束：

1. 风险等级不等于事实本体；
2. 风险等级不替代权限判断；
3. 风险等级不替代校验规则；
4. 风险等级不替代人工确认；
5. 风险等级不替代追溯与版本；
6. 风险提示不等于责任裁决；
7. 风险提示不等于结算确认；
8. 风险提示不等于客户确认或甲方确认；
9. 风险提示不等于外部可展示结论；
10. 页面风险标签不得反向定义正式风险等级；
11. 接口回执不得反向定义正式风险等级；
12. AI 输出不得自动生成正式风险结论；
13. 外部反馈不得直接生成正式风险事实；
14. 高风险事项不得通过低风险权限、页面便利、接口便利、模板便利或 AI 辅助绕过治理链路。

## 四、风险分级定义权规则

风险分级定义权遵守以下规则：

1. 本文负责定义风险等级、风险触发场景、风险处理边界和风险阻断口径；
2. 字段规范总表负责定义 `risk_level` 等风险字段；
3. 状态口径总表负责定义风险相关状态的状态化表达边界；
4. 权限与可见性口径负责定义风险事项对应的可见、可改、可确认、可导出、可分享和对外展示边界；
5. 校验规则口径负责定义风险事项的校验条件、阻断条件、待补条件和人工确认触发条件；
6. 追溯与版本口径负责定义风险事项的审计、证据、快照、版本、回滚和留痕要求；
7. 脱敏与外部展示口径负责定义风险事项对外展示前的裁剪、脱敏和确认要求；
8. 接口边界与集成约束、前后端协同边界与页面承接负责按本文风险口径执行，不得反向修改风险定义。

## 五、风险等级总表

| 风险等级 | 英文字段值 | 含义 | S2 校验 | 人工确认 | S3 追溯 | 默认处理 |
|---|---|---|---|---|---|---|
| 无风险 | `none` | 事项不触发明显业务、权限、财务、责任、外部展示或真源风险 | 条件需要 | 否 | 条件需要 | 可按常规规则推进 |
| 低风险 | `low` | 事项影响范围小，可通过常规校验和权限控制处理 | 是 | 条件需要 | 条件需要 | 可进入常规处理 |
| 中风险 | `medium` | 事项可能影响项目、主体、资料、状态、视图输出或内部协同 | 是 | 条件需要 | 是 | 需收紧权限并记录 |
| 高风险 | `high` | 事项涉及金额、责任、结算、合同、签证、付款、客户/甲方确认、对外展示、规则发布或真源修订 | 是 | 是 | 是 | 不得自动放行 |
| 阻断风险 | `blocking` | 事项存在越权、缺证、冲突、污染、违法违规、外部误导、真源破坏或无法归口风险 | 是 | 是 | 是 | 必须阻断或熔断 |

风险等级只用于处理要求判断，不代表责任结论、金额结论、结算结论或法律结论。

## 六、风险触发来源

风险可由以下来源触发：

1. 字段缺失；
2. 字段冲突；
3. 主体不明；
4. 项目归属不明；
5. 时间冲突；
6. 来源不明；
7. 证据不足；
8. 权限不足；
9. 状态不匹配；
10. 金额异常；
11. 责任归属不清；
12. 客户确认缺失；
13. 甲方确认缺失；
14. 外部反馈未经确认；
15. 对外展示范围不明；
16. AI 输出未经复核；
17. 接口载荷异常；
18. 页面动作越权；
19. 模板输出误用；
20. 历史旧口径污染；
21. 真源修订缺少依据；
22. 标准治理冲突。

风险触发来源应保留在风险原因、校验结果或追溯记录中，不得只保留风险等级而丢失触发依据。

## 七、低风险事项

低风险事项通常具备以下特征：

1. 不涉及金额、结算、付款、扣款、赔付；
2. 不涉及责任确认、授权确认、客户确认或甲方确认；
3. 不涉及对外展示、导出、分享或外部协同；
4. 不涉及正式事实修订、作废、回滚或真源改写；
5. 不涉及权限变更、规则发布或模板发布；
6. 不影响其他主体权益；
7. 可通过常规字段、枚举、状态和权限校验处理。

低风险事项仍需满足字段、状态、权限和追溯基本要求。低风险不等于无需校验，也不等于无需权限判断。

## 八、中风险事项

中风险事项通常具备以下特征：

1. 影响项目推进、资料完整性、内部协同或处理状态；
2. 涉及候选事实补齐、主体关系补齐、资料缺口、状态冲突或视图输出偏差；
3. 涉及内部处理分派、事项关闭、挂起、驳回或归档；
4. 涉及经手范围、责任范围或资料范围边界不清；
5. 涉及客户、甲方、供应商、班组或外部协作者反馈，但尚未进入确认或正式流转；
6. 涉及 AI 候选摘要、AI 候选建议、AI 候选知识被内部采用；
7. 涉及模板输出、清单、台账或草单对内部使用产生误导风险。

中风险事项应进入 S2 校验，并根据影响范围决定是否人工确认。中风险事项不得对外展示为正式结论。

## 九、高风险事项总表

以下事项默认属于高风险：

| 高风险事项 | 风险说明 | 最低处理要求 |
|---|---|---|
| 金额确认 | 涉及报价、变更、签证、付款、扣款、赔付、结算、成本、利润等金额事项 | S2 校验 + 人工确认 + S3 追溯 |
| 责任确认 | 涉及责任主体、责任范围、责任金额、责任后果 | S2 校验 + 人工确认 + S3 追溯 |
| 客户确认 | 涉及客户对事实、交付、金额、整改、结算或承诺的确认 | S2 校验 + 人工确认 + S3 追溯 |
| 甲方确认 | 涉及甲方或甲方负责人确认 | S2 校验 + 人工确认 + S3 追溯 |
| 合同 / 签约 | 涉及合同、补充协议、签约文件、授权文件 | S2 校验 + 人工确认 + S3 追溯 |
| 签证 / 变更 | 涉及范围、材料、工期、价格、责任、交付变化 | S2 校验 + 人工确认 + S3 追溯 |
| 结算草单转正式 | 涉及草单输出转入正式结算确认 | S2 校验 + 人工确认 + S3 追溯 |
| 财务事实入链 | 涉及收款、付款、报销、开票、退款、扣款、赔付 | S2 校验 + 人工确认 + S3 追溯 |
| 对外展示 | 面向客户、甲方、供应商、班组或外部协作者展示内部内容 | 权限校验 + 脱敏 + 人工确认 + S3 追溯 |
| 导出 / 分享 | 涉及高敏资料、结算、责任、合同、对外展示包 | 权限校验 + 脱敏 + S3 追溯 |
| 权限变更 | 涉及授权、撤权、临时授权、外部授权、维护权限、审计权限 | 权限校验 + 人工确认 + S3 追溯 |
| 真源修订 | 涉及正式对象、正式事实、经归口审定后的正式规则、模板候选或正式依据修订 | S2 校验 + 人工确认 + S3 追溯 |
| 作废 / 回滚 / 恢复 | 涉及对象、事实、规则、模板、输出、归档内容 | S2 校验 + 人工确认 + S3 追溯 |
| 标准治理发布 | 涉及术语、字段、枚举、状态、权限、风险、校验、追溯等标准生效 | 影响检查 + 人工确认 + S3 追溯 |
| AI 输出用于高风险用途 | AI 输出被作为正式事实入链依据、正式事实入链依据、规则候选、模板候选、对外展示内容或高风险候选入链依据、对外展示内容或高风险候选入链依据 | S2 校验 + 人工复核 + S3 追溯 |
| 外部反馈采纳 | 外部反馈被采纳为事实候选、责任线索、结算线索或确认线索 | S2 校验 + 人工确认 + S3 追溯 |

AI 输出被采纳后的治理风险等级取决于采纳目的和使用范围：如被作为正式事实入链依据、规则候选、模板候选、对外展示内容或高风险候选入链依据、对外展示内容或高风险候选入链依据，按对应高风险事项处理；如仅作为内部参考、候选整理、辅助摘要或待补提示，按中风险处理。AI 输出默认候选，不因“被采纳”这一动作本身直接成为正式事实或正式结论。

高风险事项不得自动放行，不得由页面按钮、接口回执、模板输出、AI 输出或外部反馈直接确认。

## 十、阻断风险事项

出现以下情形时，应判定为阻断风险：

1. 主体身份无法确认且事项涉及金额、责任、对外展示或正式事实入链；
2. 项目归属无法确认且事项涉及项目事实、结算、交付或责任；
3. 来源缺失且事项要求正式入链；
4. 证据链断裂且事项涉及高风险事实；
5. 权限不足但系统尝试继续放行；
6. 页面动作试图绕过后端权限、校验或确认；
7. 接口载荷试图直写正式事实；
8. 外部反馈试图直接形成正式事实或正式确认；
9. AI 输出试图直接发布为正式事实、正式规则或正式决策；
10. 视图输出试图反写真源；
11. 模板输出试图生成正式事实；
12. 导出或分享内容超出权限范围；
13. 对外展示内容未脱敏或未确认；
14. 历史旧口径试图覆盖当前正式口径；
15. 字段、枚举、状态、权限或风险定义冲突且无法唯一判断；
16. 作废、回滚、恢复或真源修订缺少追溯；
17. 系统性异常可能造成真源污染、权限泄露或错误对外展示。

阻断风险应停止推进，并保留阻断原因、触发主体、触发对象、风险来源、影响范围和处理建议。

## 十一、对象资产层风险边界

对象资产层风险主要来自对象识别、对象合并、对象作废、主体混淆、资料可见、物资状态和组织范围错误。

对象资产层应重点识别以下风险：

1. 临时对象被写入正式对象资产；
2. 同一对象被重复创建；
3. 不同主体被错误合并；
4. 对象合并影响已入链事实引用；
5. 对象作废导致历史事实追溯断裂；
6. 资料原件被无权限查看；
7. 主体联系方式、身份信息、银行卡、税务信息等敏感内容未脱敏；
8. 物资成本、库存、损耗、赔付、追责信息泄露；
9. 组织范围被项目权限反向覆盖；
10. 外部主体获得内部对象详情。

对象合并、作废、恢复、敏感资料可见和主体身份修订默认按高风险处理。

## 十二、事实记录层风险边界

事实记录层风险主要来自事实入链、事实修订、事实作废、证据不足、主体不明、金额责任和外部确认。

事实记录层应重点识别以下风险：

1. 候选事实被展示为正式事实；
2. 来源缺失但事实进入正式链路；
3. 证据不足但事实进入正式链路；
4. 主体不明但形成责任或金额判断；
5. 时间冲突被静默覆盖；
6. 金额事实缺少确认；
7. 责任事实缺少确认；
8. 客户确认缺少确认主体或确认范围；
9. 甲方确认缺少甲方负责人或授权主体；
10. 结算草单被反向写成正式财务事实；
11. 施工完成确认被误写为客户/甲方正式验收；
12. 外部反馈被直接写入正式事实；
13. 事实修订、作废或回滚缺少版本和追溯。

涉及金额、责任、客户确认、甲方确认、结算、签证、变更、作废、回滚和正式入链的事实默认高风险。

## 十三、汇总视图层风险边界

汇总视图层风险主要来自视图输出误导、权限扩大、候选内容正式化、导出分享和对外展示。

汇总视图层应重点识别以下风险：

1. 候选清单被展示为正式结论；
2. 风险提示被展示为责任裁决；
3. 结算草单被展示为正式结算；
4. 视图统计被当成正式事实；
5. 看板标签被当成后端正式状态；
6. 对外展示包暴露内部成本、利润、责任推演或未确认事实；
7. 导出包超出主体可见范围；
8. 分享链接扩大权限；
9. 清单、台账、草单无法追溯来源事实；
10. 视图输出反写对象、事实或状态。

视图输出进入导出、分享或对外展示前，应按高风险输出处理。

## 十四、经验规则层风险边界

经验规则层风险主要来自经验候选、规则候选、模板候选、候选知识和 AI 归纳结果被过早正式化。

经验规则层应重点识别以下风险：

1. 单条复盘直接写成正式规则；
2. 候选知识被写成正式依据；
3. 规则候选被直接写成正式规则；
4. 模板候选被直接作为正式依据；
5. AI 归纳结果直接成为正式规则；
6. 无来源事实的经验被发布；
7. 适用范围不明的规则被复用；
8. 高风险金额、责任、结算、客户承诺、供应商争议、班组责任经验未经复核；
9. 旧经验覆盖当前正式事实；
10. 经验规则层内容反向改写真源。

规则候选、模板候选和候选知识如被用于高风险场景，默认高风险。高风险经验应至少经过来源校验、适用范围确认和人工复核；规则候选如需进一步治理，必须由对应归口承接。

## 十五、标准治理风险边界

标准治理风险主要来自术语、字段、枚举、状态、权限、风险、校验、追溯等标准项冲突或被下游反向定义。

标准治理应重点识别以下风险：

1. 字段反向新增事实类型；
2. 枚举反向定义业务规则；
3. 状态反向替代真实进展；
4. 权限被页面按钮反向定义；
5. 风险等级被页面标签反向定义；
6. 校验规则被接口成功反向绕过；
7. 追溯要求被模板输出省略；
8. 历史旧称反向覆盖当前标准术语；
9. 标准治理项发布未检查影响范围；
10. 标准项废弃或替代未保留兼容迁移规则。

标准治理项成为当前有效标准、废弃、替代或影响下游文件时，默认高风险。

## 十六、接口风险边界

接口风险主要来自外部输入、接口载荷、接口回执、异步回调、导出接口、分享接口和高风险动作接口。

接口风险应遵守以下规则：

1. 接口鉴权通过不等于业务权限通过；
2. 接口成功不等于事实成立；
3. 外部接口不得直写正式事实；
4. 外部回执不得直接成为客户确认、甲方确认、责任确认、金额确认或结算确认；
5. 接口载荷字段缺失不得默认补齐；
6. 接口载荷冲突不得静默覆盖；
7. 导出接口必须检查权限、脱敏、风险和追溯；
8. 分享接口必须检查分享对象、范围、期限、撤回和追溯；
9. 高风险接口动作必须进入人工确认或明确授权；
10. 接口异常可能造成真源污染、权限泄露或错误对外展示时，应熔断。

## 十七、页面风险边界

页面风险主要来自按钮误导、状态误导、候选内容误展示、权限错配、对外展示误用和用户误确认。

页面风险应遵守以下规则：

1. 页面可见不等于可操作；
2. 页面按钮可点击不等于操作放行；
3. 页面点击确认不等于正式确认；
4. 页面状态不等于后端正式状态；
5. 页面标签不等于风险等级；
6. 页面展示候选内容时必须标注候选状态；
7. 页面展示风险提示时不得写成责任裁决；
8. 页面导出和分享必须等待后端权限和风险判断；
9. 页面对外展示必须执行脱敏、裁剪和确认；
10. 页面不得为了交互便利绕过校验、确认、追溯和权限。

## 十八、AI 风险边界

AI 风险主要来自 AI 输出被误当成正式事实、正式规则、正式结论、正式责任、正式金额、正式决策或正式对外展示内容。

AI 风险应遵守以下规则：

1. AI 输出默认是候选内容；
2. AI 不得自动确认事实；
3. AI 不得自动确认责任；
4. AI 不得自动确认金额、付款、结算、扣款、赔付、客户确认或甲方确认；
5. AI 不得自动发布正式规则、确认模板候选或将候选内容作为正式依据；规则线索只能进入候选治理；
6. AI 不得自动放行高风险事项；
7. AI 不得读取超出权限范围的数据；
8. AI 不得绕过 S2 校验、人工确认和 S3 追溯；
9. AI 生成对外展示内容时，必须经过脱敏、权限、确认和追溯；
10. AI 失败点、误判点和暴露出的系统短板，应归入维护测试与模型接口管理区；
11. AI 输出被采纳为内部参考、候选整理、辅助摘要或待补提示时，按中风险处理；
12. AI 输出被作为正式事实入链依据、正式事实入链依据、规则候选、模板候选、对外展示内容或高风险候选入链依据、对外展示内容或高风险候选入链依据时，按对应高风险事项处理。

AI 输出被采纳为候选事实、候选知识、规则候选、模板候选或对外展示草稿时，应按采纳目的和使用范围确定风险等级，不得一律自动降级，也不得因 AI 置信较高而自动放行。

## 十九、外部协同风险边界

外部协同风险主要来自客户、甲方、甲方员工、供应商、班组、合作方、外部协作者和外部系统提交内容被误认为正式事实或正式确认。

外部协同风险应遵守以下规则：

1. 外部反馈不等于外部确认；
2. 外部提交内容默认进入候选、待补、外部反馈或确认线索；
3. 外部主体不得直接写入正式事实；
4. 甲方员工提交问题后，甲方负责人未确认前，不得视为正式问题流转；
5. 客户确认必须具备确认主体、确认范围、确认时间、确认依据和追溯记录；
6. 甲方确认必须具备甲方确认主体、确认范围、确认时间、确认依据和追溯记录；
7. 外部反馈涉及金额、责任、结算、整改、交付、验收、争议时，默认高风险；
8. 外部展示内容不得暴露内部成本、利润、责任推演、审批意见、争议过程和未确认事实；
9. 外部回执不得直接成为内部正式结论；
10. 外部协同异常应保留来源、主体、时间、内容和处理记录。

## 二十、风险等级处理规则

不同风险等级应按以下要求处理：

| 风险等级 | 权限要求 | 校验要求 | 确认要求 | 追溯要求 | 页面 / 接口要求 |
|---|---|---|---|---|---|
| `none` | 常规权限范围内处理 | 条件校验 | 无需确认 | 条件追溯 | 常规展示 |
| `low` | 仍须满足权限与可见性口径基本约束 | S2 基础校验 | 条件确认 | 条件追溯 | 不得误导为高风险放行 |
| `medium` | 按权限与可见性口径收紧可见、操作和输出范围 | S2 完整校验 | 条件确认 | 必须追溯 | 标注风险和处理状态 |
| `high` | 按高风险收紧原则授权，限制可见、操作、确认、导出、分享和对外展示范围 | S2 完整校验 | 必须人工确认 | 必须追溯 | 不得自动放行 |
| `blocking` | 禁止继续放行，仅允许授权处理主体进入阻断处理范围 | 必须阻断 | 必须人工处理 | 必须追溯 | 页面 / 接口必须阻断或熔断 |

高风险收紧原则的具体角色、范围、授权要求、可见边界、操作边界、确认边界、导出边界、分享边界和对外展示边界，由 `06_权限与可见性口径` 承接；本文只定义高风险事项必须收紧权限、不得自动放行、必须校验确认并追溯的原则。

风险等级提升时，应按更高等级处理。风险等级不得因用户角色较高、页面操作便利、接口成功、AI 置信较高或模板输出完整而自动降低。

## 二十一、风险与权限关系

风险与权限关系应遵守以下规则：

1. 风险等级越高，权限范围越应收紧；
2. 可见权限不等于高风险操作授权；
3. 操作权限不等于确认权限；
4. 维护权限不等于业务确认权限；
5. 审计权限不等于修改权限；
6. 外部可见权限不等于内部可见权限；
7. 高风险事项必须限制可见范围、操作范围、确认主体和输出范围；
8. 高风险状态变化不得授予低风险角色自动执行；
9. 高风险导出、分享和对外展示必须单独校验；
10. 权限不足时不得以中低风险方式降级放行。

## 二十二、风险与状态关系

风险与状态关系应遵守以下规则：

1. 风险等级不替代状态；
2. 状态不替代风险等级；
3. 候选状态叠加高风险时，不得展示为正式结论；
4. 待补状态叠加高风险时，应限制可见和操作范围；
5. 阻断状态叠加高风险时，不得继续推进；
6. 熔断状态叠加系统性风险时，应停止相关链路；
7. 正式状态叠加高风险修订时，应重新进入校验、确认和追溯；
8. 已导出状态不降低风险等级；
9. 已分享状态不降低风险等级；
10. 已归档状态不消除风险追溯要求。

## 二十三、风险与校验关系

风险与校验关系应遵守以下规则：

1. 风险等级应进入 S2 校验判断；
2. S2 校验应识别风险来源、风险等级、风险触发条件和风险处理要求；
3. 高风险事项不得跳过 S2 校验；
4. 阻断风险必须触发阻断或熔断；
5. 缺少风险等级时，不得自动按低风险处理；
6. 风险等级冲突时，应按更高等级处理；
7. 风险来源不明时，应进入待补或人工确认；
8. 风险校验结果必须可追溯；
9. 校验通过不等于风险消失；
10. 风险降低必须有依据、确认和追溯。

## 二十四、风险与追溯关系

以下风险事项必须 S3 追溯：

1. 风险等级生成；
2. 风险等级调整；
3. 高风险事项放行；
4. 阻断风险触发；
5. 风险降低；
6. 人工确认风险事项；
7. 高风险事项导出、分享、对外展示；
8. 高风险事实入链；
9. 高风险事实修订、作废、回滚；
10. 高风险规则、模板、知识发布；
11. AI 输出被采纳；
12. 外部反馈被采纳；
13. 权限变更；
14. 风险相关异常恢复。

风险追溯至少应记录风险等级、风险来源、触发字段、触发主体、影响对象、处理动作、确认主体、处理时间、证据引用和版本依据。

## 二十五、风险降级规则

风险降级必须谨慎。以下情形不得自动降级：

1. 高风险事项仅因页面展示为普通事项而降级；
2. 高风险事项仅因接口调用成功而降级；
3. 高风险事项仅因 AI 判断置信较高而降级；
4. 高风险事项仅因用户角色较高而降级；
5. 高风险事项仅因缺少金额字段而降级；
6. 高风险事项仅因证据缺失而降级；
7. 高风险事项仅因尚未对外展示而降级；
8. 阻断风险仅因用户要求继续而降级；
9. 外部反馈仅因提交主体可信而降级；
10. 历史旧口径仅因曾被使用而降级。

风险降级必须具备明确依据、处理主体、确认记录和追溯记录。

## 二十六、风险新增、修订与废弃规则

风险口径新增、修订与废弃应遵守以下规则：

1. 新增风险类型前，必须判断是否可由现有风险等级和风险来源承接；
2. 新增高风险事项必须说明触发条件、权限要求、校验要求、确认要求和追溯要求；
3. 新增风险口径不得突破系统边界、系统架构、标准治理总则、字段规范总表、状态口径总表和权限与可见性口径；
4. 修订风险口径必须同步检查校验规则、追溯与版本、脱敏与外部展示、接口边界与集成约束、前后端协同边界与页面承接和验证与验收规则；
5. 废弃风险表达应保留兼容识别和迁移规则；
6. 页面标签、接口错误码、数据库字段、AI 输出和外部反馈不得直接升格为正式风险口径；
7. 风险口径调整涉及文件或压缩包修改时，应同步升版本号。

## 二十七、边界判断

本文成立，应满足以下判断口径：

1. 能说明风险分级口径只定义风险判断，不定义完整风控系统、专业法务结论、专业财税结论、安全制度全集、责任终局裁决或诉讼判断；
2. 能区分无风险、低风险、中风险、高风险和阻断风险；
3. 能说明低风险仍须满足权限与可见性口径基本约束，不得被理解为无需权限判断；
4. 能说明金额、责任、结算、合同、签证、付款、扣款、赔付、客户确认、甲方确认、对外展示、权限变更、真源修订、规则发布、AI 输出采纳和外部反馈采纳等事项默认高风险；
5. 能说明 AI 输出被采纳后的治理风险等级取决于采纳目的和使用范围，内部参考或候选整理按中风险处理，正式事实入链依据、正式事实入链依据、规则候选、模板候选、对外展示内容或高风险候选入链依据、对外展示或高风险候选入链依据按高风险处理；
6. 能说明高风险收紧原则的具体角色、范围和授权要求由 `06_权限与可见性口径` 承接，本文不定义角色全集或权限矩阵；
7. 能说明阻断风险必须阻断或熔断；
8. 能说明风险等级不替代事实、权限、状态、校验、确认和追溯；
9. 能说明页面标签、接口回执、模板输出、导出包、分享包、外部反馈和 AI 输出不得反向定义正式风险等级；
10. 能说明高风险事项必须接受权限收紧、S2 校验、人工确认和 S3 追溯；
11. 能说明外部反馈不等于外部确认，AI 输出不等于风险结论；
12. 能说明风险降级必须有依据、确认和追溯；
13. 能为校验规则口径、追溯与版本口径、脱敏与外部展示口径、接口边界与集成约束、前后端协同边界与页面承接和验证与验收规则提供风险依据；
14. 不写完整风险控制系统、权限矩阵、状态流转图、接口 schema、页面组件、数据库表结构、代码实现、测试脚本或实施计划。
