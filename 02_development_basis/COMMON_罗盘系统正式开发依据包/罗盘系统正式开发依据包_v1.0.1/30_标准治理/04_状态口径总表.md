# 04_状态口径总表

## 一、文件定位

本文是 `30_标准治理` 下的状态口径总表文件，用于统一罗盘系统正式开发依据包中对象、事实、候选内容、校验、确认、输出、回流、经验规则、标准治理、权限展示和文档治理相关状态的命名、含义、适用范围、状态边界、终态判断、异常态判断、校验要求、人工确认要求和追溯要求。

状态口径总表回答“某个对象、事实、候选、输出、反馈、校验结果或对外展示内容当前处于什么状态，该状态属于哪个状态组，是否可继续推进，是否需要 S2 校验，是否需要人工确认，是否需要 S3 追溯，是否属于终态或异常态”。

本文只定义状态口径和状态值边界，不替代字段规范总表、枚举总表、权限与可见性口径、风险分级口径、校验规则口径、追溯与版本口径、接口 schema、页面组件、数据库表结构或代码实现。

本文不是完整状态机文件，不定义所有状态流转路径，不定义数据库状态字段，不定义前端展示样式，不定义接口返回码。后续如需定义具体状态流转、触发条件、权限条件、页面提示、接口错误码和测试断言，应由对应下游文件承接。

## 二、状态口径总表职责

状态口径总表承担以下职责：

1. 定义全系统共享状态组；
2. 定义对象资产层状态；
3. 定义事实记录层状态；
4. 定义候选内容状态；
5. 定义 S2 校验状态；
6. 定义人工确认状态；
7. 定义汇总视图与输出状态；
8. 定义 AI辅助与候选输出口径状态；
9. 定义 L7 反馈回流状态；
10. 定义经验规则层状态；
11. 定义标准治理状态；
12. 定义权限展示与对外展示相关状态；
13. 定义文档治理状态；
14. 定义终态、异常态、挂起态、待补态和禁止静默覆盖的状态边界；
15. 规定哪些状态变更必须经过 S2 校验；
16. 规定哪些状态变更必须人工确认；
17. 规定哪些状态变更必须 S3 追溯；
18. 为字段规范总表中的 `status_ref` 提供正式引用依据；
19. 防止页面状态、接口回执、模板输出、AI 输出、外部反馈或数据库字段反向定义正式状态。

状态口径总表不负责新增对象类型、事实类型、字段、枚举、权限、风险等级、接口、页面、数据库表或代码逻辑。

## 三、上位约束

状态口径必须服从以下上位约束：

1. 状态是对对象、事实、候选内容、输出或运行处理阶段的受控描述，不等于事实本体；
2. 状态不得替代对象资产、事实记录、汇总视图或经验规则层的业务归口；
3. 状态不得替代真实业务进展；
4. 状态不得替代人工确认；
5. 状态不得替代权限判断；
6. 状态不得替代风险分级；
7. 状态不得替代校验规则；
8. 状态不得替代审计追溯；
9. 页面状态、接口回执、模板输出、AI 输出、导出包、分享包和外部反馈不得反向成为正式状态；
10. 状态变更不得绕过 L1、S2、人工确认、L2 或 S3 追溯链路；
11. 任何状态都不得把候选内容直接升格为正式事实；
12. 任何状态都不得把汇总视图输出反写为事实；
13. 任何状态都不得把经验规则层内容写成事实真源；
14. 历史资料中的状态表达只能作为兼容识别和迁移线索，不得直接升格为当前正式状态。

## 四、状态定义权规则

状态定义权遵守以下规则：

1. 本文负责定义标准状态组、状态值、状态含义、适用范围和状态边界；
2. 字段规范总表负责定义哪些字段引用状态口径；
3. 枚举总表负责定义非状态类受控分类值，状态值不得混入枚举总表替代本文；
4. 权限与可见性口径负责定义状态对应的可见、可改、可确认、可导出、可分享和对外展示边界；
5. 风险分级口径负责定义高风险状态触发、风险处理和人工确认要求；
6. 校验规则口径负责定义状态变更前的校验条件、阻断条件、待补条件和驳回条件；
7. 追溯与版本口径负责定义状态变更留痕、快照、版本、回滚和审计要求；
8. 接口边界与集成约束负责定义状态在接口载荷和接口回执中的传递方式；
9. 前后端协同边界与页面承接负责定义状态在页面中的展示、提示、按钮可用性和用户补全引导；
10. 验证与验收规则文件负责验证状态引用、状态边界、状态变更、异常态和终态是否符合本文。

## 五、状态命名规则

状态命名应遵守以下规则：

1. 状态组名称使用英文小写下划线格式；
2. 状态值使用英文小写下划线格式；
3. 状态中文名称应稳定、清晰、可判断；
4. 状态值不得使用中文、拼音缩写、页面文案、接口错误码、数据库临时值或自然语言句子；
5. 同一状态值在同一状态组内只能有一个含义；
6. 不同状态组中含义不同的状态值不得混用；
7. 状态值不得直接使用枚举分类值替代；
8. 状态值不得表达字段缺失原因、风险等级原因或权限拒绝原因；具体原因由校验、风险、权限或追溯文件承接；
9. 状态组名称应能说明状态归属，例如 `object_lifecycle_status`、`fact_record_status`、`validation_status`；
10. 状态值中不得混入非当前标准表达；
11. 正文术语、中文名称和说明文字中的系统层级或治理闸门名称，应写作 `L0`、`L1`、`S2`、`L2`、`L3`、`L4`、`L5`、`L6`、`L7`；状态字段或状态组名中如出现层级标识，按字段规范写作小写形式；
12. 状态不得因页面、接口、数据库或代码实现便利而绕过标准命名规则。

| `object_usage_status` | 对象使用 / 占用状态 | 物资资产、资料资产、资源池对象 | 是 | 对象资产、物资流转记录、视图 |
| `fact_record_status` | 事实记录状态 | 事实记录层 | 是 | 事实记录、校验、追溯 |

状态组只用于说明状态归属，不替代字段规范总表中的字段定义。

## 七、对象生命周期状态

对象生命周期状态用于描述对象资产本体是否处于候选、有效、停用、作废、归档等生命周期阶段。对象生命周期状态不得承接对象发生过程，不得替代事实记录。

| 状态值 | 中文名称 | 含义 | 是否终态 | 是否异常态 | S2 校验 | 人工确认 | S3 追溯 |
|---|---|---|---|---|---|---|---|
| `candidate` | 候选 | 对象尚未完成识别、去重、归属或确认 | 否 | 否 | 是 | 条件需要 | 是 |
| `active` | 有效 | 对象已完成必要识别并可被正式引用 | 否 | 否 | 是 | 条件需要 | 是 |
| `pending_completion` | 待补 | 对象关键锚点不足，需补充信息 | 否 | 是 | 是 | 条件需要 | 是 |
| `suspended` | 挂起 | 对象存在冲突、权限不足或高风险待确认，暂停使用 | 否 | 是 | 是 | 是 | 是 |
| `merged` | 已合并 | 对象经治理后并入其他对象 | 是 | 否 | 是 | 是 | 是 |
| `disabled` | 停用 | 对象暂不使用，但保留历史引用 | 否 | 否 | 是 | 条件需要 | 是 |
| `voided` | 已作废 | 对象被判定不再有效或错误创建 | 是 | 否 | 是 | 是 | 是 |
| `archived` | 已归档 | 对象进入归档保存状态 | 是 | 否 | 是 | 条件需要 | 是 |

对象合并、作废、停用或归档不得自动改写已入链事实记录。已入链事实保留原对象引用，引用修订应进入治理流程。

## 八、对象物理 / 质量状态

对象物理 / 质量状态用于表达物资、资料或其他需要状况描述的对象当前可用性、质量、完整性或物理状况。该状态不得替代维修、检测、盘点、资料补齐、资料退回等事实记录。

| 状态值 | 中文名称 | 含义 | 是否终态 | 是否异常态 | S2 校验 | 人工确认 | S3 追溯 |
|---|---|---|---|---|---|---|---|
| `normal` | 正常 | 对象状况满足当前使用要求 | 否 | 否 | 条件需要 | 否 | 是 |
| `incomplete` | 不完整 | 对象资料、属性、结构或组件不完整 | 否 | 是 | 是 | 条件需要 | 是 |
| `damaged` | 损坏 | 对象存在损坏或质量问题 | 否 | 是 | 是 | 条件需要 | 是 |
| `pending_inspection` | 待检 | 对象需要检测、复核或确认状况 | 否 | 是 | 是 | 条件需要 | 是 |
| `under_repair` | 维修中 | 对象处于维修或处理过程 | 否 | 否 | 是 | 条件需要 | 是 |
| `unavailable` | 不可用 | 对象当前不可用于正常业务 | 否 | 是 | 是 | 条件需要 | 是 |
| `scrapped` | 已报废 | 对象经事实记录或确认链路判定报废 | 是 | 否 | 是 | 是 | 是 |

对象物理 / 质量状态必须与对象生命周期状态并行存在，不得压缩为一个万能 `status` 字段。状态变化不得替代维修、检测、盘点、资料补齐或报废处理事实。

## 九、对象使用 / 占用状态

对象使用 / 占用状态用于描述物资、资料、工具、资源池等对象是否被占用、借出、在库、在项目中或处于转移过程。该状态不得替代物资流转记录、资料记录或项目事实。

| 状态值 | 中文名称 | 含义 | 是否终态 | 是否异常态 | S2 校验 | 人工确认 | S3 追溯 |
|---|---|---|---|---|---|---|---|
| `available` | 可用 | 对象当前可被业务使用 | 否 | 否 | 条件需要 | 否 | 是 |
| `reserved` | 已预留 | 对象已为某业务场景预留，但尚未正式流转 | 否 | 否 | 是 | 条件需要 | 是 |
| `in_stock` | 在库 | 物资或资料处于库存、资料库或受控存放位置 | 否 | 否 | 是 | 条件需要 | 是 |
| `project_occupied` | 项目占用中 | 对象当前被项目占用或引用 | 否 | 否 | 是 | 条件需要 | 是 |
| `borrowed` | 借出 | 对象处于借出状态 | 否 | 否 | 是 | 条件需要 | 是 |
| `in_transfer` | 流转中 | 对象正在跨仓库、项目、主体或位置流转 | 否 | 否 | 是 | 条件需要 | 是 |
| `lost` | 遗失 | 对象疑似或确认遗失 | 否 | 是 | 是 | 是 | 是 |
| `released` | 已释放 | 对象占用解除，可回到可用或在库状态 | 否 | 否 | 是 | 条件需要 | 是 |

对象使用 / 占用状态变化必须能回指来源事实。`project_occupied` 不等于项目领用事实成立，`released` 不等于结算或责任解除成立。

## 十、事实记录状态

事实记录状态用于描述候选事实、待补事实、已确认事实、正式入链事实、修订事实、作废事实等处理阶段。事实状态不得替代事实内容，不得替代来源证据和人工确认。

| 状态值 | 中文名称 | 含义 | 是否终态 | 是否异常态 | S2 校验 | 人工确认 | S3 追溯 |
|---|---|---|---|---|---|---|---|
| `draft` | 草稿 | 事实内容尚未完成基础录入或整理 | 否 | 否 | 否 | 否 | 条件需要 |
| `candidate` | 候选 | 已形成候选事实，但未完成校验、确认或入链 | 否 | 否 | 是 | 条件需要 | 是 |
| `pending_completion` | 待补 | 关键字段、证据、主体、项目或时间不完整 | 否 | 是 | 是 | 条件需要 | 是 |
| `under_validation` | 校验中 | 事实正在接受规则校验、冲突校验或风险校验 | 否 | 否 | 是 | 否 | 是 |
| `pending_confirmation` | 待确认 | 事实需要人工确认、客户确认、甲方确认或授权确认 | 否 | 是 | 是 | 是 | 是 |
| `confirmed` | 已确认 | 事实已完成必要确认，但未必已正式入链 | 否 | 否 | 是 | 是 | 是 |
| `official` | 正式 | 事实已完成治理并进入正式事实链路 | 否 | 否 | 是 | 条件需要 | 是 |
| `suspended` | 挂起 | 事实因冲突、缺证、权限不足或风险未解而暂停推进 | 否 | 是 | 是 | 条件需要 | 是 |
| `rejected` | 已驳回 | 事实候选不满足准入或校验要求 | 是 | 是 | 是 | 条件需要 | 是 |
| `voided` | 已作废 | 已存在事实被受控作废，保留追溯 | 是 | 否 | 是 | 是 | 是 |
| `revised` | 已修订 | 事实经过受控修订并保留版本关系 | 否 | 否 | 是 | 条件需要 | 是 |
| `archived` | 已归档 | 事实不再活跃但保留为历史记录 | 是 | 否 | 是 | 条件需要 | 是 |

`confirmed` 不等于 `official`。客户、甲方、内部主体或授权主体完成确认后，仍需满足来源、证据、权限、状态和追溯要求，才能进入正式事实链路。

## 十一、候选内容状态

候选内容状态用于描述候选对象、候选事实、候选字段、候选输出、候选知识、候选规则、候选模板等尚未正式化内容的处理状态。

| 状态值 | 中文名称 | 含义 | 是否终态 | 是否异常态 | S2 校验 | 人工确认 | S3 追溯 |
|---|---|---|---|---|---|---|---|
| `new_candidate` | 新候选 | 初步生成但未处理的候选内容 | 否 | 否 | 条件需要 | 否 | 条件需要 |
| `pending_completion` | 待补 | 候选内容缺少必要锚点、来源、证据或范围 | 否 | 是 | 是 | 条件需要 | 是 |
| `under_review` | 复核中 | 候选内容正在人工或规则复核 | 否 | 否 | 是 | 条件需要 | 是 |

| `pending_confirmation` | 待确认 | 外部内容需内部或外部授权主体确认 | 否 | 是 | 是 | 是 | 是 |
| `accepted_as_candidate` | 已采纳为候选 | 外部内容被采纳为候选事实、候选问题或候选反馈 | 否 | 否 | 是 | 条件需要 | 是 |
| `rejected` | 已驳回 | 外部内容被驳回 | 是 | 是 | 是 | 条件需要 | 是 |
| `blocked` | 已阻断 | 外部内容因权限、风险或来源问题被阻断 | 是 | 是 | 是 | 是 | 是 |

外部回执不得直接成为客户确认、甲方确认、正式责任、正式结算或正式事实。

## 二十三、归档状态

归档状态用于对象、事实、输出、文档、规则、模板、反馈等内容的归档处理。归档不等于删除，也不等于作废。

| 状态值 | 中文名称 | 含义 | 是否终态 | 是否异常态 | S2 校验 | 人工确认 | S3 追溯 |
|---|---|---|---|---|---|---|---|
| `not_archived` | 未归档 | 内容仍处于活跃或可处理状态 | 否 | 否 | 否 | 否 | 条件需要 |
| `archive_pending` | 待归档 | 内容已满足归档条件，等待归档处理 | 否 | 否 | 条件需要 | 条件需要 | 是 |
| `archived` | 已归档 | 内容已归档保存 | 是 | 否 | 条件需要 | 条件需要 | 是 |
| `archive_blocked` | 归档阻断 | 因追溯、权限、冲突或状态不满足不得归档 | 是 | 是 | 是 | 条件需要 | 是 |
| `recovery_pending` | 待恢复 | 已归档内容已触发恢复请求，等待校验、确认和归口状态接管 | 否 | 否 | 是 | 条件需要 | 是 |

`recovery_pending` 只表示归档内容正在等待恢复处理，不表示已经恢复为可处理业务状态。恢复完成后，应由对应业务状态组接管，例如对象回到对象生命周期状态，事实回到事实记录状态，输出回到视图输出状态，规则或模板回到经验规则层或标准治理状态。归档状态不得长期保留“已恢复”作为稳定状态值。

归档状态不得破坏原始追溯、事实链、版本链和审计记录。

## 二十四、终态、异常态与可继续推进判断

终态用于表示当前状态在该状态组内不应继续自动推进。异常态用于表示当前状态需要补充、复核、阻断、熔断、人工确认或其他治理动作。

| 判断项 | 判定规则 |
|---|---|
| 终态 | `rejected`、`blocked`、`fused`、`voided`、`archived`、`deprecated`、`superseded`、`scrapped`、`expired`、`cancelled` 等状态通常为终态 |
| 非终态 | `candidate`、`pending_completion`、`under_review`、`pending_confirmation`、`processing`、`routed`、`recovery_pending`、`exported` 等状态通常仍可继续推进或仅表示一次动作记录 |
| 异常态 | `pending_completion`、`suspended`、`rejected`、`blocked`、`fused`、`failed`、`pending_identity`、`pending_scope` 等状态通常属于异常态 |
| 可继续推进 | 必须具备归口、权限、来源、校验、必要人工确认和追溯条件 |
| 不得自动推进 | 涉及高风险、缺证据、缺主体、缺项目、权限不足、状态冲突、外部反馈未确认、AI 输出未复核时不得自动推进 |

同一个状态值是否为终态，应结合状态组判断。不得只凭状态值文字脱离状态组解释。

## 二十五、状态变更校验要求

以下状态变更必须经过 S2 校验：

1. 候选内容转正式事实；
2. 对象从候选转有效；
3. 对象合并、作废、停用、恢复；
4. 事实从候选、待补、待确认转正式；
5. 事实修订、作废、归档；
6. 输出从候选输出转正式输出；
7. 输出进入导出、分享、对外展示状态；
8. AI 输出被采纳为候选事实、候选知识、规则候选或模板候选；
9. 反馈回流转入候选事实、问题风险候选、责任确认线索、规则候选或模板候选；
10. 经验规则层候选内容完成复核或分流处理；
11. 标准治理内容从候选转当前有效；
12. 权限展示状态从内部可见转对外可见；
13. 外部回执从已接收转确认、采纳或候选入链；
14. 任一异常态转非异常态；
15. 任一终态恢复为可处理状态。

S2 校验只判断是否满足规则条件，不替代人工确认、权限裁决、风险分级和 S3 追溯。

## 二十六、人工确认要求

以下状态变更必须人工确认或具备明确授权确认：

1. 高风险事实进入正式状态；
2. 金额、付款、结算、扣款、赔付、报价、签证相关事实进入正式状态；
3. 责任候选进入正式责任确认；
4. 客户确认、甲方确认、授权确认进入已确认状态；
5. 对外展示状态从受限、需脱敏或待确认转为允许对外展示；
6. 对象合并、作废、恢复；
7. 事实作废、修订、回滚；
8. 规则候选、模板候选和经验规则层候选内容发生复核、驳回、替代或归档处理；
9. 标准治理项成为当前有效标准；
10. AI 输出被采纳为候选事实、规则候选、模板候选或候选知识；
11. 外部反馈被采纳为事实候选、责任确认线索、结算线索或客户 / 甲方确认线索；
12. 系统性异常熔断后恢复处理；
13. 归档内容恢复为可处理状态。

人工确认必须记录确认主体、确认时间、确认范围、来源证据和审计追溯，不得由页面按钮、接口回执或 AI 输出自动替代。

## 二十七、S3 追溯要求

以下状态变化必须 S3 追溯：

1. 任何进入正式对象、正式事实、正式输出、模板候选或经验规则层候选内容复核、弃用、替代、归档处理的状态变化；
2. 任何从候选、待补、待确认、挂起、驳回、阻断、熔断转入下一环节的状态变化；
3. 任何对象合并、作废、停用、恢复、归档；
4. 任何事实修订、作废、恢复、归档、回滚；
5. 任何高风险状态变化；
6. 任何人工确认、客户确认、甲方确认、授权确认；
7. 任何对外展示、导出、分享；
8. 任何 AI 输出被采纳、驳回或进入改进记录；
9. 任何标准治理项生效、弃用或替代；
10. 任何经验规则层候选内容复核、弃用或替代；
11. 任何外部反馈采纳、驳回、阻断；
12. 任何状态异常恢复或终态恢复。

追溯记录至少应保留状态变更前值、变更后值、变更主体、变更时间、变更来源、变更原因、影响对象、关联证据、权限依据和版本依据。

## 二十八、状态与字段引用规则

字段规范总表中的状态字段应通过 `status_ref` 引用本文状态组。引用规则如下：

| 字段名 | 状态组 | 使用说明 |
|---|---|---|
| `object_asset_status` | `object_lifecycle_status` | 对象生命周期状态 |
| `fact_status` | `fact_record_status` | 事实记录状态 |
| `validation_status` | `validation_status` | 校验状态 |
| `output_status` | `view_output_status` | 视图或模板输出状态 |
| `candidate_governance_status` | `experience_candidate_status` | 经验规则层轻量候选治理状态 |
| `standard_status` | `standard_governance_status` | 标准治理状态 |
| `risk_level` | 由风险分级口径承接 | 风险等级不是普通状态组，本文只承接状态化表达边界 |
| `feedback_processing_status` | `feedback_status` | 反馈处理状态 |
| `confirmation_status` | `confirmation_status` | 确认状态 |
| `visibility_status` | `visibility_status` | 可见性状态 |
| `external_sync_status` | `external_sync_status` | 外部协同与回执状态 |
| `runtime_task_status` | `runtime_task_status` | 运行任务状态 |
| `archive_status` | `archive_status` | 归档状态 |

字段不得引用不存在的状态组。字段如需新增状态组，必须先修订本文，不得在字段规范、接口 schema、页面组件或代码中自行新增。

## 二十九、状态与枚举边界

状态与枚举必须区分：

1. 枚举用于表达受控分类；
2. 状态用于表达生命周期、处理阶段、校验结果、确认结果、输出阶段、治理阶段或可见阶段；
3. 事实类型、对象类型、资料类型、视图类型、来源类型、证据类型属于枚举，不属于状态；
4. 事实是否候选、是否正式、是否待补、是否作废属于状态，不属于枚举；
5. 状态不得混入枚举总表替代；
6. 枚举不得承担状态流转；
7. 状态值不得定义业务归口；
8. 枚举值不得定义处理阶段；
9. 字段引用状态时使用 `status_ref`；
10. 字段引用枚举时使用 `enum_ref`。

## 三十、状态与页面、接口、模板、AI 的关系

状态被页面、接口、模板和 AI 承接时，应遵守以下规则：

1. 页面可以展示状态，但不得自行生成正式状态；
2. 页面按钮可触发状态变更请求，但不得直接完成正式状态变更；
3. 页面本地状态不得反向成为后端状态；
4. 接口可以传递状态，但不得用接口回执替代业务状态；
5. 接口成功不等于状态变更成功；
6. 模板可以读取状态生成清单、台账、草单和报告，但不得反写状态；
7. 导出包、分享包和对外展示包中的状态说明不得回写正式状态；
8. AI 可以辅助识别状态候选或提示状态缺口，但不得自动设置正式状态；
9. 外部反馈可以生成状态变更候选，但不得直接改变正式状态；
10. 测试样例不得反向新增状态值。

## 三十一、状态冲突与阻断规则

出现以下情形时，应阻断状态进入正式链路：

1. 状态组不存在；
2. 状态值不存在；
3. 状态值与状态组不匹配；
4. 状态字段未通过 `status_ref` 指向本文；
5. 状态变化绕过 S2 校验；
6. 高风险状态变化缺少人工确认；
7. 状态变化缺少 S3 追溯；
8. 页面状态反向修改后端状态；
9. 接口回执反向修改业务状态；
10. AI 输出反向修改正式状态；
11. 视图输出反向修改事实状态；
12. 模板输出反向修改事实状态；
13. 状态变化导致候选内容直接成为正式事实；
14. 状态变化导致输出内容反写真源；
15. 状态变化导致经验规则层内容覆盖事实记录；
16. 状态值被当成业务事实、权限结论、风险裁决或责任裁决；
17. 终态被静默恢复；
18. 异常态被静默清除；
19. 作废、归档、合并、弃用、替代等状态缺少原因和影响范围；
20. 状态使用非当前标准表达、历史状态或外部系统状态值。

## 三十二、状态新增、修订与弃用规则

状态新增、修订与弃用应遵守以下规则：

1. 新增状态组前，必须判断是否可由现有状态组承接；
2. 新增状态值前，必须判断是否可由现有状态值承接；
3. 新增状态必须说明状态组、状态值、中文名称、含义、适用范围、是否终态、是否异常态、S2 校验要求、人工确认要求和 S3 追溯要求；
4. 新增状态不得突破顶层定义、系统架构、标准治理总则、字段规范总表和业务数据体系总则；
5. 新增状态不得新增未被资料支撑的对象类型、事实类型、视图类型、经验规则类型、权限类型或接口能力；
6. 修订状态必须说明影响范围，并同步检查字段规范、枚举总表、权限与可见性口径、风险分级口径、校验规则口径、追溯与版本口径、接口边界与集成约束、前后端协同边界与页面承接和验证与验收规则；
7. 弃用状态应保留兼容识别和迁移规则，但不得继续作为新写正式状态使用；
8. 历史状态、外部状态、页面状态、接口状态、数据库状态和测试样例状态不得直接升格为正式状态；
9. 状态调整涉及文件或压缩包修改时，应同步升版本号；
10. 状态调整不得破坏已有正式事实、正式对象、正式输出、模板候选和经验规则层候选内容的来源与追溯记录。

## 三十三、边界判断

本文成立，应满足以下判断口径：

1. 能说明状态口径总表只定义状态口径，不定义完整状态机、权限矩阵、风险等级、校验规则、接口 schema、页面组件、数据库表结构、代码实现或测试脚本；
2. 能区分状态与枚举、字段、权限、风险、校验、追溯和事实本体；
3. 能为字段规范总表中的 `status_ref` 提供正式引用依据；
4. 能定义对象生命周期状态、对象物理 / 质量状态、对象使用 / 占用状态、事实记录状态、候选内容状态、S2 校验状态、人工确认状态、输出状态、AI 输出状态、反馈回流状态、经验规则层状态、标准治理状态、权限展示状态、文档文件状态、运行任务状态、外部协同状态和归档状态；
5. 能说明 `exported` 只表示一次导出操作完成，不改变输出内容本身状态，也不使输出内容进入不可再次导出的终态；
6. 能说明 `recovery_pending` 只表示归档内容待恢复，恢复完成后由对应业务状态组接管；
7. 能说明哪些状态通常属于终态、异常态和可继续推进状态；
8. 能说明哪些状态变化必须 S2 校验；
9. 能说明哪些状态变化必须人工确认；
10. 能说明哪些状态变化必须 S3 追溯；
11. 能说明页面状态、接口回执、模板输出、导出包、分享包、外部反馈和 AI 输出不得反向定义正式状态；
12. 能说明状态不得替代事实成立、权限判断、风险分级、人工确认和审计追溯；
13. 能说明物资、资料等对象可存在多维状态，且多维状态不得压缩为一个万能状态字段；
14. 能为权限与可见性口径、风险分级口径、校验规则口径、追溯与版本口径、接口边界与集成约束、前后端协同边界与页面承接和验证与验收规则提供状态依据；
15. 不写完整状态机、状态流转图、权限矩阵、风险等级全集、接口 schema、页面组件、数据库表结构、代码实现、测试脚本或实施计划。
