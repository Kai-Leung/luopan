# 09_追溯与版本口径

## 一、文件定位

本文是 `30_标准治理` 下的追溯与版本口径文件，用于统一罗盘系统中正式对象、正式事实、正式状态、候选转正、视图输出、经验规则、标准治理、接口调用、页面动作、外部反馈、AI 输出采纳、导出分享、对外展示、作废、回滚、恢复、归档、对外发布和高风险动作的追溯、版本、快照、日志、审计和证据链判断口径。

本文回答“哪些事项必须留痕、哪些事项必须形成版本、哪些事项必须产生成对快照、哪些事项必须进入审计、哪些事项不得原地覆盖、哪些事项必须保留双时间戳、哪些事项必须能回查、哪些事项允许回滚以及哪些事项不得回滚”。

本文只定义追溯与版本口径，不替代字段规范总表、状态口径总表、权限与可见性口径、风险分级口径、校验规则口径、接口 schema、页面组件、数据库表结构、代码实现、测试脚本、审批制度或完整审计平台。

## 二、追溯与版本口径职责

追溯与版本口径承担以下职责：

1. 定义追溯对象；
2. 定义版本化范围；
3. 定义版本单元；
4. 定义版本身份字段；
5. 定义快照触发条件；
6. 定义操作日志范围；
7. 定义审计记录范围；
8. 定义回滚成立条件；
9. 定义回滚禁止项；
10. 定义证据链与 `payload_hash` 关系；
11. 定义双时间戳口径；
12. 定义高风险动作、阻断、熔断和 critical 事件的增强追溯要求；
13. 定义对象资产层、事实记录层、汇总视图层、经验规则层和标准治理的追溯边界；
14. 定义接口、页面、外部反馈、AI 输出、导出分享和对外展示的追溯边界；
15. 为接口边界与集成约束、前后端协同边界与页面承接、验证与验收规则和后续系统业务运行规则提供追溯依据。

本文不负责定义完整字段全集、状态全集、权限矩阵、风险控制系统、接口协议、数据库表结构、代码实现、测试脚本或运维审计平台。

## 三、上位约束

追溯与版本必须服从以下上位约束：

1. 正式链路中的关键动作必须可追溯；
2. 正式对象不得无痕覆盖；
3. 正式事实不得无痕修改；
4. 正式状态不得静默翻转；
5. 其他文件如需参考经验规则层候选内容，只能作为候选提示或待核验材料使用，并应保留来源、适用范围、风险提示和追溯要求；该参考不形成独立对象、状态、版本链、发布链或正式依据。
6. 高风险动作不得缺少审计记录；
7. 回滚不得删除历史；
8. 作废不得破坏证据链；
9. 归档不得等于删除；
10. 视图输出不得反写真源；
11. 页面动作不得替代追溯；
12. 接口回执不得替代追溯；
13. AI 输出不得替代追溯；
14. 外部反馈不得绕过追溯；
15. 单一时间字段不得替代双时间戳；
16. 只保存当前状态不等于完成追溯；
17. 只保存日志不等于完成审计；
18. 只保存摘要不等于完成快照。

## 四、追溯定义权规则

追溯定义权遵守以下规则：

1. 本文负责定义追溯、版本、快照、日志、审计、回滚、证据链和双时间戳的标准口径；
2. 字段规范总表负责定义追溯相关字段的命名、类型、引用和必填边界；
3. 状态口径总表负责定义作废、回滚、恢复、归档、驳回、替代等状态口径；
4. 权限与可见性口径负责定义谁能查看、触发、确认、导出、分享和对外展示追溯内容；
5. 风险分级口径负责定义哪些事项必须增强追溯；
6. 校验规则口径负责定义何时因缺少追溯而阻断；
7. 接口边界与集成约束负责定义追溯字段在接口载荷和回执中的传递要求；
8. 前后端协同边界与页面承接负责定义追溯信息在页面中的可见、提示和查看边界；
9. 验证与验收规则负责验证追溯链、版本链、快照、日志和审计记录是否成立；
10. 下游文件不得反向减少本文规定的追溯和版本要求。

## 五、核心定义

| 概念 | 定义 | 边界 |
|---|---|---|
| 追溯 | 对事项来源、过程、动作、状态、版本、证据、主体和时间的可回查记录 | 不等于页面展示，不等于操作成功提示 |
| 版本 | 对正式对象、正式事实、标准治理文件、对外输出封包或回退动作的一次可识别正式变更记录；规则候选、模板候选仅保留候选线索和处理记录 | 不得跳号，不得重用，不得无父链 |
| 快照 | 对关键节点前后状态、对外输出封包状态、回滚状态或审计状态的内容证据 | 展示摘要、日志备注、口头说明不得替代快照 |
| 操作日志 | 对一次动作如何发生、由谁触发、作用于什么对象、结果如何的过程记录 | 操作日志不等于审计记录 |
| 审计记录 | 对高风险、异常、阻断、熔断、回滚、对外展示等关键事件的治理留痕 | 审计记录必须能解释原因、依据和结果 |
| 回滚 | 对已进入正式链路内容的受控纠偏动作 | 回滚必须形成新版本，不得删除历史 |
| 证据链 | 连接原始输入、资料资产、资料记录、候选内容、正式事实、汇总视图、输出、审计和回滚的引用关系 | 证据链不得只保留摘要；证据链不是资料资产本体，也不是事实记录本体 |
| `payload_hash` | 对原始载荷或关键载荷的不可变指纹 | 不替代原始载荷引用 |
| 双时间戳 | `physical_time` 与 `system_time` 的成对时间记录 | 不得用单一时间字段替代 |
| critical 事件 | 高风险、高影响、高责任动作或系统性异常事件 | 必须增强留痕、增强审计和回滚准备 |

## 六、追溯对象总表

| 追溯对象 | 必须追溯的事项 | 最低追溯要求 |
|---|---|---|
| 对象资产 | 新增、合并、作废、恢复、归档、关键字段修订 | 版本 + 快照 + 操作日志 |
| 事实记录 | 候选转正、修订、作废、回滚、归档、责任确认、金额确认 | 版本 + 快照 + 操作日志 + 条件审计 |
| 汇总视图 | 正式输出、导出、分享、对外展示、快照生成 | 来源链 + 输出快照 + 操作日志 |
| 经验规则层内容 | 候选线索、候选分流、复核、驳回、归档或替代记录 | 来源记录 + 处理记录 + 必要审计 |
| 标准治理内容 | 术语、字段、枚举、状态、权限、风险、校验、追溯规则变更 | 版本 + 影响范围 + 审计 |
| 接口调用 | 外部输入、外部回执、导出、分享、状态变更、高风险动作 | 操作日志 + 载荷指纹 + 结果记录 |
| 页面动作 | 确认、驳回、挂起、作废、导出、分享、对外展示 | 操作日志 + 权限结果 + 状态结果 |
| 外部反馈 | 提交、确认、采纳、驳回、转候选、转正式 | 来源记录 + 主体记录 + 处理记录 |
| AI 输出 | 生成、采纳、驳回、对外展示、失败点记录 | 输入输出记录 + 风险等级 + 处理结果 |
| 导出分享 | 导出、分享、撤回、对外展示 | 权限记录 + 脱敏记录 + 操作日志 |
| 回滚动作 | 发起、校验、执行、失败、恢复 | 回滚前快照 + 回滚后快照 + 审计记录 |
| critical 事件 | 高风险异常、真源污染、权限泄露、错误对外展示、系统性熔断 | 增强快照 + 增强审计 + 处理记录 |

## 七、版本化范围

以下事项必须进入版本链：

1. 正式对象资产新增；
2. 正式对象资产关键字段修订；
3. 正式对象资产合并；
4. 正式对象资产作废；
5. 正式对象资产恢复；
6. 正式事实入链；
7. 正式事实修订；
8. 正式事实作废；
9. 正式事实回滚；
10. 正式状态变化；
11. 
12. 规则候选驳回；
13. 规则候选替代；
14. 模板候选归口；
15. 模板候选修订；
16. 其他文件参考候选内容时的来源、范围和候选边界；
17. 标准治理文件成为当前有效口径；
18. 回流补丁进入正式链路；
19. 对外输出封包生成；
20. 对外输出封包回滚；
21. 高风险动作执行；
22. 对外展示内容正式发布；
23. 导出或分享涉及高风险内容；
24. critical 事件处理。

草稿、中间态、候选摘要、临时页面展示、AI 内部候选、未通过校验的测试数据，默认不直接进入正式版本链；如需进入正式链路，必须重新进入校验、确认和追溯链路。

## 八、版本单元规则

版本单元用于限定版本链归属。不同版本单元不得混用。

| 版本单元 | 适用范围 | 版本边界 |
|---|---|---|
| 对象级版本 | 组织资产、项目资产、主体资产、物资资产、资料资产 | 同一对象形成连续版本链 |
| 事实级版本 | 各类正式事实记录 | 同一事实形成连续版本链 |
| 标准治理文件版本 | 标准治理文件修订、驳回、替代或影响范围变化 | 同一标准治理文件形成连续版本链 |
| 输出级版本 | 正式视图输出、对外展示包、导出包、分享包 | 同一输出对象形成输出版本链 |
| 输出封包版本 | 对外输出封包、输出清单、输出回退 | 同一发布形成发布版本链 |
| 回滚级版本 | 回滚动作和回滚结果 | 回滚动作必须形成新版本，不得覆盖旧版本 |

版本单元规则如下：

1. 同一对象不得拆成无关版本链规避追溯；
2. 同一事实不得通过新建事实绕过修订记录；
3. 发布版本不得替代对象版本；
4. 发布版本不得替代事实版本；
5. 规则版本不得替代事实版本；
6. 输出版本不得反写事实版本；
7. 回滚版本不得删除被回滚版本；
8. 版本链应能识别根版本、父版本、当前版本和历史版本。

## 九、版本身份字段

正式版本至少应具备以下身份字段：

| 字段 | 含义 | 要求 |
|---|---|---|
| `version_id` | 版本唯一标识 | 必填，全局唯一 |
| `version_seq` | 版本序号 | 必填，不得跳号，不得重用 |
| `parent_version_id` | 父版本标识 | 根版本可为空或使用允许占位 |
| `version_unit` | 版本单元 | 必填，区分对象级、事实级、标准治理文件级、输出级或回滚级 |
| `change_type` | 变更类型 | 必填，如创建、修订、作废、替代、回滚、发布 |
| `change_scope` | 变更范围 | 必填，说明影响对象和影响字段 |
| `status_after_change` | 变更后状态 | 必填，引用状态口径 |
| `created_by` | 变更主体 | 必填，可追溯到用户、系统模块或受控服务 |
| `created_by_role` | 变更主体角色 | 必填，不能替代权限判断 |
| `payload_hash` | 载荷指纹 | 正式链路必填 |
| `physical_time` | 现实发生时间 | 条件必填，缺失需说明 |
| `system_time` | 系统记录时间 | 必填 |
| `change_reason` | 变更原因 | 条件必填，高风险、回滚、作废、替代必须填写 |
| `evidence_refs` | 证据引用 | 条件必填，高风险和正式事实必须尽可能绑定 |
| `audit_ref` | 审计引用 | 条件必填，高风险和 critical 必须绑定 |

字段命名、类型和是否进入具体 schema，由字段规范总表和后续接口 / 数据库设计承接；本文只冻结追溯身份口径。

## 十、快照规则

以下场景必须产生成对快照或等效前后状态证据：

1. 正式对象新增；
2. 正式对象关键字段变更；
3. 正式对象合并；
4. 正式对象作废；
5. 正式对象恢复；
6. 正式事实写入成功；
7. 正式事实修订；
8. 正式事实作废；
9. 正式状态翻转；
10. 正式输出生成；
11. 高风险动作执行前；
12. 高风险动作执行后；
13. 对外展示发布前；
14. 对外展示发布后；
15. 未来正式规则机制形成前；
16. 未来正式规则机制形成后；
17. 回滚前；
18. 回滚后；
19. critical 事件触发时；
20. 熔断触发与恢复时。

快照至少应包含：

1. `snapshot_id`；
2. `version_id`；
3. `snapshot_stage`；
4. `namespace`；
5. `entity_type`；
6. `entity_id`；
7. `payload_hash`；
8. `physical_time`；
9. `system_time`；
10. `snapshot_content_ref`；
11. 快照生成主体；
12. 快照生成原因。

快照不得被展示摘要、日志备注、口头说明、页面截图或 AI 摘要替代。外部截图或聊天摘录只有在进入证据链并保留引用关系后，才能作为快照关联证据，不得直接冒充正式快照。

16. 权限放行；
17. 权限拒绝；
18. 风险等级生成；

操作日志至少应包含：

操作日志记录动作过程，不自动等于审计成立；高风险、异常、阻断、熔断、回滚和 critical 事件还必须进入审计记录。

## 十二、审计记录规则

以下事项必须产生审计记录：

1. 高风险事实入链；
2. 高风险事实修订；
3. 高风险事实作废；
4. 高风险对象合并；
5. 高风险对象作废；
6. 金额确认；
7. 责任确认；
8. 客户确认；
9. 甲方确认；
10. 结算确认；
11. 对外展示放行；
12. 高敏导出；
13. 高敏分享；
14. 权限变更；
15. 维护权限授予；
16. 审计权限授予；
17. 标准治理发布；
18. 
19. AI 输出用于高风险用途；
20. 外部反馈被采纳为高风险线索；
21. 阻断；
22. 熔断；
23. 回滚；
24. critical 事件；
25. 真源污染风险；
26. 权限泄露风险；
27. 错误对外展示风险。

审计记录至少应包含：

1. `audit_event_id`；
2. `audit_type`；
3. `severity_level`；
4. `trigger_condition`；
5. `related_operation_id`；
6. `related_version_id`；
7. `related_snapshot_ids`；
8. `decision_result`；
9. `decision_by`；
10. `decision_time`；
11. `evidence_refs`；
12. `rollback_required`；
13. `residual_risk`；
14. `physical_time`；
15. `system_time`；
16. 审计结论；
17. 后续处理要求。

因追溯缺失触发阻断时，审计记录用于锁定追溯缺口，而不是证明追溯链已经完整闭合。此类审计记录至少应保留阻断原因、触发主体、触发时间、被阻断对象、已获取的不完整追溯信息、缺失的追溯要素、当前可用证据、处理建议和后续补齐要求；不要求阻断动作在发生时已经能够引用完整闭合的追溯链。

审计记录必须可持久化、可回查、可关联，不得被操作日志、页面提示、导出记录或 AI 摘要替代。

## 十三、证据链与 payload_hash 规则

证据链用于连接原始输入、资料资产、资料记录、候选内容、正式对象、正式事实、汇总视图、经验规则、导出分享、对外展示、审计记录和回滚记录。资料本体归入对象资产层中的资料资产，资料动作归入事实记录层中的资料记录，资料作为证据时进入证据链和追溯关系。

证据链应遵守以下规则：

1. 原始输入不得直接成为正式事实；
2. 原始输入进入候选链路时应保留来源引用；
3. 上传资料应进入资料资产或资料记录链路；
4. 候选事实进入正式事实前，应能回指来源和证据；
5. 正式事实修订应保留原证据链；
6. 事实作废不得删除证据链；
7. 视图输出应能回指来源事实和生成快照；
8. 对外展示应能回指正式事实、脱敏处理和授权记录；
9. AI 输出采纳应能回指输入范围、输出结果和人工处理记录；
10. 外部反馈采纳应能回指外部主体、提交时间和处理链路；
11. 回滚应能回指回滚前版本、回滚依据和回滚后版本。

`payload_hash` 应遵守以下规则：

1. 正式链路关键载荷必须具备 `payload_hash`；
2. 外部载荷进入候选链路时应生成或记录载荷指纹；
3. 高风险动作应记录动作前后相关载荷指纹；
4. 对外输出封包应记录封包载荷指纹；
5. 回滚记录应保留回滚对象的前后载荷指纹；
6. `payload_hash` 只用于识别载荷一致性，不替代原始载荷引用；
7. 只保存 `payload_hash` 而无法回查载荷来源，不得视为证据链成立；
8. 载荷指纹冲突、缺失或无法校验时，应进入校验、阻断或人工确认。

## 十四、双时间戳规则

双时间戳由 `physical_time` 和 `system_time` 构成。

`physical_time` 表示现实世界中事实、动作、外部回执、确认、付款、施工、验收、交付、导出、分享或对外展示实际发生的时间。

`system_time` 表示系统接收、记录、写入、确认、审计、归档或生成该事项的时间。

双时间戳规则如下：

1. 正式事实必须尽可能保留发生时间和系统记录时间；
2. 事实发生时间不得被系统记录时间替代；
3. 系统记录时间不得被证据时间替代；
4. 确认时间不得自动替代事实发生时间；
5. 外部回执时间不得自动替代系统接收时间；
6. 导出时间不得替代输出生成时间；
7. 回滚执行时间不得替代原事实发生时间；
8. 时间缺失时必须说明缺失原因；
9. 时间冲突时不得静默覆盖；
10. 高风险事项时间冲突必须进入人工确认或阻断；
11. 单一时间字段不得声称满足正式追溯要求；
12. 双时间戳异常应进入校验和追溯记录。

## 十五、回滚规则

回滚用于纠正已经进入正式链路的对象、事实、规则、模板、输出、发布或高风险动作。

回滚成立应同时满足以下条件：

1. 存在可识别的被回滚对象；
2. 存在可识别的被回滚版本；
3. 存在回滚原因；
4. 存在回滚发起主体；
5. 存在回滚权限；
6. 存在回滚校验结果；
7. 存在回滚前快照；
8. 存在回滚后快照；
9. 存在证据链；
10. 存在操作日志；
11. 涉及高风险时存在审计记录；
12. 回滚结果形成新版本。

以下情况不得执行静默回滚：

1. 找不到被回滚版本；
2. 找不到回滚前快照；
3. 找不到回滚依据；
4. 回滚会删除历史版本；
5. 回滚会破坏证据链；
6. 回滚会掩盖权限越界；
7. 回滚会掩盖错误对外展示；
8. 回滚会掩盖金额、责任或客户 / 甲方确认错误；
9. 回滚仅由页面动作触发且未经过后端校验；
10. 回滚仅由接口参数触发且未经过权限和风险判断。

回滚不是删除历史。回滚完成后，应保留原版本、回滚版本、回滚后版本和审计记录。

## 十六、作废、恢复、归档与替代追溯规则

作废应遵守以下规则：

1. 作废必须说明作废对象；
2. 作废必须说明作废原因；
3. 作废必须保留作废前状态；
4. 作废必须保留作废后状态；
5. 作废不得删除历史；
6. 高风险作废必须审计；
7. 作废不得破坏已入链事实引用。

恢复应遵守以下规则：

1. 恢复必须说明恢复对象；
2. 恢复必须说明恢复原因；
3. 恢复必须经过校验；
4. 高风险恢复必须人工确认；
5. 恢复后应由对应业务状态组接管；
6. 恢复不得绕过版本链和审计链。

归档应遵守以下规则：

1. 归档不等于删除；
2. 归档必须保留历史可追溯；
3. 归档恢复必须形成处理记录；
4. 归档不得清除风险、证据、版本和审计记录。

替代应遵守以下规则：

1. 被替代内容不得删除；
2. 替代关系必须可识别；
3. 替代原因必须记录；
4. 替代前后版本必须可追溯；
5. 标准治理、规则、模板、知识替代必须说明影响范围。

## 十七、对象资产层追溯边界

对象资产层追溯应覆盖：

1. 对象创建；
2. 候选对象转正式对象；
3. 对象身份变更；
4. 对象归属变更；
5. 对象别名映射；
6. 对象合并；
7. 对象拆分；

11. 对象关键字段修订；
12. 对象权限范围变化；
13. 对象关联事实变化。

对象追溯不得改写已入链事实。对象合并、作废、恢复和关键字段修订必须保留对原对象和关联事实的引用关系。

## 十八、事实记录层追溯边界

事实记录层追溯应覆盖：

1. 候选事实创建；
2. 候选事实待补；
3. 候选事实确认；
4. 候选事实转正式事实；
5. 正式事实修订；
6. 正式事实作废；
7. 正式事实回滚；

12. 外部反馈采纳为事实线索；
13. AI 输出采纳为事实候选或正式入链依据；
14. 校验结果；
15. 权限结果；
16. 风险等级；
17. 审计记录。

正式事实不得无痕修改。事实修订必须保留旧版本、新版本、修订原因、修订主体、修订时间和影响范围。

## 十九、汇总视图层追溯边界

汇总视图层追溯应覆盖：

2. 视图生成主体；

11. 分享记录；
12. 对外展示记录；
13. 脱敏处理记录；
14. 权限放行记录。

视图输出不得反写真源。正式输出、导出、分享和对外展示必须能回查生成依据、权限依据、脱敏依据和输出快照。

## 二十、经验规则层追溯边界

经验规则层追溯应覆盖：

1. 经验候选线索；
2. 经验规则层候选内容的来源；
4. 候选知识来源；
5. 适用范围；

8. 复核主体；

12. 替代关系；
13. 回滚记录；
14. AI 参与记录；
15. 来源事实或复盘记录。

经验、规则候选、模板候选和候选知识不得脱离来源事实、来源视图或复盘反馈直接作为正式依据。AI 归纳内容不得跳过追溯和人工复核。

## 二十一、标准治理追溯边界

15. 旧口径兼容处理。

标准治理内容成为当前有效口径、驳回、替代或影响下游文件时，必须保留版本、审计和影响范围，不得由下游实现反向覆盖标准口径。

14. 熔断原因；
15. `payload_hash`；
16. 关联版本；
17. 关联审计记录。

接口成功不等于业务成功。外部回执不得直接成为客户确认、甲方确认、责任确认、金额确认或正式事实，必须经过校验、权限、风险和追溯链路。

页面按钮可见不等于权限通过。页面点击确认不等于正式确认。页面本地状态不得替代后端追溯记录。

## 二十四、外部反馈追溯边界

15. 是否需要外部确认；
16. 是否需要内部确认；
17. 证据引用；
18. 审计记录。

外部反馈不等于外部确认。甲方员工提交问题在甲方负责人确认前，不得视为正式问题流转；但其提交、查看、处理、确认和驳回过程必须可追溯。

## 二十五、AI 输出追溯边界

15. 是否进入候选链路；
16. 是否进入对外展示草稿；
17. 是否进入维护测试与模型接口管理区。

AI 输出默认是候选内容。AI 输出被作为正式事实入链依据、规则候选线索依据、模板候选线索依据、对外展示内容或高风险候选入链依据时，必须保留完整输入输出、人工复核、风险、校验、权限和审计记录。

8. 风险等级；
9. 来源事实；

11. 撤回记录；
12. 审计记录。

导出成功、分享成功、展示成功均不等于外部确认成立，不得反写正式事实。

## 二十七、critical 事件追溯规则

以下事项应判定为 critical 事件：

1. 真源污染；
2. 权限泄露；
3. 错误对外展示；
4. 高风险事实错误入链；
5. 金额确认错误；
6. 责任确认错误；
7. 客户确认错误；
8. 甲方确认错误；
9. 结算确认错误；
10. 回滚失败；
11. 对外输出封包错误；
12. 标准治理错误发布；
13. 外部接口异常造成正式链路污染；
14. AI 输出被误发布为正式结论；
15. 系统性熔断；
16. 审计链断裂；
17. 证据链断裂；
18. 双时间戳严重冲突。

critical 事件必须触发：

1. 增强操作日志；
2. 增强快照；
3. 增强审计；
4. 影响范围识别；
5. 是否需要回滚判断；
6. 是否可回滚判断；
7. 不可回滚原因记录；
8. 残余风险记录；
9. 后续处理建议；
10. 责任主体记录。

## 二十八、追溯缺失与阻断规则

出现以下情形时，应阻断正式链路：

1. 正式对象缺少版本记录；
2. 正式事实缺少版本记录；
3. 正式事实缺少来源或证据引用；
4. 高风险事项缺少审计记录；
5. 关键状态变化缺少操作日志；
6. 作废、回滚、恢复缺少快照；
7. 导出、分享、对外展示缺少权限记录；
8. 外部反馈采纳缺少来源和处理链路；
9. AI 输出采纳缺少输入输出和人工处理记录；
10. 缺少 `payload_hash` 却声称可追溯；
11. 缺少 `physical_time` 或 `system_time` 却声称正式追溯成立；
12. 只保留当前值，不保留历史版本；
13. 只保留展示摘要，不保留快照依据；
14. 只保留日志，不保留审计；
15. 删除历史版本后伪造从未发生；
16. 下游实现试图降低追溯要求。

因追溯缺失触发阻断时，阻断动作本身必须形成最低限度审计记录，用于证明阻断发生和锁定缺失项。该记录应至少保留阻断原因、触发主体、触发时间、被阻断对象、已获取的不完整追溯信息、缺失追溯要素、当前可用证据和后续补齐要求；不要求阻断动作引用的追溯链在阻断时刻已经完整闭合。

追溯缺失不得通过页面、接口、AI、模板、导出包、分享包或外部反馈绕过。

## 二十九、追溯新增、修订与驳回规则

追溯口径新增、修订与驳回应遵守以下规则：

1. 新增追溯对象前，必须判断是否可由现有追溯对象承接；
2. 新增版本字段前，必须判断是否属于追溯最小字段或后续实现字段；
3. 新增快照触发条件前，必须判断是否涉及正式链路、高风险、对外展示、回滚或 critical 事件；
4. 新增审计场景前，必须说明风险来源、触发条件、审计对象和保留要求；
5. 修订追溯口径必须同步检查字段规范、状态口径、权限与可见性、风险分级、校验规则、接口边界与集成约束、前后端协同边界与页面承接和验证与验收规则；
6. 驳回追溯表达应保留兼容识别和迁移规则；
7. 页面日志、接口日志、数据库日志、AI 调用记录和外部系统回执不得直接升格为完整追溯口径；
8. 追溯口径调整涉及文件或压缩包修改时，应同步升版本号。

## 三十、边界判断

本文成立，应满足以下判断口径：

1. 能说明追溯与版本口径只定义追溯、版本、快照、日志、审计、回滚、证据链和双时间戳，不定义完整审计平台、数据库表结构、接口 schema、页面组件、代码实现或测试脚本；
2. 能区分追溯、版本、快照、操作日志、审计记录、回滚、证据链、`payload_hash` 和双时间戳；
3. 能说明正式对象、正式事实、正式状态、规则候选、模板候选、正式输出、对外展示、对外输出封包、回退动作和高风险动作必须可追溯；经验规则层候选内容只保留候选处理追溯，不形成独立发布版本；
4. 能说明正式内容不得原地覆盖、不得跳号、不得重用版本号、不得删除历史后伪造从未发生；
5. 能说明快照不得被展示摘要、日志备注、页面截图、口头说明或 AI 摘要替代；
6. 能说明操作日志不等于审计记录，高风险、阻断、熔断、回滚和 critical 事件必须增强审计；
7. 能说明因追溯缺失触发阻断时，审计记录用于锁定缺口和不完整信息，不要求阻断动作引用的追溯链在阻断时刻已经完整闭合；
8. 能说明回滚必须形成新版本，不得删除被回滚版本；
9. 能说明 `payload_hash` 不替代原始载荷引用；
10. 能说明双时间戳不得被单一时间字段替代；
11. 能说明对象资产层、事实记录层、汇总视图层、经验规则层和标准治理的追溯边界；
12. 能说明接口、页面、外部反馈、AI 输出、导出、分享和对外展示不得绕过追溯；
13. 能说明追溯缺失时不得进入正式链路；
14. 能为接口边界与集成约束、前后端协同边界与页面承接、验证与验收规则和后续系统业务运行规则提供追溯依据；
15. 不写完整权限矩阵、风险控制系统、状态流转图、接口 schema、页面组件、数据库表结构、代码实现、测试脚本或实施计划。
