# 02_字段规范总表

## 一、文件定位

本文是 `30_标准治理` 下的字段规范总表文件，用于统一罗盘系统正式开发依据包中可被开发、接口、页面、系统业务运行规则、验证与验收规则和后续维护长期引用的标准字段口径。

字段规范总表回答“系统中哪些字段可以作为标准字段被引用、字段名称如何写、字段含义是什么、字段归属哪类对象或事实、字段值应受哪些枚举或状态口径约束、字段写入和读取边界是什么、字段缺失时应如何进入校验或反问”。

本文只定义字段标准，不替代枚举总表、状态口径总表、权限与可见性口径、风险分级口径、校验规则口径、追溯与版本口径、接口 schema、页面组件、数据库表结构或代码实现。

本文不是数据库字段全集，不是 ORM 模型，不是接口参数全集，不是页面表单全集。数据库表、接口结构、页面控件和代码对象可以引用本文字段，但不得反向定义本文字段。

## 二、字段规范总表职责

字段规范总表承担以下职责：

1. 定义罗盘系统正式字段的命名规则、字段族、字段值类型、引用方式和使用边界；
2. 统一对象资产层、事实记录层、汇总视图层和经验规则层可共用的字段口径；
3. 明确字段与枚举、状态、权限、风险、校验、追溯、反问、脱敏和 AI辅助与候选输出口径的关系；
4. 规定字段不得生成事实、不得定义状态流转、不得替代权限判断、不得替代风险分级、不得替代校验规则；
5. 为接口边界与集成约束、前后端协同边界与页面承接、系统业务运行规则和验证与验收规则提供字段引用依据；
6. 防止页面表单项、接口参数、数据库列名、模板字段、AI 输出、外部字段和历史表达反向成为标准字段；
7. 为字段缺失、字段冲突、字段映射、字段迁移和字段一致性检测提供标准口径。

字段规范总表不负责定义字段取值集合。字段如需使用受控分类值，应通过 `enum_ref` 引用 `03_枚举总表`；字段如需表达生命周期、处理阶段或运行状态，应通过 `status_ref` 引用 `04_状态口径总表`。

## 三、上位约束

字段规范必须服从以下上位约束：

1. 罗盘系统定位为公司级经营执行系统，字段标准必须服务经营执行主链路，不得扩展成独立数据平台字段体系；
2. 标准治理只统一字段口径，不替代业务数据体系定义对象、事实、视图和经验规则层；
3. 对象资产层字段只能服务稳定对象识别、归属、分类、状态投影和追溯，不得承接发生过程；
4. 事实记录层字段只能服务过程事实记录、来源、证据、状态、确认、追溯和风险边界，不得定义对象本体；
5. 汇总视图层字段只能服务读取、聚合、裁剪、展示、输出和追溯，不得反写真源；
6. 经验规则层字段只能服务经验候选、规则候选、模板候选、候选知识的治理，不得覆盖正式事实；
7. AI 输出默认是候选内容，不得通过字段写入直接成为正式事实、正式字段、正式枚举、正式状态、正式规则或模板候选；
8. 页面动作、页面状态、接口回执、模板输出、导出包、分享包、外部反馈和测试样例不得反向定义标准字段；
9. 历史字段、外部字段、旧包字段、数据库列名和自然语言表达只能进入兼容识别或映射规则，不得直接升格为标准字段；
10. 字段规范总表不得新增未被上位文件和业务数据体系支撑的对象类型、事实类型、视图类型、经验规则类型、状态类型或权限类型。

## 四、字段定义权规则

字段定义权遵守以下规则：

1. 字段是否成为标准字段，由本文定义；
2. 字段所属对象、所属事实、所属视图或所属经验规则层内容，由对应业务数据体系文件定义；
3. 字段的受控分类值由 `03_枚举总表` 定义；
4. 字段的状态含义、状态组、流转边界和终态由 `04_状态口径总表` 定义；
5. 字段的可见、可改、可确认、可导出、可分享和对外展示边界，由权限与可见性口径定义；
6. 字段涉及高风险触发、金额、责任、结算、客户确认、甲方确认、对外展示或真源修订时，由风险分级口径定义风险判断；
7. 字段缺失、冲突、格式错误、锚点不足、证据不足和权限不足时，由校验规则口径定义处理要求；
8. 字段来源、证据、快照、版本、回滚、修订和审计留痕，由追溯与版本口径定义；
9. 字段缺失后是否触发反问、反问内容如何组织，由关键字段反问口径定义；
10. 字段在接口、页面、模板、导出包和分享包中的承接方式，由对应下游文件定义，但不得反向修改本文字段含义。

## 五、字段命名规则

标准字段命名应遵守以下规则：

1. 字段名使用英文小写下划线格式；
2. 字段名应稳定、可读、可映射、可测试；
3. 字段名不得使用中文、拼音缩写、自然语言句子、页面按钮文案、接口临时参数名或数据库临时列名；
4. 字段名应表达业务含义，不得只表达页面位置、表单顺序或代码实现便利；
5. 同一字段跨文件引用时必须保持同一字段名；
6. 不同含义的字段不得使用同一字段名；
7. 同一含义不得在不同文件中自造多个字段名；
8. 字段名中不得混入旧目录名、非当前标准表达或历史分类体系；
9. 字段如为 ID，应以 `_id` 结尾；
10. 字段如为时间，应以 `_at`、`_date`、`_time`、`_range` 或 `_period` 体现时间口径；
11. 字段如为列表，应以复数含义或 `_ids`、`_refs`、`_list`、`_items` 等方式表达；
12. 字段如为引用外部受控分类，应通过 `enum_ref` 指向枚举总表；
13. 字段如为状态口径，应通过 `status_ref` 指向状态口径总表；
14. 字段如用于追溯，应能说明来源、证据、版本、快照、操作者或审计关系；
15. 正文术语、中文名称和说明文字中的系统层级或治理闸门名称，应按标准术语写作 `L0`、`L1`、`S2`、`L2`、`L3`、`L4`、`L5`、`L6`、`L7`；标准字段名仍必须遵守英文小写下划线规则，对应写作 `l0`、`l1`、`s2`、`l2`、`l3`、`l4`、`l5`、`l6`、`l7`，例如 `l2_snapshot_id`；
16. 字段不得因页面、接口、模板或数据库实现便利而绕过标准命名规则。

## 六、字段属性说明表

字段规范总表中的字段项至少应具备以下属性：

| 属性 | 含义 | 填写规则 |
|---|---|---|
| `field_name` | 标准字段名 | 必填，英文小写下划线 |
| `field_label` | 字段中文名称 | 必填，用于人工理解 |
| `field_domain` | 字段适用域 | 必填，标明对象资产、事实记录、汇总视图、经验规则、标准治理、运行链路或跨域 |
| `field_family` | 字段族 | 必填，引用本文字段族 |
| `value_type` | 字段值类型 | 必填，引用本文值类型 |
| `enum_ref` | 枚举引用 | 条件必填，字段使用受控分类时填写 |
| `status_ref` | 状态引用 | 条件必填，字段表达状态时填写；字段表达状态时应引用 `04_状态口径总表` 或其明确口径，不得在本文定义状态值或状态流转 |
| `required_rule` | 必填规则 | 必填，填写必填、条件必填、推荐、系统生成或只读 |
| `write_boundary` | 写入边界 | 必填，说明谁可写、在哪个层级写、是否只读 |
| `read_boundary` | 读取边界 | 必填，说明哪些下游可读取 |
| `validation_dependency` | 校验依赖 | 条件必填，指向校验规则口径或后续校验文件 |
| `trace_requirement` | 追溯要求 | 必填，说明来源、证据、快照、审计或版本要求 |
| `privacy_requirement` | 脱敏要求 | 条件必填，涉及对外展示或敏感信息时填写 |
| `notes` | 说明 | 可选，只作解释，不得新增规则 |

字段属性表用于规范字段定义，不等于数据库 schema。后续接口、页面和数据库实现可以映射这些属性，但不得删改字段标准含义。

## 七、字段值类型

字段值类型用于说明字段承载的数据形态，不定义业务取值范围。

| 值类型 | 含义 | 使用规则 |
|---|---|---|
| `string` | 短文本 | 用于名称、标题、编码、摘要等 |
| `text` | 长文本 | 用于说明、备注、描述、复盘内容等 |
| `id` | 单一 ID | 用于对象、事实、视图、规则或快照唯一引用 |
| `id_list` | ID 列表 | 用于多对象、多事实、多资料、多证据引用 |
| `enum` | 枚举值 | 必须填写 `enum_ref` |
| `enum_list` | 枚举值列表 | 必须填写 `enum_ref`，不得使用裸值 |
| `status` | 状态值 | 必须填写 `status_ref`；状态值应按 `04_状态口径总表` 或其明确口径承接，不得在本文另行定义状态值 |
| `boolean` | 布尔值 | 只能表达是/否，不承接复杂状态 |
| `integer` | 整数 | 用于数量、次数、排序、版本序号等 |
| `decimal` | 小数 | 用于金额、比例、面积、长度、工时等数值 |
| `money` | 金额 | 必须说明币种、金额口径和确认要求 |
| `date` | 日期 | 只表达日期，不表达具体时刻 |
| `datetime` | 日期时间 | 用于记录、确认、入链、审计等时间点 |
| `time_range` | 时间范围 | 用于工期、阶段、出勤、履历等 |
| `json_object` | 结构化对象 | 仅用于确需保留结构化摘要或扩展对象，不得替代正式字段 |
| `json_list` | 结构化列表 | 仅用于受控列表，不得成为非治理字段池 |
| `file_ref` | 文件引用 | 用于资料、附件、导出包、截图等引用 |
| `hash` | 哈希值 | 用于载荷、文件、快照、证据一致性校验 |
| `url` | 链接 | 用于外部资源或分享入口，需权限和脱敏约束 |

字段值类型不得替代枚举、状态、权限、风险、校验或追溯规则。

## 八、字段族总表

| 字段族 | 含义 | 主要适用范围 |
|---|---|---|
| `identity` | 唯一识别字段 | 对象、事实、视图、规则、快照、模板 |
| `classification` | 分类字段 | 对象资产、事实记录、视图、经验规则、标准治理 |
| `status` | 状态字段 | 对象、事实、候选、输出、规则、模板、运行链路 |
| `ownership` | 归属字段 | 组织、项目、主体、资料、物资、事实 |
| `relationship` | 关联字段 | 对象引用、事实引用、资料引用、证据引用、视图引用 |
| `time` | 时间字段 | 原始输入、候选、事实、确认、审计、视图、复盘 |
| `source` | 来源字段 | 原始输入、事实记录、证据、追溯、回流 |
| `evidence` | 证据字段 | 事实成立、责任确认、客户确认、甲方确认、验收交付 |
| `confirmation` | 确认字段 | 人工确认、客户确认、甲方确认、授权确认 |
| `validation` | 校验字段 | 校验结果、阻断、驳回、挂起、待补、人工确认 |
| `permission` | 权限字段 | 可见性、可编辑、可导出、可分享、对外展示 |
| `risk` | 风险字段 | 高风险标记、风险等级、风险原因、确认要求 |
| `trace` | 追溯字段 | 审计、快照、版本、回滚、修订、来源链 |
| `content` | 内容字段 | 标题、摘要、说明、正文、备注、复盘 |
| `amount` | 金额字段 | 财务、结算、赔付、扣款、报价、签证 |
| `quantity` | 数量字段 | 物资、出勤、施工、资料、结算 |
| `view` | 视图输出字段 | 汇总视图、台账、清单、看板、草单 |
| `ai_candidate` | AI 候选字段 | AI 摘要、候选建议、候选知识、辅助识别 |
| `compatibility` | 兼容识别字段 | 外部字段、历史字段、自然语言表达、迁移映射 |
| `system` | 系统字段 | 系统生成、运行链路、处理结果、内部标识 |

字段族只用于字段归类，不替代字段定义。

字段族选择应遵守以下优先级：

1. 字段首先按核心业务职责选择字段族，例如识别字段优先归 `identity`，时间字段优先归 `time`，来源字段优先归 `source`，证据字段优先归 `evidence`，确认字段优先归 `confirmation`；
2. `ai_candidate`、`compatibility`、`system` 为特殊字段族，只在字段核心职责分别是 AI辅助与候选输出口径、兼容识别迁移或系统内部控制时使用；
3. 如果字段同时具备普通业务属性和特殊属性，应优先归入普通业务字段族，并在写入边界、读取边界或说明中标明 AI 候选、兼容识别或系统生成属性；
4. 不得为了实现方便把普通业务字段归入 `system`；
5. 不得把 AI 候选字段归入正式事实字段族以绕过确认；
6. 不得把兼容识别字段归入正式字段族以绕过字段迁移。

## 九、跨域通用字段

| 字段名 | 中文名称 | 字段域 | 字段族 | 值类型 | 必填规则 | 写入边界 | 追溯要求 |
|---|---|---|---|---|---|---|---|
| `record_id` | 记录唯一标识 | 跨域 | identity | id | 系统生成 | 系统生成，只读 | 需记录生成时间和来源 |
| `record_title` | 记录标题 | 跨域 | content | string | 条件必填 | 人工录入或系统生成候选 | 需保留来源 |
| `record_summary` | 记录摘要 | 跨域 | content | text | 推荐 | 人工录入、系统生成或 AI 候选 | AI 摘要须标记候选 |
| `owner_org_id` | 归属组织 ID | 跨域 | ownership | id | 必填 | 由组织资产或权限上下文提供 | 需可追溯 |
| `primary_project_id` | 主项目 ID | 跨域 | ownership | id | 项目类内容必填 | 由项目资产或候选项目提供 | 需可追溯 |
| `linked_project_ids` | 关联项目 ID 列表 | 跨域 | relationship | id_list | 条件必填 | 由业务关系或人工确认提供 | 需保留引用来源 |
| `primary_subject_id` | 主体 ID | 跨域 | ownership | id | 主体相关内容必填 | 由主体资产或候选主体提供 | 需可追溯 |
| `linked_subject_ids` | 关联主体 ID 列表 | 跨域 | relationship | id_list | 条件必填 | 由关系、事实或人工确认提供 | 需保留引用来源 |
| `source_type` | 来源类型 | 跨域 | source | enum | 必填 | 输入链路、接口或人工录入 | `enum_ref: source_type` |
| `source_record_id` | 来源记录 ID | 跨域 | source | id | 条件必填 | 系统关联或人工补充 | 需保留来源链 |
| `source_payload_id` | 原始载荷 ID | 跨域 | source | id | 原始输入相关必填 | L0 生成，只读 | 需保留载荷追溯 |
| `evidence_refs` | 证据引用列表 | 跨域 | evidence | id_list | 事实与确认类条件必填 | 来源材料、资料资产或人工绑定 | 需保留证据链 |
| `recorded_at` | 记录时间 | 跨域 | time | datetime | 必填 | 系统生成或人工录入后校验 | 需保留系统记录时间 |
| `occurred_at` | 发生时间 | 跨域 | time | datetime | 事实类条件必填 | 人工录入、来源材料或候选抽取 | 与记录时间区分 |
