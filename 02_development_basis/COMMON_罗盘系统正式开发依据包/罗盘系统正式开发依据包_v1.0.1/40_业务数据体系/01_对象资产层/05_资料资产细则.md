# 05_资料资产细则

## 一、文件定位

本文是 `40_业务数据体系/01_对象资产层` 下的资料资产细则文件，用于定义资料作为稳定对象资产的成立边界、承接范围、资料身份识别、资料归属、资料版本、资料证据链、资料与项目 / 主体 / 物资 / 事实的引用关系，以及资料资产被事实记录、汇总视图层、经验规则层和运行规则引用的规则。

资料资产用于承接罗盘系统中可被多条事实反复引用、可作为证据链来源、可支撑项目执行、签证变更、结算交付、客户确认、甲方确认、资料归档和复盘沉淀的稳定资料对象。

本文只定义资料资产的业务边界和开发依据，不替代资料记录、资料上传流程、附件存储系统、文件管理系统、合同管理系统、结算系统、字段规范、枚举总表、状态口径、接口 schema、页面组件、数据库表结构或代码实现。

## 二、资料资产职责

资料资产的核心职责，是为项目经营执行中的合同、报价、预算、图纸、照片、签证、验收资料、结算资料、付款凭证、发票回执、客户确认材料和归档材料提供稳定资料对象锚点。

资料资产承担以下职责：

1. 定义资料作为稳定对象资产的成立条件；
2. 定义各类资料对象的归口边界；
3. 定义资料本体、资料载体、资料版本、资料状态投影和资料证据链的边界；
4. 定义资料与组织资产、项目资产、主体资产、物资资产之间的关系；
5. 定义资料如何被资料记录、施工记录、财务记录、问题与风险记录、决策与变更记录、责任与确认记录、验收与交付记录引用；
6. 定义资料如何被经营视图、执行视图、结算视图和交付与协同视图消费；
7. 定义候选资料、正式资料资产、资料状态投影和资料关系摘要的边界；
8. 定义资料资产不得被单次上传、页面标签、接口回执、AI 摘要、模板输出、导出包、分享包或历史旧称反向定义。

资料资产不记录资料上传、提交、补齐、确认、退回、更新、引用、作废、归档等过程事实，不替代资料记录，不替代文件存储，不替代合同管理、结算管理或完整文档管理系统。

## 三、上位约束

资料资产必须服从以下上位约束：

1. 对象资产层只承接稳定对象，不承接单次过程事实；
2. 资料资产是五类对象资产之一，服务证据链、项目资料归集、结算交付追溯、客户确认和事实引用；
3. 资料过程事实应归资料记录，不得由资料资产吸收；
4. 资料资产中的当前主版本、当前状态、当前归属、当前引用关系只能作为状态投影或关系摘要，不得替代资料过程事实；
5. 资料资产变化的依据应来自资料记录、责任与确认记录、决策与变更记录、财务记录、验收与交付记录或治理记录；
6. 资料资产的字段、枚举、状态、权限、校验、追溯和脱敏口径由标准治理承接；
7. 汇总视图层可以按资料维度消费正式资料和正式事实，但不得反向修改资料资产；
8. 经验规则层可以按资料类型、资料缺口、资料补齐、资料争议和模板复用沉淀经验、模板和规则候选，但不得覆盖资料资产；
9. AI 可以辅助识别候选资料、资料摘要、资料类型、资料缺口和引用关系，但不得自动确认正式资料、正式事实、正式签署、正式结算依据或正式规则；
10. 历史旧称、旧分类体系、数据库表名、接口字段名、页面入口和代码模型名不得反向定义资料资产。

## 四、资料资产成立条件

一个资料能够进入资料资产，应同时满足以下条件：

1. 具有相对稳定的资料身份；
2. 可以被项目、主体、物资、事实记录、视图输出或经验规则反复引用；
3. 可以作为证据、依据、凭证、附件、确认材料、交付材料或归档材料被追溯；
4. 具有可识别的资料名称、资料类型、来源、载体、归属、版本或其他识别依据；
5. 可以明确组织、项目、主体、物资、事实或业务场景中的至少一种稳定关系；
6. 可以通过标准治理完成候选识别、重复校验、冲突处理、必要补齐、权限判断和追溯记录；
7. 其归属、版本、状态、引用关系或作废归档情况变化能够被记录和追溯，而不是被静默覆盖。

以下内容不得直接作为正式资料资产：

1. 只有文件名但缺少资料类型、归属和来源判断的上传文件；
2. 截图、照片、聊天记录、语音转文字、表格或 PDF 中尚未识别归口的原始载体；
3. AI 从图片、文档或聊天记录中生成的资料摘要；
4. 页面临时标签、接口载荷、外部反馈或模板输出中的资料名称；
5. 无法区分是合同、报价、预算、图纸、签证、验收资料、结算资料、凭证还是普通附件的资料线索；
6. 只用于临时传递、无需归档、无需引用、无需追溯的一次性附件。

上述内容应先作为候选资料、原始输入、资料识别线索、待补项或运行中间数据处理。只有在类型、归属、来源、版本、冲突和必要确认满足要求后，才能进入正式资料资产。

## 五、资料资产承接范围

资料资产承接的是资料对象本体和长期稳定摘要。

| 资料资产对象 | 承接内容 | 不承接内容 | 主要作用 |
|---|---|---|---|
| 合同资料 | 合同文件、补充协议、合同附件、合同确认材料 | 签署过程、合同变更过程、付款过程、争议处理过程 | 项目边界、责任依据、结算依据、追溯证据 |
| 报价资料 | 报价单、报价清单、报价说明、报价确认材料 | 报价沟通过程、价格确认过程、报价调整过程 | 报价依据、客户确认、结算参考 |
| 预算资料 | 预算表、预算清单、预算说明、成本预算资料 | 成本发生过程、付款过程、预算调整事实 | 成本参考、结算取数、经营视图 |
| 图纸资料 | 设计图、施工图、变更图、节点图、现场示意图 | 图纸设计过程、图纸修改确认过程 | 施工依据、交付依据、变更追溯 |
| 照片 / 影像资料 | 现场照片、施工照片、隐蔽照片、验收照片、问题照片、视频截图 | 拍摄动作、上传动作、现场事实确认过程 | 证据链、施工追溯、问题风险、交付展示 |
| 签证资料 | 签证单、签证附件、签证确认材料、签证照片 | 签证发起、沟通、确认、价格裁决过程 | 变更依据、结算依据、客户确认 |
| 验收资料 | 验收单、验收照片、验收清单、验收确认材料 | 验收过程、整改过程、交付过程 | 交付追溯、客户 / 甲方确认、项目归档 |
| 结算资料 | 结算书、结算清单、结算依据包、结算确认材料 | 结算取数过程、结算确认过程、付款过程 | 结算视图、交付资料、经营复盘 |
| 付款与发票资料 | 付款凭证、收款凭证、发票、发票回执、银行回单 | 收付款事实、开票申请过程、发票确认过程 | 财务证据、结算追溯、经营视图 |
| 客户 / 甲方确认材料 | 签字确认、聊天确认、盖章确认、邮件确认、审批回执 | 确认过程、责任裁决、正式承诺判断 | 责任与确认、交付协同、结算依据 |
| 归档资料 | 项目归档包、资料归档清单、最终交付资料、复盘资料包 | 归档操作过程、资料补齐过程、归档审批过程 | 历史查询、审计追溯、复盘沉淀 |
| 模板资料 | 合同模板、报价模板、确认单模板、资料清单模板、日报 / 周报模板 | 模板规则发布、模板优化建议、模板字段定义、模板生成逻辑 | 资料复用、经验规则层、页面承接 |

经有权限主体人工确认、明确版本、适用范围、启用要求和追溯关系的模板文件，可以作为资料资产中的模板资料成立。模板文件是否作为资料资产成立，不由经验规则层、模板候选线索、页面展示、AI 摘要或模板输出直接确认。

资料资产可以保存当前主版本、当前状态、主要归属和引用摘要，但资料形成、上传、提交、补齐、确认、引用、作废、归档和替换过程必须由资料记录或对应事实记录承接。

## 六、资料资产不承接范围

以下内容不得写入资料资产本体：

| 内容 | 正确归口 | 原因 |
|---|---|---|
| 单次资料上传、提交、补齐、退回、确认、引用、作废、归档 | 资料记录 | 属于资料过程事实 |
| 合同签署、签证确认、价格确认、范围调整 | 决策与变更记录或责任与确认记录 | 属于高风险确认或决策事实 |
| 单次付款、收款、报销、开票申请、发票确认 | 财务记录 | 属于财务事实 |
| 施工现场事实、隐蔽事实、整改过程 | 施工记录或问题与风险记录 | 属于施工或风险过程 |
| 验收过程、交付过程、整改确认 | 验收与交付记录 | 属于验收交付事实 |
| 客户沟通、甲方沟通、资料催补、资料说明 | 沟通与服务记录 | 属于沟通过程事实 |
| 资料缺口、资料风险、资料争议 | 问题与风险记录 | 属于问题风险事实 |
| 项目本体、客户、甲方、供应商、物资对象 | 项目资产、主体资产、物资资产 | 属于其他对象资产 |
| 资料清单、结算草单、归档台账、客户确认清单 | 汇总视图层或模板输出 | 属于输出结果，不是真源 |
| 资料模板优化、资料规则候选、归档经验 | 经验规则层 | 属于经验规则沉淀 |
| 文件存储路径、缓存、OCR 中间结果、AI 摘要 | 运行中间数据或候选内容 | 不能直接成为正式资料资产 |

资料资产不得因为某个文件“被上传”或“被页面展示”而直接成立。上传成功、识别成功、摘要生成、模板生成、导出成功和分享成功，均不等于资料正式确认。

## 七、资料唯一识别规则

资料资产应具备稳定唯一识别能力。资料正式标识创建后，不得因文件名、页面标签、资料状态、存储路径、项目阶段、引用次数或资料版本变化而复用给其他资料对象。

资料唯一识别应遵守以下规则：

1. 文件名可以帮助识别资料，但不得单独作为唯一判断依据；
2. 同名资料在不同项目、不同版本、不同签署状态、不同来源或不同资料类型下，可能对应不同资料资产；
3. 同一资料可以存在多个版本、多个载体、多个扫描件、多个附件和多个引用关系；
4. 资料类型、项目归属、主体归属、来源、版本、签署状态、确认材料和证据链可作为辅助识别依据；
5. 疑似重复资料不得自动合并；
6. 资料合并、拆分、替换、作废、恢复、归档、版本修订和来源修正必须保留来源、原因、操作者、时间、影响范围和追溯依据；
7. 已入链事实记录中的历史资料引用不得因资料合并、改名、版本替换或归属修正被自动替换。

资料识别冲突时，应进入候选重复资料、待补、挂起、人工确认或对象治理流程，不得静默创建、静默合并或静默覆盖。

## 八、资料载体、版本与主版本边界

资料资产必须区分资料对象、资料载体、资料版本和当前主版本。

| 类型 | 回答的问题 | 不等于 | 主要作用 |
|---|---|---|---|
| 资料对象 | 这份资料是什么 | 文件存储路径 | 资料识别、证据链、事实引用 |
| 资料载体 | 资料以什么形式存在 | 资料正式成立 | 文件、图片、PDF、表格、录音、截图等载体管理 |
| 资料版本 | 资料经历过哪些版本 | 当前正式事实 | 历史追溯、替换记录、版本比对 |
| 当前主版本 | 当前被系统默认引用的版本 | 自动作废历史版本 | 读取便利、视图消费、输出引用 |

资料载体可以是文件、图片、PDF、表格、文档、录音、视频截图、聊天记录截图或其他附件。载体存在不等于资料资产成立。

资料版本应遵守以下规则：

1. 新版本不得无痕覆盖旧版本；
2. 当前主版本变化应有来源、原因、操作者、时间、影响范围和追溯依据；
3. 历史版本仍应保留追溯关系，不得被静默删除；
4. 已入链事实引用历史资料版本时，不得因主版本变化自动替换引用；
5. 资料版本作废、恢复、替换和回滚应进入治理流程；
6. AI 可辅助识别版本差异，不得自动确认主版本或作废版本。

当前主版本只是资料资产的读取便利，不替代资料确认事实，也不自动改变已入链事实的引用依据。

## 九、资料归属与引用边界

资料资产必须具备明确归属。资料归属不清时，应进入待补、挂起、人工确认或治理回流，不得直接作为正式资料资产放行。

资料归属至少包括以下维度：

| 归属维度 | 回答的问题 | 边界 |
|---|---|---|
| 组织归属 | 资料属于哪个公司或组织范围 | 不等于外部可见权限 |
| 项目归属 | 资料服务哪个项目 | 不等于资料中所有事实均已成立 |
| 主体归属 | 资料与哪个客户、甲方、供应商、班组、员工、联系人相关 | 不等于主体身份已确认 |
| 物资归属 | 资料是否涉及具体物资、材料、设备或工具 | 不等于物资事实已成立 |
| 事实引用 | 资料被哪些事实作为证据或依据 | 不等于资料可直接创造事实 |
| 业务场景归属 | 资料服务合同、报价、预算、施工、签证、验收、结算、归档等哪个场景 | 不等于场景结果已确认 |

资料可以被多个对象和事实引用。一份资料可以同时关联项目、主体、物资和多条事实，但资料资产不得因此吸收这些对象或事实本身。

资料归属变化如构成业务事实，应进入资料记录、责任与确认记录或对象治理流程。资料归属不得由页面默认值、AI 推测、接口导入、文件名或模板结果自动确认。

## 十、资料资产与组织资产的关系

组织资产为资料资产提供组织归属和数据隔离边界。

资料资产与组织资产的关系如下：

1. 资料应具备组织归属或候选组织归属；
2. 公司级模板、组织级资料清单、组织级归档材料可以按组织资产归属；
3. 资料所属组织决定资料可见性、导出范围、分享范围和外部展示边界；
4. 跨组织资料、外部来源资料或归属不清资料，应进入待补、挂起、权限确认或人工确认；
5. 组织归属变化如构成事实，应进入资料记录、责任与确认记录或对象治理流程；
6. 组织资产不替代资料资产，资料资产不替代组织资产；
7. 组织维度资料清单不得反向修改资料资产。

组织资产回答“资料归属于哪个组织范围”，资料资产回答“这份资料是什么”，资料记录回答“这份资料发生了什么过程”。

## 十一、资料资产与项目资产的关系

项目资产为资料资产提供项目归属和项目锚点。

资料资产与项目资产的关系如下：

1. 项目资料应绑定项目资产或候选项目；
2. 合同、报价、预算、图纸、照片、签证、验收资料、结算资料和归档资料通常应具备项目归属；
3. 同一资料可能被多个项目引用，但跨项目引用必须有明确依据和权限边界；
4. 项目归档后，资料归档关系仍应可追溯，不得自动删除；
5. 项目合并、拆分、作废或恢复后，已入链事实中的资料引用不得被自动替换；
6. 项目资料归属不清时，应进入待补、挂起或人工确认；
7. 项目资料关系不得由文件名、页面目录、AI 摘要或接口载荷自动确认。

项目资产提供项目锚点，资料资产提供资料锚点，资料记录承接资料上传、确认、归档和引用过程。

## 十二、资料资产与主体资产的关系

主体资产为资料资产提供客户、甲方、供应商、班组、员工、联系人、签署人、确认人、经办人等主体锚点。

资料资产与主体资产的关系如下：

1. 资料可以关联提交人、确认人、签署人、经办人、客户、甲方、供应商、设计师、资料负责人等主体；
2. 资料中的签名、盖章、电话、抬头、联系人、微信名、群昵称，不自动成为正式主体资产；
3. 资料识别出的主体线索应先形成候选主体；
4. 高风险资料中的主体确认、签署、授权和责任归属，应进入责任与确认记录或对应事实链路；
5. 主体关系不清、身份不清、签署主体不清时，应进入待补、挂起或人工确认；
6. 资料资产不得直接确认主体责任、付款责任、验收责任或客户承诺；
7. 主体资产不得替代资料本体。

资料中的主体信息是证据线索，不是自动成立的正式主体或正式确认事实。

## 十三、资料资产与物资资产的关系

物资资产为资料资产提供材料、设备、工具、库存物品、可复用物品等物资锚点。

资料资产与物资资产的关系如下：

1. 报价单、预算表、采购单、送货单、发票、照片、签证、结算资料中可能包含物资线索；
2. 资料中出现的物资名称、规格、数量、价格、供应商、项目名称，不自动成为正式物资资产或正式物资事实；
3. 资料识别出的物资线索应先形成候选物资；
4. 高风险资料中的物资价格、数量、规格、替代、损耗、报废和结算依据，应进入决策与变更记录、财务记录、物资流转记录、责任与确认记录或对应事实链路；
5. 物资资料归属不清、规格冲突、数量冲突、价格冲突时，应进入待补、挂起或人工确认；
6. 资料资产可以引用物资资产作为证据关联，但不得替代物资资产。

资料是证据对象，物资是业务对象，物资过程事实应由物资流转记录等事实记录承接。

## 十四、资料资产与事实记录层的关系

资料资产为事实记录层提供证据锚点、附件锚点和依据锚点，但不替代事实记录层。

| 事实记录类型 | 与资料资产的关系 | 资料资产不承接内容 |
|---|---|---|
| 资料记录 | 资料形成、上传、提交、补齐、确认、退回、引用、作废、归档必须绑定资料 | 不记录过程本身 |
| 沟通与服务记录 | 聊天记录、邮件、回访记录、服务反馈可作为沟通证据 | 不记录沟通过程 |
| 施工记录 | 施工照片、隐蔽照片、现场视频、施工图可作为施工证据 | 不记录施工动作 |
| 验收与交付记录 | 验收单、验收照片、交付清单、签收材料可作为交付证据 | 不记录验收交付过程 |
| 财务记录 | 付款凭证、发票、银行回单、收据可作为财务证据 | 不记录收付款事实 |
| 问题与风险记录 | 问题照片、整改照片、风险说明、责任资料可作为问题证据 | 不记录问题处理过程 |
| 决策与变更记录 | 签证单、变更单、价格确认材料、客户确认材料可作为决策依据 | 不记录决策变更事实 |
| 物资流转记录 | 采购单、送货单、领料单、退库单、发票可作为物资流转证据 | 不记录物资流转过程 |
| 责任与确认记录 | 签字、盖章、聊天确认、邮件确认可作为确认材料 | 不记录确认链路 |
| 复盘与反馈记录 | 复盘资料、反馈截图、归档材料可作为复盘来源 | 不记录复盘过程 |

事实记录引用资料资产时，应遵守以下规则：

1. 高风险事实应尽可能绑定资料证据；
2. 事实记录不得临时定义正式资料资产；
3. 资料资产不得吸收事实过程；
4. 单次事实不得直接覆盖资料资产主版本、归属或状态；
5. 资料确认后如影响长期资料口径，应形成候选资料修订，经治理后再更新资料资产；
6. 资料合并、作废、归档或恢复后，已入链事实记录应保留原资料引用，不得自动替换；
7. 如需修订既有事实的资料引用关系，应进入事实引用修订或资料治理流程，并保留原引用、修订原因、操作者、时间、版本和追溯依据。

## 十五、资料资产与汇总视图层的关系

汇总视图层可以按资料维度消费资料资产和事实记录层内容，生成经营视图、执行视图、结算视图、交付与协同视图中的资料相关结果。

| 汇总视图 | 资料资产提供什么 | 视图消费什么 | 禁止项 |
|---|---|---|---|
| 经营视图 | 合同、报价、预算、付款凭证、结算资料、风险资料 | 财务记录、决策变更记录、问题风险记录 | 不把经营分析反写资料资产 |
| 执行视图 | 图纸、照片、施工资料、资料缺口、资料待补项 | 施工记录、资料记录、问题风险记录 | 不用视图状态替代资料确认事实 |
| 结算视图 | 合同、报价、预算、签证、付款凭证、结算资料、确认材料 | 财务记录、施工记录、资料记录、决策与变更记录 | 不自动形成正式结算确认 |
| 交付与协同视图 | 验收资料、交付资料、客户确认材料、对外可见资料 | 验收交付记录、资料记录、沟通服务记录 | 不自动对外承诺、签收或确认 |

汇总视图层应遵守以下规则：

1. 视图只能消费正式资料资产和正式事实；
2. 视图不得创造资料事实；
3. 视图不得反写资料资产；
4. 资料清单、资料缺口清单、结算资料包、归档台账、客户确认清单和对外展示包属于视图输出、模板输出或业务输出，不是资料资产本体；
5. 视图发现资料缺失、版本冲突、归属冲突、证据链断裂或权限异常时，只能生成待补项、候选问题或治理回流；
6. 对外协同视图必须接受权限、脱敏、字段裁剪和高风险校验。

## 十六、资料资产与经验规则层的关系

经验规则层可以按资料类型、资料缺口、资料补齐、资料争议、资料归档和模板复用沉淀经验、模板、候选知识和规则候选，但不得覆盖资料资产。

资料资产与经验规则层的关系应遵守以下规则：

1. 经验规则层可以按合同、报价、预算、图纸、签证、验收资料、结算资料、付款凭证等资料类型归纳经验；
2. 多项目资料缺口、资料退回、资料争议、资料补齐和结算资料问题可以形成规则候选；
3. 经验规则层可以形成资料清单模板、资料补齐模板、结算资料模板、客户确认模板、归档模板和资料风险提示；
4. 经验规则层不得直接修改资料名称、资料类型、资料归属、资料版本、资料状态或资料引用关系；
5. AI 归纳出的资料经验只能作为候选经验、候选规则或待确认建议；
6. 正式规则如影响资料创建、资料归属、资料确认、资料版本、资料归档、资料脱敏或资料对外展示，应由标准治理和资料资产细则共同承接；
7. 资料类经验进入正式规则前，必须经过来源校验、适用范围确认、人工确认、版本记录和追溯。

资料资产为经验规则层提供资料维度，经验规则层不替代资料资产本体，也不替代资料事实。

## 十七、候选资料与正式资料资产

资料资产必须区分候选资料和正式资料资产。

候选资料来源包括：

1. 用户上传的文件、图片、表格、PDF、WPS 文档、录音、视频截图或聊天截图；
2. 用户录入的资料名称、资料说明、资料归属、资料类型或资料缺口描述；
3. 合同、报价、预算、图纸、签证、验收资料、结算资料等资料线索；
4. 外部反馈、接口载荷或页面输入中的资料线索；
5. AI 辅助识别出的资料候选、资料类型候选、版本候选、归属候选或缺口候选。

候选资料不得直接作为正式资料资产消费。候选资料进入正式资料资产前，应完成类型判断、归属确认、版本判断、重复校验、冲突处理、必要补齐、权限判断和追溯记录。

正式资料资产应满足以下要求：

1. 有明确资料类型；
2. 有可识别资料身份；
3. 有来源或载体；
4. 有组织、项目、主体、物资、事实或业务场景中的必要归属依据；
5. 有版本或版本未知标记；
6. 有状态投影；
7. 有权限和可见性边界；
8. 有必要确认和追溯依据；
9. 与对象、事实记录和视图输出的关系可被追溯。

资料别名、历史名称、文件名、页面标签、AI 摘要和自然语言描述只能作为识别辅助，不得替代正式资料资产标识。

## 十八、资料资产生命周期边界

资料资产生命周期应至少支持以下治理动作：

1. 创建；
2. 更新；
3. 补齐；
4. 归档；
5. 作废；
6. 恢复；
7. 合并；
8. 拆分；
9. 资料类型修订；
10. 资料归属修订；
11. 资料版本修订；
12. 当前主版本变更；
13. 资料状态变更；
14. 资料引用关系变更；
15. 资料脱敏状态变更；
16. 来源修正；
17. 版本回滚。

上述治理动作之间的流转关系、前置条件、权限要求、状态名称、状态流转、字段要求和校验规则，由标准治理中的状态口径、追溯与版本口径、权限与可见性口径以及资料记录运行规则承接。本文只定义资料资产需要支持的生命周期治理动作范围，不定义完整状态机。

资料资产变更不得无痕覆盖。资料合并、拆分、作废、恢复、归档、版本修订、主版本变更、归属变更、引用关系变更和脱敏状态变更，应保留来源、原因、确认主体、操作者、时间、版本、影响范围和追溯依据。

## 十九、资料归档、作废与历史引用

资料归档和资料作废都不等于删除。

资料归档应遵守以下规则：

1. 归档用于历史保留、审计追溯、项目交付、结算交付、复盘或低频查询；
2. 归档后资料仍可被历史事实、视图、复盘、经验规则和审计链路引用；
3. 归档后不得自动新增普通资料过程事实；
4. 归档后允许按权限进行历史查询、审计、修订、复盘、经验沉淀和必要补证；
5. 归档后恢复必须进入人工确认、权限校验、风险校验和追溯记录。

资料作废应遵守以下规则：

1. 作废属于高风险状态或治理结果，应由资料记录、责任与确认记录、决策与变更记录或治理记录支撑；
2. 作废不等于删除；
3. 作废后历史事实引用不得自动替换或删除；
4. 作废后如需恢复或纠错，必须进入治理流程；
5. 作废涉及金额、责任、结算、客户承诺、验收交付或对外展示时，必须具备必要确认和追溯依据。

资料上传完成、资料确认完成、资料归档、资料作废、项目归档、结算完成和客户交付完成是不同事项，不得在资料资产中混写。

## 二十、资料权限、脱敏与外部展示边界

资料资产是外部展示和权限控制中的高敏对象，应接受权限、脱敏和外部展示口径约束。

资料权限与脱敏应遵守以下规则：

1. 用户只能查看其权限范围内的资料资产；
2. 外部客户、甲方、供应商、班组和外部协作者只能查看授权范围内、经裁剪或脱敏后的资料；
3. 内部成本、内部责任判断、内部经营分析、内部规则、未确认事实、未脱敏资料不得直接对外展示；
4. 对外展示资料前，应判断资料状态、资料归属、资料类型、脱敏要求、可见主体和展示范围；
5. 导出包、分享包、对外资料包、客户确认清单和结算资料包不得绕过资料可见性边界；
6. AI 不拥有资料确认权、资料作废权、资料归档权、资料对外发布权或资料脱敏裁决权；
7. 涉金额、责任、合同、结算、客户承诺、甲方确认、风险关闭和对外发布的资料动作，必须接受高风险校验和必要人工确认。

具体角色可见性、字段脱敏、操作权限、外部展示、导出范围、高风险动作审批和审计追溯要求，由标准治理、接口边界、页面承接和验证与验收规则继续定义。

## 二十一、与接口、页面、AI 和模板的关系

资料资产对接口、页面、AI 和模板形成以下约束：

1. 输入接口只能提交候选资料、资料补齐、资料归属修订请求或受控写入，不得绕过校验直接创建正式资料资产；
2. 上传成功只能表示资料载体进入原始输入或候选链路，不代表资料正式确认；
3. 查询接口只能读取权限范围内的资料资产、资料关系和资料维度视图；
4. 页面可以展示资料资产、候选资料、待补项、版本冲突、归属冲突、重复资料候选和状态提示，但不得裁决正式资料资产、资料作废、资料归档、资料确认或高风险资料动作；
5. 页面补全项应以后端返回的缺失项、阻断原因、候选项和可选动作范围为准；
6. AI 可以辅助识别资料类型、资料摘要、资料缺口、资料版本差异、资料归属和引用关系，但 AI 输出默认是候选内容；
7. 模板可以读取资料资产作为合同、报价、预算、签证、结算草单、客户确认清单、资料清单或归档资料包的来源之一，但模板输出不得创建或修改资料资产；
8. 日报、周报、资料清单、结算草单、客户确认清单、导出包和分享包中的资料名称、资料状态或资料归属，不得反向修改资料资产；
9. 涉金额、责任、合同、结算确认、签证确认、验收交付、客户承诺、资料作废、资料归档、对外展示授权的动作，必须接受高风险校验和必要人工确认。

## 二十二、禁止混写与反向定义规则

资料资产必须防止以下混写和反向定义：

1. 把资料资产写成完整文件管理系统、合同管理系统、结算系统、附件库或网盘；
2. 把资料资产写成资料记录、沟通与服务记录、财务记录、决策与变更记录、责任与确认记录或验收与交付记录；
