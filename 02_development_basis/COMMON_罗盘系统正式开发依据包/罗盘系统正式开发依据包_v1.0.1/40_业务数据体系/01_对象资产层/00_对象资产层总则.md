# 00_对象资产层总则

## 一、文件定位

本文是 `40_业务数据体系/01_对象资产层` 的总则文件，用于定义罗盘系统对象资产层的共性规则、稳定对象边界、对象分类、对象归属、对象关系、对象可见性边界，以及对象被事实记录、汇总视图层和经验规则层引用的规则。

对象资产层是业务数据体系的第一层，用于承接系统中长期存在、可被多条事实反复绑定、可被多个视图反复消费、可被经验规则层反复引用的稳定业务对象。

本文只负责对象资产层总规则和层内文件分工，不替代组织资产、项目资产、主体资产、物资资产、资料资产细则，不替代事实记录层、汇总视图层、经验规则层，不替代字段规范、枚举总表、状态口径、权限与可见性口径、接口 schema、页面规则、数据库表结构或代码实现。

## 二、对象资产层总职责

对象资产层的总职责，是为罗盘系统中的经营执行事实提供稳定锚点，为汇总视图层提供聚合维度，为经验规则层提供适用对象范围。

对象资产层承担以下职责：

1. 定义稳定对象的成立边界；
2. 定义五类对象资产的一级归口；
3. 定义对象资产与事实记录层之间的锚定关系；
4. 定义对象资产与汇总视图层之间的聚合关系；
5. 定义对象资产与经验规则层之间的适用范围关系；
6. 定义对象归属、对象关系、对象别名、对象合并、对象拆分、对象归档和对象作废的总边界；
7. 定义对象资产进入正式链路前必须接受的校验、确认、权限和追溯要求；
8. 定义对象资产不得被原始输入、AI 输出、页面状态、接口回执、模板输出、视图结果或历史旧称反向定义。

对象资产层不记录一次性发生过程，不承接事实流水，不发布正式规则，不生成经营结论，不承担页面展示、接口传输、数据库落表或代码模型职责。

## 三、上位约束

对象资产层必须服从以下上位约束：

1. 业务数据体系由对象资产层、事实记录层、汇总视图层和经验规则层组成；
2. 对象资产层只承接稳定对象，不承接单次过程事实；
3. 事实记录层承接真实发生或经确认的过程；
4. 汇总视图层只消费对象资产层和事实记录层，不创造事实、不反写真源；
5. 经验规则层承接经验、模板、规则候选、候选知识和正式规则，不覆盖对象资产层和事实记录层；
6. 正式对象资产必须具备来源、归口、状态、权限、必要确认和追溯依据；
7. 对象资产的字段、枚举、状态、权限、校验、追溯和脱敏口径由标准治理承接；
8. 对象资产不得被数据库表、接口字段、页面入口、代码模型名、AI 输出或历史旧称反向定义。

对象资产层可以为详细设计、接口联调、页面承接和验收提供对象归口依据，但不得提前写成数据库结构或接口协议。

## 四、对象资产成立条件

一个对象能够进入对象资产层，应同时满足以下条件：

1. 具有相对稳定的业务身份；
2. 可以被多条事实记录反复引用；
3. 可以作为项目、主体、资料、物资、组织、责任、权限或视图的锚点；
4. 可以被标准治理分配对象类型、生命周期状态、来源和追溯要求；
5. 可以与其他对象、事实、资料、视图或经验规则建立稳定引用关系；
6. 其变化能够被记录、追溯和治理，而不是被静默覆盖。

临时性、单项目内的一次性组合对象，不具备稳定业务身份的，不得直接进入正式对象资产层，应作为候选对象、事实记录中的参与描述、运行中间数据或待治理对象线索处理。例如临时拼凑且仅服务单个事项的一次性施工组合，不应直接作为正式主体资产；若该班组后续形成稳定合作身份、可被多条事实反复引用，并满足来源、归属、权限和追溯要求，才可进入主体资产治理链路。

不满足上述条件的内容，不应直接进入对象资产层。临时描述、一次性动作、单次沟通、单次付款、单次采购、单次资料提交、单次上传、AI 抽取结果、页面临时状态、接口回执和导出结果，应先按原始输入、候选内容、事实记录、运行中间数据或视图输出归口处理。

## 五、五类对象资产分工

对象资产层至少包括五类对象资产：组织资产、项目资产、主体资产、物资资产和资料资产。

| 对象资产 | 承接内容 | 不承接内容 | 主要作用 |
|---|---|---|---|
| 组织资产 | 公司、组织节点、仓库、库存池、共享资源、组织级规则归属、组织级模板归属 | 项目执行过程、组织变更过程、规则执行流水、完整组织制度、一次性临时资源组合 | 组织归属、权限隔离、资源归属、规则和模板归属 |
| 项目资产 | 装修 / 工程项目本体、项目范围摘要、项目阶段、项目状态投影、项目参与方、项目归档信息 | 施工过程、财务过程、资料流转过程、结算过程、项目看板结果 | 项目执行类事实的强制锚点 |
| 主体资产 | 客户、甲方、供应商、班组、员工、设计师、联系人、外部协作者等具备稳定业务身份的主体 | 主体行为流水、单次沟通、主体关系变化过程、主观评价、完整客户画像、一次性临时组合人员 | 沟通、责任、确认、协作、权限和外部协同锚点 |
| 物资资产 | 材料、设备、工具、库存物品、规格型号、当前状态投影、归属摘要 | 采购、入库、领用、调拨、损耗、付款、完整流转过程 | 物资流转、施工使用、成本关联、库存状态锚点 |
| 资料资产 | 合同、报价、预算、图纸、照片、签证、验收资料、结算资料、付款凭证、发票回执、客户确认材料、归档材料等资料对象 | 资料上传、提交、补齐、确认、退回、更新、引用、作废等过程事实 | 资料证据链、结算交付追溯、事实引用、项目资料归集 |

五类对象资产共同构成对象资产层的基本承接范围。后续细则可以细化对象分类和对象规则，但不得新增与业务数据体系四层结构冲突的并列对象体系。

## 六、对象资产与事实记录层的关系

对象资产层回答“系统中有哪些稳定对象”，事实记录层回答“围绕这些对象实际发生了什么”。

对象资产与事实记录层的关系如下：

1. 事实记录应尽可能绑定对象资产或候选对象；
2. 项目执行类事实必须绑定项目资产；
3. 主体相关事实应绑定主体资产；
4. 物资流转、施工使用、损耗、复用等事实应绑定物资资产；
5. 资料提交、补齐、确认、归档、引用等事实应绑定资料资产；
6. 组织归属、仓库、库存池、共享资源和组织级规则相关事实应绑定组织资产；
7. 一条事实可以关联多个对象；
8. 一个对象可以被多条事实反复引用；
9. 事实记录不得临时定义正式对象资产；
10. 对象资产不得吸收事实流水或替代事实记录。

对象变化本身如构成业务事实，应由事实记录层承接。例如项目状态变化、资料确认、物资入库、主体关系变化、组织归属调整、对象合并确认等，应形成对应事实记录或确认记录，再由对象资产层更新状态投影或对象关系。

对象状态投影不是事实真源。对象资产中的当前状态只能作为读取便利或聚合结果，状态依据必须能够追溯到事实记录、确认记录或治理记录。

对象合并、作废、拆分、恢复或归档后，已入链事实记录应保留对原对象的历史引用关系，不得自动替换为新对象，也不得无痕改写事实链。若业务上需要将既有事实与新对象、合并后对象或恢复后对象建立新的引用关系，应进入对象治理和事实引用修订流程，并保留原引用、修订原因、操作者、时间、版本和追溯依据。

## 七、对象资产与汇总视图层的关系

汇总视图层以对象资产为聚合维度，以事实记录层为内容来源。

对象资产与汇总视图层的关系如下：

1. 经营视图可以按组织、项目、主体、物资和资料维度聚合经营结果；
2. 执行视图可以按项目、主体、资料和物资维度聚合执行事项；
3. 结算视图可以按项目、资料、主体、财务事实和决策变更事实聚合结算依据；
4. 交付与协同视图可以按项目、客户、甲方、资料、验收与交付事实聚合对外展示内容；
5. 汇总视图层可以读取对象资产作为维度，但不得修改对象资产；
6. 汇总视图层发现对象缺失、对象冲突或对象关系异常时，只能形成待补项、候选对象或治理回流；
7. 看板、台账、摘要、日报、周报、结算草单和客户确认清单不得反向创造对象资产。

对象资产提供维度，事实记录提供内容，汇总视图层提供消费结果。三者不得混写。

## 八、对象资产与经验规则层的关系

经验规则层可以基于对象类型、对象关系、对象状态和对象相关事实沉淀经验、模板、候选知识和规则候选。

对象资产与经验规则层的关系如下：

1. 经验规则层可以按组织、项目、主体、物资、资料等对象类型归纳经验；
2. 经验规则层可以引用对象资产作为规则适用范围；
3. 经验规则层可以基于多项目、多主体、多资料、多物资相关事实形成规则候选；
4. 经验规则层不得直接修改对象资产；
5. 经验规则层不得把候选知识、AI 归纳或复盘结论直接写成对象字段、对象状态或对象关系；
6. 正式规则如影响对象资产创建、合并、拆分、归档、作废或可见性，应由标准治理和对应对象资产细则承接；
7. 对象类经验进入正式规则前，必须经过来源校验、适用范围确认、人工确认、版本记录和追溯。

经验规则层服务对象资产长期优化，但不替代对象资产本体，也不覆盖事实记录层。

## 九、对象候选、正式对象与生命周期边界

对象资产层必须区分候选对象、正式对象和对象状态投影。

候选对象是从原始输入、AI 辅助抽取、接口载荷、上传资料、页面录入或外部反馈中识别出的对象线索。候选对象不是正式对象资产，不得直接被事实记录层、汇总视图层或经验规则层作为正式对象消费。

正式对象是经过对象类型判断、归属确认、重复校验、冲突处理、必要补齐、权限判断和追溯记录后进入对象资产层的稳定对象。

对象状态投影是正式对象基于事实记录、确认记录或治理记录形成的当前状态摘要。对象状态投影不得替代事实证据，不得无来源更新，不得无痕覆盖。

对象生命周期应至少覆盖以下治理动作：

1. 创建；
2. 更新；
3. 补齐；
4. 合并；
5. 拆分；
6. 归档；
7. 作废；
8. 恢复；
9. 状态变更；
10. 关系变更；
11. 来源修正；
12. 版本回滚。

上述治理动作之间的流转关系、前置条件、权限要求、状态名称、状态流转、字段要求和校验规则，由 `30_标准治理/状态口径总表` 及对应对象资产细则承接。本文只定义对象资产层需要支持的治理动作范围，不定义完整对象状态机，不授权开发自行推导归档后恢复、作废后恢复、合并后回滚、拆分后回滚等具体流转路径。

## 十、对象归属、关系、别名与合并拆分

对象资产必须具备清晰归属。归属不明时，应进入待补、挂起、人工确认或治理回流，不得直接作为正式对象放行。

对象归属应遵守以下规则：

1. 组织资产应明确组织归属和资源归属；
2. 项目资产应明确所属组织、项目范围和项目参与关系；
3. 主体资产应明确主体类型、内部 / 外部属性和可见性边界；
4. 物资资产应明确组织、项目、仓库、库存池或使用范围归属；
5. 资料资产应明确组织归属，并尽可能明确项目、主体、事实或证据归属。

对象关系应遵守以下规则：

1. 对象之间可以建立项目参与、主体关系、资料引用、物资关联、组织归属等稳定关系；
2. 对象关系变化如构成业务事实，应进入事实记录层；
3. 当前关系摘要可以作为对象状态投影，但必须能够追溯；
4. 关系记录不得被对象字段静默替代；
5. 对象关系不得绕过权限和可见性约束向无权限角色暴露。

对象别名、对象合并和对象拆分应遵守以下规则：

1. 别名只能帮助识别对象，不得替代正式对象标识；
2. 同一对象存在多个称呼时，应形成别名候选、冲突判断和人工确认；
3. 对象合并不得删除旧对象痕迹，应保留来源、原因、操作者、时间和映射关系；
4. 对象拆分不得覆盖原对象，应形成新对象和来源关系；
5. 对象重复、对象冲突、主体身份不清、项目归属不清、资料证据链断裂时，不得静默放行。

## 十一、对象可见性与权限边界

对象资产层必须承接权限与可见性要求，但不展开完整权限矩阵。

对象可见性应遵守以下原则：

1. 用户只能查看其权限范围内的对象资产；
2. 用户只能基于其权限范围录入、补齐、确认或修改对象信息；
3. 外部对象只能按授权范围参与提交、确认、反馈或查看裁剪后的对象相关信息；
4. 客户、甲方、供应商、班组、外部协作者不得直接访问内部组织真源、内部成本、内部责任判断或内部经营分析；
5. AI 不拥有对象确认权、对象合并权、对象作废权、对象权限变更权或高风险对象操作权；
6. 页面展示对象时，应以后端返回的权限裁剪结果为准；
7. 导出包、分享包和对外展示内容不得绕过对象可见性边界。

对象可见性、字段脱敏、外部展示、角色范围、动作权限和审计要求由标准治理、接口边界、页面承接和验证与验收规则继续定义。

## 十二、对象资产与 L0-L7 的关系

对象资产层贯穿 L0-L7 纵向运行链路，但不替代运行规则。

| 运行层级 | 对象资产层关系 |
|---|---|
| L0 原始输入 | 原始输入中可能包含项目名、客户、甲方、人员、资料、物资、组织节点等对象线索 |
| L1 候选抽取 | 从原始输入中形成候选组织、候选项目、候选主体、候选物资、候选资料、别名候选和对象缺口 |
| S2 校验 | 对对象类型、对象归属、对象重复、对象冲突、关键字段缺失、来源不明、权限不足等情况进行校验、待补、挂起、驳回或人工确认判断 |
| 人工确认 | 对对象合并、拆分、作废、关键归属、主体身份、资料证据链、高风险对象变更等动作进行必要确认 |
| L2 真源入链 | 将符合校验、确认、权限和追溯要求的对象写入正式对象资产 |
| L3 结果生成 | 基于正式对象和正式事实生成清单、台账、摘要、视图和资料缺口输出 |
| L4 分析判断 | 基于对象维度进行风险、偏差、趋势、异常和经营分析，不创造对象事实 |
| L5 建议编排层 | 基于对象关系、对象状态和事实链形成建议候选，不替代正式决策 |
| L6 执行响应 | 执行动作必须绑定对象资产或候选对象，不允许无对象高风险动作 |
| L7 反馈回流 | 回流内容不得直接覆盖对象资产，应先形成候选对象、对象待补项或对象治理回流 |

L0、L1、页面状态、交互缓存、任务状态、AI 输出和接口载荷不得直接成为正式对象资产。

## 十三、对象资产与标准治理的关系

对象资产层必须接受标准治理约束。

标准治理对对象资产层至少提供以下约束：

1. 对象类型命名；
2. 对象主标识规则；
3. 对象字段命名与字段归口；
4. 对象生命周期状态；
5. 对象来源类型；
6. 对象重复、冲突、待补、挂起和驳回判断；
7. 对象合并、拆分、归档、作废和恢复规则；
8. 对象权限与可见性；
9. 对象脱敏与外部展示；
10. 对象版本、快照、日志、审计、证据链和回滚要求；
11. AI 候选对象输出边界；
12. 前端补全提示和反问字段归口。

对象资产层不得自行发布字段全集、枚举全集、状态机、权限矩阵、校验规则全集或追溯字段全集。对象资产层只能提出对象治理需求，具体标准项由标准治理文件承接。

## 十四、资料资产特别边界

资料资产属于对象资产层，不得另起独立资料体系，也不得被降级为普通附件库。

资料资产承接资料对象本体。资料记录承接资料过程事实。两者边界如下：

1. 资料资产回答“这份资料是什么、属于谁、当前主版本是什么、主要支撑什么”；
2. 资料记录回答“这份资料何时形成、上传、提交、补齐、确认、退回、引用、作废、归档”；
3. 附件、图片、文件、截图、表格、录音、PDF、WPS 文件等可以成为资料资产的载体，但载体存在不等于正式资料资产成立；
4. 文件名、聊天记录描述、页面标签、自然语言摘要不得替代资料资产正式识别；
5. 资料被上传成功，不等于资料被确认，不等于事实成立；
6. 资料被视图展示，不等于资料可反写事实；
7. 资料作为证据时，应绑定相关事实、项目、主体、时间、确认和追溯依据。

合同、报价、预算、图纸、照片、签证、验收资料、结算资料、付款凭证、发票回执、客户确认材料、归档材料等，首先作为资料资产承接；其签署、提交、确认、变更、退回、补齐、结算引用等过程，按事实记录层归口承接。

## 十五、禁止混写与反向定义规则

对象资产层必须防止以下混写和反向定义：

1. 把对象资产写成事实流水；
2. 把事实记录写成对象主数据；
3. 把项目资产写成项目看板；
4. 把主体资产写成客户画像或关系流水；
5. 把物资资产写成物资流转记录；
6. 把资料资产写成资料上传过程；
7. 把资料附件、文件名、截图或页面标签当作正式资料资产；
8. 把原始输入、AI 输出、页面状态、接口回执、模板输出或导出结果直接写成正式对象；
9. 让汇总视图层反向修改对象资产；
10. 让经验规则层反向覆盖对象资产；
11. 让对象状态投影替代事实证据；
12. 静默合并对象、静默拆分对象、静默覆盖对象字段或无证据更新对象状态；
13. 用数据库表、接口字段、页面入口、代码模型名或历史旧称反向定义对象资产层；
14. 历史旧称、旧目录、旧分类体系或旧数据模型不得反向覆盖当前对象资产层的正式对象分类和命名；例如“人物资产”“System 领域”“type / subtype 分类体系”等旧称或旧分类只能作为历史参考线索，不得升格为正式对象资产层口径；
15. 把分步实施、页面便利、接口便利、技术预留或架构预留能力作为绕过治理和追溯的理由，也不得把架构预留能力表述为当前已完成能力；
16. 把对象资产层扩写成完整 ERP、CRM、OA、仓储系统、资料库或客户门户。

发现上述问题时，应按顶层定义、系统架构、标准治理、业务数据体系、系统业务运行规则、接口边界、页面承接和验证与验收规则的职责顺序归口处理，不得在对象资产层直接新增未被支撑的字段、枚举、状态、权限、接口、页面或事实类型。

## 十六、下游承接规则

`01_对象资产层` 内部文件应按以下职责承接：

| 下游文件 | 承接内容 | 不得突破 |
|---|---|---|
| `01_组织资产细则.md` | 公司、组织节点、仓库、库存池、共享资源、组织级规则归属、组织级模板归属 | 不写项目执行过程，不写完整组织制度，不替代权限治理 |
| `02_项目资产细则.md` | 项目本体、项目范围、项目阶段、项目状态投影、项目参与关系、项目归档 | 不写施工事实、财务事实、资料事实、结算过程 |
| `03_主体资产细则.md` | 客户、甲方、供应商、班组、员工、设计师、联系人、外部协作者等主体对象 | 不写主体行为流水，不写完整客户画像，不替代关系记录 |
| `04_物资资产细则.md` | 材料、设备、工具、库存物品、规格型号、状态投影和物资归属 | 不写采购、入库、领用、调拨、损耗、付款等过程事实 |
| `05_资料资产细则.md` | 合同、报价、预算、图纸、照片、签证、验收资料、结算资料、凭证、确认材料等资料对象 | 不写资料上传、提交、补齐、确认、退回、引用、归档过程 |

下游细则可以细化对象类型、对象成立条件、对象归属、对象关系、对象候选、对象状态投影和对象追溯要求，但不得反向改变对象资产层总边界，不得替代事实记录层、汇总视图层、经验规则层和标准治理。

## 十七、判断口径

本文成立，应满足以下判断口径：

1. 能明确对象资产层只承接稳定对象，不承接单次过程事实；
2. 能说明临时性、单项目内的一次性组合对象不得直接进入正式对象资产层；
3. 能稳定区分组织资产、项目资产、主体资产、物资资产和资料资产；
4. 能说明对象资产为事实记录层提供对象锚点；
5. 能说明对象合并、作废、拆分、恢复或归档后，已入链事实引用不得被自动替换；
6. 能说明对象资产为汇总视图层提供聚合维度；
7. 能说明对象资产为经验规则层提供适用对象范围；
8. 能说明候选对象、正式对象和对象状态投影的边界；
9. 能说明资料资产属于对象资产层，资料记录属于事实记录层；
10. 能防止原始输入、AI 输出、页面状态、接口回执、模板输出、导出结果或历史旧称反向定义正式对象；
11. 没有写入字段全集、枚举全集、状态机、权限矩阵、接口 schema、页面组件、数据库表、代码实现、测试脚本或实施计划；
12. 能支撑五类对象资产细则继续展开。
