# 12_商务维护记录细则

## 一、文件定位

本文是 `40_业务数据体系/02_事实记录层` 下的商务维护记录细则文件，用于定义客户、甲方、供应商、班组、合作方、外部介绍人、设计师、渠道方、潜在客户、既有客户和其他商务相关主体在跟进、维护、回访、复购、转介绍、合作意向、商务承诺、报价沟通、关系推进、供应协同和合作终止等过程中的事实边界、入链条件、对象锚点、来源证据、确认要求、追溯要求，以及与主体资产、项目资产、沟通与服务记录、决策与变更记录、财务记录、问题与风险记录、责任与确认记录、履历记录、汇总视图层和经验规则层的关系。

商务维护记录用于回答“围绕哪个主体、项目、机会、合作关系或商务事项，发生了什么维护动作、跟进动作、复购线索、转介绍线索、合作意向或关系变化，依据是什么，后续如何被经营视图、执行视图、交付与协同视图和经验沉淀消费”。

本文只定义商务维护过程事实的业务边界和开发依据，不替代主体资产、项目资产、组织资产、沟通与服务记录、财务记录、决策与变更记录、问题与风险记录、责任与确认记录、履历记录、完整 CRM 系统、完整供应商管理系统、合同管理系统、销售管理系统、财务结算系统、接口 schema、页面组件、数据库表结构或代码实现。本文不写字段全集、枚举全集、状态机、权限矩阵、测试脚本或实施计划。

## 二、商务维护记录职责

商务维护记录的核心职责，是把经营执行中围绕客户、甲方、供应商、班组、合作方和外部渠道的维护、跟进、复购、转介绍、合作机会和关系变化过程沉淀为可追溯事实。

商务维护记录承担以下职责：

1. 定义商务维护类事实的成立条件；
2. 定义客户跟进、甲方维护、供应商维护、班组维护、合作方维护、复购线索、转介绍线索、合作意向、报价跟进、商务承诺、合作调整和合作终止的边界；
3. 定义商务维护记录必须绑定主体、项目、组织、业务场景、来源证据和时间口径的规则；
4. 定义商务维护记录与主体资产、项目资产之间的分层关系；
5. 定义商务维护记录与沟通与服务记录、决策与变更记录、财务记录、问题与风险记录、责任与确认记录、履历记录之间的边界；
6. 定义商务维护记录如何支撑经营视图、执行视图、结算视图、交付与协同视图和经验规则层；
7. 定义候选商务维护事实与正式商务维护事实的边界；
8. 定义商务维护记录不得被页面标签、AI 评价、视图摘要、客户画像、供应商画像、模板输出、主观印象或历史旧称反向定义。

商务维护记录不定义主体本体，不自动形成客户价值等级，不自动形成供应商等级，不自动形成合作准入，不自动生成成交结论，不自动形成合同成立，不自动确认收付款，不自动裁决责任，不自动形成黑名单或淘汰结论。

## 三、上位约束

商务维护记录必须服从以下上位约束：

1. 事实记录层只承接真实发生或经确认的过程，不承接稳定对象本体；
2. 商务维护记录是事实记录层中的事实类型之一，不得扩写成完整 CRM 系统、销售系统、供应商评级系统或渠道管理系统；
3. 商务相关主体应绑定主体资产或候选主体，不得以昵称、电话、微信名、公司简称、渠道称呼、客户备注或页面标签直接替代主体锚点；
4. 项目相关商务维护应绑定项目资产；组织级、客户级、供应商级或渠道级维护应绑定组织资产、主体资产或业务场景；
5. 商务维护记录应绑定来源事实、时间口径、维护事项、权限判断和审计追溯；
6. 涉及报价、合同、承诺、价格、付款、结算、回扣、赔付、责任、客户评价、供应商评价、黑名单、合作终止和对外展示的商务维护内容，应按高风险事实或高风险候选处理；
7. 汇总视图层可以消费商务维护记录，但不得反写商务维护事实；
8. 经验规则层可以从商务维护记录中沉淀客户维护经验、供应商协同经验、复购经验、转介绍经验、风险识别经验和规则候选，但不得覆盖商务维护事实；
9. AI 可以辅助整理候选跟进、候选机会、候选风险、候选标签和待补提示，但不得自动确认正式商务结论、正式客户等级、正式供应商等级、正式成交、正式合同、正式承诺或正式责任；
10. 页面标签、视图摘要、AI 评价、客户画像、供应商画像、模板输出、导出包、分享包、前端 Mock 状态和历史资料，不得直接成为正式商务维护事实；
11. 历史旧称、旧分类体系、数据库表名、接口字段名、页面入口和代码模型名不得反向定义商务维护记录。

## 四、商务维护事实成立条件

一条内容能够进入商务维护记录，应同时满足以下条件：

1. 有明确主体资产、候选主体、客户主体、甲方主体、供应商主体、班组主体、合作方主体、渠道主体、介绍人主体或外部协同主体；
2. 有明确项目资产、组织资产、业务场景、合作场景、服务场景、商机线索或候选归属锚点；
3. 有明确商务维护事项，例如跟进、回访、维护、报价沟通、合作意向、复购线索、转介绍线索、供应协同、商务承诺、合作调整、合作暂停或合作终止；
4. 有发生时间、跟进时间、回访时间、确认时间、记录时间、时间范围或明确未知时间标记；
5. 有来源或证据；
6. 能说明商务维护类型、参与主体、维护事项、来源事实、业务结果、下一步线索、风险提示、待补内容或关联对象中的至少一种；
7. 有状态口径；
8. 有权限判断；
9. 涉及报价、合同、付款、结算、承诺、客户价值、供应商评价、渠道收益、责任、黑名单、合作终止或对外展示时，具备必要确认或待确认标记；
10. 具备审计追溯依据；
11. 不与已入链商务维护事实产生未处理冲突。

来源或证据存在，但其中的主体身份、项目归属、业务场景、商务事项、时间、来源事实、承诺范围或评价依据不清的，不视为无来源，应视为主体待识别、项目待补、业务场景待补、事项待补、时间待补、来源待补或依据待补，进入待补、校验、挂起、驳回或人工确认流程，不得直接正式入链。

“待补、校验、挂起、驳回或人工确认流程”是事实记录层通用治理动作集合。各动作的触发条件、状态流转、权限要求、字段要求、提示规则和人工处理路径，由标准治理中的状态口径、校验规则、权限与可见性口径、追溯与版本口径，以及后续事实记录层通用治理流程承接。本文只在商务维护场景中指出应进入治理流程的业务情形，不定义完整状态机。

以下内容不得直接作为正式商务维护记录：

1. 只有姓名、电话、公司名、客户备注或一句“这个客户不错”的无锚点描述；
2. 未识别主体、项目、业务场景、时间或来源的聊天截图、客户备注、供应商介绍、电话记录、语音转文字或图片摘要；
3. AI 从沟通记录、施工记录、财务记录、履历记录、问题记录或视图摘要中推测出的客户价值、供应商等级、合作机会或成交结论；
4. 页面标签、前端草稿、接口载荷、模板输出、经营视图、客户画像、供应商画像、导出包中的主体描述；
5. 未能区分是主体资产、沟通服务、商务维护、决策变更、财务事实、问题风险、责任确认还是履历沉淀的混合描述；
6. 无权限来源提交的客户评价、供应商评价、合作评级、黑名单建议或渠道承诺；
7. 缺少必要主体锚点、来源事实、时间口径或证据链的高风险商务维护内容。

上述内容应先作为候选商务维护事实、候选主体、待补项、待确认项、原始输入或运行中间数据处理。只有完成必要锚定、补齐、校验、权限判断和追溯后，才能进入正式商务维护记录。

## 五、商务维护记录承接范围

商务维护记录承接以下事实范围：

| 商务维护类型 | 承接内容 | 不承接内容 | 主要作用 |
|---|---|---|---|
| 客户跟进 | 对潜在客户、既有客户、复购客户的联系、跟进、回访和需求线索 | 客户主体本体、正式合同成立 | 客户维护、经营线索、后续服务 |
| 甲方维护 | 对甲方、甲方代表、甲方员工或甲方协同方的关系维护、反馈跟进和协同线索 | 甲方主体本体、正式确认链路 | 项目协同、关系追溯、风险提示 |
| 供应商维护 | 对供应商供货、服务、协作、价格、质量、响应和关系变化的维护记录 | 供应商主体本体、供应商等级自动确认 | 供应协同、风险识别、后续选择参考 |
| 班组维护 | 对班组合作、响应、质量、配合、问题、复用和后续安排的维护记录 | 班组主体本体、工资结算 | 班组协作、履历线索、项目安排 |
| 合作方维护 | 对设计师、介绍人、渠道方、外部协作者等合作方的跟进和维护 | 合作方主体本体、完整渠道管理系统 | 协作关系、转介绍线索、经营视图 |
| 复购线索 | 既有客户、甲方、合作方再次产生项目、服务或维护需求的线索 | 成交结论、合同成立 | 经营机会、客户维护、后续跟进 |
| 转介绍线索 | 客户、甲方、合作方、员工或外部主体提供的新线索、新客户或新项目机会 | 新客户正式主体自动确认、成交结论 | 获客线索、渠道追溯、经营分析 |
| 报价跟进 | 报价沟通、价格反馈、预算沟通、报价调整线索 | 价格确认、财务事实、合同成立 | 商务推进、决策变更候选 |
| 商务承诺 | 对服务、价格、工期、优惠、售后、资料、交付等商务性承诺线索 | 正式责任确认、合同条款自动成立 | 风险提示、后续确认、责任线索 |
| 合作调整 | 合作方式、合作范围、供应关系、服务方式或协作关系调整线索 | 正式决策变更、责任裁决 | 关系演进、经营视图、履历线索 |
| 合作终止 | 暂停合作、终止合作、不再合作、供应退出、客户流失等过程事实 | 黑名单、法律责任、终局评价 | 风险复盘、关系追溯、后续筛选 |
| 商务维护修正 | 对已记录商务维护的补充、修订、作废、归档、来源修正或版本回滚 | 静默覆盖旧记录 | 事实纠错、版本保护、审计追溯 |

商务维护记录承接商务维护过程事实，不承接主体对象本体、项目对象本体、合同成立事实、财务收付款事实、责任终局裁决、完整客户关系体系、完整供应商评级体系或完整销售管理体系。

## 六、商务维护记录不承接范围

以下内容不得写入商务维护记录本体：

| 内容 | 正确归口 | 原因 |
|---|---|---|
| 客户、甲方、供应商、班组、介绍人、设计师、渠道方等主体本体 | 主体资产 | 属于稳定主体对象 |
| 项目本体、项目范围、项目阶段、项目状态投影 | 项目资产 | 属于稳定项目对象 |
| 组织、公司、部门、资源池等组织对象 | 组织资产 | 属于稳定组织对象 |
| 客户沟通、甲方沟通、投诉沟通、服务响应过程 | 沟通与服务记录 | 属于沟通服务事实 |
| 报价确认、价格确认、范围调整、合同承诺、签证变更 | 决策与变更记录 | 属于决策变更事实 |
| 收付款、报销、开票、结算确认、退款 | 财务记录 | 属于财务事实 |
| 问题成立、风险识别、整改过程、合作风险闭环 | 问题与风险记录 | 属于问题风险事实 |
| 正式责任确认、授权确认、客户确认、甲方确认 | 责任与确认记录 | 属于确认链路事实 |
| 主体项目参与经历、供应商协作经历、客户服务经历 | 履历记录 | 属于主体经历沉淀 |
| 客户画像、供应商画像、经营看板、商机清单、转介绍台账 | 汇总视图层、模板输出或业务输出 | 属于输出结果 |
| 客户维护经验、供应商筛选规则、转介绍经验、风险识别规则 | 经验规则层 | 属于经验规则沉淀 |
| 完整 CRM、完整销售系统、供应商评级系统、渠道管理系统 | 后续运行规则、外部系统或专门规则 | 超出本文职责 |
| AI 评价、页面标签、接口载荷、模板输出、导出包、分享包 | 候选内容或运行中间数据 | 不能直接成为正式商务维护事实 |

商务维护记录不得因为某项内容“涉及客户”“涉及供应商”“可能带来项目机会”或“可用于经营分析”而直接吸收该内容本身。被商务维护记录提及的主体、项目、沟通、报价、财务、责任、问题风险和履历，应按对应层级和事实类型归口。

## 七、主体资产与商务维护记录边界

主体资产回答“这个主体是谁”，商务维护记录回答“围绕这个主体发生了什么商务维护、跟进、协作或关系推进过程”。

二者边界如下：

| 对比项 | 主体资产 | 商务维护记录 |
|---|---|---|
| 所属层级 | 对象资产层 | 事实记录层 |
| 主问题 | 主体是谁 | 围绕主体发生了什么商务维护过程 |
| 核心内容 | 名称、类型、身份、联系方式、关系、归属、状态投影 | 跟进、回访、复购、转介绍、合作意向、供应协同、合作调整 |
| 是否记录单次过程 | 否 | 是 |
| 是否承接主体本体 | 是 | 否 |
| 是否承接商务过程事实 | 否 | 是 |
| 是否可作为视图消费来源 | 是 | 是 |
| 是否自动形成等级 | 否 | 否 |
| 是否自动形成成交或淘汰 | 否 | 否 |

商务维护记录与主体资产应遵守以下规则：

1. 主体资产承接客户、甲方、供应商、班组、合作方、介绍人等主体本体；
2. 商务维护记录承接围绕主体发生的商务维护过程事实；
3. 主体资产不得吸收跟进、回访、报价沟通、复购线索、转介绍线索、供应协同、合作终止等过程动作；
4. 商务维护记录不得定义主体正式名称、主体类型、联系方式、长期归属、主体关系和对象状态；
5. 商务维护记录可以触发主体候选创建、主体合并候选、主体身份修订候选或主体关系待确认，但不得静默覆盖主体资产；
6. 主体资产发生合并、作废、归档或版本变更后，已入链商务维护记录应保留原主体引用，不得自动替换；
7. 如需修订商务维护记录与主体资产之间的引用关系，应进入治理流程，并保留原引用、修订原因、操作者、时间、版本和追溯依据。

## 八、客户、甲方与服务维护边界

客户维护、甲方维护和沟通服务必须区分。

客户维护侧重潜在客户、既有客户、复购客户和服务客户的关系跟进、需求线索、回访反馈、复购线索和转介绍线索。甲方维护侧重甲方、甲方代表、甲方员工或甲方协同方的关系维护、协同线索、反馈跟进和商务关系变化。沟通与服务记录侧重具体沟通过程和服务响应过程。

客户和甲方维护应遵守以下规则：

1. 客户或甲方主体本体归主体资产；
2. 客户沟通、甲方沟通、投诉沟通和服务响应过程归沟通与服务记录；
3. 围绕后续合作、复购、转介绍、商务机会、关系变化、服务回访和经营维护形成的过程事实，可以归商务维护记录；
4. 客户满意、客户价值、合作等级、流失风险和复购概率属于归纳性内容，不得由商务维护记录自动确认；
5. 涉及客户承诺、甲方承诺、价格、工期、范围、资料、验收或责任的内容，应转入决策与变更记录或责任与确认记录；
6. 涉及投诉、重大不满、争议、风险或合作中断的内容，应转入问题与风险记录或责任与确认记录；
7. 对外展示客户或甲方维护内容时，应接受权限、脱敏和确认约束。

商务维护记录可以保留客户或甲方相关维护线索，但不得替代沟通与服务记录记录具体沟通过程，不得替代责任与确认记录确认正式承诺。

## 九、供应商、班组与合作方维护边界

供应商维护、班组维护和合作方维护必须区分。

供应商维护侧重供应商供货、响应、价格、质量、退换、配合和后续合作线索。班组维护侧重班组合作、施工配合、响应、质量、人员稳定、复用安排和问题线索。合作方维护侧重设计师、介绍人、渠道方、外部协作者等主体的合作关系推进和机会来源追溯。

供应商、班组和合作方维护应遵守以下规则：

1. 供应商、班组、合作方主体本体归主体资产；
2. 采购、入库、退换、物资流转过程归物资流转记录；
3. 班组出勤、工时、工天归出勤记录；
4. 施工过程、质量和现场完成状态归施工记录；
5. 付款、结算、扣款、报销和开票归财务记录；
6. 供应商、班组、合作方的长期协作经历和项目参与经历可以形成履历记录；
7. 供应商等级、班组等级、合作方价值和渠道贡献不得由单条商务维护记录自动确认；
8. 涉及合作终止、黑名单、扣款、赔付、责任或重大争议时，应转入问题与风险记录或责任与确认记录。

商务维护记录可以承接供应商、班组和合作方维护线索，但不得自动形成供应商评级、班组评级、渠道结算或合作准入结论。

## 十、复购线索、转介绍线索与商机边界

复购线索、转介绍线索和商机结果必须区分。

复购线索是既有客户、甲方或合作主体再次产生服务、项目、维修、整改、扩项或新项目需求的线索。转介绍线索是客户、甲方、员工、供应商、班组、合作方或外部主体提供的新客户、新项目或新合作机会线索。商机结果、合同成立、项目成立和收付款事实不由商务维护记录自动确认。

复购线索应遵守以下规则：

1. 复购线索应绑定原主体、原项目或服务场景、需求内容、发生时间和来源证据；
2. 复购线索不等于成交；
3. 复购线索不等于合同成立；
4. 复购线索不等于项目资产已创建；
5. 复购线索不等于客户价值已确认；
6. 复购线索进入项目立项、报价确认、合同确认或财务收款时，应转入对应事实类型或对象资产流程。

转介绍线索应遵守以下规则：

1. 转介绍线索应绑定介绍主体、被介绍主体或候选主体、线索内容、发生时间和来源证据；
2. 转介绍线索不等于新客户正式主体已确认；
3. 转介绍线索不等于成交；
4. 转介绍线索不等于介绍收益、返利、佣金或责任成立；
5. 涉及返利、佣金、利益分配或渠道承诺时，应进入决策与变更记录、财务记录或责任与确认记录；
6. 转介绍线索用于对外展示或内部激励时，应具备必要确认和权限控制。

商机边界应遵守以下规则：

1. 商务维护记录可以保留商机线索；
2. 商机线索不等于项目资产；
3. 商机线索不等于合同；
4. 商机线索不等于收入；
5. 商机线索不等于客户等级；
6. AI、页面标签、视图评分或模板输出不得自动确认商机结果。

## 十一、报价跟进、商务承诺与决策变更边界

报价跟进、商务承诺和决策变更必须区分。

报价跟进侧重围绕报价意向、报价反馈、预算沟通、客户接受度、供应商报价、价格敏感点和后续沟通安排形成的商务过程事实。价格确认、范围调整、优惠承诺、工期承诺、资料承诺、售后承诺和合同条款确认，应按决策与变更记录或责任与确认记录处理。

报价跟进应遵守以下规则：

1. 报价沟通、报价反馈、预算沟通和价格敏感点可以进入商务维护记录；
2. 报价跟进不等于价格确认；
3. 报价跟进不等于合同成立；
4. 报价跟进不等于客户承诺；
5. 报价跟进不等于收款事实；
6. 报价资料本体归资料资产，报价资料形成和提交归资料记录；
7. 报价确认、价格确认、优惠确认、范围调整和签证变更，应归决策与变更记录。

商务承诺应遵守以下规则：

1. 商务维护记录可以保留承诺线索；
2. 正式承诺确认应归责任与确认记录或决策与变更记录；
3. 客户口头反馈不等于正式承诺；
4. 甲方口头反馈不等于正式承诺；
5. 页面标签、AI 摘要、报价草稿和模板输出不得自动形成商务承诺；
6. 涉及金额、工期、范围、质量、售后、赔付、扣款或对外发布的承诺，应按高风险事实处理。

## 十二、合作调整、合作终止与风险边界

合作调整和合作终止属于高风险商务维护内容，应保留完整来源和追溯依据。

合作调整应遵守以下规则：

1. 合作方式、合作范围、协作对象、供应关系、渠道关系、服务方式或维护策略变化，可以形成合作调整记录；
2. 合作调整不等于主体资产本体被修改；
3. 合作调整不等于合同变更已成立；
4. 合作调整不等于责任确认；
5. 合作调整涉及价格、范围、工期、材料、供应、客户承诺或付款安排时，应归决策与变更记录或财务记录；
6. 合作调整不得由 AI、页面标签或视图分析自动确认。

合作终止应遵守以下规则：

1. 合作暂停、不再合作、供应退出、客户流失、渠道终止等，可以形成合作终止线索或合作终止记录；
2. 合作终止不等于黑名单；
3. 合作终止不等于责任成立；
4. 合作终止不等于法律结论；
5. 合作终止应说明主体、原因、时间、来源、影响范围和确认依据；
6. 合作终止涉及合同、款项、责任、赔付、投诉或对外展示时，应转入问题与风险记录、责任与确认记录、财务记录或决策与变更记录。

风险边界应遵守以下规则：

1. 商务维护记录可以保留合作风险、流失风险、供应风险、渠道风险和客户风险线索；
2. 风险线索不等于问题成立；
3. 风险线索不等于责任确认；
4. 风险线索不等于等级调整；
5. 风险线索进入闭环处理时，应转入问题与风险记录；
6. 风险线索用于主体筛选、合作终止或内部奖惩时，应按高风险内容处理。

## 十三、商务维护时间与版本边界

商务维护记录必须区分跟进时间、回访时间、沟通时间、确认时间、计划下次跟进时间、系统记录时间和修订时间。

| 时间类型 | 含义 | 边界 |
|---|---|---|
| 跟进时间 | 商务跟进、维护或联系发生的时间 | 不代表成交时间 |
| 回访时间 | 对客户、甲方、供应商或合作方进行回访的时间 | 不代表满意度结论 |
| 沟通时间 | 与商务维护事项相关的沟通发生时间 | 不代表正式承诺 |
| 确认时间 | 商务维护事项被人工确认或来源事实确认的时间 | 不替代发生时间 |
| 计划下次跟进时间 | 后续维护计划或提醒时间 | 不代表事实已发生 |
| 系统记录时间 | 用户、页面、接口或系统记录候选商务维护的时间 | 不代表商务维护实际发生时间 |
| 修订时间 | 对商务维护记录进行补充、修订、作废或引用修订的时间 | 不得覆盖原事实时间 |

商务维护时间不清时，应明确未知、待补或待确认，不得用默认当前时间冒充事实发生时间。沟通时间、资料时间、报价时间、确认时间、系统时间或多个来源时间不一致时，应进入待补、校验、挂起、驳回、人工确认或事实修订流程。

商务维护记录变更不得无痕覆盖。补充、修订、作废、归档、引用修订、来源修正和版本回滚，应保留原记录、变更原因、操作者、时间、版本、影响范围和追溯依据。

## 十四、证据、来源与确认要求

商务维护记录应绑定来源或证据。来源可以来自人工录入、沟通与服务记录、项目记录、主体资产、资料记录、财务记录、问题与风险记录、责任与确认记录、履历记录、复盘与反馈记录、页面录入、接口载荷、外部反馈或其他可追溯来源。

证据与来源应遵守以下规则：

1. 来源存在不等于商务维护事实成立；
2. 主体名称存在不等于主体已确认；
3. 项目名称存在不等于项目归属已确认；
4. 聊天记录存在不等于正式承诺成立；
5. 报价记录存在不等于价格确认成立；
6. 客户反馈存在不等于客户价值结论；
7. 供应商反馈存在不等于供应商等级结论；
8. AI 摘要不等于商务维护结论；
9. 页面标签不等于正式商务维护事实；
10. 视图摘要不等于商务维护事实本体；
11. 证据链断裂时，不得直接生成正式商务维护结论；
12. 证据冲突时，应进入待补、校验、挂起、驳回或人工确认流程。

影响客户评价、供应商评价、合作等级、返利佣金、合同、报价、承诺、付款、责任、黑名单、合作终止或对外展示的商务维护记录，应具备必要人工确认或明确待确认标记。

## 十五、候选商务维护事实与正式商务维护事实

商务维护记录必须区分候选商务维护事实和正式商务维护事实。

候选商务维护事实来源包括：

1. 用户手动录入；
2. 主体资产线索；
3. 项目记录；
4. 沟通与服务记录；
5. 资料记录；
6. 财务记录；
7. 决策与变更记录；
8. 问题与风险记录；
9. 责任与确认记录；
10. 履历记录；
11. 复盘与反馈记录；
12. 日报周报；
13. 视图摘要；
14. 页面标签；
15. 外部反馈；
16. 接口载荷；
17. AI 辅助摘要；
18. 导入记录。

候选商务维护事实不得直接作为正式商务维护事实消费。候选商务维护事实进入正式商务维护记录前，应完成以下处理：

1. 判断商务维护事实类型；
2. 识别并确认主体、项目、组织、业务场景或商务线索锚点；
3. 识别客户、甲方、供应商、班组、合作方、渠道方、介绍人或外部协同主体；
4. 识别维护事项、跟进事项、复购线索、转介绍线索、报价跟进、合作调整或风险线索；
5. 绑定来源事实或证据；
6. 识别发生时间、跟进时间、确认时间或时间范围；
7. 判断是否涉及报价、合同、付款、结算、承诺、评价、等级、黑名单、责任、争议、客户价值、供应商选择、渠道收益或对外展示；
8. 判断权限与可见性；
9. 执行必要校验；
10. 标记待补、挂起、驳回、待确认或正式状态；
11. 保留审计追溯依据。

若候选商务维护事实中包含沟通过程、财务收付款、价格确认、合同承诺、问题风险、责任确认、履历评价或项目立项，应拆分或转归口到对应事实类型，不得以商务维护记录直接放行。

## 十六、商务维护记录生命周期边界

商务维护记录生命周期应至少支持以下治理动作：

1. 创建候选商务维护事实；
2. 补齐；
3. 校验；
4. 挂起；
5. 驳回；
6. 人工确认；
7. 正式入链；
8. 客户跟进；
9. 甲方维护；
10. 供应商维护；
11. 班组维护；
12. 合作方维护；
13. 复购线索记录；
14. 转介绍线索记录；
15. 报价跟进记录；
16. 商务承诺线索记录；
17. 合作调整记录；
18. 合作终止记录；
19. 关联来源事实；
20. 补充；
21. 修订；
22. 作废；
23. 归档；
24. 引用修订；
25. 来源修正；
26. 版本回滚。

上述动作之间的流转关系、状态名称、前置条件、权限要求、字段要求和校验规则，由系统业务运行规则、标准治理中的状态口径、追溯与版本口径、权限与可见性口径或相关承接文件按职责承接。本文只定义商务维护记录需要支持的生命周期治理动作范围，不定义完整状态机。

## 十七、与汇总视图层的关系

汇总视图层可以消费商务维护记录，生成经营视图、执行视图、结算视图和交付与协同视图中的商务维护相关结果。

| 汇总视图 | 可消费内容 | 禁止项 |
|---|---|---|
| 经营视图 | 客户维护、供应商维护、复购线索、转介绍线索、合作机会、合作风险 | 不自动形成客户等级、供应商评级、成交结论或收入结论 |
| 执行视图 | 待跟进事项、待回访事项、商务阻断、客户反馈、供应商协同事项 | 不把视图摘要写成正式商务维护事实 |
| 结算视图 | 与报价、供应商、班组、客户承诺、合作收益相关的线索 | 不自动形成结算确认、付款事实或返利佣金结论 |
| 交付与协同视图 | 对外可见的客户回访、甲方协同、供应商协同和服务维护摘要 | 不暴露内部评价、责任判断或未确认高风险商务信息 |

汇总视图层只能消费正式商务维护事实和授权范围内的候选内容。视图发现主体不清、项目不清、来源不清、时间冲突、评价依据不足、权限不足或高风险事项未确认时，只能生成待补项、候选问题或治理回流，不得反写商务维护记录。

客户画像、供应商画像、商机看板、合作看板、转介绍台账、复购清单、经营分析摘要和对外展示包属于视图输出、模板输出或业务输出，不是商务维护记录本体。

## 十八、与经验规则层的关系

经验规则层可以从商务维护记录中沉淀客户维护经验、供应商协同经验、班组复用经验、复购经验、转介绍经验、报价跟进经验、合作风险识别经验和模板优化候选。

商务维护记录与经验规则层的关系如下：

1. 多条商务维护事实可以形成客户维护经验、供应商协同经验和转介绍经验；
2. 高频复购、流失、投诉、供应异常、价格敏感、合作中断可以形成候选规则或提示；
3. 商务维护事实可以支撑后续客户维护、供应商选择、项目承接和经营复盘的候选建议；
4. AI 可以辅助归纳商务维护模式，但输出默认是候选经验；
5. 经验规则层不得直接修改商务维护记录；
6. 单条商务维护事实不得直接晋升为正式规则；
7. 经验规则层发现商务维护缺口时，只能生成待补项、候选问题或治理回流。

经验规则层服务后续优化，不替代商务维护记录本体，也不替代正式事实入链。

## 十九、与接口、页面、AI 和模板的关系

商务维护记录对接口、页面、AI 和模板形成以下约束：

1. 输入接口只能提交原始商务维护输入、候选商务维护事实、待补项、确认请求或受控写入，不得绕过校验直接创建正式商务维护事实；
2. 查询接口只能读取权限范围内的商务维护记录、候选商务维护事实或商务维护维度视图；
3. 页面可以展示候选商务维护、正式商务维护、来源事实、待补事项、阻断原因、确认入口和状态提示，但不得裁决正式评价、正式等级、正式成交、正式合同、黑名单或高风险责任事项；
4. 页面补全项应以后端返回的缺失项、阻断原因、候选项和可选动作范围为准；
5. AI 可以辅助整理客户、甲方、供应商、班组、合作方、项目、沟通、资料、问题风险、确认和复盘记录中的商务维护内容，生成候选摘要、候选线索、候选标签和待补提示，但不得自动确认正式商务维护事实；
6. 模板可以读取商务维护记录生成客户跟进摘要、供应商协作摘要、复购线索清单、转介绍线索清单、项目复盘摘要或经营视图草稿，但模板输出不得创建或修改正式商务维护事实；
7. 导出包、分享包、客户画像、供应商画像、经营看板和对外展示内容中的商务维护描述，不得反向修改商务维护记录；
8. 涉报价、合同、付款、结算、承诺、评价、等级、黑名单、责任、渠道收益和对外发布的商务维护相关内容，必须接受高风险校验和必要人工确认。

## 二十、禁止混写与反向定义规则

商务维护记录必须防止以下混写和反向定义：

1. 把商务维护记录写成主体资产、项目资产或组织资产；
2. 把客户跟进写成成交结论；
3. 把复购线索写成项目资产或合同成立；
4. 把转介绍线索写成正式客户或正式成交；
5. 把报价跟进写成价格确认、收款事实或结算确认；
6. 把商务承诺线索写成正式责任确认；
7. 把供应商维护写成供应商等级或合作准入；
8. 把合作终止线索写成黑名单、责任成立或法律结论；
9. 把视图摘要、页面标签、客户画像、供应商画像、日报周报、AI 摘要、接口回执或模板输出直接写成正式商务维护事实；
10. 让汇总视图层、经验规则层、页面、接口、模板或 AI 输出反向修改商务维护记录；
11. 静默修订商务维护记录、静默替换主体锚点、静默替换项目锚点、静默替换来源事实或无证据更新商务维护状态；
12. 用数据库表、接口字段、页面入口、代码模型名或历史旧称反向定义商务维护记录；
13. 把分步实施、页面便利、接口便利、技术预留或架构预留能力作为绕过商务维护治理、权限隔离、人工确认和追溯要求的理由；
14. 把商务维护记录写成自动 CRM、自动销售系统、自动客户评级、自动供应商评级、自动成交判断、自动黑名单或自动渠道结算能力；未来如需实现相关自动化能力，应由系统业务运行规则、标准治理、接口边界、权限与状态治理、测试验收等对应文件另行定义，并不得反向改变本文的商务维护事实边界、入链条件和追溯要求。
