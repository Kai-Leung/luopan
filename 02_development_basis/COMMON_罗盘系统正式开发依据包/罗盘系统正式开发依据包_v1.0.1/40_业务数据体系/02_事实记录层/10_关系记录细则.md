# 10_关系记录细则

## 一、文件定位

本文是 `40_业务数据体系/02_事实记录层` 下的关系记录细则文件，用于定义主体与主体、主体与项目、主体与组织、主体与资料、主体与物资以及主体与特定业务事项之间发生的关系建立、关系变更、关系解除、介绍关系、合作关系、对接关系、归属关系、责任关联关系和角色挂接关系的事实边界、入链条件、对象锚点、来源证据、确认要求、追溯要求，以及与主体资产、项目资产、其他事实记录、汇总视图层和经验规则层的关系。

关系记录用于回答“谁和谁、谁和哪个项目或对象，在什么时间建立、变化或解除了一种业务关系，以及依据是什么”。

本文只定义关系事实的业务边界和开发依据，不替代主体资产、项目资产、组织资产、资料资产、物资资产、沟通与服务记录、财务记录、物资流转记录、问题与风险记录、决策与变更记录、责任与确认记录、商务维护记录、履历记录、完整关系图谱、完整 CRM 系统、权限系统、接口 schema、页面组件、数据库表结构或代码实现。本文不写字段全集、枚举全集、状态机、权限矩阵、测试脚本或实施计划。

## 二、关系记录职责

关系记录的核心职责，是把业务主体、项目、组织、资料、物资和业务事项之间已经形成或被确认的关系过程沉淀为可追溯事实。

关系记录承担以下职责：

1. 定义关系类事实的成立条件；
2. 定义主体与主体、主体与项目、主体与组织、主体与资料、主体与物资、主体与业务事项之间关系事实的边界；
3. 定义介绍关系、合作关系、对接关系、联系人关系、项目角色关系、供应关系、班组关系、归属关系、责任关联线索和关系解除的承接范围；
4. 定义关系记录必须绑定关系双方、关系对象、关系类型、关系动作、发生时间、来源证据和确认依据的规则；
5. 定义关系记录与主体资产、项目资产、资料资产、物资资产之间的分层关系；
6. 定义关系记录与沟通与服务、商务维护、决策与变更、责任与确认、问题与风险、履历记录之间的边界；
7. 定义候选关系事实与正式关系事实的边界；
8. 定义关系记录如何支撑客户确认清单、商务维护线索、项目协同、主体履历、经营视图、交付与协同视图和经验规则层；
9. 定义关系记录不得被页面标签、关系图谱、AI 评价、视图摘要、客户画像、供应商画像、模板输出、主观印象或历史旧称反向定义。

关系记录不定义主体本体，不自动形成权限，不自动确认责任，不自动确认合作成立，不自动确认合同成立，不自动确认客户承诺，不自动确认成交，不自动确认结算，不自动形成客户画像、供应商评级、班组评级或关系图谱结论。

## 三、上位约束

关系记录必须服从以下上位约束：

1. 事实记录层只承接真实发生或经确认的过程，不承接稳定对象本体；
2. 关系记录是事实记录层中的事实类型之一，不得扩写成主体资产、完整关系图谱、完整 CRM 系统、完整权限系统或完整客户关系管理系统；
3. 关系双方应绑定主体资产、项目资产、组织资产、资料资产、物资资产、业务事项或候选锚点，不得以姓名、昵称、电话、微信名、地址、备注、页面标签或 AI 摘要直接替代正式锚点；
4. 项目相关关系应绑定项目资产；组织级关系应绑定组织资产或业务场景；
5. 关系记录应绑定关系动作、关系类型、来源证据、时间口径、权限判断和审计追溯；
6. 涉及责任、授权、承诺、合同、报价、付款、结算、返佣、挂靠、分包、外部协同、客户确认、甲方确认和对外展示的关系内容，应按高风险事实或高风险候选处理；
7. 汇总视图层可以消费关系记录，但不得反写关系事实；
8. 经验规则层可以从关系记录中沉淀协作经验、介绍关系经验、合作关系经验、主体关系治理经验和规则候选，但不得覆盖关系事实；
9. AI 可以辅助识别候选关系、候选主体、候选项目、候选介绍链和待补提示，但不得自动确认正式关系、正式合作、正式责任、正式权限、正式承诺或正式客户画像；
10. 页面标签、关系图谱、视图摘要、AI 评价、客户画像、供应商画像、模板输出、导出包、分享包、前端 Mock 状态和历史资料，不得直接成为正式关系事实；
11. 历史旧称、旧分类体系、数据库表名、接口字段名、页面入口和代码模型名不得反向定义关系记录。

## 四、关系事实成立条件

一条内容能够进入关系记录，应同时满足以下条件：

1. 有明确关系动作，例如建立、变更、解除、确认、挂接、取消挂接、归属调整、角色切换或来源说明；
2. 有明确关系主体、候选主体、项目、组织、资料、物资或业务事项锚点；
3. 有明确关系另一端对象，能够说明“谁与谁”或“谁与哪个对象”发生关系；
4. 有明确关系类型，例如介绍、合作、对接、项目角色、联系人、供应、班组、归属、资料关联、物资关联、责任关联线索或私人关系参考；
5. 有发生时间、确认时间、记录时间、关系开始时间、关系结束时间、时间范围或明确未知时间标记；
6. 有来源或证据；
7. 能说明关系来源、关系依据、关系场景、关系影响范围、待补内容或关联事实中的至少一种；
8. 有状态口径；
9. 有权限判断；
10. 涉及责任、授权、承诺、合同、报价、付款、结算、返佣、挂靠、分包、外部协同、客户确认、甲方确认或对外展示等高风险关系时，具备必要确认或待确认标记；
11. 具备审计追溯依据；
12. 不与已入链关系事实产生未处理冲突。

来源或证据存在，但其中的主体身份、项目归属、组织归属、关系类型、关系动作、关系对象、时间、来源事实或确认依据不清的，不视为无来源，应视为主体待识别、对象待补、项目待补、组织待补、关系类型待补、时间待补、来源待补或依据待补，进入待补、校验、挂起、驳回或人工确认流程，不得直接正式入链。

“待补、校验、挂起、驳回或人工确认流程”是事实记录层通用治理动作集合。各动作的触发条件、状态流转、权限要求、字段要求、提示规则和人工处理路径，由标准治理中的状态口径、校验规则、权限与可见性口径、追溯与版本口径，以及后续事实记录层通用治理流程承接。本文只在关系记录场景中指出应进入治理流程的业务情形，不定义完整状态机。

以下内容不得直接作为正式关系记录：

1. 只有姓名、电话、微信名、公司名、项目名或一句“他们认识”的无锚点描述；
2. 未识别关系双方、关系对象、关系类型、关系动作、时间或来源的聊天截图、照片、客户备注、电话记录、语音转文字或图片摘要；
3. AI 从沟通记录、商务维护记录、施工记录、财务记录、问题记录、履历记录或视图摘要中推测出的正式合作、正式权限、正式责任或正式客户关系；
4. 页面标签、前端草稿、接口载荷、模板输出、关系图谱、客户画像、供应商画像、导出包中的关系描述；
5. 未能区分是主体资产、沟通服务、商务维护、关系事实、责任确认、决策变更、财务事实、问题风险还是履历沉淀的混合描述；
6. 无权限来源提交的合作关系、责任关系、挂靠关系、分包关系、介绍关系或黑名单建议；
7. 缺少必要主体锚点、关系对象、来源事实、时间口径或证据链的高风险关系内容。

上述内容应先作为候选关系事实、候选主体、候选项目、待补项、待确认项、原始输入或运行中间数据处理。只有完成必要锚定、补齐、校验、权限判断和追溯后，才能进入正式关系记录。

## 五、关系记录承接范围

关系记录承接以下事实范围：

| 关系类型 | 承接内容 | 不承接内容 | 主要作用 |
|---|---|---|---|
| 主体与主体关系 | 两个或多个主体之间形成、变化或解除的业务关系 | 主体本体、完整关系图谱 | 主体关系追溯、协作边界、经营视图 |
| 主体与项目角色关系 | 主体在项目中担任客户、甲方联系人、施工负责人、资料对接人、结算对接人、供应商、班组等角色 | 项目本体、权限系统、责任确认 | 项目协同、客户确认清单、执行视图 |
| 主体与组织关系 | 主体与公司、部门、资源池、供应链、合作组织之间的归属或协作关系 | 组织资产本体、完整组织架构 | 组织归属、协作追溯、权限线索 |
| 主体与资料关系 | 主体与资料之间的提交、持有、来源、确认、移交或关联关系 | 资料资产本体、资料记录全集 | 资料追溯、责任线索、结算准备 |
| 主体与物资关系 | 主体与物资之间的保管、借用、使用、移交、责任线索或归属关联 | 物资资产本体、物资流转记录全集 | 物资追溯、责任线索、项目协同 |
| 介绍关系 | 介绍人、被介绍人、客户、项目、合作机会或资源之间的引荐关系 | 佣金、返利、付款、成交结论 | 获客追溯、商务维护、经营分析 |
| 合作关系 | 主体之间发生合作、协作、长期对接、供应协同或服务协同关系的事实 | 合同成立、付款、完整 CRM / SRM | 协作追溯、履历沉淀、经营视图 |
| 对接关系 | 客户对接、甲方对接、资料对接、结算对接、现场对接、供应对接等关系 | 具体沟通过程、权限配置 | 协同入口、沟通归口、责任线索 |
| 责任关联线索 | 主体与事项、项目、资料、物资、问题或风险之间的责任相关关系线索 | 正式责任确认、处罚、赔付 | 责任确认前置线索、问题风险归口 |
| 归属调整关系 | 主体、项目、组织、资料、物资等对象之间归属关系发生调整的事实 | 对象本体重定义、静默替换历史引用 | 归属追溯、治理回流、历史保护 |
| 私人关系参考 | 亲属、朋友、同学、同乡、前同事、上下级等背景关系在业务中的来源说明 | 业务结论、权限放行、责任确认 | 来源说明、风险提示、沟通辅助 |
| 关系修正 | 对已记录关系的补充、修订、作废、归档、来源修正或版本回滚 | 静默覆盖旧记录 | 事实纠错、版本保护、审计追溯 |

关系记录承接关系变化过程事实，不承接主体对象本体、项目对象本体、组织对象本体、资料对象本体、物资对象本体、正式责任确认、正式权限配置、正式合同成立、正式付款结算或完整关系图谱。

## 六、关系记录不承接范围

以下内容不得写入关系记录本体：

| 内容 | 正确归口 | 原因 |
|---|---|---|
| 客户、甲方、供应商、员工、班组、介绍人、合作方等主体本体 | 主体资产 | 属于稳定主体对象 |
| 项目本体、项目范围、项目阶段、项目状态投影 | 项目资产 | 属于稳定项目对象 |
| 组织、公司、部门、资源池等组织对象 | 组织资产 | 属于稳定组织对象 |
| 资料本体、资料名称、资料版本、资料状态投影 | 资料资产 | 属于稳定资料对象 |
| 物资本体、物资名称、规格、型号、状态投影 | 物资资产 | 属于稳定物资对象 |
| 单次沟通、服务响应、投诉沟通、客户回访 | 沟通与服务记录 | 属于沟通服务事实 |
| 报价确认、范围调整、合同承诺、签证变更 | 决策与变更记录 | 属于决策变更事实 |
| 收付款、报销、开票、结算确认、返佣付款 | 财务记录 | 属于财务事实 |
| 问题成立、风险识别、整改闭环、争议处理 | 问题与风险记录 | 属于问题风险事实 |
| 正式责任确认、授权确认、客户确认、甲方确认 | 责任与确认记录 | 属于确认链路事实 |
| 客户跟进、供应商维护、复购线索、转介绍线索 | 商务维护记录 | 属于商务维护事实 |
| 主体项目参与经历、合作经历、服务经历 | 履历记录 | 属于主体经历沉淀 |
| 关系图谱、客户画像、供应商画像、主体画像 | 汇总视图层、模板输出或经验规则层 | 属于输出、归纳或候选经验 |
| 完整 CRM、完整权限系统、完整关系网系统 | 后续运行规则、外部系统或专门规则 | 超出本文职责 |
| AI 评价、页面标签、接口载荷、模板输出、导出包、分享包 | 候选内容或运行中间数据 | 不能直接成为正式关系事实 |

关系记录不得因为某项内容“涉及两个主体”“出现在关系图里”或“可用于协同判断”而直接吸收该内容本身。被关系记录提及的主体、项目、组织、资料、物资、沟通、财务、责任、问题风险、商务维护和履历，应按对应层级和事实类型归口。

## 七、主体资产与关系记录边界

主体资产回答“这个主体是谁”，关系记录回答“这个主体与另一个主体、项目、组织或对象之间发生了什么关系变化”。

二者边界如下：

| 对比项 | 主体资产 | 关系记录 |
|---|---|---|
| 所属层级 | 对象资产层 | 事实记录层 |
| 主问题 | 主体是谁 | 主体与谁或什么对象形成了什么关系 |
| 核心内容 | 名称、类型、身份、联系方式、归属、状态投影 | 关系建立、关系变更、关系解除、介绍、合作、对接、角色挂接 |
| 是否记录单次过程 | 否 | 是 |
| 是否承接主体本体 | 是 | 否 |
| 是否承接关系过程事实 | 否 | 是 |
| 是否可作为视图消费来源 | 是 | 是 |
| 是否自动形成权限 | 否 | 否 |
| 是否自动形成责任 | 否 | 否 |

关系记录与主体资产应遵守以下规则：

1. 主体资产承接主体本体；
2. 关系记录承接主体之间或主体与对象之间的关系过程事实；
3. 主体资产不得吸收介绍、合作、对接、项目角色、关系解除等过程动作；
4. 关系记录不得定义主体正式名称、主体类型、联系方式、长期归属、主体状态或主体本体关系；
5. 关系记录可以触发主体候选创建、主体合并候选、主体关系待确认或主体身份修订候选，但不得静默覆盖主体资产；
6. 主体资产发生合并、作废、归档或版本变更后，已入链关系记录应保留原主体引用，不得自动替换；
7. 如需修订关系记录与主体资产之间的引用关系，应进入治理流程，并保留原引用、修订原因、操作者、时间、版本和追溯依据。

## 八、主体与项目关系边界

主体与项目关系用于记录主体在项目中承担角色、参与协同、作为联系人、作为客户、作为甲方、作为供应商、作为班组、作为资料对接人、作为结算对接人或作为其他项目关系方的事实。

主体与项目关系应遵守以下规则：

1. 主体与项目关系必须绑定主体和项目；
2. 项目角色关系不等于项目资产本体；
3. 项目角色关系不等于主体资产本体；
4. 项目角色关系不等于权限配置；
5. 项目角色关系不等于责任确认；
6. 项目角色关系可以作为沟通、服务、资料、结算、验收、协同和履历的基础线索；
7. 项目角色来自聊天称呼、页面选择、AI 推测、资料备注或历史旧称时，应作为候选项目关系，不得直接正式入链；
8. 同一主体在不同项目、不同阶段或不同事项中可形成不同关系记录；
9. 项目归属不清时，应进入待补、校验、挂起、驳回或人工确认流程。

涉及项目责任、授权、结算、客户确认、甲方确认、对外承诺或高风险协同时，应转入责任与确认记录、决策与变更记录或对应事实记录处理。

## 九、主体与组织、资料、物资关系边界

主体与组织关系用于记录主体与公司、部门、资源池、供应链、合作组织或外部组织之间的归属、协作、挂接或解除关系。

主体与组织关系应遵守以下规则：

1. 组织本体归组织资产；
2. 主体与组织的归属、协作、挂接、解除或调整可以形成关系记录；
3. 主体与组织关系不等于权限配置；
4. 主体与组织关系不等于劳动关系、合同关系或法律关系自动成立；
5. 涉及授权、责任、合同、付款或高风险关系时，应转入责任与确认记录、决策与变更记录或财务记录；
6. 组织关系变化不得静默覆盖历史关系记录。

主体与资料关系用于记录主体与资料之间的提交、持有、来源、确认、移交、关联或责任线索。

主体与资料关系应遵守以下规则：

1. 资料本体归资料资产；
2. 资料形成、上传、补齐、退回、归档过程归资料记录；
3. 主体与资料之间的来源关系、持有关系、确认关系、移交关系和责任线索可以形成关系记录；
4. 主体与资料关系不等于资料正式确认；
5. 主体与资料关系不等于资料责任成立；
6. 涉及正式资料确认、客户确认、甲方确认或责任确认时，应转入责任与确认记录或资料记录。

主体与物资关系用于记录主体与物资之间的保管、借用、使用、移交、归属线索或责任关联线索。

主体与物资关系应遵守以下规则：

1. 物资本体归物资资产；
2. 物资采购、入库、出库、领用、调拨、退库、损耗、报废和盘点归物资流转记录；
3. 主体与物资的保管关系、借用关系、责任线索或关联关系可以形成关系记录；
4. 主体与物资关系不等于物资流转事实；
5. 主体与物资关系不等于损耗责任成立；
6. 涉及损耗、赔付、扣款、结算或责任确认时，应转入物资流转记录、问题与风险记录、财务记录或责任与确认记录。

## 十、介绍关系、合作关系与商务维护边界

介绍关系、合作关系和商务维护必须区分。

介绍关系用于记录介绍人、被介绍人、客户、项目、合作机会或资源之间的引荐事实。合作关系用于记录主体之间形成合作、协作、长期对接、供应协同或服务协同关系的事实。商务维护记录用于记录围绕客户、甲方、供应商、班组、合作方和渠道的跟进、维护、复购、转介绍、合作机会和关系推进过程。

介绍关系应遵守以下规则：

1. 介绍关系应绑定介绍主体、被介绍主体、客户主体、项目线索、合作机会或业务场景；
2. 介绍关系不等于新客户正式主体已确认；
3. 介绍关系不等于成交；
4. 介绍关系不等于合同成立；
5. 介绍关系不等于佣金、返利、报酬、渠道收益或责任成立；
6. 涉及返利、佣金、利益分配或渠道承诺时，应转入决策与变更记录、财务记录或责任与确认记录；
7. 介绍关系用于对外展示或内部激励时，应具备必要确认和权限控制。

合作关系应遵守以下规则：

1. 合作关系应说明合作主体、合作对象、合作范围、合作时间、合作来源或确认依据；
2. 合作关系不等于合同成立；
3. 合作关系不等于付款事实；
4. 合作关系不等于供应商评级；
5. 合作关系不等于客户价值判断；
6. 合作关系发生调整、终止、争议或高风险事项时，应转入商务维护记录、问题与风险记录、责任与确认记录或决策与变更记录。

商务维护边界应遵守以下规则：

1. 关系记录可以保留关系事实；
2. 商务维护记录承接后续跟进、维护、复购、转介绍和经营关系推进过程；
3. 单次介绍关系不等于完整商务维护；
4. 商务维护结果不得反向修改已入链关系事实；
5. AI、页面标签、客户画像、供应商画像或视图评分不得自动确认关系结果。

## 十一、责任关联关系边界

关系记录可以承接责任关联线索，但不得替代责任与确认记录。

责任关联关系应遵守以下规则：

1. 主体与项目、资料、物资、问题、风险、决策、变更、验收、交付或财务事项之间存在责任关联线索时，可以形成关系记录；
2. 责任关联线索不等于责任成立；
3. 责任关联线索不等于赔付成立；
4. 责任关联线索不等于扣款成立；
5. 责任关联线索不等于授权确认；
6. 责任关联线索不等于客户确认或甲方确认；
7. 正式责任确认、授权确认、客户确认、甲方确认应归责任与确认记录；
8. 涉及争议、投诉、风险或整改的责任关系，应转入问题与风险记录或责任与确认记录；
9. AI、页面标签、关系图谱、风险看板或经营视图不得自动裁决责任关系。

关系记录可以为责任与确认记录提供关系来源和候选线索，但不得直接输出正式责任结论。

## 十二、私人关系参考边界

私人关系参考用于记录对业务有来源解释价值的亲属、朋友、同学、同乡、前同事、上下级、熟人介绍等背景关系。

私人关系参考应遵守以下规则：

1. 私人关系参考只能用于说明业务关系来源、沟通背景、介绍链路或风险提示；
2. 私人关系参考不等于业务合作关系；
3. 私人关系参考不等于权限放行；
4. 私人关系参考不等于责任确认；
5. 私人关系参考不等于客户价值、供应商评级、班组评级或信用判断；
6. 私人关系参考涉及敏感展示时，应接受权限、脱敏和必要确认；
7. 私人关系参考不得在无业务必要时扩大采集或对外展示；
8. AI、页面标签、聊天称呼或第三方口述不得自动确认私人关系参考。

私人关系参考只作为业务关系来源说明，不得成为正式业务结论、正式权限、正式责任或正式决策依据。

## 十三、关系时间与版本边界

关系记录必须区分关系发生时间、关系开始时间、关系结束时间、确认时间、系统记录时间和修订时间。

| 时间类型 | 含义 | 边界 |
|---|---|---|
| 关系发生时间 | 关系建立、变更、解除、确认或挂接实际发生的时间 | 不等于系统记录时间 |
| 关系开始时间 | 一段关系开始的时间 | 不代表关系已确认终止 |
| 关系结束时间 | 一段关系结束、解除或失效的时间 | 不代表责任已确认 |
| 确认时间 | 关系事项被人工确认或来源事实确认的时间 | 不替代发生时间 |
| 系统记录时间 | 用户、页面、接口或系统记录候选关系的时间 | 不代表关系实际发生时间 |
| 修订时间 | 对关系记录进行补充、修订、作废或引用修订的时间 | 不得覆盖原关系时间 |

关系时间不清时，应明确未知、待补或待确认，不得用默认当前时间冒充事实发生时间。聊天时间、资料时间、项目时间、确认时间、系统时间或多个来源时间不一致时，应进入待补、校验、挂起、驳回、人工确认或事实修订流程。

关系记录变更不得无痕覆盖。补充、修订、作废、归档、引用修订、来源修正和版本回滚，应保留原记录、变更原因、操作者、时间、版本、影响范围和追溯依据。

## 十四、证据、来源与确认要求

关系记录应绑定来源或证据。来源可以来自人工录入、主体资产、项目资产、资料记录、沟通与服务记录、商务维护记录、物资流转记录、问题与风险记录、责任与确认记录、履历记录、复盘与反馈记录、页面录入、接口载荷、外部反馈或其他可追溯来源。

证据与来源应遵守以下规则：

1. 来源存在不等于关系成立；
2. 主体名称存在不等于主体已确认；
3. 项目名称存在不等于项目关系已确认；
4. 聊天记录存在不等于正式关系成立；
5. 页面上的状态标记或分类标签存在不等于正式关系成立；
6. 关系图谱存在不等于关系事实成立；
7. AI 摘要不等于关系结论；
8. 视图摘要不等于关系事实本体；
9. 外部反馈不等于关系正式确认；
10. 证据链断裂时，不得直接生成正式关系结论；
11. 证据冲突时，应进入待补、校验、挂起、驳回或人工确认流程。

影响责任、权限、合同、承诺、付款、结算、介绍收益、渠道收益、客户确认、甲方确认、合作终止、对外展示或私人关系参考的关系记录，应具备必要人工确认或明确待确认标记。

## 十五、候选关系事实与正式关系事实

关系记录必须区分候选关系事实和正式关系事实。

候选关系事实来源包括：

1. 用户手动录入；
2. 主体资产线索；
3. 项目记录；
4. 沟通与服务记录；
5. 商务维护记录；
6. 资料记录；
7. 物资流转记录；
8. 财务记录；
9. 决策与变更记录；
10. 问题与风险记录；
11. 责任与确认记录；
12. 履历记录；
13. 复盘与反馈记录；
14. 关系图谱；
15. 页面标签；
16. 外部反馈；
17. 接口载荷；
18. AI 辅助摘要；
19. 导入记录。

候选关系事实不得直接作为正式关系事实消费。候选关系事实进入正式关系记录前，应完成以下处理：

1. 判断关系事实类型；
2. 识别并确认关系双方或关系对象锚点；
3. 识别主体、项目、组织、资料、物资或业务事项归属；
4. 识别关系动作、关系类型、关系来源和影响范围；
5. 绑定来源事实或证据；
6. 识别发生时间、开始时间、结束时间、确认时间或时间范围；
7. 判断是否涉及责任、权限、合同、承诺、付款、结算、返佣、挂靠、分包、客户确认、甲方确认、合作终止、私人关系参考或对外展示；
8. 判断权限与可见性；
9. 执行必要校验；
10. 标记待补、挂起、驳回、待确认或正式状态；
11. 保留审计追溯依据。

若候选关系事实中包含沟通过程、商务维护、财务收付款、价格确认、合同承诺、问题风险、责任确认、履历评价或项目立项，应拆分或转归口到对应事实类型，不得以关系记录直接放行。

## 十六、关系记录生命周期边界

关系记录生命周期应至少支持以下治理动作：

1. 创建候选关系事实；
2. 补齐；
3. 校验；
4. 挂起；
5. 驳回；
6. 人工确认；
7. 正式入链；
8. 关系建立；
9. 关系变更；
10. 关系解除；
11. 关系确认；
12. 角色挂接；
13. 取消挂接；
14. 归属调整；
15. 介绍关系记录；
16. 合作关系记录；
17. 对接关系记录；
18. 责任关联线索记录；
19. 私人关系参考记录；
20. 关联来源事实；
21. 补充；
22. 修订；
23. 作废；
24. 归档；
25. 引用修订；
26. 来源修正；
27. 版本回滚。

上述动作之间的流转关系、状态名称、前置条件、权限要求、字段要求和校验规则，由系统业务运行规则、标准治理中的状态口径、追溯与版本口径、权限与可见性口径或相关承接文件按职责承接。本文只定义关系记录需要支持的生命周期治理动作范围，不定义完整状态机。

## 十七、与汇总视图层的关系

汇总视图层可以消费关系记录，生成执行视图、经营视图、结算视图、交付与协同视图和专题台账中的关系相关结果。

| 汇总视图 | 可消费内容 | 禁止项 |
|---|---|---|
| 执行视图 | 项目联系人、对接主体、协同主体、待补关系、关系冲突 | 不把视图摘要写成正式关系事实 |
| 经营视图 | 客户关系、供应商关系、介绍关系、合作关系、渠道关系、关系风险 | 不自动形成客户等级、供应商评级或成交结论 |
| 结算视图 | 结算对接关系、资料确认关系、责任关联线索、介绍收益线索 | 不自动形成结算确认、付款事实或返佣结论 |
| 交付与协同视图 | 客户、甲方、供应商、班组和外部协作者的可见协同关系 | 不暴露内部关系、私人关系或未确认高风险关系 |
| 专题台账 | 联系人台账、介绍关系台账、合作关系台账、责任关联线索台账 | 不替代正式事实入链和责任确认 |

汇总视图层只能消费正式关系事实和授权范围内的候选内容。视图发现主体不清、项目不清、来源不清、关系冲突、权限不足或高风险事项未确认时，只能生成待补项、候选问题或治理回流，不得反写关系记录。

关系图谱、客户画像、供应商画像、联系人清单、介绍关系台账、合作看板和对外展示包属于视图输出、模板输出或业务输出，不是关系记录本体。

## 十八、与经验规则层的关系

经验规则层可以从关系记录中沉淀协作经验、介绍关系经验、合作关系经验、客户关系维护经验、供应商协同经验、主体关系治理经验和规则候选。

关系记录与经验规则层的关系如下：

1. 多条关系事实可以形成主体协作经验、介绍关系经验和合作关系经验；
2. 高频关系冲突、介绍链路、合作中断、对接异常和责任关联线索可以形成候选规则或提示；
3. 关系记录可以支撑后续客户维护、供应商选择、项目协同和经营复盘的候选建议；
4. AI 可以辅助归纳关系模式，但输出默认是候选经验；
5. 经验规则层不得直接修改关系记录；
6. 单条关系事实不得直接晋升为正式规则；
7. 经验规则层发现关系缺口时，只能生成待补项、候选问题或治理回流。

经验规则层服务后续优化，不替代关系记录本体，也不替代正式事实入链。

## 十九、与接口、页面、AI 和模板的关系

关系记录对接口、页面、AI 和模板形成以下约束：

1. 输入接口只能提交原始关系输入、候选关系事实、待补项、确认请求或受控写入，不得绕过校验直接创建正式关系事实；
2. 查询接口只能读取权限范围内的关系记录、候选关系事实或关系维度视图；
3. 页面可以展示候选关系、正式关系、来源事实、待补事项、阻断原因、确认入口和状态提示，但不得裁决正式关系、正式责任、正式权限、正式合作、正式承诺或高风险关系事项；
4. 页面补全项应以后端返回的缺失项、阻断原因、候选项和可选动作范围为准；
5. AI 可以辅助整理主体、项目、沟通、商务维护、资料、物资、问题风险、确认和复盘记录中的关系内容，生成候选摘要、候选关系、候选链路和待补提示，但不得自动确认正式关系事实；
6. 模板可以读取关系记录生成联系人清单、客户确认清单、供应商协同摘要、介绍关系清单、合作关系摘要或经营视图草稿，但模板输出不得创建或修改正式关系事实；
7. 导出包、分享包、关系图谱、客户画像、供应商画像和对外展示内容中的关系描述，不得反向修改关系记录；
8. 涉责任、权限、合同、承诺、付款、结算、返佣、挂靠、分包、客户确认、甲方确认、私人关系参考和对外发布的关系相关内容，必须接受高风险校验和必要人工确认。

## 二十、禁止混写与反向定义规则

关系记录必须防止以下混写和反向定义：

1. 把关系记录写成主体资产、项目资产、组织资产、资料资产或物资资产；
2. 把主体称呼写成正式主体关系；
3. 把一次沟通写成正式合作关系；
4. 把介绍关系写成成交结论；
5. 把合作关系写成合同成立；
6. 把项目角色关系写成权限配置；
7. 把责任关联线索写成责任确认；
8. 把私人关系参考写成业务结论、权限放行或责任确认；
9. 把关系图谱、视图摘要、页面标签、客户画像、供应商画像、AI 摘要、接口回执或模板输出直接写成正式关系事实；
10. 让汇总视图层、经验规则层、页面、接口、模板或 AI 输出反向修改关系记录；
11. 静默修订关系记录、静默替换主体锚点、静默替换项目锚点、静默替换关系对象或无证据更新关系状态；
12. 用数据库表、接口字段、页面入口、代码模型名或历史旧称反向定义关系记录；
13. 把分步实施、页面便利、接口便利、技术预留或架构预留能力作为绕过关系治理、权限隔离、人工确认和追溯要求的理由；
14. 把关系记录写成自动关系图谱、自动权限系统、自动责任裁决、自动 CRM、自动成交判断、自动客户评级或自动供应商评级能力；未来如需实现相关自动化能力，应由系统业务运行规则、标准治理、接口边界、权限与状态治理、测试验收等对应文件另行定义，并不得反向改变本文的关系事实边界、入链条件和追溯要求。

## 二十一、下游承接规则

本文当前不指定已成型直接下游文件。后续如形成关系记录相关的系统业务运行规则、接口边界、页面承接或验收规则，应承接以下内容：

1. 如何采集和识别关系输入；
2. 如何区分主体资产、项目资产、组织资产、资料资产、物资资产、关系记录、沟通服务、商务维护、问题风险、责任确认和履历记录；
3. 主体、项目、组织、资料、物资、业务场景、关系类型、关系动作、时间和证据缺失时如何补齐；
4. 关系事实如何进入候选、待补、确认、正式、修订、作废、归档和回滚流程；
5. 关系内容如何被视图、模板、对外展示和经验规则层消费；
6. 客户、甲方、供应商、班组、合作方、介绍人和外部协作者的关系记录如何处理权限、脱敏和高风险展示；
7. 介绍关系、合作关系、项目角色关系、对接关系、责任关联线索和私人关系参考如何接受事实入链、权限隔离和审计追溯约束。

上述承接方向属于跨目录职责承接，不构成本文 YAML downstream 的直接下游。本文不以统称虚构直接下游文件，也不得把本文中的“系统业务运行规则”等承接表述理解为当前文件的直接下游文件。

下游文件不得反向改变关系记录的事实边界，不得把关系记录写成完整关系图谱、完整 CRM 系统、完整权限系统、自动责任裁决系统、自动成交系统或自动客户价值判断系统。

## 二十二、边界判断

本文成立，应满足以下判断口径：

1. 能明确关系记录只承接主体与主体、主体与项目、主体与组织、主体与资料、主体与物资及主体与业务事项之间的关系过程事实，不承接对象本体；
2. 能说明主体资产回答“主体是谁”，关系记录回答“主体与谁或什么对象形成了什么关系”；
3. 能说明关系记录与主体资产、项目资产、组织资产、资料资产和物资资产的锚定关系；
4. 能区分关系记录、沟通与服务记录、商务维护记录、决策与变更记录、财务记录、问题与风险记录、责任与确认记录和履历记录；
5. 能说明介绍关系不等于成交，合作关系不等于合同成立，项目角色关系不等于权限配置，责任关联线索不等于责任确认，私人关系参考不等于业务结论；
6. 能说明来源或证据存在但主体身份、项目、组织、关系对象、关系类型、关系动作、时间或来源事实不清时，应进入待补、校验、挂起、驳回或人工确认，不得直接正式入链；
7. 能说明主要关系类型、关系双方、关系对象、项目或组织归属、时间口径、来源事实和状态口径未完整时不得正式入链；
8. 能说明 AI 摘要、页面标签、接口回执、关系图谱、客户画像、供应商画像、视图摘要、模板输出和导出包不得直接成为正式关系事实；
9. 能防止汇总视图层、经验规则层、页面、接口、模板或 AI 输出反向修改关系记录；
10. 能说明自动关系图谱、自动权限系统、自动责任裁决、自动 CRM、自动成交判断、自动客户评级或自动供应商评级等能力即使未来实现，也必须由对应下游文件另行定义，且不得反向改变本文事实边界；
11. 能说明 YAML downstream 只声明直接下游，跨目录承接由对应目录文件按职责承接，不得虚构下游文件；
12. 不写字段全集、枚举全集、状态机、权限矩阵、接口 schema、页面组件、数据库表、代码实现、测试脚本或实施计划。
