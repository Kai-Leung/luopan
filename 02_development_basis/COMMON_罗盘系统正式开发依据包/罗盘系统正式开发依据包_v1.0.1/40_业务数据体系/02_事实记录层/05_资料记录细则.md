# 05_资料记录细则

## 一、文件定位

本文是 `40_业务数据体系/02_事实记录层` 下的资料记录细则文件，用于定义围绕资料发生的过程事实，包括资料形成、收集、上传、提交、补齐、确认、审核、退回、作废、归档、引用、复核、发送、签收、回执、移交、缺失和资料状态变化等资料过程事实的成立边界、入链条件、对象锚点、证据要求、状态与追溯要求，以及与资料资产、其他事实记录、汇总视图层和经验规则层的关系。

资料记录用于承接装修 / 工程经营执行中资料在业务过程中的流转、补齐、确认、采信、退回、归档和证据链变化，回答“某份资料、某类资料或某个资料缺口，在什么时间、由谁、围绕哪个项目、主体、事项或流程，发生了什么资料过程事实”。

本文只定义资料过程事实的业务边界和开发依据，不替代资料资产、项目资产、主体资产、物资资产、施工记录、财务记录、验收与交付记录、问题与风险记录、决策与变更记录、责任与确认记录、完整档案管理制度、文件存储系统、OCR / 文件预览 / 下载 / 水印 / 压缩 / 脱敏算法、接口 schema、页面组件、数据库表结构或代码实现。本文不写字段全集、枚举全集、状态机、权限矩阵、测试脚本或实施计划。

## 二、资料记录职责

资料记录的核心职责，是把资料在项目经营执行中的形成、接收、提交、补齐、确认、退回、作废、归档、引用、复核、发送、签收和回执过程沉淀为可追溯事实。

资料记录承担以下职责：

1. 定义资料过程事实的成立条件；
2. 定义资料形成、收集、上传、提交、补齐、确认、审核、退回、作废、归档、发送、签收、回执、引用、复核和缺失的归口边界；
3. 定义资料记录与资料资产之间的分层关系；
4. 定义资料记录必须绑定项目、资料、主体、证据和来源的规则；
5. 定义资料记录与施工、财务、验收交付、问题风险、决策变更、沟通服务、责任确认等相邻事实的边界；
6. 定义资料记录如何支撑结算视图、交付与协同视图、执行视图、经营视图、资料缺口清单和客户确认清单草稿；
7. 定义候选资料过程事实、正式资料过程事实、资料缺失事实、资料确认事实和资料状态投影的边界；
8. 定义资料记录不得被资料对象本体、AI 摘要、页面状态、接口回执、模板输出、导出包、分享包、汇总视图层输出或客户确认清单草稿反向定义。

资料记录不定义资料本体，不定义资料唯一身份，不定义资料长期属性，不定义资料对象状态全集，不生成正式结算依据，不自动确认客户承诺，不自动确认验收通过，不自动确认变更成立，不自动确认签证成立，不自动形成财务收付款事实。

## 三、上位约束

资料记录必须服从以下上位约束：

1. 事实记录层只承接真实发生或经确认的过程，不承接稳定对象本体；
2. 资料记录是事实记录层中的事实类型之一，不得扩写成完整文件管理系统、档案管理系统、资料库、网盘、客户门户或结算系统；
3. 资料资产承接资料对象本体，资料记录承接资料过程事实；
4. 项目相关资料过程正式入链前必须绑定项目资产；
5. 已存在资料资产时，资料过程应绑定资料资产；资料对象尚未成立时，应形成候选资料、资料识别线索或资料待补项；
6. 涉及客户确认、甲方确认、签收、回执、结算、验收、签证、变更、资料作废和对外发布的资料过程，应按高风险事实处理；
7. 资料记录应绑定必要主体、资料证据、时间口径、权限判断、确认链路和审计追溯；
8. 汇总视图层可以消费资料记录，但不得反写资料过程事实；
9. 经验规则层可以从资料记录中沉淀资料补齐经验、资料缺口模式、资料清单模板和规则候选，但不得覆盖资料记录；
10. AI 可以辅助识别候选资料、候选缺口、候选摘要、候选归属和资料异常线索，但不得自动确认正式资料、资料有效、客户已确认、验收已通过或结算依据成立；
11. 页面状态、接口回执、导出包、分享包、模板输出、资料缺失清单、客户确认清单草稿和前端 Mock 状态，不得直接成为正式资料过程事实；
12. 历史旧称、旧分类体系、数据库表名、接口字段名、页面入口和代码模型名不得反向定义资料记录。

## 四、资料过程事实成立条件

一条内容能够进入资料记录，应同时满足以下条件：

1. 有明确资料过程行为；
2. 有明确项目资产、组织资产或候选归属锚点；
3. 有资料资产、候选资料、资料类型、资料缺口或资料证据线索；
4. 有操作主体、提交主体、接收主体、确认主体、复核主体、回执主体或候选主体；
5. 有资料过程发生时间、提交时间、接收时间、确认时间、回执时间、归档时间、记录时间或明确未知时间标记；
6. 有来源或证据；
7. 能说明资料过程类型、过程结果、资料范围、关联事项、关联事实或待补内容中的至少一种；
8. 有状态口径；
9. 有权限判断；
10. 涉及高风险内容时具备必要确认或待确认标记；
11. 具备审计追溯依据；
12. 不与已入链资料过程事实产生未处理冲突。

来源或证据存在，但其中的主体身份、资料归属、项目归属、资料类型、资料版本、资料范围、业务场景或时间不清的，不视为无来源，应视为锚点缺失、资料待识别、时间待补、范围待补或归属待补，进入待补、校验、挂起、驳回或人工确认流程，不得直接正式入链。

以下内容不得直接作为正式资料记录：

1. 只有一句无资料、无主体、无时间、无项目或无来源的资料描述；
2. 未识别归属的文件、图片、截图、语音转文字、表格、PDF、聊天记录或图片摘要；
3. AI 从图片、文件、表格、聊天记录或资料包中推测出的资料结论；
4. 页面临时资料状态、前端草稿、接口载荷、模板输出、资料缺失清单、客户确认清单草稿或导出包中的资料描述；
5. 未能区分是资料对象、资料提交、资料确认、客户确认、验收交付、财务结算、签证变更还是问题整改的混合描述；
6. 无权限来源提交的外部资料反馈；
7. 缺少必要项目锚点、资料锚点或缺失资料类型的资料过程内容。

上述内容应先作为候选资料过程事实、候选资料、资料缺失线索、待补项、待确认项、原始输入或运行中间数据处理。只有完成必要锚定、补齐、校验、权限判断和追溯后，才能进入正式资料记录。

## 五、资料记录承接范围

资料记录承接以下资料过程事实范围：

| 资料记录类型 | 承接内容 | 不承接内容 | 主要作用 |
|---|---|---|---|
| 资料形成记录 | 资料在业务中形成、生成、签发、取得或被识别为候选资料 | 资料本体长期属性、资料唯一身份、资料对象状态全集 | 资料链路起点、证据线索、候选资料治理 |
| 资料收集记录 | 内部或外部收集到资料、取得资料、接收资料线索 | 资料资产本体、完整文件采集系统 | 资料补齐、资料归集、项目证据链 |
| 资料上传记录 | 用户、外部主体或系统入口提交文件、图片、表格、截图等载体 | 文件存储实现、OCR 识别实现、正式资料确认 | 原始输入归集、候选资料形成 |
| 资料提交记录 | 资料被提交给内部、客户、甲方、供应商、系统或协同方 | 客户已确认、甲方已认可、结算依据成立 | 协同追溯、资料流转、对外提交证据 |
| 资料补齐记录 | 缺失资料被补交、补正、补充说明或重新提交 | 原缺失记录无痕覆盖、资料自动有效 | 缺口闭环、资料完整性治理 |
| 资料确认记录 | 某主体确认收到、认可、采信或确认某资料范围 | 客户承诺、验收通过、结算成立、责任终局确认 | 资料采信链路、确认依据、后续视图消费 |
| 资料审核记录 | 内部或授权主体对资料完整性、归属、版本、采信范围进行审核 | 完整审批系统、责任终局裁决 | 资料质量控制、风险拦截 |
| 资料退回记录 | 资料被退回、驳回、要求修改、要求补充或拒绝采信 | 资料作废、问题关闭、责任裁决 | 待补回流、交付阻断、资料缺口 |
| 资料作废记录 | 某份资料在业务过程中被确认不再采信、被替代或被标记为作废 | 删除历史资料、静默覆盖旧资料 | 版本追溯、证据保护、错误纠正 |
| 资料归档记录 | 资料被归档、封存、整理或纳入项目资料包 | 项目完成、资料全部有效、交付已完成 | 项目归档、历史追溯、审计查询 |
| 资料发送记录 | 资料被发送给客户、甲方、供应商、班组、内部人员或外部协作者 | 对方已签收、对方已认可、对外承诺成立 | 外部协同、交付链路、证据留痕 |
| 资料签收记录 | 外部或内部主体签收、接收、确认收到某份资料 | 内容认可、资料有效、结算依据成立 | 接收追溯、责任线索、对外协同 |
| 资料回执记录 | 外部主体对资料作出确认、退回、补充说明、备注、拒绝或异常反馈 | 自动入链正式事实、自动形成客户承诺 | 外部反馈链、资料补齐、协同闭环 |
| 资料引用记录 | 某份资料被事实记录、视图、清单、台账或输出包引用为证据 | 视图反写真源、引用即采信 | 证据链、来源追溯、视图消费 |
| 资料复核记录 | 对资料真实性、完整性、版本、归属、采信范围或引用关系进行复核 | 自动改写资料资产、自动覆盖历史事实 | 质量复核、版本治理、资料修订依据 |
| 资料缺失记录 | 某项目、阶段、事项、结算、验收、签证或交付缺少必要资料 | 资料对象本体、正式问题关闭、自动补齐 | 资料缺口清单、待补入口、执行阻断 |

资料记录承接资料过程事实，不承接资料对象本体、资料唯一身份、资料长期属性、文件存储实现、资料模板正文、客户承诺结论、验收通过结论、结算依据成立、财务收付款事实或责任终局裁决。

模板文件的上传、更新、启用、停用、作废、替换、引用和归档等动作，如具备来源、主体、时间、适用范围、确认依据和追溯关系，可以作为资料过程事实进入资料记录。资料记录只承接模板动作事实，不确认模板文件本体的资料资产身份，也不发布模板规则。

## 六、资料记录不承接范围

以下内容不得写入资料记录本体：

| 内容 | 正确归口 | 原因 |
|---|---|---|
| 合同、报价、预算、图纸、照片、签证、验收资料、结算资料、付款凭证、发票回执等资料本体 | 资料资产 | 属于稳定资料对象 |
| 资料唯一身份、资料类型、资料长期属性、资料版本主规则、资料敏感等级 | 资料资产或标准治理 | 属于对象定义或标准治理内容 |
| 项目本体、项目范围、项目阶段、项目状态投影 | 项目资产 | 属于稳定项目对象 |
| 客户、甲方、供应商、员工、班组、提交人、接收人、确认人等主体本体 | 主体资产 | 属于稳定主体对象 |
| 材料、设备、工具、库存物品等物资本体 | 物资资产 | 属于物资对象 |
| 施工动作、现场进展、施工完成状态、返工施工 | 施工记录 | 属于施工过程事实 |
| 正式收款、付款、报销、开票、结算确认 | 财务记录 | 属于财务事实 |
| 客户 / 甲方正式验收、交付确认、整改复验、交付签收结果 | 验收与交付记录 | 属于验收交付事实 |
| 问题成立、整改过程、整改责任、风险关闭 | 问题与风险记录 | 属于问题风险事实 |
| 签证变更、范围调整、价格确认、责任划分 | 决策与变更记录 | 属于决策变更事实 |
| 客户确认、甲方确认、授权确认、责任确认的独立确认链路 | 责任与确认记录 | 属于确认链路事实 |
| 日报、周报、各类清单、台账、结算草单、资料缺口清单、客户确认清单、对外展示包 | 汇总视图层、模板输出或业务输出 | 属于输出结果 |
| 资料补齐经验、资料模板、资料风险提示、资料清单模板优化 | 经验规则层 | 属于经验规则沉淀 |
| OCR、文件预览、下载、水印、压缩、存储、脱敏算法 | 接口边界、页面承接或技术实现 | 超出本文职责 |
| AI 摘要、页面状态、接口载荷、模板输出、导出包、分享包 | 候选内容或运行中间数据 | 不能直接成为正式资料过程事实 |

资料记录不得因为某项内容“以文件形式存在”或“被上传到系统”而吸收该内容本身。被资料过程提及的施工、财务、验收、变更、责任、问题、物资和主体，应按对应层级和事实类型归口。

## 七、资料资产与资料记录边界

资料资产回答“这份资料是什么”，资料记录回答“围绕这份资料发生了什么过程”。

二者边界如下：

| 对比项 | 资料资产 | 资料记录 |
|---|---|---|
| 所属层级 | 对象资产层 | 事实记录层 |
| 主问题 | 资料对象是什么 | 资料过程发生了什么 |
| 核心内容 | 资料名称、类型、归属、载体、版本、当前状态投影、引用摘要 | 形成、上传、提交、补齐、确认、退回、作废、归档、发送、签收、回执、引用、复核 |
| 是否记录单次过程 | 否 | 是 |
| 是否承接资料本体 | 是 | 否 |
| 是否承接资料过程事实 | 否 | 是 |
| 是否可以形成状态投影依据 | 被动承接 | 作为依据来源之一 |
| 是否可以被视图消费 | 是 | 是 |
| 是否可以自动确认客户承诺 | 否 | 否 |
| 是否可以自动确认结算依据成立 | 否 | 否 |

资料记录与资料资产应遵守以下规则：

1. 资料资产承接资料对象本体；
2. 资料记录承接资料过程事实；
3. 资料资产不得吸收资料提交、补齐、确认、退回、签收、回执、归档等过程动作；
4. 资料记录不得定义资料对象身份、资料类型全集、资料长期属性、资料敏感等级、资料版本主规则和资料对象状态全集；
5. 同一内容不得同时承担资料资产和资料记录双重职责；
6. 资料记录可以触发资料资产候选创建、资料资产修订候选、资料状态投影更新候选或资料引用关系修订候选，但不得静默覆盖资料资产；
7. 资料资产发生合并、作废、归档或版本变更后，已入链资料记录应保留原资料引用，不得自动替换；
8. 如需修订资料记录与资料资产之间的引用关系，应进入资料治理或事实引用修订流程，并保留原引用、修订原因、操作者、时间、版本和追溯依据。

## 八、项目、组织与资料归属边界

资料记录必须明确资料过程的归属。项目相关资料过程应绑定项目资产；组织级资料过程应绑定组织资产和业务场景。

项目归属应遵守以下规则：

1. 与某项目合同、报价、预算、图纸、施工照片、签证、验收、结算、付款凭证、客户确认和归档相关的资料过程，应绑定项目资产或候选项目；
2. 项目不唯一时，不得静默归入默认项目；
3. 客户姓名、地址、微信群名称、文件夹名称、资料文件名不得单独替代项目唯一识别；
4. 项目归属不清时，应进入待补、校验、挂起、驳回或人工确认流程；
5. 跨项目资料提交、批量上传、合并发送或混合归档，应拆分归口或明确分摊待补，不得混写为单一项目资料过程事实；
6. 项目归档后新增资料记录，应区分历史补证、售后资料、补交资料、结算补充、归档修订、重新开放线索或新项目线索；
7. 资料记录不得直接修改项目范围、项目阶段、项目状态或执行开放状态。

组织归属应遵守以下规则：

1. 公司级模板、组织级制度、组织级资料清单、共享资料、非项目类凭证或组织级归档资料过程，应绑定组织资产；
2. 组织归属不清时，应进入待补、校验、挂起、驳回或人工确认流程；
3. 组织资料过程不得无依据分摊到项目；
4. 项目资料过程不得无依据沉入组织级资料摘要而失去项目追溯；
5. 组织归属变化不得静默覆盖历史资料记录。

## 九、资料参与主体边界

资料记录必须绑定操作主体、提交主体、接收主体、确认主体、复核主体、回执主体或候选主体。

资料参与主体包括：

1. 资料形成主体；
2. 上传人；
3. 收集人；
4. 提交人；
5. 接收人；
6. 补齐人；
7. 确认人；
8. 审核人；
9. 退回人；
10. 作废批准人；
11. 归档人；
12. 发送人；
13. 签收人；
14. 回执主体；
15. 复核人；
16. 资料责任人；
17. 客户、甲方、供应商、班组、员工、设计师或外部协作者。

资料参与主体应遵守以下规则：

1. 主体本体归主体资产；
2. 资料记录只记录主体参与某次资料过程事实的行为；
3. 主体身份不清时，应形成候选主体、待补项或身份识别问题；
4. 同一资料记录可以关联多个主体；
5. 主体在资料过程中的角色应区分为形成人、上传人、提交人、接收人、确认人、审核人、退回人、签收人、回执人、归档人、复核人或责任候选人；
6. 资料参与主体不得因页面选择、AI 推测、文件名、签名截图、群昵称、电话尾号或发票抬头自动确认为正式主体；
7. 涉及客户确认、甲方确认、资料作废、结算、验收、签证、变更、责任和对外发布的主体关系，必须具备必要确认和追溯依据。

本文对辅助参与主体的处理，是对上位总则中“记录主体、相关主体或责任主体”规则在资料记录场景下的具体化。资料记录的基本信息必须完整，至少应明确资料过程类型、项目或组织归属、资料锚点或缺失资料类型、主要操作主体、事实时间、来源证据和状态口径。基本信息缺失时，整条记录不得正式入链。辅助参与主体身份不清时，可作为待补项、候选主体或后续补充关系处理；在不影响主要资料过程事实成立和历史追溯的前提下，不应阻断已确认主体和已确认资料过程事实的入链。

## 十、资料类型、资料范围与资料缺失边界

资料记录必须区分资料对象类型、资料过程类型和资料缺失类型。

资料对象类型回答“这是什么资料”，归资料资产和标准治理承接。资料过程类型回答“资料发生了什么过程”，归资料记录承接。资料缺失类型回答“缺少哪类资料或哪类资料信息”，属于资料记录中的缺失事实或待补事项。

资料类型与资料范围应遵守以下规则：

1. 资料记录可以记录资料过程涉及合同、报价、预算、图纸、照片、签证、验收资料、结算资料、付款凭证、发票回执、客户确认材料或归档材料；
2. 资料记录不得定义资料对象类型全集；
3. 资料记录不得用资料过程状态反向修改资料对象类型；
4. 资料范围不清时，应进入待补、校验、挂起、驳回或人工确认流程；
5. 同一资料过程同时涉及多个资料范围时，应拆分归口或明确多资料关系；
6. 高风险资料范围不得由 AI 摘要、文件名、页面目录或模板结果自动确认。

资料缺失应遵守以下规则：

1. 资料缺失记录用于说明某项目、阶段、事项、验收、签证、结算、交付或客户确认缺少必要资料；
2. 资料缺失不等于资料对象本体；
3. 资料缺失不等于问题风险已经成立；
4. 资料缺失可以生成待补项、视图提示、资料缺口清单或治理回流；
5. 资料补齐后不得静默覆盖原资料缺失记录，应形成补齐事实、引用关系和状态变化依据；
6. 资料缺失涉及责任、风险、结算、验收或客户承诺时，应按对应事实类型继续归口。

## 十一、资料来源、证据与载体边界

资料记录必须绑定来源或证据。来源可以是原始输入、上传文件、图片、表格、PDF、聊天截图、语音转文字、邮件、外部回执、页面录入、接口载荷、人工录入、已有资料资产或其他可追溯来源。

资料来源与证据应遵守以下规则：

1. 文件存在不等于资料已确认；
2. 上传成功不等于资料已提交；
3. 资料已提交不等于客户已确认；
4. 客户签收不等于内容认可；
5. 资料已确认不等于客户承诺成立；
6. 资料已确认不等于验收通过；
7. 资料已确认不等于签证成立；
8. 资料已确认不等于结算依据成立；
9. 资料已归档不等于项目已完成；
10. 资料作废不等于删除历史资料；
11. AI 摘要不等于资料内容已确认；
12. 模板输出不等于资料过程事实成立。

资料证据链断裂时，应根据缺失内容进入待补、校验、挂起、驳回、人工确认或阻断流程，不得直接生成正式资料过程结论。

资料记录可以保留证据线索和资料引用关系，但不得把证据线索直接写成资料有效、客户确认、验收通过、签证成立、结算成立或责任确认。

## 十二、资料过程状态与对象状态边界

资料记录必须区分事实记录治理状态、资料过程状态和资料对象状态投影。

| 状态类型 | 承接位置 | 含义 | 边界 |
|---|---|---|---|
| 事实记录治理状态 | 事实记录层 / 标准治理 | 候选、待补、待校验、挂起、驳回、待确认、正式、修订、作废、归档等治理状态 | 不等于资料对象当前状态 |
| 资料过程状态 | 资料记录 | 待提交、已提交、待补齐、已补齐、已确认、已退回、已签收、已回执、已归档等过程结果 | 不等于资料资产本体状态 |
| 资料对象状态投影 | 资料资产 | 使用中、停用、已作废、已归档、当前主版本等读取便利 | 必须可追溯到资料记录、确认记录或治理记录 |

资料状态应遵守以下规则：

1. 资料过程状态不得写入资料资产对象状态；
2. 资料对象状态不得替代资料过程状态；
3. 资料记录可以作为资料资产状态投影变化的依据之一；
4. 资料资产状态投影变化不得静默覆盖资料记录；
5. 资料过程状态变化应保留来源、主体、时间、原因、影响范围和追溯依据；
6. 资料作废、归档、恢复、回滚、替换和引用修订应接受高风险校验和必要确认。

## 十三、资料形成、上传与提交边界

资料形成、上传和提交必须区分。

资料形成回答“资料在业务中产生或取得”。资料上传回答“资料载体进入系统或候选链路”。资料提交回答“资料被提交给内部、客户、甲方、供应商、系统或协同方”。

资料形成应遵守以下规则：

1. 资料形成可以来自合同签署、报价生成、预算整理、图纸取得、现场拍摄、签证制作、验收资料准备、结算资料整理、付款凭证取得等；
2. 资料形成不等于资料资产正式成立；
3. 资料形成不等于资料已提交；
4. 资料形成不等于资料已确认；
5. 资料形成应尽可能绑定项目、主体、资料类型、来源和时间；
6. 资料形成涉及合同、签证、价格、责任、验收或结算时，应按对应事实类型继续归口。

资料上传应遵守以下规则：

1. 上传成功只表示资料载体进入原始输入或候选链路；
2. 上传成功不等于资料识别完成；
3. 上传成功不等于资料正式提交；
4. 上传成功不等于资料有效；
5. 上传失败、重复上传、归属不清、文件损坏、权限不足，应进入待补、挂起、驳回或错误处理；
6. 上传行为不得绕过资料资产治理和事实入链规则。

资料提交应遵守以下规则：

1. 资料提交应说明提交主体、接收主体、提交时间、提交资料、提交范围和提交证据；
2. 资料提交不等于接收方已签收；
3. 资料提交不等于接收方认可；
4. 资料提交不等于结算依据成立；
5. 资料提交涉及对外主体时，应接受权限、脱敏和对外展示边界约束；
6. 资料提交被退回、补正、撤回或重新提交时，应形成独立资料过程事实。

## 十四、资料补齐、退回与缺失闭环

资料补齐、退回和缺失闭环必须保留原缺失依据和补齐过程，不得无痕覆盖。

资料补齐应遵守以下规则：

1. 资料补齐用于记录缺失资料被补交、补正、补充说明或重新提交；
2. 资料补齐应关联原资料缺失记录、原退回记录、原待补事项或明确无法关联原因；
3. 资料补齐不等于资料已确认；
4. 资料补齐不等于原问题关闭；
5. 资料补齐不等于验收通过或结算成立；
6. 资料补齐涉及版本替换、资料作废、资料确认或对外提交时，应形成对应资料过程事实；
7. 资料补齐不得静默删除原缺失记录。

资料退回应遵守以下规则：

1. 资料退回用于记录资料被拒收、驳回、要求修改、要求补充或拒绝采信；
2. 资料退回应说明退回主体、退回原因、退回时间、退回资料和证据；
3. 资料退回不等于资料作废；
4. 资料退回不等于责任裁决；
5. 资料退回不等于问题风险关闭；
6. 退回后重新提交，应形成新的资料提交或补齐记录；
7. 退回涉及客户、甲方、结算、验收、签证或责任时，应按高风险事实处理。

资料缺失闭环应遵守以下规则：

1. 缺失发现、缺失提示、缺失补齐、补齐确认和缺失关闭应有追溯链路；
2. 缺失关闭不得由视图自动完成；
3. 缺失关闭不得由 AI 自动裁决；
4. 缺失关闭涉及客户、甲方、验收、签证、结算或责任时，应有必要确认；
5. 资料缺失清单只能消费资料记录，不得反写资料记录。

## 十五、资料确认、签收与回执边界

资料确认、资料签收和资料回执必须区分。

资料确认回答“某主体是否确认收到、认可、采信或确认某资料范围”。资料签收回答“某主体是否收到或签收某资料”。资料回执回答“外部或内部主体对资料作出何种反馈”。

资料确认应遵守以下规则：

1. 资料确认应说明确认主体、确认时间、确认资料、确认范围、确认方式和证据；
2. 资料确认可以是内部确认、客户确认、甲方确认、供应商确认或外部协作确认；
3. 资料确认不等于客户承诺成立；
4. 资料确认不等于验收通过；
5. 资料确认不等于签证成立；
6. 资料确认不等于结算依据成立；
7. 资料确认不等于财务收付款发生；
8. 涉及责任、金额、范围、验收、签证、结算或风险关闭的资料确认，应转入责任与确认记录、决策与变更记录、验收与交付记录、财务记录或问题与风险记录继续归口。

资料签收应遵守以下规则：

1. 签收表示资料被接收或收到；
2. 签收不等于内容认可；
3. 签收不等于资料有效；
4. 签收不等于客户承诺或甲方确认；
5. 签收异常、拒收、漏签、代签和主体不清时，应进入待补、校验、挂起、驳回或人工确认流程；
6. 签收涉及对外主体时，应保留授权、权限、脱敏和证据链。

资料回执应遵守以下规则：

1. 回执可以记录确认、退回、补充说明、备注、拒绝、异常反馈或待补要求；
2. 回执不等于自动入链正式事实；
3. 回执中的金额、责任、范围、验收、结算和承诺内容，应拆分或转归口；
4. 外部回执来源不明、主体不明或授权不明时，不得正式入链；
5. 接口回执成功不等于业务回执已确认。

## 十六、资料作废、替代与归档边界

资料作废、替代和归档属于高风险资料过程，应保留完整追溯依据。

资料作废应遵守以下规则：

1. 资料作废不等于删除资料；
2. 资料作废应说明作废主体、作废原因、作废时间、作废资料、替代资料或无替代说明；
3. 资料作废应保留原资料、原引用、原版本和历史影响范围；
4. 资料作废不得静默覆盖既有事实引用；
5. 资料作废涉及结算、验收、签证、客户确认、甲方确认或对外发布时，必须具备必要确认；
6. 作废后如需恢复、回滚或纠错，应进入资料治理或事实修订流程。

资料替代应遵守以下规则：

1. 新资料替代旧资料，应形成替代过程事实；
2. 替代不等于旧资料删除；
3. 替代不等于已入链事实引用自动改写；
4. 替代应说明替代原因、替代主体、替代时间、替代范围和影响范围；
5. 替代涉及历史引用时，应进入引用修订流程；
6. 资料替代不得由页面默认值、AI 摘要或模板结果自动完成。

资料归档应遵守以下规则：

1. 归档用于历史保留、审计追溯、项目交付、结算交付、复盘或低频查询；
2. 归档不等于项目完成；
3. 归档不等于验收通过；
4. 归档不等于结算完成；
5. 归档不等于资料全部有效；
6. 归档后资料仍可被历史事实、视图、复盘、经验规则和审计链路引用；
7. 归档后补证、纠错、恢复、回滚或重新开放，应进入治理流程并保留追溯依据。

## 十七、资料引用、复核与证据链边界

资料引用和资料复核是维护证据链的重要过程，但不得替代正式事实本身。

资料引用应遵守以下规则：

1. 资料可以被施工记录、财务记录、验收与交付记录、问题与风险记录、决策与变更记录、责任与确认记录、汇总视图层和经验规则层引用；
2. 引用应说明引用目的、引用范围、引用时点和关联事实；
3. 资料被引用不等于资料内容被确认；
4. 资料被引用不等于被引用事实成立；
5. 资料被视图引用不等于视图可反写资料记录；
6. 资料引用修订不得无痕覆盖原引用；
7. 资料引用涉及历史事实、结算、验收、签证、责任或对外展示时，应保留版本和证据链。

资料复核应遵守以下规则：

1. 资料复核可以检查真实性、完整性、版本、归属、采信范围、引用关系和证据链；
2. 复核通过不等于资料自动成为结算依据；
3. 复核退回不等于资料作废；
4. 复核发现问题时，应形成待补项、退回记录、问题风险候选或资料修订候选；
5. 复核涉及高风险事项时，应经过必要人工确认；
6. AI 可以辅助提示复核缺口，但不得自动给出正式复核结论。

资料证据链应遵守以下规则：

1. 资料资产提供证据对象本体；
2. 资料记录提供证据对象在业务过程中被形成、上传、提交、补齐、确认、退回、作废、归档、引用、复核、签收和回执的事实链；
3. 证据对象存在不等于证据链完整；
4. 证据链完整不等于相关业务结论自动成立；
5. 证据链断裂时，不得直接生成正式资料过程结论。

## 十八、资料时间与记录时间边界

资料记录必须区分资料形成时间、上传时间、提交时间、接收时间、确认时间、回执时间、归档时间、系统记录时间和修订时间。

| 时间类型 | 含义 | 边界 |
|---|---|---|
| 资料形成时间 | 资料在业务中形成、生成、签发、取得或拍摄的时间 | 不得用上传时间静默替代 |
| 上传时间 | 文件、图片、表格或资料载体进入系统的时间 | 不代表资料形成时间或提交时间 |
| 提交时间 | 资料被提交给内部、客户、甲方、供应商、系统或协同方的时间 | 不代表接收或确认时间 |
| 接收时间 | 接收主体收到资料或系统记录接收的时间 | 不代表内容认可 |
| 确认时间 | 某主体确认收到、认可、采信或确认某资料范围的时间 | 不代表资料形成时间 |
| 回执时间 | 外部或内部主体返回确认、退回、补充、备注或拒绝的时间 | 不等于业务结论必然成立 |
| 归档时间 | 资料被归档、封存或纳入资料包的时间 | 不代表项目完成 |
| 系统记录时间 | 用户、页面、接口或系统记录资料候选事实的时间 | 不代表资料过程实际发生时间 |
| 修订时间 | 对资料记录进行补充、修订、作废或引用修订的时间 | 不得覆盖原资料过程时间 |

资料过程时间不清时，应明确未知、待补或待确认，不得用默认当前时间冒充事实发生时间。文件时间、拍摄时间、上传时间、提交时间、签收时间、回执时间、系统时间、聊天时间或多个来源时间不一致时，应进入待补、校验、挂起、驳回、人工确认或事实修订流程。

时间冲突的具体判定规则，由标准治理中的校验规则口径和系统业务运行规则承接。本文只规定资料时间冲突不得静默覆盖，不得用单一系统时间、上传时间、文件时间、截图时间或页面默认时间替代事实发生时间。

## 十九、候选资料过程事实与正式资料过程事实

资料记录必须区分候选资料过程事实和正式资料过程事实。

候选资料过程事实来源包括：

1. 用户手动录入；
2. 文件上传；
3. 图片上传；
4. 表格或 PDF 上传；
5. 语音转文字；
6. 聊天截图；
7. 邮件或外部回执；
8. 接口载荷；
9. 页面草稿；
10. AI 辅助摘要；
11. 模板生成结果；
12. 导入记录；
13. 资料缺失清单；
14. 客户确认清单草稿；
15. 其他原始输入或候选内容。

候选资料过程事实不得直接作为正式资料过程事实消费。候选资料过程事实进入正式资料记录前，应完成以下处理：

1. 判断资料过程事实类型；
2. 识别项目或组织锚点；
3. 识别资料资产、候选资料、资料类型或缺失资料类型；
4. 识别操作主体、提交主体、接收主体、确认主体、回执主体或复核主体；
5. 绑定来源或证据；
6. 识别关联施工事实、关联财务事实、关联验收交付、关联决策变更、关联问题风险或关联责任确认；
7. 补齐必要时间；
8. 判断是否涉及高风险事项；
9. 判断权限与可见性；
10. 执行必要校验；
11. 标记待补、挂起、驳回、待确认或正式状态；
12. 保留审计追溯依据。

若候选资料过程事实中包含施工完成、验收交付、财务收付款、签证变更、金额确认、责任确认、问题风险或客户承诺，应拆分或转归口到对应事实类型，不得以资料记录直接放行。

## 二十、资料记录生命周期边界

资料记录生命周期应至少支持以下治理动作：

1. 创建候选资料过程事实；
2. 补齐；
3. 校验；
4. 挂起；
5. 驳回；
6. 人工确认；
7. 正式入链；
8. 上传；
9. 收集；
10. 提交；
11. 接收；
12. 补交；
13. 补正；
14. 确认；
15. 审核；
16. 退回；
17. 发送；
18. 签收；
19. 回执；
20. 引用；
21. 复核；
22. 作废；
23. 替代；
24. 归档；
25. 补充；
26. 修订；
27. 引用修订；
28. 来源修正；
29. 版本回滚。

上述动作之间的流转关系、状态名称、前置条件、权限要求、字段要求和校验规则，由标准治理中的状态口径、追溯与版本口径、权限与可见性口径以及系统业务运行规则承接。本文只定义资料记录需要支持的生命周期治理动作范围，不定义完整状态机。

资料记录变更不得无痕覆盖。补充、修订、作废、替代、归档、引用修订、来源修正和版本回滚，应保留原记录、变更原因、操作者、时间、版本、影响范围和追溯依据。

## 二十一、与其他事实记录的边界

资料记录与其他事实记录的边界如下：

| 相邻事实类型 | 区分规则 |
|---|---|
| 沟通与服务记录 | 沟通中讨论资料催补、资料发送安排归沟通与服务；资料实际提交、补齐、回执、签收归资料记录 |
| 施工记录 | 现场施工过程归施工记录；施工照片、施工日志、隐蔽资料的形成、上传、提交、归档归资料记录 |
| 验收与交付记录 | 正式验收、交付确认、整改复验归验收与交付记录；验收资料提交、交付资料移交、签收资料留痕归资料记录 |
| 财务记录 | 收付款、报销、开票、结算确认归财务记录；付款凭证、发票、结算资料的上传、提交、补齐、确认、归档归资料记录 |
| 问题与风险记录 | 问题成立、整改、风险关闭归问题与风险记录；问题资料、整改照片、风险证据的提交、退回、补齐归资料记录 |
| 决策与变更记录 | 签证、范围调整、价格确认、责任划分归决策与变更记录；签证单、变更单、确认材料的提交、确认、退回、归档归资料记录 |
| 物资流转记录 | 采购、领用、调拨、损耗、报废归物资流转记录；送货单、采购单、发票、照片等资料过程归资料记录 |
| 责任与确认记录 | 正式责任、授权、客户 / 甲方确认链路归责任与确认记录；确认材料、签字材料、回执材料的提交和归档归资料记录 |
| 商务维护记录 | 商务跟进、复购、转介绍归商务维护记录；商务资料、报价资料、客户材料的资料过程归资料记录 |
| 复盘与反馈记录 | 项目复盘、系统性反馈和经验线索归复盘与反馈记录；复盘资料、反馈资料的收集、提交、归档归资料记录 |

同一原始输入中包含多个事实类型时，应按事实类型拆分归口，保留同一来源和引用关系，不得把多类事实混写为一条资料记录。

## 二十二、与汇总视图层的关系

汇总视图层可以消费资料记录，生成经营视图、执行视图、结算视图和交付与协同视图中的资料相关结果。

| 汇总视图 | 可消费内容 | 禁止项 |
|---|---|---|
| 经营视图 | 资料缺口、合同资料、付款凭证、发票回执、结算资料、风险资料状态摘要 | 不把经营分析反写资料记录 |
| 执行视图 | 待提交、待补齐、待确认、已退回、待归档、资料阻断原因 | 不把待补事项写成已完成资料事实 |
| 结算视图 | 合同、报价、预算、签证、验收、付款凭证、发票、结算资料的过程状态 | 不自动形成正式结算确认 |
| 交付与协同视图 | 对外可见资料提交、签收、回执、交付资料、归档资料和资料缺口摘要 | 不自动对外承诺、签收或修改事实 |

汇总视图层只能消费正式资料记录和授权范围内的候选内容。视图发现资料缺失、主体不清、项目不清、资料版本冲突、证据链断裂、权限不足或高风险事项未确认时，只能生成待补项、候选问题或治理回流，不得反写资料记录。

资料缺口清单、客户确认清单草稿、结算草单、交付清单、资料台账、归档包、对外展示包和项目资料包属于视图输出、模板输出或业务输出，不是资料记录本体。

## 二十三、与经验规则层的关系

经验规则层可以从资料记录中沉淀资料补齐经验、资料缺口模式、资料退回原因、资料确认规则候选、资料清单模板、归档模板、结算资料模板和客户确认材料模板。

资料记录与经验规则层的关系如下：

1. 多条资料过程事实可以形成资料补齐经验；
2. 高频资料缺失和资料退回问题可以形成风险提示或模板优化候选；
3. 资料确认、资料签收和资料回执可以形成对外协同经验候选；
4. 资料作废、替代和归档可以形成资料治理规则候选；
5. AI 可以辅助归纳资料模式，但输出默认是候选经验；
6. 经验规则层不得直接修改资料记录；
7. 单条资料记录不得直接晋升为正式规则；
8. 经验规则层发现资料缺口时，只能生成待补项、候选问题或治理回流。

经验规则层服务后续优化，不替代资料记录本体，也不替代正式事实入链。

## 二十四、与接口、页面、AI 和模板的关系

资料记录对接口、页面、AI 和模板形成以下约束：

1. 输入接口只能提交原始资料输入、候选资料过程事实、待补项、确认请求或受控写入，不得绕过校验直接创建正式资料记录；
2. 查询接口只能读取权限范围内的资料记录、候选资料过程事实或资料维度视图；
3. 页面可以展示候选资料、正式资料记录、待补事项、阻断原因、确认入口和状态提示，但不得裁决正式高风险资料事项；
4. 页面补全项应以后端返回的缺失项、阻断原因、候选项和可选动作范围为准；
5. AI 可以辅助整理文件、图片、表格、聊天、语音和资料包中的资料内容，生成候选摘要、候选缺口、候选归属、候选版本、候选异常和待补提示，但不得自动确认正式资料记录；
6. 模板可以读取资料记录生成资料缺口清单、资料提交清单、客户确认清单草稿、结算资料清单、交付资料清单或项目归档草稿，但模板输出不得创建或修改正式资料记录；
7. 导出包、分享包、客户确认清单和对外展示内容中的资料描述，不得反向修改资料记录；
8. 涉客户确认、甲方确认、验收、签证、结算、责任、资料作废、资料归档、资料对外发布和资料脱敏的内容，必须接受高风险校验和必要人工确认。

## 二十五、禁止混写与反向定义规则

资料记录必须防止以下混写和反向定义：

1. 把资料记录写成资料资产、项目资产、主体资产或物资资产；
2. 把资料上传成功写成资料正式提交、资料正式确认或资料有效；
3. 把资料提交写成客户已确认、甲方已认可或结算依据成立；
4. 把资料签收写成内容认可、验收通过或客户承诺；
5. 把资料确认写成签证成立、变更成立、结算成立或财务收付款事实；
6. 把资料归档写成项目完成、交付完成或资料全部有效；
7. 把资料作废写成删除历史资料或自动替换历史引用；
8. 把资料缺失清单、客户确认清单草稿、结算草单、交付清单、资料台账、导出包或对外展示包写成资料记录本体；
9. 把文件名、截图、语音转文字、OCR 结果、AI 摘要、页面备注、接口回执或模板输出直接写成正式资料过程事实；
10. 把资料缺失写成问题风险已经成立、责任已经裁决或整改已经关闭；
11. 让汇总视图层、经验规则层、页面、接口、模板或 AI 输出反向修改资料记录；
12. 静默修订资料记录、静默替换资料锚点、静默替换项目锚点、静默替换资料主体或无证据更新资料过程状态；
13. 用数据库表、接口字段、页面入口、代码模型名或历史旧称反向定义资料记录；
14. 把分步实施、页面便利、接口便利、技术预留或架构预留能力作为绕过资料治理、权限隔离、人工确认和追溯要求的理由；
15. 把资料记录写成当前已完成的自动识别、自动确认、自动签收、自动归档、自动结算依据确认、自动对外发布或自动资料裁决能力。

## 二十六、下游承接规则

本文当前不指定已成型直接下游文件。后续如形成资料记录相关的系统业务运行规则、沉淀池与资料存储规则、接口边界、页面承接或验收规则，应承接以下内容：

1. 如何采集和识别资料输入；
2. 如何区分资料资产、资料记录、施工记录、财务记录、验收交付、决策变更、责任确认和问题风险；
3. 项目、组织、资料、主体、时间、来源和证据缺失时如何补齐；
4. 资料过程事实如何进入候选、待补、确认、正式、修订、作废和归档流程；
5. 资料内容如何被视图、模板、对外展示和经验规则层消费；
6. 客户、甲方、供应商、员工、班组和外部协作者参与资料提交、签收、回执、确认和退回时如何处理权限和脱敏；
7. 资料上传、资料识别、资料归档、资料缺口、资料对外输出和资料授权展示如何接受事实入链、权限隔离和审计追溯约束。

下游文件不得反向改变资料记录的事实边界，不得把资料记录写成完整文件管理系统、档案管理系统、资料库、网盘、客户门户、自动识别系统、自动签收系统、自动归档系统或自动结算依据确认系统。

## 二十七、边界判断

本文成立，应满足以下判断口径：

1. 能明确资料记录只承接资料形成、上传、提交、补齐、确认、审核、退回、作废、归档、发送、签收、回执、引用、复核和缺失等资料过程事实，不承接资料对象本体；
2. 能说明资料资产回答“资料是什么”，资料记录回答“资料过程发生了什么”；
3. 能说明资料记录与项目资产、主体资产、资料资产、物资资产的锚定关系；
4. 能说明资料过程状态、资料对象状态投影和事实记录治理状态不得混写；
5. 能说明资料提交、资料签收、资料确认、客户确认、验收通过、签证成立、结算依据成立和财务收付款事实之间的边界；
6. 能说明资料记录与施工、财务、验收交付、问题风险、决策变更、责任确认等事实类型的边界；
7. 能说明来源或证据存在但主体身份、资料归属、项目、时间、范围或业务场景不清时，应进入待补、校验、挂起、驳回或人工确认，不得直接正式入链；
8. 能说明主要资料过程类型、项目或组织归属、资料锚点或缺失资料类型、主要操作主体、事实时间、来源证据和状态口径未完整时不得正式入链，辅助参与主体可后续补充；
9. 能说明 AI 摘要、页面状态、接口回执、资料缺失清单、客户确认清单草稿、模板输出和导出包不得直接成为正式资料过程事实；
10. 能防止汇总视图层、经验规则层、页面、接口、模板或 AI 输出反向修改资料记录；
11. 不写字段全集、枚举全集、状态机、权限矩阵、接口 schema、页面组件、数据库表、代码实现、测试脚本或实施计划。
