# 01_执行视图细则

## 一、文件定位

本文是 `40_业务数据体系/03_汇总视图层` 下的执行视图细则文件，用于定义执行视图的服务对象、取数范围、输出边界、执行状态聚合规则、事项处理视图规则、追溯要求和下游承接边界。

执行视图是汇总视图层中的项目执行消费视图，面向项目负责人、一线人员和内部协同角色，基于项目资产、对象资产、正式事实记录、校验结果和追溯锚点，生成项目现场执行所需的进度摘要、当前待办、施工执行清单、资料缺失清单、问题风险清单、物资待处理清单、变更确认事项、出勤摘要和日报 / 周报输入摘要。

执行视图只消费对象资产层和事实记录层中满足可消费条件的数据，不创造事实，不修改对象资产，不改写事实记录，不自动确认客户承诺、变更、签证、验收、付款、收款或结算。

本文不写数据库表、ORM 模型、接口 schema、页面组件、运行步骤、测试代码和实施计划。具体接口、页面、权限矩阵、状态机、测试断言和实现方案，由系统业务运行规则、接口边界、前后端协同边界与页面承接、验证与验收规则继续承接。

## 二、执行视图定义

执行视图是以项目执行为主锚点的派生消费视图，用于回答：

1. 项目当前推进到什么状态；
2. 项目负责人和一线协同角色今天需要看什么；
3. 当前有哪些待处理、待补、待确认、待复核和阻断事项；
4. 施工、资料、问题、物资、变更、出勤和沟通线索如何汇总；
5. 哪些事项需要回流到对象资产层、事实记录层或运行链路继续处理；
6. 哪些内容不得被视图结果自动确认为正式事实、正式责任、正式承诺或正式结算结论。

执行视图不是项目资产，不是任务系统，不是施工记录，不是资料记录，不是问题与风险记录，不是决策与变更记录，不是物资流转记录，不是出勤记录，不是客户确认工具，也不是完整项目管理软件。

## 三、服务对象与使用场景

执行视图主要服务以下内部角色：

| 服务对象 | 主要关注问题 | 执行视图输出 |
|---|---|---|
| 项目负责人 | 项目当前进展、待办、风险、资料、物资、变更和确认事项 | 项目进度摘要、当前待办清单、风险阻断提示、日报 / 周报输入摘要 |
| 一线人员 | 当日施工事项、资料补齐、问题反馈、物资状态和现场协同 | 施工执行清单、资料缺失清单、物资待处理清单、问题风险清单 |
| 内部协同角色 | 需要跟进的资料、财务、采购、确认、出勤和协同事项 | 待补清单、待确认清单、协同阻塞提示、来源事实索引 |
| 授权管理角色 | 项目执行状态和异常概览 | 执行摘要、风险提示、关键阻断事项、需确认事项 |

执行视图默认属于内部执行消费视图，不默认对客户、甲方、供应商、合作方或外部协同方开放。任何对外展示、对外导出、客户确认、甲方确认或供应商协同输出，必须转入交付与协同视图，或经过权限校验、脱敏裁剪、人工确认和追溯处理。

## 四、取数范围

执行视图的取数必须以项目为主锚点，并从已满足可消费条件的对象资产、事实记录、校验结果和追溯锚点中读取。

执行视图可以读取以下对象资产：

| 对象资产 | 读取用途 | 边界 |
|---|---|---|
| 项目资产 | 确定项目范围、项目阶段、项目状态、项目负责人和执行归属 | 不修改项目本体，不改变项目阶段和项目状态 |
| 主体资产 | 识别人员、班组、供应商、客户、甲方、内部协同角色和责任相关主体 | 不新增主体，不静默合并主体，不自动确认责任 |
| 资料资产 | 识别资料应有项、资料归属、资料状态和资料缺失线索 | 不创建资料资产，不确认资料已提交或归档 |
| 物资资产 | 识别材料、设备、物资归属和物资状态 | 不改写库存、采购、损耗、报废或结算结果 |
| 组织资产 | 识别内部组织、部门、角色和权限范围 | 不改变组织结构和角色权限 |

执行视图可以读取以下事实记录：

| 事实记录 | 读取用途 | 边界 |
|---|---|---|
| 施工记录 | 生成施工摘要、施工执行清单、进度摘要和日报 / 周报输入 | 不替代施工事实，不确认施工完成或验收通过 |
| 资料记录 | 生成资料缺失清单、待补资料、待确认资料和资料归档提示 | 不确认资料已补齐，不替代资料记录 |
| 问题与风险记录 | 生成问题风险清单、阻塞事项、复核事项和风险提示 | 不自动定责，不自动关闭问题 |
| 决策与变更记录 | 生成变更确认事项、签证线索、范围调整和价格影响提示 | 不自动确认变更、签证、价格、责任或工期 |
| 物资流转记录 | 生成物资待处理清单、缺料、到场、领用、退库、损耗和报废线索 | 不创建流转事实，不确认采购、付款、损耗或报废 |
| 出勤记录 | 生成出勤摘要、到场异常、工时线索和现场参与情况 | 不确认工资、工时争议或付款 |
| 沟通与服务记录 | 生成沟通待办、客户确认线索、协同阻塞和下游动作摘要 | 不自动形成客户承诺 |
| 财务记录 | 读取与执行相关的待确认付款、费用、凭证和结算影响线索 | 不确认付款、收款、成本、利润或结算 |
| 责任与确认记录 | 读取责任、确认、待复核和人工确认状态 | 不自动生成责任结论 |
| 验收与交付记录 | 读取验收、交付、待确认和待复核线索 | 不自动确认验收完成或交付通过 |

执行视图不得直接从 Raw Store、未经治理的原始输入、未确认候选内容、AI 输出、页面缓存、临时导出结果或外部反馈生成正式执行结论。


本文当前不直接消费经验规则层中的正式规则、模板候选和提示候选；如后续执行视图需要消费此类规则，应明确规则版本、适用范围、来源依据、展示边界和不得反向发布规则的限制，并服从《00_汇总视图层总则》的取数与不反写真源规则。
## 五、输出范围

执行视图可以生成以下派生输出：

| 输出项 | 含义 | 主要来源 | 输出属性 | 人工确认要求 |
|---|---|---|---|---|
| 项目进度摘要 | 项目当前推进位置、关键节点、近期变化和阻塞提示 | 项目资产、施工记录、问题与风险记录、决策与变更记录、出勤记录 | 派生摘要 | 涉对外、验收、承诺、结算时必须确认 |
| 当前待办清单 | 当前待处理、待补、待确认、待复核事项 | 施工、资料、问题、物资、沟通、决策与变更、出勤记录 | 候选清单 | 高风险事项必须确认 |
| 施工执行清单 | 施工相关当前事项和现场推进线索 | 施工记录、问题记录、资料记录、物资流转记录 | 候选清单 | 涉验收、返工、责任时必须确认 |
| 资料缺失清单 | 当前缺失、待补、待确认、待归档资料 | 资料资产、资料记录、沟通记录、决策与变更记录 | 候选清单 | 正式资料确认必须回到资料记录 |
| 问题风险清单 | 当前问题、风险、阻塞和异常 | 问题与风险记录、施工记录、资料记录、沟通记录、财务记录 | 候选清单 / 风险提示 | 中高风险和责任事项必须确认 |
| 物资待处理清单 | 缺料、待到场、待领用、待退库、损耗和报废线索 | 物资资产、物资流转记录、施工记录、问题记录 | 候选清单 | 涉采购、付款、损耗、报废、赔偿时必须确认 |
| 变更确认事项 | 范围、价格、材料、工期、责任、签证、验收等待确认事项 | 决策与变更记录、沟通记录、资料记录、施工记录、财务记录 | 待确认清单 | 必须人工确认 |
| 出勤摘要 | 到场、工时、参与人员、班组和现场协同摘要 | 出勤记录、施工记录、主体资产 | 草稿摘要 | 涉工资、费用、争议时不得自动确认 |
| 日报 / 周报输入摘要 | 日报和周报所需事实素材 | 多类事实记录和追溯锚点 | 草稿素材 | 对外发布前必须确认 |
| 执行异常提示 | 字段缺失、锚点缺失、状态冲突、证据不足、权限不足 | 校验结果、事实记录、对象资产 | 待补 / 挂起 / 阻断提示 | 阻断项必须进入归口链路 |

执行视图输出只能作为执行辅助、候选清单、草稿素材、派生摘要、风险提示、待补事项或待确认事项。任何输出如需成为正式事实、正式任务、正式确认、正式报告或正式对外材料，必须分流至对应事实记录、运行链路或交付与协同视图继续处理。

## 六、项目进度摘要规则

项目进度摘要用于帮助项目负责人快速判断项目当前推进位置。

项目进度摘要可以读取：

1. 项目资产中的项目范围、项目阶段、项目状态和负责人信息；
2. 最近施工记录和施工相关证据；
3. 当前问题与风险记录；
4. 当前资料缺失和资料待确认事项；
5. 当前变更、签证、范围、价格、责任和工期影响线索；
6. 当前物资待处理事项；
7. 最近沟通与服务记录；
8. 最近出勤记录；
9. 与项目推进相关的责任与确认记录、验收与交付记录。

项目进度摘要不得：

1. 修改项目阶段；
2. 修改项目状态；
3. 确认施工完成；
4. 确认验收完成；
5. 确认客户承诺；
6. 确认结算；
7. 作为正式对外项目进度报告。

项目进度摘要如存在关键输入缺失、事实冲突、证据不足、中高风险或权限不足，应标记为输入不足、需补充、需复核或阻断，不得生成正式结论。

## 七、当前待办清单规则

当前待办清单用于汇总项目当前应处理事项。

当前待办可以来源于：

1. 施工记录中的未完成事项；
2. 资料记录中的待补、待确认、待归档事项；
3. 问题与风险记录中的待处理、待复核、待关闭事项；
4. 物资流转记录中的待采购、待到场、待领用、待退库、待处理事项；
5. 决策与变更记录中的待确认、待执行、待留痕事项；
6. 沟通与服务记录中的下游动作摘要；
7. 出勤记录中的到场异常或待确认情况；
8. 责任与确认记录中的待确认、待复核和待回执事项。

当前待办清单不得直接创建正式任务，不得自动派工，不得自动承诺客户，不得自动确认责任，不得自动关闭问题，不得自动修改事实记录状态。

待办事项必须能够追溯到来源对象、来源事实或受控规则。无法定位来源的事项只能作为待补提示或异常提示，不得进入正式待办清单。

## 八、施工执行清单规则

施工执行清单用于汇总项目现场施工相关的当前事项。

施工执行清单可以读取：

1. 当日或周期施工记录；
2. 施工位置、工序、进度和施工证据；
3. 施工相关问题与风险；
4. 施工相关资料缺失；
5. 施工相关物资到场、领用和异常线索；
6. 施工相关变更确认事项；
7. 施工相关出勤摘要和现场参与主体。

施工执行清单不得替代施工记录，不得确认施工完成，不得确认验收通过，不得确认返工责任，不得直接生成对外报告，不得直接写入日报 / 周报正式稿。

施工执行清单发现施工事实缺失时，只能生成施工输入不足、待补事实、待补证据或待复核提示，不得补造施工事实。

## 九、资料缺失清单规则

资料缺失清单用于帮助项目负责人识别项目执行中缺失、待补、待确认、待归档的资料。

资料缺失清单可以读取：

1. 资料资产中的应有资料和资料归属；
2. 资料记录中的提交、补齐、确认、退回、归档过程；
3. 沟通与服务记录中的资料待办线索；
4. 决策与变更记录中的签证、变更、确认资料需求；
5. 财务记录中的凭证、发票、收据、付款凭证需求；
6. 问题与风险记录中的证据缺失线索；
7. 验收与交付记录中的验收资料和交付资料线索。

资料缺失清单不得创建资料资产，不得确认资料已提交，不得确认资料已归档，不得伪造资料证据，不得替代资料记录，不得直接确认结算依据完整。

资料缺失清单可以触发待补资料提示、资料确认提示、资料回流建议和资料归档候选，但必须回到资料资产、资料记录和标准治理链路处理。

## 十、问题风险清单规则

问题风险清单用于汇总当前影响项目执行推进的问题、风险、阻塞和异常。

问题风险清单可以读取：

1. 问题与风险记录；
2. 施工记录中的异常线索；
3. 资料记录中的缺失、退回、冲突；
4. 沟通与服务记录中的投诉、确认风险、客户不满；
5. 决策与变更记录中的范围、价格、责任、工期影响；
6. 财务记录中的付款、结算、应收应付风险；
7. 物资流转记录中的缺料、损耗、报废、到场异常；
8. 出勤记录中的缺勤、工时异常。

问题风险清单不得自动创建正式问题与风险记录，不得自动定责，不得自动关闭问题，不得自动确认整改完成，不得自动生成赔偿、扣款、付款或结算结论。

风险等级、责任主体、整改状态和关闭状态必须以正式问题与风险记录、责任与确认记录、校验结果和追溯记录为准。

## 十一、物资待处理清单规则

物资待处理清单用于汇总当前项目中的物资缺口、到场、领用、退库、调拨、损耗和报废相关事项。

物资待处理清单可以读取：

1. 物资资产状态；
2. 物资流转记录；
3. 施工记录中的物资需求；
4. 问题与风险记录中的物资异常；
5. 财务记录中的采购、付款、应付候选；
6. 资料记录中的物资凭证、送货单、验收单。

物资待处理清单不得创建物资流转事实，不得改写物资资产账面数量，不得确认采购完成，不得确认付款完成，不得确认损耗、报废或赔偿，不得替代库存管理系统。

涉及采购、付款、损耗、报废、赔偿、退库、调拨和结算影响的事项，只能作为待确认事项或候选线索输出。

## 十二、变更确认事项规则

变更确认事项用于汇总项目执行中需要确认的范围、价格、材料、工期、责任、签证、验收等事项。

变更确认事项可以读取：

1. 决策与变更记录；
2. 沟通与服务记录中的确认线索；
3. 资料记录中的签证、变更、确认资料；
4. 施工记录中的现场变更线索；
5. 财务记录中的金额影响和结算候选；
6. 问题与风险记录中的责任和风险线索；
7. 责任与确认记录中的人工确认状态；
8. 验收与交付记录中的待确认验收和交付事项。

变更确认事项不得自动确认客户承诺，不得自动确认价格，不得自动确认责任，不得自动确认签证，不得自动确认结算，不得直接转为正式决策与变更记录。

所有变更确认事项必须保留来源事实、证据锚点、涉及主体、风险等级和确认状态。涉客户、甲方、价格、责任、工期、验收、签证和结算的事项必须人工确认。

## 十三、出勤摘要规则

出勤摘要用于汇总现场参与人员、班组、管理人员的到场和工时情况。

出勤摘要可以读取：

1. 出勤记录；
2. 施工记录中的现场参与主体；
3. 主体资产中的人员、班组、管理人员；
4. 项目资产中的项目负责人和现场负责人；
5. 财务记录中的工资、报销、费用线索。

出勤摘要不得替代出勤记录，不得自动确认工资，不得自动生成付款，不得自动确认工时争议，不得自动评价工人或班组能力，不得反写主体履历。

出勤摘要用于项目执行判断和日报 / 周报输入时，应明确其输出属性为草稿摘要或候选线索，不得作为工资结算依据直接使用。

## 十四、日报 / 周报输入摘要规则

日报 / 周报输入摘要用于为项目日报、项目周报或内部执行复盘提供事实素材。

日报 / 周报输入摘要可以包含：

1. 项目基本摘要；
2. 当日或周期施工摘要；
3. 当日或周期资料摘要；
4. 当日或周期问题风险摘要；
5. 当日或周期物资摘要；
6. 当日或周期变更确认事项；
7. 当日或周期出勤摘要；
8. 当日或周期沟通服务摘要；
9. 当前待办和阻塞事项；
10. 需要人工确认的高风险事项。

日报 / 周报输入摘要不得替代日报 / 周报模板全文，不得自动对外发布，不得自动确认客户承诺，不得自动确认施工、验收、结算，不得反写事实记录，不得把缺失事实自动补齐。

日报 / 周报输入摘要如需对外发送，必须经过人工确认、权限裁剪、脱敏处理和追溯留痕，并按交付与协同视图或对外输出规则承接。

## 十五、对象资产关系

执行视图只能读取对象资产作为项目范围、主体识别、资料归属、物资归属、权限判断和展示维度。

执行视图不得创建对象资产，不得修改对象资产，不得静默合并对象，不得更改对象状态。发现对象锚点缺失、对象冲突、主体关系不清、项目归属不明或资料物资归属不明时，只能生成待补提示、候选对象线索、候选合并线索或人工确认事项。

对象资产修订必须回到对象资产层、标准治理和运行链路处理。执行视图重新生成时，应按查询请求对应的对象状态读取；涉及历史时间范围或历史快照版本的，应按指定快照或历史状态处理。

## 十六、事实记录关系

执行视图只能消费事实记录，不得创造事实记录，不得更改事实记录状态，不得关闭问题，不得确认变更，不得确认资料，不得确认付款，不得确认结算。

执行视图发现事实缺失、事实冲突、状态冲突、证据不足、风险等级异常或权限不足时，应生成待补提示、挂起提示、风险提示、候选修订、候选事实或分流建议，并进入对应事实记录链路和标准治理链路处理。

执行视图输出不得作为正式事实来源。清单、摘要、看板、日报 / 周报输入和异常提示只能作为派生消费结果，不能替代来源事实。

## 十七、校验与阻断规则

执行视图生成前应完成以下校验：

1. 是否存在唯一项目锚点；
2. 项目资产是否可被当前角色正式消费；
3. 来源事实是否具备明确事实类型；
4. 来源事实是否具备可识别状态；
5. 来源事实是否通过校验，或明确处于候选、待补、挂起、驳回、历史参考等状态；
6. 高风险事项是否标记人工确认；
7. 来源证据是否可追溯；
8. 对象锚点是否缺失；
9. 字段缺失是否影响输出可信度；
10. 是否存在事实冲突、状态冲突、证据冲突或权限冲突；
11. 输出是否试图反写对象资产或事实记录；
12. 输出是否涉及对外展示、客户承诺、金额、责任、验收、签证、付款或结算。

本节的正式执行视图输出，是指以正式结论、正式状态、已确认事实、可直接执行结果或可对外承接结果形式展示的视图结果。问题风险清单、待补事项、候选清单、风险提示、阻断提示和待确认事项可以展示未完成确认的高风险线索，但必须明确其候选、风险、待补、待确认或阻断属性，不得被展示为正式结论或已确认事实。

以下情形不得生成正式执行视图输出：

1. 无法绑定唯一项目；
2. 项目对象不唯一或不可见；
3. 来源事实不明；
4. 来源事实无状态；
5. 来源证据不可追溯；
6. 高风险事项未标记人工确认；
7. 客户承诺未确认却试图作为已确认结果展示；
8. 付款、收款或结算事项被自动确认；
9. 变更、签证、责任或验收事项被自动确认；
10. 清单事项无法定位来源对象或来源事实；
11. 内部执行底稿被默认对外开放；
12. 视图输出试图反写对象资产或事实记录。

## 十八、追溯要求

执行视图必须具备来源追溯、生成追溯、权限追溯、输出追溯和回流追溯。

执行视图至少应保留以下追溯信息：

1. 视图类型；
2. 项目锚点；
3. 查询范围或生成范围；
4. 服务角色；
5. 来源对象资产集合；
6. 来源事实记录集合；
7. 校验结果；
8. 生成规则版本；
9. 输出状态；
10. 生成时间；
11. 视图输出快照标识；
12. 人工确认记录；
13. 对外裁剪和脱敏记录；
14. 回流记录；
15. 异常、挂起、阻断或熔断原因。

当视图输出因校验失败进入挂起、阻断或熔断状态时，应至少保留触发条件、缺失项、冲突来源、风险等级、处理建议和建议归口；同一事项同时触发异常提示与挂起、阻断或熔断的，应分别保留异常原因和状态处理原因。回流记录应保留来源视图、来源对象、来源事实、触发原因、建议归口和处理状态。

执行视图不得无源生成，不得无痕修改，不得用最新视图覆盖历史发布快照，不得让页面缓存、前端本地状态、AI 摘要、截图或临时导出结果替代可追溯视图输出。

## 十九、回流规则

执行视图发现缺失、冲突、异常、风险或待确认事项时，只能生成候选回流，不得直接覆盖对象资产或事实记录。

回流可以包括：

1. 对象锚点待补；
2. 主体关系待确认；
3. 资料缺失待补；
4. 施工事实待补；
5. 问题风险待处理；
6. 物资流转待确认；
7. 变更事项待确认；
8. 出勤异常待复核；
9. 财务影响待确认；
10. 日报 / 周报输入缺口；
11. 对外展示前的裁剪、脱敏和确认事项。

候选回流必须明确来源视图、来源对象、来源事实、触发原因、建议归口和处理状态。回流内容不得自动成为正式事实、正式对象、正式责任、正式承诺或正式决策。

## 二十、项目负责人执行看板承接

执行视图应能够支撑项目负责人执行看板，但看板只是执行视图的展示形态，不新增一级视图，不新增业务数据体系层级。

项目负责人执行看板最低应能展示：

1. 今日待办；
2. 施工进度；
3. 问题风险；
4. 资料缺失；
5. 物资待处理；
6. 变更待确认；
7. 班组或供应商协同阻塞；
8. 出勤与现场参与摘要；
9. 问题闭环状态；
10. 日报 / 周报输入提示。

项目负责人执行看板只消费执行视图输出，不直接消费 Raw Store，不反写对象资产和事实记录。看板中的待办、提醒和建议如需修正事实，必须提交候选修正并回到标准治理、运行链路和对应事实记录处理。

## 二十一、下游承接关系

系统业务运行规则中的 L3 结果生成规则，应承接执行视图的输入筛选、聚合生成、输出状态、快照留痕、失败阻断、候选回流和不反写真源规则。

前后端协同边界与页面承接中的查询与结果展示页面映射，应承接执行视图的角色化展示、状态提示、待补提示、风险提示、候选与正式区分、人工确认提示、对外转交边界和页面不裁决事实规则。

验证与验收规则应至少验证：执行视图只消费正式对象和正式事实；未确认候选不得展示为正式执行结论；待办清单不得自动派工；问题风险不得自动关闭；变更确认事项不得自动确认客户承诺、价格、责任、工期、签证或结算；内部执行视图不得默认对外开放；视图输出不得反写对象资产和事实记录。

下游承接文件如发现本文未覆盖的执行视图边界场景，应回流为本文修订候选，不得在下游文件中直接新增与本文冲突的取数、输出、确认、对外展示或反写规则。

## 二十二、边界判断口径

执行视图相关设计满足以下条件时，视为边界成立：

1. 执行视图服务项目负责人、一线人员和内部协同角色；
2. 执行视图以项目执行消费为主，不默认对外开放内部执行底稿；
3. 执行视图只消费对象资产和事实记录；
4. 执行视图不创造事实；
5. 执行视图不修改对象资产；
6. 执行视图不改写事实记录；
7. 执行视图不自动确认客户承诺；
8. 执行视图不自动确认付款、收款或结算；
9. 执行视图不自动确认变更、签证、责任、工期或验收；
10. 执行视图不自动关闭问题；
11. 执行视图不替代完整项目管理软件；
12. 执行视图输出能够区分派生摘要、候选清单、草稿素材、待补提示、待确认事项和阻断提示；
13. 未完成确认的高风险线索只能作为候选、风险、待补、待确认或阻断内容展示，不得展示为正式结论；
14. 执行视图能够追溯来源对象、来源事实、校验结果、生成规则、输出状态、视图输出快照标识、异常原因和状态处理原因；
15. 项目负责人执行看板只作为执行视图展示形态，不新增一级视图；
16. 对外展示必须转入交付与协同视图或经过权限、脱敏、人工确认和追溯处理；
17. 后续接口、页面、测试和代码实现不得反向改变本文确定的执行视图边界。
