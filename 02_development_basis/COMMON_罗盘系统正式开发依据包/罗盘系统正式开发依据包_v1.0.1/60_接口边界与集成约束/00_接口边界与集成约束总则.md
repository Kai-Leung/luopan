# 00_接口边界与集成约束总则

## 一、文件定位

本文定义罗盘系统接口边界与集成约束的总口径，用于承接输入、上传、外部系统接入、外部反馈、页面动作、候选生成、授权输出、回执接入、失败回退、熔断控制和前后端联调中的接口边界。

本文只定义接口在系统主链路中的承接范围、治理约束、禁止越界事项和下游分工，不定义具体接口路径、方法、请求响应结构、数据库字段、代码实现、SDK 选型、部署方式或实施计划。

60 目录下各细则文件、70 目录页面承接文件和 80 目录验证验收文件，均应以本文作为接口边界总入口，不得通过接口实现便利性反向改变系统架构、业务数据体系、标准治理或系统业务运行规则。

## 二、目录总职责

60_接口边界与集成约束承担以下职责：

1. 定义系统输入、上传、外部反馈、页面动作和外部连接进入罗盘系统时的接口承接边界。
2. 明确接口与 L0-L7 纵向架构、横向治理、业务数据体系和系统业务运行规则之间的衔接关系。
3. 约束接口不得绕过身份识别、访问范围、权限校验、风险校验、关键字段反问、追溯记录、版本记录和失败熔断。
4. 约束接口不得直接写入正式事实、正式状态、正式权限、正式规则或正式业务结论。
5. 定义输入、外部系统映射、回执、失败回退、页面动作、前后端联调和 X1 接口控制的分工边界。
6. 为后续页面承接、联调验证和验收规则提供接口侧判断依据。

60 目录不是业务事实定义目录，不是页面设计目录，不是技术接口契约目录，不是数据库或代码实现目录。

## 三、接口边界的上位约束

接口边界必须继承以下上位约束：

1. 罗盘系统的运行主链路以 L0-L7 纵向架构为基础，接口只能按职责接入对应层级，不得新增独立运行链路。
2. 正式事实只允许由 L2 真源入链层写入，接口、页面、AI、外部系统、回执、汇总视图和授权输出均不得直接生成或改写正式事实。
3. 原始输入、上传资料、外部反馈、外部系统载荷和接口回执，应先作为原始输入、资料、候选内容、反馈线索或回执记录进入对应治理链路。
4. 候选内容转为正式内容前，必须经过标准治理、权限校验、风险校验、关键字段补齐、必要人工确认和追溯记录。
5. 汇总视图层只消费对象资产层和事实记录层，不通过接口反向创造事实。
6. 经验规则层只形成可复用候选内容，不通过接口直接发布正式规则。
7. AI 辅助预处理、候选归整、缺口提示和复杂关口算力支撑均不得替代系统校验、权限判断、风险裁决、人工确认或 L2 入链。
8. 外部展示和授权输出必须服从脱敏、可见性、授权范围、版本和追溯要求。

接口调用成功、页面操作成功、外部系统返回成功、文件上传成功、导出成功、回执接收成功，均不等同于业务事实成立、状态正式变更、权限正式授予或规则正式发布。

## 四、接口可承接对象与不可改写对象

| 接口承接对象 | 接口可承接内容 | 接口不可改写内容 |
|---|---|---|
| 原始输入 | 接收用户输入、语音转写结果、图片、文件、表格、聊天记录、外部载荷等原始来源 | 不得直接改写正式事实、正式状态或正式业务结论 |
| 上传资料 | 接收资料本体、资料来源、资料归属线索、资料与项目或主体的候选关联 | 不得因上传成功直接认定资料为正式证据或正式事实 |
| 外部系统数据 | 接收外部字段、外部状态、外部编号、外部回执和外部反馈 | 不得用外部字段直接覆盖系统标准字段、状态、权限或真源内容 |
| 页面动作 | 承接页面触发、提交、确认、查询、导出、反馈等动作请求 | 不得让页面动作反向定义业务规则、事实真源或权限边界 |
| 候选生成 | 承接候选内容、缺口提示、反问结果和候选校验结果 | 不得跳过治理链路直接形成正式内容 |
| 授权输出 | 承接查询、导出、分享、外部展示和文件生成的授权边界 | 不得因输出成功认定事实新增、确认完成或状态变更 |
| 回执接入 | 承接发送结果、外部响应、处理反馈、失败信息和执行反馈 | 不得把回执直接等同于业务确认、责任确认或事实确认 |
| 失败回退 | 承接阻断、挂起、重试、降级、熔断和回流处理结果 | 不得静默丢弃失败、伪造成功或绕过追溯记录 |

## 五、接口与 L0-L7 主链路的承接边界

| 主链路位置 | 接口承接边界 | 禁止越界 |
|---|---|---|
| L0 原始输入层 | 接收原始输入、上传资料、外部载荷和外部反馈，并保留来源、上下文和证据线索 | 不得直接生成候选结论、正式事实或汇总视图结果 |
| L1 候选治理层 | 承接候选生成、候选归整、缺口提示、反问补齐和候选校验结果 | 不得把候选内容、AI 输出或外部字段直接认定为正式事实 |
| L2 真源入链层 | 仅承接已满足治理、权限、风险、确认和追溯要求的正式入链请求 | 不得允许接口绕过治理闸门直接写入正式事实 |
| L3 汇总视图层 | 承接查询、汇总、看板、统计和展示类读取请求 | 不得通过视图查询结果反向改写事实记录或对象资产 |
| L4 分析判断层 | 承接受控分析、辅助判断和风险提示类请求 | 不得把分析结果作为自动裁决或正式业务决定 |
| L5 经验规则层 | 承接经验、模板、规则候选、复盘候选和可复用建议 | 不得直接发布正式规则或覆盖既有治理规则 |
| L6 执行响应层 | 承接受控执行、外部发送、授权输出、外部协同和回执接入 | 不得因执行或回执成功直接改写真源 |
| L7 反馈回流层 | 承接外部反馈、使用反馈、问题反馈和执行反馈回流 | 不得让反馈内容直接覆盖正式数据或正式规则 |

接口层只承担接入、提交、触发、读取、返回、记录和回流的边界职责，不承担事实裁决、状态裁决、权限裁决或规则发布职责。

## 六、横向治理嵌入规则

所有接口必须嵌入横向治理要求。接口设计、联调和验收不得只检查能否调用成功，还必须检查是否满足治理边界。

### 6.1 身份与访问范围

接口在承接输入、查询、确认、导出、外部展示、外部发送和回执接入前，应识别操作者、所属组织、角色、项目范围、主体范围和可见范围。

无法确认身份、组织归属、访问范围或授权边界时，接口不得继续执行会影响候选生成、正式入链、授权输出或外部展示的动作。

### 6.2 权限与可见性

接口返回内容、导出内容、外部展示内容和页面可见内容，必须受权限与可见性口径约束。

页面可见不等于接口可操作，接口可调用不等于业务可执行，外部可访问不等于外部可见全部内容。

### 6.3 状态与动作约束

接口只能承接符合当前状态边界的动作请求。状态不满足、前置治理未完成、候选内容被阻断或风险未处理时，接口不得继续承接确认、入链、输出或外部发送动作。

接口返回的处理结果只表示本次接口承接动作的处理状态，不得被解释为业务事实状态或正式业务结论。

### 6.4 校验、风险与反问

接口在承接输入、候选生成、确认、输出、外部连接和回执处理时，应按标准治理要求触发校验、风险识别和关键字段反问。

关键锚点缺失、证据不足、归属不明、权限不足、风险等级不明或校验不通过时，接口应进入补齐、挂起、阻断、熔断或回流处理，不得通过默认值、前端补写或外部字段自动补齐正式内容。

### 6.5 追溯、版本与审计

接口承接的原始输入、候选内容、确认动作、外部发送、外部回执、授权输出、失败回退和熔断处理，均应保留可追溯关系。

接口不得产生无来源、无版本、无操作者、无上下文、无处理结果的业务动作记录。涉及外部系统、外部协同和授权输出时，应保留输出范围、输出内容、输出对象、输出版本和后续反馈关系。

### 6.6 脱敏与外部展示

对客户、甲方、甲方员工、供应商、班组、外部协作方或其他外部角色展示内容时，接口必须执行授权范围与脱敏边界。

外部展示只能展示其权限范围内、已被允许展示的内容；不得通过接口暴露内部经营、成本利润、未授权资料、审计记录、模型调用记录、内部规则配置或其他不应外显内容。

### 6.7 AI 辅助接口边界

AI 相关接口只能承接辅助录入、语音转文字增强、候选预处理、候选归整、缺口提示、复杂关口辅助分析和模型调用记录。

AI 输出默认是候选内容。接口不得把 AI 输出作为事实确认结果、权限判断结果、风险裁决结果、状态流转结果、正式规则发布结果或对外展示放行结果。

## 七、输入、上传与外部接入规则

输入、上传和外部接入类接口必须遵守以下规则：

1. 所有输入优先进入 L0 原始输入层或资料资产相关链路，不得直接进入 L2 真源入链层。
2. 上传资料首先作为资料资产或资料线索处理，资料动作按资料记录处理，资料作为证据时再进入证据链和追溯关系。
3. 外部系统载荷、外部字段、外部状态和外部回执必须保留原始来源与映射关系，不得直接覆盖系统内部标准口径。
4. 同一来源或相似内容重复提交时，接口应按重复识别、关联挂接或补充材料处理，不得重复制造事实。
5. 无法识别项目、主体、组织、权限、时间、来源或证据关系的输入，应进入补齐或挂起处理。
6. 来自外部角色的反馈、问题、确认、补充和异议，均应先作为外部反馈或候选线索处理，不得直接改写正式事实。
7. 任何接口不得以上传成功、解析成功、接收成功替代业务确认。

## 八、候选生成、确认与入链接口边界

候选生成、确认与入链相关接口应区分候选、确认和正式入链三类边界。

1. 候选生成接口可承接原始输入归整、资料识别结果、AI 辅助预处理结果、系统校验结果和缺口提示。
2. 候选内容进入确认前，必须满足权限、范围、关键字段、风险、证据和追溯的基本要求。
3. 确认接口只能承接符合权限和状态要求的确认动作，不得替代确认主体作出确认。
4. 被阻断、驳回、挂起或熔断的候选内容，不得通过接口创建正式入链结果。
5. 补齐后的候选内容必须重新进入治理校验，不得因补齐动作完成而直接正式化。
6. 正式入链接口只承接已完成必要治理和确认的入链请求，正式事实仍以 L2 真源入链层为准。
7. 页面确认动作、外部确认动作和接口处理成功均不等同于 L2 入链完成。

## 九、授权输出、外部展示与回执规则

授权输出、外部展示和回执接入必须遵守以下规则：

1. 授权输出应基于权限范围、数据来源、版本状态、脱敏边界和追溯要求生成。
2. 导出、分享、外部展示和候选文件生成，不得创造新的正式事实。
3. 输出内容包含候选内容、未确认内容、辅助分析内容或模板生成内容时，应保留其候选或辅助属性，不得伪装为正式事实。
4. 外部系统或外部对象返回的回执，只能作为回执记录、反馈线索、执行结果线索或候选内容进入系统。
5. 回执接收成功不等于对方业务确认，不等于责任确认，不等于金额确认，不等于事实确认。
6. 外部反馈涉及事实变更、责任变化、问题处理、资料补充或状态异议时，应按回流规则重新进入候选治理。
7. 授权输出后的纠错、异议、补充和反馈不得直接覆盖原正式数据，应进入回流挂接与治理链路。

## 十、失败回退与熔断边界

接口失败、外部调用失败、回执异常、权限异常、校验异常、状态异常、映射异常、重复提交、证据缺失和高风险动作异常，均应进入失败回退与熔断边界处理。

接口失败处理必须满足以下要求：

1. 失败原因应可追溯，不得静默丢弃。
2. 失败结果应区分可补齐、可重试、需人工处理、需阻断、需熔断和需回流等处理方向。
3. 高风险动作、外部发送、授权输出和正式入链相关动作不得在风险未解除时自动重试。
4. 熔断后不得继续执行外部发送、确认、入链、导出或展示等受控动作。
5. 失败回退不得篡改原始输入、候选内容、正式事实或既有追溯关系。
6. 接口不得伪造成功结果，不得通过前端提示掩盖后端失败。
7. 失败恢复后，相关内容仍应回到对应治理节点继续处理，不得跳过校验与确认。

## 十一、页面动作接口边界

页面动作接口用于承接前端页面的提交、查询、确认、补齐、上传、导出、反馈、外部展示触发和状态查看等动作。

页面动作接口必须遵守以下边界：

1. 页面只触发动作，不定义业务规则。
2. 页面只展示接口返回结果，不定义事实真源。
3. 页面状态提示只表达当前处理结果或可执行动作，不定义正式状态。
4. 页面按钮、弹窗、提示、入口和交互路径不得绕过后端治理链路。
5. 页面补齐内容仍应回到候选治理链路，不得直接写入正式事实。
6. 页面导出或分享动作必须受权限、脱敏、版本和追溯约束。
7. 页面联调通过不等于业务验收通过。

70 目录可以承接页面如何展示、如何提示、如何组织用户动作，但不得改变本文定义的接口边界。

## 十二、外部连接控制边界

X1 接口控制用于汇总外部连接、外部输入、外部输出、外部系统映射、外部协同和回执接入的控制要求。X1 不新增独立业务链路，不替代 L0-L7 主链路，不替代横向治理，不替代 L2 真源入链层。

外部连接控制必须遵守以下边界：

1. 外部系统只能作为输入来源、输出对象、回执来源、反馈来源或协同对象。
2. 外部系统字段不得直接成为系统标准字段。
3. 外部系统状态不得直接成为系统正式状态。
4. 外部系统权限不得直接成为系统内部权限。
5. 外部系统回执不得直接成为业务事实确认。
6. 外部协同对象提交的问题、反馈、补充和确认，必须按身份、范围、权限、风险和追溯要求治理。
7. 外部系统异常时，应触发失败回退、熔断或人工处理，不得继续自动推进高风险动作。

## 十三、与前后端联调和验收的关系

前后端联调应验证接口边界是否正确承接系统规则，而不是只验证接口是否能够调用。

联调至少应覆盖以下判断：

1. 输入是否先进入原始输入或候选链路。
2. 上传资料是否未被直接认定为正式事实。
3. 页面动作是否未反向定义正式状态、权限或规则。
4. 外部反馈和回执是否未直接改写正式事实。
5. 候选内容是否经过治理后才允许进入确认与入链。
6. 权限不足、范围不明、关键字段缺失、风险未处理时是否被阻断或挂起。
7. 授权输出是否受脱敏、版本、权限和追溯约束。
8. 失败、异常和熔断是否保留追溯并阻止越界推进。
9. AI 辅助结果是否保持候选属性。
10. L2 正式入链是否未被接口、页面、外部系统或回执绕过。

80 目录的验证与验收规则应基于上述边界设计测试判断，不得把接口调用成功、页面显示正常或外部系统返回成功作为业务规则成立的唯一依据。

## 十五、禁止事项

60 目录及其下游接口边界文件禁止写入以下内容：

1. 禁止写入具体接口路径、方法、请求响应结构、数据库字段、代码实现、SDK 选型和部署脚本。
2. 禁止通过接口绕过 L0-L7 主链路、横向治理和 L2 真源入链层。
3. 禁止让接口、页面、AI、外部系统、回执、导出文件或汇总视图直接定义正式事实。
4. 禁止让外部字段、外部状态或外部权限直接覆盖系统标准口径。
5. 禁止把上传成功、解析成功、调用成功、发送成功、导出成功或回执成功解释为业务事实成立。
6. 禁止让页面动作反向定义业务规则、状态流转、权限边界或正式事实。
7. 禁止让 AI 输出替代系统校验、人工确认、风险裁决或正式入链。
8. 禁止让授权输出、外部展示或模板生成文件创造正式事实。
9. 禁止失败静默丢弃、伪造成功、无追溯回退或绕过熔断继续执行。
10. 禁止为了接口实现便利新增字段、枚举、状态、权限、事实类型、架构层级或系统能力。
