# 02_外部系统映射规范

## 一、文件定位

本文定义外部系统、外部表格、外部表单、外部资料库、历史台账、外部协同反馈和外部回执中的对象、字段、状态、分类、身份、项目、资料、动作结果与罗盘系统内部标准之间的映射边界。

本文只定义外部内容进入罗盘系统时的映射原则、候选化规则、保真要求、冲突处理和禁止反写边界，不定义具体 URL、HTTP 方法、JSON schema、数据库字段、代码实现、SDK 选型、数据迁移脚本或实施计划。

外部系统映射的核心职责是：保留外部原始表达，将外部表达转换为罗盘系统可识别的候选映射关系，并交给标准治理、业务数据体系和系统业务运行规则继续处理。外部系统映射不得直接覆盖系统内部标准口径或正式结果。

## 二、外部系统映射总职责

外部系统映射承担以下职责：

1. 识别外部对象、外部字段、外部状态、外部分类、外部编号、外部主体、外部资料和外部回执的来源。
2. 保留外部原始名称、原始值、原始状态、原始分类、原始编号、来源系统、来源文件和上下文。
3. 将外部表达映射为罗盘系统内部标准的候选对象线索、候选字段线索、候选状态线索、候选事实线索、候选资料线索或候选回执线索。
4. 判断映射是否明确、是否冲突、是否低置信、是否涉及高风险、是否需要人工确认。
5. 防止外部字段、外部状态、外部分类、外部权限和外部回执绕过系统标准治理直接进入正式链路。
6. 为后续输入接口、回执接入、失败回退、前后端联调、页面展示和验收判断提供映射边界依据。

外部系统映射不承担以下职责：

1. 不定义罗盘系统正式字段。
2. 不定义罗盘系统正式枚举。
3. 不定义罗盘系统正式状态。
4. 不定义罗盘系统正式权限。
5. 不确认外部内容是否构成正式事实。
6. 不确认外部主体是否具备系统内正式身份。
7. 不确认外部回执是否构成业务确认。
8. 不把外部系统结构反向写成罗盘系统数据模型、运行链路或接口契约。

## 三、可映射外部来源范围

外部系统映射可承接以下来源：

| 外部来源 | 可映射内容 | 映射边界 |
|---|---|---|
| 外部表格 | 项目名称、客户名称、金额、日期、施工项、资料名称、状态列、备注列 | 只形成候选映射，不直接生成正式财务记录、结算结果或汇总结果 |
| 外部表单 | 提交主体、问题描述、项目线索、附件、选择项、提交时间 | 只形成候选输入和候选反馈，不直接确认事实 |
| 外部资料库 | 文件名称、目录、资料类型、资料归属、版本、上传人 | 只形成资料候选线索，不确认资料有效性 |
| 外部项目管理工具 | 项目、任务、进度、责任人、完成状态、评论、附件 | 只形成候选执行线索，不直接确认施工或责任事实 |
| 外部财务工具 | 收款、付款、发票、对账、报销、凭证、金额状态 | 只形成候选财务线索，不直接确认财务事实 |
| 外部沟通工具 | 消息、截图、语音转写、群名、成员、客户反馈 | 只形成原始输入或候选线索，不直接确认承诺 |
| 外部协同入口 | 客户、甲方、甲方员工、供应商、班组提交的问题或反馈 | 只形成外部反馈候选，不直接改写真源 |
| 历史系统导出 | 历史对象、历史字段、历史状态、历史事实、历史附件 | 只形成迁移候选，不直接进入当前正式链路 |
| 外部回执来源 | 签收、拒绝、补充、完成、失败、退回、系统响应 | 只形成回执候选，具体接入由回执接入规范承接 |

上述范围只说明可被映射的外部来源，不表示其内容可以自动通过治理。所有映射结果必须继续服从身份、权限、状态、风险、校验、追溯、反问和人工确认要求。

## 四、映射对象分类

外部系统映射应按对象类型识别，不得把所有外部字段统一压成“数据导入”。

| 外部表达对象 | 可映射为 | 不得直接形成 |
|---|---|---|
| 外部项目名称、项目编号、群名、合同编号、地址 | 候选项目资产线索或项目归属线索 | 正式项目资产 |
| 外部客户、联系人、甲方人员、供应商、班组、员工 | 候选主体资产线索或角色关系线索 | 正式主体身份或正式角色关系 |
| 外部材料、设备、工具、物资名称 | 候选物资资产线索或物资事实线索 | 正式物资资产或正式物资流转事实 |
| 外部文件、附件、目录、资料包 | 候选资料资产线索或资料记录线索 | 正式资料资产、正式证据或正式资料记录 |
| 外部施工项、任务、节点、进度 | 候选施工记录线索或执行线索 | 正式施工记录 |
| 外部收付款、发票、对账、报销、结算 | 候选财务记录线索 | 正式财务记录 |
| 外部问题、风险、投诉、整改、异常 | 候选问题与风险记录线索 | 正式问题与风险记录 |
| 外部变更、签证、确认、审批、承诺 | 候选决策与变更记录线索 | 正式决策与变更记录 |
| 外部评论、沟通、留言、确认截图 | 候选沟通与服务记录线索 | 正式沟通与服务记录 |
| 外部完成、失败、签收、驳回、补充 | 候选回执线索 | 正式确认、正式状态或正式事实 |

外部映射对象只作为候选锚点进入治理链路。是否形成对象资产或事实记录，应由业务数据体系、系统业务运行规则和 L2 真源入链规则裁决。

## 五、外部字段映射规则

外部字段映射必须遵守以下规则：

1. 必须保留外部字段原始名称、原始值、来源位置、来源文件或来源系统。
2. 外部字段只能映射为系统标准字段的候选引用或候选线索，不得直接成为正式标准字段。
3. 外部字段无法对应现有标准字段时，应标记为未归口候选，不得临时新增标准字段。
4. 外部字段名称与系统标准字段名称相同，也不得跳过来源保留、权限校验、状态校验和追溯要求。
5. 外部字段一对多映射时，应保留多个候选映射方向，并标明需要人工确认。
6. 多个外部字段映射到同一标准含义时，应保留来源差异，不得直接合并覆盖。
7. 外部字段值不完整、口径不明、单位不明、时间不明或责任不明时，应进入待补、挂起或人工确认。
8. 涉及金额、责任、工期、验收、结算、客户确认、甲方确认、外部承诺和对外展示的字段，应触发风险与人工确认要求。
9. 外部字段不得绕过字段规范总表、枚举总表、状态口径总表和权限与可见性口径。
10. 外部字段映射结果不得被页面、接口或导入程序解释为正式入链结果。

本文不得列出或新增新的系统字段全集。涉及系统字段定义时，应引用标准治理文件既有口径；标准缺失时，只能形成标准治理候选，不得在本文直接补齐。

## 六、外部状态映射规则

外部系统状态必须作为候选状态线索处理，不得直接成为罗盘系统正式状态。

外部状态映射必须遵守以下规则：

1. 外部状态原值必须保留，不得只保留转换后的系统状态候选。
2. 外部状态只能映射到系统状态口径的候选引用，不得新增正式状态值。
3. 外部状态表达含义不明时，应进入人工确认，不得按字面含义自动转换。
4. 外部状态与系统标准状态名称相似时，也必须判断其适用对象、状态组和业务语义是否一致。
5. 外部状态如同时表达进度、确认、异常、权限或回执结果，应拆分为多个候选线索，不得强行压缩成一个状态。
6. 外部状态涉及“完成、通过、确认、已收、已付、已验收、已签收、已关闭”等表达时，不得自动认定正式事实成立。
7. 外部状态与系统既有对象、事实、候选、输出或回流状态冲突时，应保留冲突并进入待核对。
8. 外部状态不得由页面展示、接口回执或导出结果反向升格为正式状态。

状态映射只解决“外部状态如何被理解和候选化”，不解决状态变更是否成立。状态变更是否成立，应由系统业务运行规则、确认规则、追溯规则和 L2 真源入链规则裁决。

## 七、外部枚举、分类与选项映射规则

外部枚举、分类、下拉选项、标签、分组、阶段、类型和外部系统自定义值，应按候选分类线索处理。

映射规则如下：

1. 外部分类原值必须保留。
2. 外部分类不得直接进入系统受控枚举。
3. 外部自定义值不得直接成为系统正式枚举值。
4. 外部分类与系统枚举名称相同时，仍需判断适用范围和业务含义。
5. 外部分类存在多义、混用、旧称或组织内习惯表达时，应标记为候选映射。
6. 外部标签不得直接成为系统状态、权限、风险等级或事实类型。
7. 外部阶段不得直接成为系统流程状态。
8. 外部分组不得直接成为系统组织、项目或主体归属。
9. 无法归口的外部分类，应进入标准治理候选或人工确认，不得在接口层新增枚举。
10. 外部分类映射必须保留版本和来源，便于后续追溯与调整。

## 八、外部身份、权限与组织关系映射规则

外部系统中的用户、客户、甲方、供应商、班组、联系人、账号、群成员、审批人、提交人、执行人、确认人和系统账号，均只能作为候选主体或候选关系线索处理。

映射规则如下：

1. 外部账号不等于系统用户。
2. 外部联系人不等于正式主体资产。
3. 外部群成员不等于项目成员。
4. 外部审批人不等于系统确认主体。
5. 外部提交人不等于事实责任人。
6. 外部系统管理员不等于罗盘系统管理员。
7. 外部权限不等于系统内部权限。
8. 外部可见范围不等于系统授权范围。
9. 外部组织架构不等于系统组织归属。
10. 外部身份映射为系统候选主体、候选角色、候选成员关系或候选外部协同关系前，必须经过身份识别与访问范围规则约束。

涉及外部协同对象时，接口应保留其来源、提交范围、可见范围和关联项目线索。外部协同对象提交的问题、反馈、确认或补充，不得直接进入正式链路。

## 九、外部编号与引用关系映射规则

外部系统中的编号、单号、表格行号、文件编号、任务编号、审批编号、凭证编号、合同编号和回执编号，只能作为外部引用线索或候选关联线索处理。

映射规则如下：

1. 外部编号应保留原值、来源系统、来源文件和上下文。
2. 外部编号不得替代系统内部对象标识。
3. 外部编号不得替代正式事实标识。
4. 外部编号相同不等于对象相同。
5. 外部编号不同不等于对象不同。
6. 外部编号可用于辅助去重、关联、追溯和外部回执挂接。
7. 外部编号冲突时，应保留冲突来源并进入人工核对。
8. 外部编号被多个外部对象复用时，不得强行映射为唯一内部对象。
9. 外部编号缺失时，不得用接口生成值伪造外部编号。
10. 外部编号与内部标识之间的映射关系应可追溯、可回查、可废止。

## 十、映射保真与追溯要求

外部系统映射必须保证映射前后均可追溯。

最低保真要求包括：

1. 保留外部原始内容。
2. 保留外部原始字段名、原始状态、原始分类和原始编号。
3. 保留来源系统、来源文件、来源表格、来源表单、来源页面或来源渠道。
4. 保留映射发生时间线索。
5. 保留映射规则版本或映射依据线索。
6. 保留映射结果属于候选、已映射、待复核、被驳回、冲突或挂起的处理状态。
7. 保留人工确认、人工驳回、人工修订或人工归属的处理痕迹。
8. 保留多来源冲突、同名异义、一名多义、单位不一致、时间口径不一致和身份混用等冲突线索。
9. 保留与原始输入、资料资产、资料记录、外部回执和后续候选内容之间的关联。
10. 保留映射结果被后续治理、确认、入链、驳回或废止的追溯关系。

映射结果不得覆盖外部原值，不得只保留内部候选结果，不得因后续确认而删除映射过程。

## 十一、映射冲突处理规则

发生以下情况时，应进入冲突处理：

| 冲突类型 | 典型表现 | 处理边界 |
|---|---|---|
| 字段名冲突 | 外部“客户”可能指客户、联系人、甲方或主体资产 | 保留原值，形成候选主体线索，不直接定锚 |
| 状态冲突 | 外部“已完成”可能表示任务完成、施工完成、审批完成或回执完成 | 保留外部状态，进入状态候选和人工确认 |
| 分类冲突 | 外部“项目阶段”同时表达施工阶段、结算阶段或资料阶段 | 不直接映射为系统状态或枚举 |
| 时间冲突 | 外部提交时间、发生时间、审批时间、系统时间混用 | 保留多类时间线索，后续治理裁决 |
| 主体冲突 | 提交人、责任人、确认人、经办人混用 | 不形成责任事实，进入待补或人工确认 |
| 单位冲突 | 金额、面积、长度、数量、工时单位不一致 | 不自动换算入链，进入待核对 |
| 来源冲突 | 多个外部系统对同一事项给出不同结果 | 保留多来源，不覆盖正式事实 |
| 权限冲突 | 外部系统允许查看，但系统内无授权 | 以系统权限与可见性口径为准 |
| 回执冲突 | 外部返回成功，但系统校验失败 | 不以外部成功覆盖系统阻断 |
| 历史冲突 | 历史资料与当前治理结果不一致 | 历史资料作为候选线索，不反写真源 |

冲突处理不得静默覆盖，不得自动择优，不得以最新外部值覆盖系统正式值。无法唯一裁决时，应挂起、反问或转人工处理。

## 十二、映射结果流向规则

外部系统映射结果应按以下规则进入系统：

| 映射结果类型 | 后续流向 | 禁止事项 |
|---|---|---|
| 候选项目线索 | 进入对象资产层相关候选识别或项目归属补齐 | 不得直接创建正式项目资产 |
| 候选主体线索 | 进入主体资产候选识别或角色关系识别 | 不得直接确认身份、角色或权限 |
| 候选资料线索 | 进入资料资产、资料记录或证据链候选挂接 | 不得直接确认资料有效或证据成立 |
| 候选字段线索 | 进入标准治理、字段校验或候选内容治理 | 不得新增正式字段 |
| 候选状态线索 | 进入状态口径校验、运行规则或人工确认 | 不得直接变更正式状态 |
| 候选事实线索 | 进入 L1 候选抽取、横向治理和 L2 入链前校验 | 不得直接形成正式事实 |
| 候选回执线索 | 进入回执接入规范或 L7 反馈回流 | 不得直接形成业务确认 |
| 冲突映射线索 | 进入待补、挂起、反问或人工处理 | 不得自动覆盖既有内容 |
| 标准缺口线索 | 进入标准治理候选 | 不得在接口层发布正式标准 |

映射结果只能作为后续治理输入，不得作为正式结论输出给页面、外部系统或汇总视图。

## 十三、与输入接口、回执接入和失败回退的关系

外部系统映射与 60 目录其他文件的分工如下：

| 文件 | 与本文关系 | 分工边界 |
|---|---|---|
| 01_输入接口规范 | 负责外部内容如何被接收、保留、待补和交接 | 本文负责接收后的外部表达如何候选映射到系统标准 |

## 十四、与页面承接、联调和验收的关系

70 目录应基于本文承接以下页面表达：

1. 页面可展示外部原值和候选映射结果，但不得展示为正式事实。
2. 页面应区分“未映射”“已候选映射”“需复核”“冲突”“已驳回”“已确认进入后续治理”等处理方向。
3. 页面不得让用户误以为外部状态已经成为系统正式状态。
4. 页面不得用外部字段名直接替代系统标准字段。
5. 页面应在低置信、冲突、高风险、权限不足、项目不明和主体不明时提供补齐或人工确认入口。
6. 页面不得用导入成功、同步成功、外部成功回执替代系统校验结果。

80 目录应基于本文验证以下断言：

1. 外部原值是否被保留。
2. 外部字段是否未直接覆盖系统标准字段。
3. 外部状态是否未直接成为系统正式状态。
4. 外部分类是否未直接新增系统枚举。
5. 外部身份是否未直接成为系统用户、角色或权限。
6. 外部编号是否未直接替代系统内部标识。
7. 映射冲突是否被挂起、反问或人工处理。
8. 高风险映射是否触发风险与确认要求。
9. 映射结果是否只作为候选进入后续治理链路。
10. 外部成功、导入成功、同步成功是否未被当作正式事实成立。

## 十五、禁止事项

外部系统映射禁止出现以下行为：

1. 禁止外部字段直接成为正式字段。
2. 禁止外部状态直接成为正式状态。
3. 禁止外部分类直接成为正式枚举。
4. 禁止外部权限直接成为系统内部权限。
5. 禁止外部账号直接成为系统用户。
6. 禁止外部编号直接替代系统内部标识。
7. 禁止外部回执直接成为业务确认。
8. 禁止外部项目、客户、供应商、班组、资料、任务或财务记录直接成为正式对象或正式事实。
9. 禁止只保留映射结果而丢弃外部原值。
10. 禁止用映射置信、外部成功状态、页面确认或接口同步结果替代系统校验、人工确认和 L2 真源入链。
11. 禁止映射冲突时自动覆盖、自动合并、自动删除或自动择优。
12. 禁止为了兼容外部系统而新增字段、枚举、状态、权限、事实类型、架构层级、系统能力或业务边界。
