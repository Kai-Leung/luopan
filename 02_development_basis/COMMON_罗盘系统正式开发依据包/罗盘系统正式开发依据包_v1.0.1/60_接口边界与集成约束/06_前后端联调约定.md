# 06_前后端联调约定

## 一、文件定位

本文定义罗盘系统前端页面与后端接口联调时的边界约定，用于约束录入、上传、反问补齐、候选处理、外部映射、回执接入、失败回退、页面动作、授权输出、外部协同和 Mock 数据在联调过程中的接收、返回、记录、阻断和归口方式。

本文只回答前后端联调时应验证哪些接口动作边界、前端应如何识别接口处理方向、后端应如何返回受控结果、Mock 数据如何隔离、失败如何交接、回执如何展示和联调问题如何归口。

本文不定义具体 URL、HTTP 方法、JSON schema、数据库字段、代码实现、SDK 选型、页面布局、交互细节、测试脚本、部署命令或实施计划。

前后端联调的核心作用是：验证页面动作调用接口时，没有绕过输入、候选、回执、失败、权限、外部展示和后续业务运行边界；验证接口返回结果被页面正确展示为处理方向，而不是被误展示为正式事实、正式状态或正式确认。

## 二、联调总边界

前后端联调按以下模型处理：

| 联调环节 | 联调应验证的问题 | 不承担内容 |
|---|---|---|
| 前端发起什么 | 页面动作、提交内容、上下文、目标对象和操作主体是否被明确传递 | 不定义页面布局和组件样式 |
| 后端接收什么 | 接口是否按输入、映射、回执、失败或页面动作边界接收 | 不定义具体接口协议 |
| 后端记录什么 | 是否保留来源、动作、对象、结果、失败、回执和追溯线索 | 不替代审计规则本身 |
| 后端返回什么 | 是否返回接收、待补、挂起、阻断、失败、回执、撤回、熔断等处理方向 | 不定义正式状态口径 |
| 前端展示什么 | 页面是否把处理方向展示为处理方向，而不是业务事实结论 | 不定义具体交互设计 |
| 双方停止什么 | 是否阻止越权、重复、失败、错误外显、错误确认和继续推进 | 不替代业务规则裁决 |
| 问题交给谁 | 问题是否归口到输入接口、回执接入、失败回退、页面承接、验收或业务运行规则 | 不直接修改上游规则 |

联调通过只表示前后端对接口边界的承接一致，不表示业务事实成立，不表示正式入链完成，也不表示后续验收自动通过。

## 三、联调对象范围

前后端联调应覆盖以下对象：

| 联调对象 | 典型动作 | 联调关注点 |
|---|---|---|
| 输入接口联调 | 文本录入、语音转写提交、图片上传、文件上传、表格导入 | 是否保留原始输入、来源线索和待补方向 |
| 外部映射联调 | 外部字段、状态、编号、主体、资料、回执表达进入系统 | 是否保留外部原值并形成候选映射 |
| 回执接入联调 | 生成结果、输出结果、外部响应、失败结果、反馈结果进入系统 | 是否形成可关联回执而非业务确认 |
| 失败回退联调 | 上传失败、识别失败、权限失败、超时、重复、外部展示异常 | 是否返回受控处理方向并停止后续动作 |
| 页面动作联调 | 提交、补齐、候选确认、生成、导出、查询、反馈、状态查看 | 是否按页面动作接口边界处理 |
| Mock 联调 | Mock 输入、Mock 回执、Mock 外部系统、Mock 页面状态 | 是否被标记为联调数据并与正式链路隔离 |
| 权限联调 | 查询、导出、分享、外部展示、外部协同范围控制 | 是否阻断越权数据返回和越权动作 |
| 状态提示联调 | 已接收、待补、挂起、阻断、失败、回执、熔断等页面提示 | 是否只展示处理方向，不展示为正式状态 |
| 外部协同联调 | 客户反馈、甲方反馈、甲方员工提交问题、供应商或班组反馈 | 是否只作为反馈或候选线索接入 |
| 授权输出联调 | 导出、分享、对外展示、生成分享包、外部发送 | 是否保留输出范围、版本、接收对象和处理结果 |

联调对象不得扩展为接口 schema 设计、页面原型设计、数据库设计或代码实现说明。

## 四、联调最低记录要求

前后端联调过程中，应至少保留以下记录类别：

| 信息类别 | 记录要求 | 不得误用 |
|---|---|---|
| 联调场景 | 标记本次联调对应的页面动作、接口动作和业务入口 | 联调场景不等于正式业务场景完成 |
| 发起主体 | 记录当前用户、外部协同对象或系统模拟主体 | 模拟主体不等于正式主体身份 |
| 页面动作 | 记录页面提交、上传、补齐、确认、生成、导出、查询或反馈动作 | 页面动作不等于业务确认 |
| 请求上下文 | 记录项目、主体、资料、候选、输出、查询范围或外部协同上下文 | 上下文不等于正式锚点 |
| 接口处理方向 | 记录接收、待补、挂起、阻断、失败、回执、撤回、熔断等结果 | 处理方向不等于正式状态 |
| 返回内容 | 记录接口返回给页面的可展示内容、原因提示和后续方向 | 返回内容不得替代正式事实 |
| 页面展示结果 | 记录页面是否正确展示处理方向、失败原因、待补项和回执结果 | 页面显示成功不等于业务成功 |
| Mock 标记 | 记录是否使用 Mock 输入、Mock 回执、Mock 外部系统或 Mock 页面数据 | Mock 数据不得进入正式链路 |
| 失败记录 | 记录失败原因、停止动作、归口方向和是否触发熔断 | 失败记录不等于业务否定结论 |
| 问题归口 | 记录问题属于前端展示、接口边界、回执接入、失败处理、权限、页面承接或验收断言 | 归口记录不替代正式修订 |

联调记录用于证明接口边界是否被前后端正确承接，不用于生成正式事实、正式状态或正式业务结论。

## 五、输入接口联调约定

| 前端发起 | 后端接收 | 后端返回 | 前端展示 | 问题归口 |
|---|---|---|---|---|
| 文本、语音转写、图片、文件、表格、附件、混合输入 | 原始输入、来源线索、提交主体、上下文、接收时间、资料线索 | 已接收、待补、挂起、阻断、上传失败或识别失败 | 展示输入处理方向、缺口提示、失败原因或继续补齐入口 | 输入接口规范、页面动作接口边界规则、失败回退与熔断规则 |

联调时必须验证：

1. 前端是否传递原始输入或原始输入引用，而不是只传递整理结果。
2. 后端是否返回输入接收结果和处理方向，而不是返回事实成立结论。
3. 页面是否把上传成功、提交成功、识别成功展示为接口处理结果，而不是资料有效、证据成立或事实成立。
4. 输入缺少项目、主体、资料、时间、证据或来源时，页面是否展示待补或挂起方向。
5. 输入失败、不可读、重复或权限不足时，是否进入失败回退。

## 六、外部系统映射联调约定

| 前端或外部来源发起 | 后端接收 | 后端返回 | 前端展示 | 问题归口 |
|---|---|---|---|---|
| 外部字段、外部状态、外部编号、外部主体、外部资料、外部回执表达 | 外部原值、来源系统、来源文件、候选映射方向、冲突线索 | 候选映射、待复核、冲突、挂起或人工处理 | 展示外部原值与候选映射关系，不展示为正式内部结果 | 外部系统映射规范、失败回退与熔断规则 |

联调时必须验证：

1. 外部原值是否被保留并可回看。
2. 外部字段是否只形成候选映射，不直接替代系统标准字段。
3. 外部状态是否只作为候选状态线索，不直接展示为正式状态。
4. 外部账号、联系人、群成员或审批人是否未直接展示为系统正式用户、正式主体或正式确认人。
5. 外部映射冲突时，接口是否返回待复核、挂起或人工处理方向。
6. 页面是否区分“外部原值”“候选映射”“需复核”“冲突”“已驳回”等处理方向。

## 七、回执接入联调约定

| 前端或后端动作产生 | 后端接收 | 后端返回 | 前端展示 | 问题归口 |
|---|---|---|---|---|
| 候选生成结果、资料识别结果、模板生成结果、授权输出结果、外部响应、失败结果 | 回执来源、原始回执、关联动作、关联对象、处理结果、时间线索 | 回执已接收、已关联、待补、挂起、失败、冲突或熔断 | 展示回执处理方向和关联对象，不展示为业务确认 | 回执接入规范、页面动作接口边界规则、失败回退与熔断规则 |

联调时必须验证：

1. 回执是否能关联到原输入、候选、资料、输出、外部动作或失败记录。
2. 回执成功是否未被页面展示为客户确认、甲方确认、付款确认、验收确认或责任确认。
3. 资料识别回执是否未被展示为证据成立。
4. 模板生成回执是否未被展示为正式文件成立。
5. 授权输出回执是否未被展示为外部主体已接受或已确认。
6. 回执缺失、超时、冲突或无法关联时，是否进入挂起、阻断或人工处理。

## 八、失败回退联调约定

| 失败来源 | 后端返回 | 前端展示 | 停止动作 | 问题归口 |
|---|---|---|---|---|
| 上传失败、识别失败、模板生成失败、外部提交失败、回执超时、权限失败、重复提交、外部展示异常 | 待补、挂起、阻断、受控重试、重复关联、撤回、纠偏、熔断或人工处理 | 展示失败原因、处理方向和后续动作，不展示为业务完成 | 停止继续生成、确认、导出、外显、入链或高风险动作 | 失败回退与熔断规则、页面状态与提示映射、前后端协同验收断言 |

联调时必须验证：

1. 失败是否被后端返回为明确处理方向。
2. 页面是否没有把失败隐藏为成功提示。
3. 页面是否没有在失败后继续触发下一受控动作。
4. 上传失败是否未被展示为资料有效。
5. 识别失败是否未被展示为正式内容已生成。
6. 外部提交失败是否未被展示为外部对象已确认。
7. 权限失败是否阻断返回数据、生成文件、分享和外部展示。
8. 熔断后相关受控动作是否暂停。

## 九、页面动作联调约定

| 页面动作 | 后端应返回 | 前端应展示 | 不得出现 |
|---|---|---|---|
| 录入提交 | 已接收、待补、挂起、阻断 | 输入处理方向 | 录入成功即事实成立 |
| 上传 | 已接收、上传失败、待补、阻断 | 上传处理方向和失败原因 | 上传成功即证据成立 |
| 反问补齐 | 已接收、继续待补、重新处理 | 补齐结果和剩余缺口 | 补齐完成即正式确认 |
| 候选确认 | 已接收、待补、阻断、交由后续处理 | 候选处理方向 | 页面确认即 L2 入链 |
| 候选驳回 | 已接收、挂起、驳回处理方向 | 当前候选不继续推进 | 驳回即事实不成立 |
| 模板生成 | 生成中、生成成功、待补、失败 | 候选文件或缺口提示 | 生成成功即正式文件成立 |
| 授权输出 | 生成中、输出成功、阻断、撤回、熔断 | 输出范围、版本和处理结果 | 分享成功即外部确认 |
| 查询筛选 | 查询结果、空结果、权限不足、阻断 | 权限范围内结果 | 越权数据返回 |
| 外部协同反馈 | 已接收、待补、挂起、回流 | 反馈处理方向 | 外部反馈直接改写真源 |
| 状态查看 | 当前处理方向、回执结果、失败原因 | 处理方向和提示 | 处理方向展示为正式状态 |

页面动作联调应验证页面是否正确承接接口返回的处理方向，而不是用前端文案或交互结果覆盖接口边界。

## 十、权限联调约定

权限联调用于验证前端页面可见范围、接口可调用范围和后端返回范围是否一致。

联调时应覆盖以下场景：

| 场景 | 后端应返回 | 前端应展示 | 停止动作 |
|---|---|---|---|
| 无权查询 | 权限不足或阻断 | 无权查看或无结果提示 | 停止返回数据 |
| 无权导出 | 阻断 | 无权导出提示 | 停止生成文件 |
| 无权分享 | 阻断 | 无权分享提示 | 停止外部发送 |
| 无权查看资料 | 权限不足或脱敏结果 | 权限受限提示或脱敏展示 | 停止原始资料直出 |
| 外部协同越界 | 阻断或挂起 | 外部身份范围不足提示 | 停止接收高风险动作 |
| 页面可见但接口无权 | 接口阻断 | 页面不得继续推进 | 停止后续动作 |

权限联调不得只以“页面隐藏按钮”作为通过依据。后端接口必须能在权限不足时返回受控处理方向。

## 十一、Mock 联调约定

Mock 数据用于联调页面承接和接口边界，不得被误认为正式数据或正式回执。

Mock 联调必须遵守以下规则：

1. Mock 输入、Mock 回执、Mock 外部系统、Mock 页面状态和 Mock 输出结果必须明确标记。
2. Mock 数据不得进入正式对象、正式事实、正式状态、正式权限或正式规则链路。
3. Mock 成功不得证明真实接口成功。
4. Mock 页面展示通过不得证明业务验收通过。
5. Mock 外部回执不得证明外部主体已确认。
6. Mock 授权输出不得形成真实导出、真实分享或真实外部展示。
7. Mock 失败、Mock 超时、Mock 权限不足和 Mock 熔断应覆盖负向联调场景。
8. Mock 结果应交给联调记录或验收断言，不得写入正式业务数据。
9. 由 Mock 切换到真实接口时，应重新验证输入、回执、失败、权限和页面提示边界。
10. 前端不得用 Mock 数据补齐后端未返回的数据并展示为真实结果。

Mock 的作用是验证页面与接口承接方式，不是替代后端规则、接口边界或正式验收。

## 十二、状态与提示联调约定

联调中的状态和提示应表达接口处理方向，不得反向定义正式状态。

| 接口返回 | 页面应表达 | 页面不得表达 |
|---|---|---|
| 已接收 | 系统已接收该动作或输入 | 事实已成立 |
| 待补 | 需要继续补充信息 | 系统已确认缺失事实 |
| 挂起 | 等待复核、回执、补齐或人工处理 | 业务已完成 |
| 阻断 | 当前动作不能继续 | 事实不成立 |
| 生成中 | 候选文件或结果正在生成 | 正式文件已成立 |
| 生成成功 | 候选结果已生成 | 正式文件已确认 |
| 输出成功 | 输出动作完成 | 外部主体已确认 |
| 回执已接收 | 回执进入系统 | 业务确认完成 |
| 失败 | 当前接口动作失败 | 业务否定结论 |
| 熔断 | 相关受控动作暂停 | 业务链路关闭 |

状态与提示联调应验证页面文案、提示框、状态标签和结果区是否避免把接口处理方向误写成正式业务结论。

## 十三、联调问题归口规则

联调过程中发现问题时，应按以下规则归口：

| 问题类型 | 归口位置 |
|---|---|
| 原始输入未保留、上传结果误展示、输入缺口未提示 | 输入接口规范、页面动作接口边界规则 |
| 外部字段、状态、编号直接覆盖内部结果 | 外部系统映射规范 |
| 回执无法关联、回执成功误展示为确认 | 回执接入规范 |
| 失败被隐藏、超时默认成功、失败后继续推进 | 失败回退与熔断规则 |
| 页面按钮或提示绕过接口边界 | 页面动作接口边界规则、70 页面承接文件 |
| Mock 数据进入正式链路 | 本文件、前后端协同验收断言 |
| 权限不足仍返回数据或生成文件 | 页面动作接口边界规则、权限相关上游规则 |
| 页面展示与接口返回不一致 | 70 页面状态与提示映射、页面动作与接口承接总表 |
| 联调通过但业务断言未覆盖 | 80 前后端协同验收断言 |
| 问题涉及字段、状态、权限或事实类型新增 | 阻断，不得在联调文件中补写 |

联调问题不得通过前端临时提示、接口临时返回值、Mock 数据或人工口头约定绕过正式归口。

## 十四、联调准出边界

前后端联调满足以下条件时，才可作为接口边界联调通过：

1. 页面动作能把来源、主体、上下文、目标对象和提交内容交给接口。
2. 后端能返回明确处理方向，而不是只返回成功或失败字样。
3. 页面能正确展示接收、待补、挂起、阻断、失败、回执、撤回、纠偏、熔断等处理方向。
4. 上传、识别、模板生成、外部提交、回执、权限、重复、超时和外部展示异常均有负向联调结果。
5. Mock 数据被隔离，并未进入正式链路。
6. 权限不足时，后端接口能够阻断读取、导出、分享、外显或确认动作。
7. 页面未把接口处理方向展示为正式事实、正式状态或正式确认。
8. 回执成功、输出成功、生成成功和上传成功均未被误展示为业务确认。
9. 失败后相关受控动作被停止或交给失败回退处理。
10. 联调问题能够归口到具体接口边界、页面承接或验收断言文件。

联调准出只表示前后端接口边界承接一致，不表示系统业务验收完成。

## 十五、禁止事项

前后端联调禁止出现以下行为：

1. 禁止把联调通过写成业务验收通过。
2. 禁止把 Mock 成功写成真实接口成功。
3. 禁止用 Mock 数据补齐后端未返回内容并展示为真实结果。
4. 禁止页面把接口返回的处理方向展示为正式事实、正式状态或正式确认。
5. 禁止上传成功、识别成功、生成成功、输出成功、回执成功被展示为业务确认完成。
6. 禁止权限不足时仅靠前端隐藏入口，不做后端接口阻断。
7. 禁止失败、超时、冲突、重复或熔断只在前端提示层消化。
8. 禁止联调中通过临时接口返回、前端默认值、外部字段或人工口头约定绕过接口边界。
9. 禁止联调文件新增字段、枚举、状态、权限、事实类型、接口 schema、页面布局、数据库结构或代码实现。
10. 禁止联调问题无归口、无记录、无处理方向。
