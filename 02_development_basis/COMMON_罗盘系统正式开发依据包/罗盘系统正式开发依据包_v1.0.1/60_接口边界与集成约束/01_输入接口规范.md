# 01_输入接口规范

## 一、文件定位

本文定义罗盘系统中输入类接口的接入边界和约束规则，用于约束文本、语音转写、图片、文件、表格、模板文件、外部反馈、外部回执和历史导入资料等输入通过接口进入系统时，如何被接收、保留、标记、挂接、阻断和交接。

本文只负责输入接口层面的承接边界，不判断输入内容是否成立为候选事实或正式事实，不替代 L0 原始输入规则，不定义 URL、HTTP 方法、请求响应结构、JSON schema、数据库字段、代码实现、上传组件、文件解析算法或 OCR 实现。

输入接口的核心职责是：把外部或页面提交的信息安全、完整、可追溯地接入系统，并交给 L0 原始输入层或对应治理链路处理。输入接口不得直接生成候选事实，不得直接触发 L2 真源入链或对外输出。

## 二、输入接口总职责

输入接口承担以下职责：

1. 接收人工录入、语音转写、图片、文件、表格、模板、外部反馈和外部载荷等输入来源。
2. 保留输入原始内容、原始材料引用、来源线索、提交主体线索、接收时间线索和上下文线索。
3. 初步识别输入形态、来源渠道、提交主体、项目线索、主体线索、资料线索和风险线索。
4. 判断输入是否具备进入 L0 原始输入层的最低接收条件。
5. 对来源不明、权限不明、项目归属不明、材料不可读、内容重复、证据不足或高风险事项触发待补、挂起、阻断、熔断或人工处理。
6. 为后续 L0 原始输入规则、L1 候选抽取规则、横向治理规则、资料归属规则和失败回退规则提供可追溯来源。
7. 向页面承接和联调验收提供输入接收结果、缺口提示、阻断原因和后续处理方向。

输入接口不承担以下职责：

1. 不确认事实是否发生。
2. 不确认资料是否有效。
3. 不确认主体身份和权限的最终结论。
4. 不确认客户、甲方、供应商、班组或内部人员是否已作出正式承诺。
5. 不把输入内容转为正式对象、正式事实、正式状态或正式规则。
6. 不生成汇总视图、经营判断、正式输出文件或对外展示内容。

## 三、可接入输入范围

输入接口可承接以下输入形态：

| 输入形态 | 可承接内容 | 接口边界 |
|---|---|---|
| 文本输入 | 人工录入、聊天文本、现场说明、会议记录、备注、复制粘贴内容 | 只接收原文和来源线索，不判断文字内容是否真实 |
| 语音转写输入 | 电话、语音、口述记录转写后的文本和不确定片段说明 | 只接收转写结果和不确定提示，不把转写结果直接写成事实 |
| 图片输入 | 现场照片、资料照片、截图、施工照片、问题照片 | 只接收图片本体或引用、说明和来源，不因图片内容推定事实成立 |
| 文件输入 | 合同、报价、预算、图纸、签证、验收资料、结算资料、付款凭证、发票回执、资料包 | 只接收文件本体、来源和读取状态，不确认文件效力或证据成立 |
| 表格输入 | 报价表、预算表、工程量清单、材料清单、结算表、统计表、导入表 | 只接收表格来源、结构线索和读取状态，不直接生成正式财务记录、结算结果或汇总结果 |
| 模板文件输入 | 公司模板、项目模板、签证模板、验收模板、结算模板、资料模板 | 只接收模板文件或模板候选线索，不确认模板正式启用 |
| 外部反馈输入 | 客户反馈、甲方反馈、甲方员工问题、供应商反馈、班组反馈、外部协同意见 | 只接收反馈原文和来源线索，不直接确认反馈事实成立 |
| 外部回执输入 | 签收、确认、驳回、补充、退回、执行结果、发送结果、系统返回结果 | 只接收回执材料和关联线索，具体回执边界由回执接入规范承接 |
| 历史导入输入 | 历史项目资料、历史台账、历史图片、历史表格、旧系统导出资料 | 只接收历史来源和导入线索，不直接进入当前正式事实链 |
| 混合输入 | 图文混合、文件加说明、表格加附件、语音转写加图片、外部反馈加资料 | 必须保留各输入组成部分和输入顺序，不得只保留整理结果 |

上述输入范围用于定义接入边界，不等于全部输入均可自动进入后续治理。是否继续流转，应按身份、权限、项目归属、资料归属、风险、校验和追溯要求判断。

## 四、输入接入前置条件

输入通过接口进入系统前，必须满足以下前置条件或进入相应处理分支：

1. 能识别输入来源或来源渠道；无法识别来源时，不得进入自动候选处理。
2. 能识别提交主体线索；提交主体不明时，应待补、挂起或阻断。
3. 能识别当前用户、组织、角色、项目范围或输入作用域；无法识别作用域时，不得进入确认、入链或授权输出方向。
4. 能保留原始内容或原始材料引用；只保留摘要、解析结果或 AI 处理结果的输入，不得替代原始输入。
5. 能记录接收时间，并保留业务发生时间线索与系统接收时间之间的区分。
6. 能保留资料、图片、文件、表格、附件和外部回执等证据线索。
7. 能初步识别是否涉及金额、责任、工期、变更、验收、结算、客户承诺、外部展示、隐私或高风险事项。
8. 能判断是否存在明显重复、来源冲突、内容冲突、权限不足、文件不可读、材料缺失或归属不明问题。
9. 能给出后续处理方向，包括进入 L0、待补、反问、挂起、阻断、重复关联、熔断或人工处理。

缺少上述条件时，输入接口不得以默认值、页面最近上下文、AI 推测、历史项目、用户习惯或外部字段自动补齐正式内容。

## 五、输入接口最低承接信息

输入接口不得直接定义数据库字段或接口 schema，但必须保证后续治理链路能够取得以下信息类别：

| 信息类别 | 承接要求 | 不得误用 |
|---|---|---|
| 输入标识 | 每次输入应具备可追溯的接收标识或载荷线索 | 不得复用旧输入标识制造新事实 |
| 输入来源 | 保留来源渠道、来源系统、页面入口、人工录入或外部提交线索 | 来源不等于事实可信 |
| 提交主体 | 保留提交人、提交组织、外部主体或系统来源线索 | 提交主体不等于确认主体 |
| 接收时间 | 保留系统接收时间，并区分业务发生时间线索 | 接收时间不得替代事实发生时间 |
| 原始内容 | 保留原文、原图、原文件、原表格、原始附件或可追溯引用 | 摘要、识别结果、AI 转译不得替代原始内容 |
| 输入形态 | 标记文本、图片、语音转写、文件、表格、模板、反馈、回执或混合输入 | 输入形态不得决定事实类型 |
| 项目线索 | 保留项目名称、地址、合同、资料包、上下文等候选线索 | 项目线索不等于正式项目锚点 |
| 主体线索 | 保留客户、甲方、员工、供应商、班组、外部协作方等候选主体线索 | 主体线索不等于正式主体身份 |
| 资料线索 | 保留资料名称、资料类型、附件关系、读取状态和归属线索 | 资料存在不等于证据成立 |
| 权限上下文 | 保留提交主体和当前作用域下的可见、提交、确认、导出或外部协同边界 | 接口可提交不等于业务可确认 |
| 风险线索 | 标记金额、责任、工期、结算、验收、变更、隐私、对外展示等风险线索 | 风险线索不等于风险裁决 |
| 去重线索 | 保留可用于重复识别的内容指纹、来源差异和版本差异 | 重复识别不得自动删除或覆盖原输入 |
| 处理结果 | 返回接收、待补、挂起、阻断、重复关联、需人工处理等处理方向 | 处理结果不得写成业务事实状态 |

输入接口承接上述信息，是为了保证 L0 原始输入层、横向治理和后续追溯可执行，不代表这些信息已经完成确认或入链。

## 六、输入形态处理规则

### 6.1 文本输入

文本输入应完整保留原文、来源、提交主体、接收时间、项目线索、主体线索和资料线索。

文本中出现的金额、责任、承诺、验收、变更、结算、收付款、工期或风险描述，只能作为候选线索进入后续治理，不得由输入接口直接转为正式事实。

### 6.2 语音转写输入

语音转写输入应保留转写文本、转写来源、转写不确定片段、原语音引用或来源说明。

方言、噪声、断句、金额、姓名、项目名、责任主体和时间存在不确定时，应标记待核对，不得由接口自动修正为正式表达。

### 6.3 图片和截图输入

图片和截图输入应保留图片本体或引用、来源、上传主体、拍摄或提交时间线索、关联项目线索、读取状态和说明。

图片识别结果、截图文字、现场照片内容和资料照片内容，不得直接确认施工完成、验收完成、签收完成、收付款完成或责任成立。

### 6.4 文件和附件输入

文件和附件输入应保留文件本体或引用、来源、文件名称、读取状态、资料线索、项目线索和异常情况。

文件上传成功不等于资料有效，文件可读不等于证据成立，合同、报价、预算、签证、验收、结算和付款凭证类文件不得由输入接口直接确认其业务效力。

### 6.5 表格和清单输入

表格和清单输入应保留表格来源、表格名称、读取状态、表头线索、项目线索、资料线索和异常情况。

表格读取结果不得直接生成正式财务记录、结算结果、正式物资流转事实或汇总视图结果。表格内容如需进入事实链，应由后续候选抽取、标准治理、人工确认和 L2 真源入链承接。

### 6.6 模板文件输入

模板文件输入应先作为资料类输入或模板候选线索处理。

模板文件上传、引用或解析成功，不等于模板正式启用，不等于模板输出内容正式成立，不等于经验规则层已发布正式规则。模板本体、模板使用动作、模板候选沉淀和候选文件生成，应分别按资料资产、资料记录、经验规则层和模板取数规则归口。

### 6.7 外部反馈输入

外部反馈输入应保留反馈原文、反馈来源、提交主体线索、关联项目线索、关联资料线索、反馈时间线索和风险提示。

客户、甲方、甲方员工、供应商、班组或外部协作方提交的问题、意见、补充、拒绝、确认或异议，不得由输入接口直接改写正式事实。涉及问题闭环、责任变化、资料补充、状态异议或事实修正的内容，应进入候选治理和回流挂接。

### 6.8 外部回执输入

外部回执输入应保留回执材料、来源主体、关联动作线索、关联输入线索、关联输出线索、接收时间线索和风险线索。

发送成功、阅读成功、签收、付款截图、系统返回成功、客户确认截图、供应商反馈等回执，不得由输入接口直接认定为业务确认。回执接入、分级、关联和后续流转，由回执接入规范承接。

### 6.9 历史导入输入

历史导入输入应保留历史来源、导入批次、来源范围、资料形成时间线索、当前有效性边界和待治理状态。

历史资料、旧台账、旧系统导出、旧表格和旧文件在完成当前规则治理、项目锚定、主体锚定、资料锚定和追溯补齐前，不得进入当前正式事实链。

## 七、输入接入后的流向规则

输入接口接收内容后，应按以下规则确定后续流向：

| 情况 | 后续流向 | 处理边界 |
|---|---|---|
| 来源、主体、权限、项目线索和原始内容具备最低接收条件 | 进入 L0 原始输入层 | 只形成原始输入和来源线索，不形成事实 |
| 项目、主体、资料、时间或证据线索不足 | 进入待补或关键字段反问 | 不得默认补齐 |
| 输入内容涉及金额、责任、工期、变更、验收、结算、外部承诺等高风险事项 | 进入高风险标记、人工处理或熔断 | 不得自动确认、自动外发或自动入链 |
| 输入主体权限不明或越权 | 阻断、降级为待确认输入或进入人工处理 | 不得进入自动候选处理 |
| 输入疑似重复 | 关联既有输入或标记重复线索 | 不得删除、覆盖或重复制造事实 |
| 文件不可读、损坏、缺页、格式异常或附件缺失 | 保留输入存在和异常原因 | 不得静默丢弃 |
| 输入属于外部回执或执行结果 | 交由回执接入规范或 L7 反馈回流规则承接 | 不得直接写成确认事实 |
| 输入属于历史资料或迁移资料 | 标记历史来源和待治理状态 | 不得直接进入当前正式事实链 |

输入接口只能决定输入是否被接收、挂起、待补、阻断、重复关联或转交对应治理链路，不决定业务事实是否成立。

## 八、重复提交与版本差异处理

输入接口应识别疑似重复提交，并保留重复线索。疑似重复不得被自动删除、覆盖、合并或替换既有输入、候选内容、正式对象或正式事实。

重复处理应至少区分以下情况：

1. 同一内容由同一主体重复提交。
2. 同一内容由不同主体提交。
3. 同一文件以不同版本提交。
4. 同一截图、图片或表格经过裁剪、转发或二次编辑后提交。
5. 同一外部反馈在不同渠道重复出现。
6. 历史资料与当前输入内容相似但来源不同。

重复输入可以被关联、标记、挂起或进入人工复核，但不得直接重复生成候选事实，更不得重复写入正式事实。

## 九、失败提示与阻断规则

输入接口应向页面、调用方或联调过程返回清晰的处理方向。处理方向应表达接口承接结果，不得表达业务事实结论。

输入接口应阻断或挂起以下情况：

1. 来源完全不明，且涉及金额、责任、验收、结算、变更、工期或外部承诺。
2. 提交主体不明，且无法确认其所在组织、项目或外部协同关系。
3. 权限不足或作用域不明，且输入可能影响候选生成、正式入链、外部展示或授权输出。
4. 项目归属无法判断，且无法通过上下文线索形成待补问题。
5. 原始内容缺失，只剩摘要、识别结果或 AI 整理结果。
6. 文件、图片、表格或附件不可读，且缺少可追溯来源。
7. 输入内容与既有内容冲突，且涉及高风险事项。
8. 外部反馈或回执无法关联任何项目、主体、动作、资料或输出对象。
9. 疑似恶意、污染、越权、跨组织、跨项目或跨主体提交。
10. 输入试图绕过 L0、L1、横向治理或 L2 真源入链层。

阻断、挂起、待补、重复关联和人工处理均应保留原因、来源、处理时间线索和后续处理方向，不得静默失败或伪造接收成功。

## 十、与 L0 原始输入规则的关系

输入接口与 L0 原始输入规则的分工如下：

| 分工对象 | 输入接口规范 | L0 原始输入规则 |
|---|---|---|
| 核心职责 | 规定输入如何通过接口被接收、保留、提示、阻断和交接 | 规定输入进入系统后如何作为原始输入被保留、隔离、标记、待补和交给 L1 |
| 处理对象 | 页面提交、外部提交、上传、导入、反馈、回执等接口接入动作 | 已进入系统的原始输入、来源记录、输入元信息和待补线索 |
| 可形成结果 | 接收结果、缺口提示、阻断原因、重复关联、转交方向 | 原始输入记录、来源记录、待补要求、阻断原因和 L1 交接材料 |
| 禁止事项 | 不判断事实成立，不直接生成候选或正式事实 | 不定义接口协议，不定义上传实现，不定义页面交互 |

输入接口是 L0 原始输入层的入口承接，不是 L0 的替代。输入接口接收成功，只表示输入材料已被系统承接或进入处理分支，不表示输入内容已经进入候选事实，更不表示正式事实成立。

## 十一、与页面承接、联调和验收的关系

70 目录应基于本文承接以下页面表达：

1. 页面应明确区分“已接收”“待补”“挂起”“阻断”“重复关联”“需人工处理”等输入处理方向。
2. 页面不得把上传成功、提交成功、识别成功、转写成功或导入成功展示成事实成立。
3. 页面应在项目归属不明、主体不明、资料不明、证据缺失、权限不足或高风险事项出现时，引导补齐或提示阻断原因。
4. 页面不得用默认项目、最近项目、默认主体、默认资料或 AI 推测替代用户确认。
5. 页面应保留用户理解成本，但不得因此省略必要的权限、风险和追溯提示。

80 目录应基于本文验证以下断言：

1. 输入接口是否保留原始输入和来源线索。
2. 输入接口是否未直接写入正式事实。
3. 输入接口是否未跳过 L0 原始输入层。
4. 权限不足、来源不明、项目不明、证据不足和高风险输入是否被待补、挂起、阻断或熔断。
5. 上传成功、解析成功、识别成功和接收成功是否未被误判为业务确认。
6. 重复输入是否被关联或标记，而不是重复制造事实。
7. 外部反馈和回执是否未直接改写真源。

## 十二、禁止事项

输入接口禁止出现以下行为：

1. 禁止绕过 L0 原始输入层直接进入 L1、L2、L3 或外部输出。
2. 禁止把输入接收成功、上传成功、解析成功、导入成功或识别成功写成业务事实成立。
3. 禁止把文本、图片、语音转写、文件、表格、模板、外部反馈或回执直接写入正式事实。
4. 禁止只保留摘要、识别结果、结构化结果或 AI 辅助预处理结果而丢弃原始输入。
5. 禁止用接口默认值、页面默认值、最近上下文、AI 推测或外部字段自动补齐正式内容。
6. 禁止让外部主体提交内容直接形成客户确认、甲方确认、供应商承诺、班组完成、金额确认、结算确认、验收确认或责任确认。
7. 禁止疑似重复输入自动覆盖、删除、合并或替换正式事实。
8. 禁止来源不明、权限不明、证据不足或高风险输入继续自动推进到确认、入链或授权输出方向。
9. 禁止把模板文件输入、模板使用结果或候选文件生成结果写成正式模板、正式规则或正式事实。
10. 禁止为了接口实现便利新增字段、枚举、状态、权限、事实类型、架构层级、系统能力或业务边界。
