# 模块边界图

本文描述当前罗盘仓库中主要模块的职责、输入、输出和禁止项。

> 模块目录存在不等于能力已经完成验收。边界用于约束开发方向，实际状态以测试和联调结果为准。

## 前端边界

| 模块 | 主要职责 | 允许输出 | 禁止事项 |
|---|---|---|---|
| `apps/h5` | 用户输入、状态承接、页面动作、查询、上传、语音和待确认交互 | API 请求、页面状态、用户提示 | 不决定权限，不裁决 S2，不直接生成正式事实 |
| `apps/pc` | 治理工作台、人工处理、正式事实和权限范围展示 | 人工处理请求、查询请求、工作台视图 | 不绕过后端确认和入链规则 |
| `apps/mobile-shell` | WebView 容器、原生插件和移动端桥接 | 原生能力事件、容器状态 | 不复制业务规则，不成为事实真源 |

## 后端纵向模块

| 模块 | 职责 | 主要输入 | 主要输出 | 禁止事项 |
|---|---|---|---|---|
| `l0_input` | 接收并保存原始输入 | 文本、来源、幂等键、运行上下文 | 原始输入记录、输入会话 | 不直接创建正式事实 |
| `l1_candidate` | 从原始输入形成候选 | L0 输入及上下文 | 一个或多个候选记录 | 不替代 S2 治理和人工确认 |
| `l2_fact` | 在条件满足后创建正式事实 | 候选、治理结果、确认记录、来源链 | L2 正式事实 | 不接受未经治理或未经确认的前端直写 |
| `l3_query_view` | 查询和展示已有正式事实 | 查询条件、正式事实标识 | 只读列表、详情和视图 | 不通过查询创造或修改事实 |
| `l4_analysis` | 基于正式事实形成分析结果 | L2/L3 正式事实和上下文 | 分析结果或预览 | 不把分析结果伪装成正式事实 |
| `l5_recommendation` | 基于分析形成建议候选 | 分析结果和正式事实 | 建议候选 | 不自动执行，不替代人工决策 |
| `l6_execution` | 承接经确认的执行动作和状态 | 建议、执行指令、权限上下文 | 执行响应和状态 | 不绕过权限与治理边界 |
| `l7_feedback` | 接收执行反馈并形成回流候选 | 执行结果、人工反馈 | 反馈记录或新候选输入 | 不直接回写或篡改既有正式事实 |

## 横向治理模块

| 模块 | 职责 | 贯穿范围 | 禁止事项 |
|---|---|---|---|
| `s1_runtime_context` | 提供用户、组织、角色、项目和允许动作等运行上下文 | 业务路由和关键页面 | 不把前端声明直接当成最终权限真源 |
| `s2_governance_gate` | 校验候选完整性、风险、状态和下一步动作 | L1 到 L2 之间 | 不允许被前端或 AI 绕过 |
| `s3_audit_trace` | 记录来源、动作、状态变化和追溯信息 | 关键业务动作 | 不承担业务裁决，不替代正式事实 |
| `standard_governance` | 提供统一字段、状态、规则、问题和风险口径 | 各纵向和横向模块 | 不在各模块复制冲突规则 |

## 扩展模块

| 模块 | 职责 | 边界 |
|---|---|---|
| `upload` | 保存上传原件并返回文件标识 | 上传成功不等于生成候选或正式事实 |
| `voice_transcription` | 将语音转为文本并返回来源信息 | 转写结果仍需按录入、查询或分析入口继续处理 |
| `ai_assist` | 输入整理、候选辅助、分析或建议预览 | AI 不拥有治理放行、确认和权限裁决权 |
| `external_collaboration` | 外部协作能力的接入口 | 外部输入必须进入受控来源链和治理链路 |
| `assets` | 项目、主体、文件、材料等对象资产能力 | 对象资产与事实记录职责不得混用 |
| `system_admin` | 系统级管理入口 | 不应承载普通业务流程 |

## 数据与契约边界

- `services/api/app/db` 当前集中承接后端持久化基础设施。
- `packages/contracts` 承接 OpenAPI 和 JSON Schema 契约。
- 后端 FastAPI 路由与 Pydantic Schema 是运行时 API 真源。
- H5、PC 和共享类型只能镜像后端关键状态，不得各自发明冲突枚举。
- 视图只消费事实，不创造事实。

## 开发规则

1. 新功能必须先确定所属模块，禁止把跨模块流程长期堆在页面或总路由中。
2. 跨模块调用优先通过明确的 service、port、API 或契约，不依赖隐式状态。
3. S1、S2、S3 是横向约束，不得被当成普通可选功能。
4. 所有 L2 写入必须能够追溯到 L0/L1、S2 和人工确认。
5. 模块 README、架构文档和代码状态需要同步更新，但执行过程报告不得进入源码仓库。
