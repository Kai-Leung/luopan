# L0–L7 纵向链路图

罗盘纵向链路用于把原始输入逐步转化为可追溯的正式事实、分析、建议、执行和反馈。

```text
L0 原始输入
  ↓
L1 候选提取
  ↓
S2 治理校验
  ↓
人工确认 / 待补 / 驳回
  ↓
L2 正式事实
  ↓
L3 查询与视图
  ↓
L4 分析
  ↓
L5 建议
  ↓
L6 执行响应
  ↓
L7 反馈回流
```

S1 运行上下文在进入各业务能力前提供身份、组织、角色、项目和允许动作。S3 审计追踪横向记录关键来源和状态变化。

## L0：原始输入

职责：

- 保存用户或外部来源提交的原始内容；
- 记录来源类型、输入会话和幂等信息；
- 保留后续追溯所需的原始载荷。

禁止：

- 直接生成 L2 正式事实；
- 在原始输入层完成最终业务裁决。

## L1：候选提取

职责：

- 根据 L0 内容提取一个或多个候选事项；
- 形成候选类型、字段和摘要；
- 将多事项输入拆成可独立治理的候选。

禁止：

- 把候选当成正式事实；
- 绕过 S2 和人工确认。

## S2 与人工确认

L1 到 L2 之间必须经过治理闸门。

S2 输出可能包括：

```text
need_confirm
ask_more
blocked
ready_to_chain
```

具体状态以当前 contracts 和后端实现为准。

人工处理包括：

- 确认；
- 退回补充；
- 驳回。

前端不得根据页面状态自行认定已经入链。

## L2：正式事实

职责：

- 在来源、候选、治理和确认条件满足后创建正式事实；
- 保存事实类型、载荷、状态和来源关联；
- 作为后续查询、分析和执行的真源。

禁止：

- 接受未经后端复核的前端直写；
- 通过查询、分析或 AI 结果反向伪造事实。

## L3：查询与视图

职责：

- 查询正式事实；
- 提供列表、详情、摘要和只读视图；
- 为 L4 分析提供正式事实输入。

禁止：

- 查询时新增或修改事实；
- 把视图汇总结果当成新的正式事实。

## L4：分析

职责：

- 基于已有正式事实形成分析结果或分析预览；
- 明确分析依据和关联事实。

禁止：

- 在没有正式事实依据时伪造结论；
- 自动将分析结论写入 L2。

## L5：建议

职责：

- 根据正式事实和分析结果形成建议候选；
- 保留建议依据、适用范围和风险提示。

禁止：

- 把建议描述成已执行结果；
- 未经人工决策自动进入执行。

## L6：执行响应

职责：

- 承接经确认的执行动作；
- 记录执行请求、状态和结果；
- 为 L7 反馈提供执行上下文。

禁止：

- 绕过权限范围；
- 用执行状态覆盖或篡改 L2 正式事实。

## L7：反馈回流

职责：

- 接收执行后的结果、偏差和人工反馈；
- 形成可追溯的反馈记录；
- 必要时将新信息送回候选和治理链路。

禁止：

- 直接修改既有事实以隐藏历史；
- 将反馈自动放行为新的正式事实。

## 当前验收口径

- L0–L3 是当前核心事实闭环，应优先保持稳定和可验证。
- L4–L7 已有模块和路由，不等于完整业务闭环已完成生产验收。
- 任何阶段新增状态、字段或动作，都必须同步 contracts 和测试。
- 页面展示、目录占位和 Mock 不能作为能力完成证据。
