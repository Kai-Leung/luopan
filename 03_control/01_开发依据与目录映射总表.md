# 01_开发依据与目录映射总表

文件名：01_开发依据与目录映射总表.md  
文件类型：开发依据承接控制文件  
目录架构版本：ARCH_DIR_v0.1.0  
用途：说明罗盘系统正式开发依据包在 ARCH_DIR_v0.1.0 目录树中的承接关系。  

---

## 1. 文件定位

本文件是开发依据包与代码目录之间的总映射表。

它只回答三个问题：

1. 开发依据包中的每一类依据，应由哪些目录承接；
2. 目录树中的主要目录，分别受哪些开发依据约束；
3. 哪些开发依据只能作为上位约束，不应直接生成同名代码模块。

本文件不负责：

- 编写任务卡；
- 安排开发顺序；
- 编写代码；
- 编写执行器指令；
- 修改正式开发依据；
- 判断阶段验收通过。

---

## 2. 总体映射原则

| 原则 | 说明 |
|---|---|
| 开发依据不等于代码目录 | 不得把 `10_顶层定义`、`20_系统架构`、`30_标准治理` 等直接生成同名代码模块 |
| 代码目录必须承接依据 | 所有代码目录必须能说明其承接的开发依据 |
| 前端不裁决事实 | `apps/h5`、`apps/pc`、`apps/mobile-shell` 只做交互、展示、动作发起 |
| 后端承接主业务规则 | `services/api` 承接权限、治理、事实、查询、接口、追溯 |
| contracts 先行约束前后端 | `packages/contracts` 统一请求、响应、状态、错误和处理方向 |
| L2 是正式事实入口 | 任何输入、候选、AI、上传、外部反馈不得绕过 S2 直接进入 L2 |
| 视图和分析不反写真源 | L3/L4/L5/L6/L7 只能消费、建议、执行、反馈，不得覆盖正式事实 |
| 验收不等于运行无报错 | 页面可点、接口 200、构建通过、执行器无报错，都不能单独代表验收通过 |

## 7. 结论

本文件是开发依据与 ARCH_DIR_v0.1.0 的总映射表。

```text
开发依据
→ 目录落位
→ 目录反查依据
→ 禁止误用
```

后续任务卡和代码开发必须以本文件为承接索引之一。  
未被本文件映射支撑的能力，不应进入代码实现。
